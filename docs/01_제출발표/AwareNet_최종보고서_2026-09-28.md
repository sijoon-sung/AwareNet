## 요 약 문

개발 목적 및 필요성

분할 연합학습은 클라이언트의 계산 부담을 서버와 나누지만, 배치마다 활성값과 기울기를 전송하므로 통신 지연에 민감하다. 모델 폭을 줄이면 계산과 전송 부담을 낮출 수 있으나 학습 정확도에도 영향을 준다. 따라서 느려졌다는 이유만으로 모델을 축소하기보다, 네트워크 조정으로 해소할 수 있는 지연을 먼저 판단해야 한다.

제안 방법

AwareNet은 클라이언트의 계산 시간과 경로별 전송 상태를 바탕으로 다음 라운드의 모델 크기, 중계 서버, 전송 비율을 결정한다. 모델 조절 방식은 학습 모듈로 분리했다. 초기의 고정된 채널 선택을 보완해 FedRolex식 순환 선택을 추가했으며, CNN과 LoRA 언어모델의 두 구현에서 각각 결합 제어와 분할 공동 학습을 확인했다. 핵심은 특정 모델의 축소법보다, 학습 부담과 네트워크 상태를 같은 완료 시간 기준으로 연결하는 데 있다.

실험 및 주요 결과

먼저 KOREN을 경유하는 실제 전송 구간에서 동시 전송 증가에 따른 지연을 확인했다. 이를 바탕으로 CPU·메모리 한도 안에서 혼잡을 반복 평가하도록 회선 조건과 참여 규모를 축소했다. 32개 논리 클라이언트의 단기 제어 평가와 8개 클라이언트의 장기 학습을 수행하고, 실제 Jetson 측정과 LoRA 실행으로 자원 제약을 함께 확인했다.

## Ⅰ. 서 론

1. 개발 목적 및 필요성

병원이나 제조 현장에 쌓인 데이터를 공동 모델 학습에 활용하려면, 자원이 서로 다른 클라이언트도 학습에 참여할 수 있어야 한다. 연합학습은 데이터를 각 현장에 두고 학습 결과를 모으며, 분할 연합학습은 모델의 계산을 클라이언트와 서버에 나눈다.[1,2] 이때 배치마다 활성값과 기울기를 교환하므로 계산이 느린 클라이언트뿐 아니라 전송이 밀리는 구간도 전체 학습을 지연시킨다.

모델 폭을 줄이는 부분 모델 학습은 이러한 부담을 낮추는 방법이다. 그러나 모델을 작게 할수록 표현 능력과 파라미터의 학습 기회가 바뀌므로 정확도 손실을 함께 고려해야 한다.[3,4] 네트워크 경합 때문에 느려진 클라이언트까지 일괄 축소하면, 경로 조정으로 해결할 수 있는 상황에서도 정확도를 불필요하게 낮출 수 있다. 반대로 계산 자체가 느리거나 우회 경로도 포화돼 있으면 경로 변경만으로는 대기가 줄지 않는다.

본 프로젝트는 이 차이에 주목한다. 동기식 학습에서는 마지막 클라이언트가 끝나야 다음 라운드로 진행하므로, 계산과 전송 가운데 무엇이 완료를 늦추는지 판단해야 한다. AwareNet은 허용된 경로의 여유와 모델 축소의 시간 이득을 함께 평가해, 필요한 클라이언트에 필요한 만큼 조절을 적용한다. 목표는 불필요한 모델 축소를 줄이면서 라운드 완료 시간을 단축하는 것이다.

2. 특징(차별성·독창성·혁신성)

FjORD와 FedRolex는 자원에 맞는 부분 모델 학습을, AdaptSFL과 SuperSFL은 이질적인 자원에서의 분할 학습 구성을 다룬다.[3–6] AwareNet은 이러한 학습 방법을 네트워크 상태 관측과 연결한다. 모델 크기에 따른 계산·전송량 변화와 경로 배정에 따른 통신 시간을 함께 계산하고, 실제 텐서 전송 결과를 다음 라운드의 결정에 반영한다.

첫째, 학습 부담 조절과 전송 경로 선택을 동일한 시간 기준으로 비교하는 스케줄러를 구현했다. 둘째, 모델 추출·집계와 전송 제어를 분리해 학습 알고리즘을 교체할 수 있게 했다. CNN에서는 채널 선택을, 언어모델에서는 LoRA를 연결해 적용 범위를 살폈다. 셋째, KOREN 실망에서 관찰한 전송 경합을 바탕으로 축소 실험을 구성하고 실제 Jetson의 연산 특성까지 측정했다. 각 실험은 Ⅲ장에서 목적과 조건을 함께 제시한다.

## Ⅱ. 아이디어 개발 추진 내용과 범위

1. 개발 목표 및 추진 내용

가. 모델과 네트워크를 연결하는 구조

개발 목표는 계산과 통신 상태가 바뀌어도 여러 클라이언트가 함께 학습을 진행할 수 있도록 모델 구성과 전송 배정을 조정하는 것이다. 클라이언트는 모델 앞부분을, 학습 서버는 뒷부분을 실행한다. 중계 서버는 텐서를 전달하고, 스케줄러는 측정 결과를 받아 다음 라운드의 설정을 정한다.

그림 1. 상태 수집, 모델 조절, 전송 제어를 연결한 전체 구조. 실선은 데이터 전달, 점선은 설정·상태의 흐름을 나타낸다.

상태 수집부는 클라이언트별 계산 시간과 연결별 전송량·소요 시간을 모은다. 계획부는 후보 모델 크기와 허용 경로의 예상 완료 시간을 비교한다. 실행부는 선택한 부분 모델, 중계 배정, 연결별 전송 비율을 적용한다. 이 결과를 다시 측정하므로 설정과 관측이 라운드마다 연결된다.

모델 조절 모듈은 사용할 파라미터와 집계 위치를 정하고, 전송 모듈은 텐서 조각의 전달과 재조립을 맡는다. 따라서 부분 모델 선택 알고리즘을 바꾸더라도 전송 구조를 다시 만들 필요가 없다. 새 알고리즘을 연결할 때에는 계산 시간, 전송량, 메모리와 집계 규칙을 해당 모델에 맞게 제공한다.

나. 폭 축소의 문제와 채널 선택의 개선

초기 구현은 FjORD 계열의 앞쪽 채널 선택으로 클라이언트의 계산 부담을 줄였다. 이 방식에서는 작은 모델을 쓰는 클라이언트가 같은 부분만 반복 학습하므로, 해당 클라이언트의 데이터가 반영되는 파라미터가 제한될 수 있다. 기존 정확도 검토를 바탕으로 FedRolex식 채널 순환 선택을 추가했다. 순환 선택은 부분 모델의 크기를 유지하면서 라운드마다 학습할 채널을 바꾸어 전역 모델의 학습 기회를 분산한다.[3,4,12]

CNN에서 모델 폭은 계층별 채널 수다. 따라서 이번 개선은 폭 대신 다른 차원을 줄이는 것이 아니라, 축소된 모델에 넣을 채널을 선택하는 방법을 바꾼 것이다. 계층 수인 깊이와 클라이언트·서버의 계산 경계인 분할 위치는 구분한다. CNN 평가에서는 계층 구조와 분할 위치를 고정하고 채널 수와 선택 위치를 조절했다.

다. CNN과 LoRA를 함께 평가한 이유

CNN은 채널 수를 바꾸었을 때 계산량과 전송량의 관계가 명확해 결합 제어를 평가하기에 적합하다. 예를 들어 같은 배치와 공간 크기에서 활성값의 채널 수를 128개에서 96개로 줄이면 활성값 크기도 25% 감소한다. 이 관계를 이용해 경로 변경과 모델 축소의 시간 이득을 비교했다. CNN은 스케줄러를 검증하는 구체적인 모델이며, 적용 범위를 정하는 전제는 아니다.

표 2. 공통 시스템에 연결한 두 학습 구현

| 구분 | CNN 부분 모델 학습 | LoRA 언어모델 학습 |
| --- | --- | --- |
| 부담을 줄이는 방식 | 사용 채널 수 조절 고정·순환 선택 | 기반 가중치 고정 작은 추가 행렬 학습 |
| 전송량과의 관계 | 채널 수에 따라 활성값 크기 변화 | 랭크는 집계량에 영향 활성값 크기는 유지 |
| 확인한 범위 | 폭·경로 제어의 시간과 정확도 별도 순환 선택 학습 | 분할 실행, 메모리 사용, 3클라이언트 연합 집계 |

LoRA는 큰 언어모델의 학습 파라미터를 줄이는 방법으로, CNN과 다른 모델에서도 자원이 제한된 클라이언트의 공동 학습을 구성할 수 있는지 확인하기 위해 사용했다.[7,8] 두 구현은 분할 실행과 연합 집계라는 공통 구조를 사용한다. LoRA 실험은 고정 랭크로 수행했으며, 같은 동적 제어를 확대 적용하려면 랭크별 계산·통신 특성을 별도로 측정해 스케줄러에 연결한다.

라. 라운드 완료 시간과 선택 기준

동기식 분할 연합학습의 한 배치 시간은 클라이언트 계산 Cᵢ, 활성값 전송 Uᵢ, 서버 처리 Sᵢ, 기울기 반환 Dᵢ의 합이다.[2,5] 각 항은 초 단위이고 서버 처리에는 대기 시간도 포함한다. 클라이언트 i의 배치 평균을 τᵢ, 라운드당 배치 수를 B, 모델 배포·집계 등의 시간을 T₀라고 하면 다음처럼 정리할 수 있다.

$$
\tau_i=C_i+U_i+S_i+D_i
$$

$$
T_{round}\approx T_0+\max_i(B\tau_i)
$$

모델 설정 mᵢ와 경로 배정 P가 정해지면, 계산 시간과 전송 시간을 측정 프로파일로 예측한다. 아래 식에서 bᵢ는 한 배치의 왕복 전송 바이트, Rᵢ는 해당 배정에서 예상하는 실효 전송률이다. oᵢ는 서버 처리 등 나머지 시간이다. mᵢ를 바꾸면 계산량과 전송량이, P를 바꾸면 Rᵢ가 달라지므로 두 변수를 함께 평가한다.

$$
\widehat T_i(m_i,P)=B\left[c_i(m_i)+\frac{8b_i(m_i)}{R_i(P)}+o_i\right]
$$

CNN 구현은 모델 설정을 폭 비율 w로 나타내고 계산 시간은 cᵢwᵞ, 전송량은 bᵢw로 근사한다. γ는 폭에 따른 계산량 변화를 나타내는 지수다. 경로 배정은 공유 접속 회선과 중계 용량을 함께 고려한다. 다른 모델에는 해당 모델의 계산·전송 프로파일을 적용한다. N개 클라이언트의 폭 선택은 다음 비용으로 평가한다.

$$
J=\max_i\widehat T_i+\frac{\lambda}{N}\sum_i(1-w_i)
$$

λ는 모델 폭을 보존하는 정도를 정하는 가중치다. 단위는 초이며, 값이 클수록 모델 축소에 더 큰 시간 이득을 요구한다. 32개 중 4개의 폭을 1.0에서 0.75로 줄이면 평균 폭 감소는 0.03125다. λ=70일 때 축소 비용은 약 2.19초이므로, 그보다 큰 완료 시간 감소가 있는지 비교한다. 정확도 손실은 이 값으로 환산했다고 가정하지 않고 학습 평가로 확인한다.

계획부는 현재 폭에서 경로 후보를 먼저 평가하고 남는 지연에 폭 조절을 적용한다. 경로 단계는 시간 합계와 N배의 최대 시간을 함께 반영해 가장 늦은 클라이언트의 영향을 높인다. 폭이 바뀌면 전송량도 변하므로 경로를 다시 확인한다. 유한한 후보를 단계적으로 탐색해 실제 라운드에 적용할 설정을 정한다.[12]

2. 단계별 세부 구현 계획

가. 다중 경로 전송과 결합

전송부는 한 텐서를 여러 조각으로 나누어 허용된 중계 연결에 배분한다. 수신 측은 전송 식별자와 조각 위치로 원래 텐서를 복원한 뒤 학습을 진행한다. 학습이 끝난 후에는 모델 모듈이 파라미터의 위치를 맞추어 연합 집계를 수행한다. 텐서 재조립과 모델 집계는 서로 다른 단계다.

그림 2. 다중 연결을 통한 텐서 전달. 전송 조각을 원래 순서로 결합해 하나의 학습 입력을 복원한다.

조각 배분은 가장 늦게 도착하는 연결의 전송 시간을 줄이도록 정한다. 독립적인 30 Mbps·10 Mbps 연결이라면 3:1 배분을 검토할 수 있으며, 공유 구간이 있으면 그 상한을 함께 적용한다. λ는 조각의 비율이 아니라 모델 축소 여부에 작용한다. 경로를 바꾼 뒤 계산 또는 공유 회선의 부담이 남을 때 모델 축소를 선택한다.

나. 계측부터 실행까지의 단계

첫 단계에서는 모델 크기별 계산 시간과 전송량, 연결별 전송 상태를 측정한다. 두 번째 단계에서는 이 값을 시간 모형에 넣어 경로와 부분 모델을 선택한다. 세 번째 단계에서는 실제 전송과 학습을 실행하고, 예측 시간과 관측 시간의 차이를 다음 계획에 반영한다. 작은 관측 변화에 반복 전환하지 않도록 이동 수와 변경 속도를 제한한다.

제어 에이전트는 라운드 단위로 설정을 갱신하고 패킷 전달과 재전송은 TCP가 처리한다. 현재는 후보와 판단식이 명확하므로 계산 비용이 작고 선택 이유를 확인할 수 있는 규칙 기반 탐색을 사용한다. PyTorch 학습과 지속 TCP 전송을 연결했으며, 통제 실험의 회선 제한은 관리 호스트의 Linux 트래픽 제어로 적용했다.

## Ⅲ. 아이디어 개발 진행 내용 및 결과

1. 개발 수행 현황 및 중간 결과물

가. KOREN에서 확인한 병목과 축소 실험

KOREN과 같은 연구망에서도 여러 클라이언트가 같은 시점에 데이터를 보내면 종단 간 전송 구간에 경합이 생긴다. 본 프로젝트는 HPC에서 KOREN VM을 경유하는 실제 텐서 전송을 먼저 측정했다. 접속·중계 상한을 4 Gbps 수준으로 높인 조건에서 동시 전송 수를 8~96개로 늘려, 낮은 인위적 제한에 앞서 실제 경로에서 생기는 지연을 확인했다.[11]

그림 3. KOREN 실경로의 동시 전송 규모별 완료 시간. 상·하행 각 4.2 MB, 4배치×3라운드, TCP 두 연결. 배치 왕복과 동시 버스트를 각각 측정했다.

배치 왕복 중앙값은 8개에서 0.41초, 32개에서 2.18초로 늘었다. 이 관측은 양호한 연구망에서도 학습 트래픽의 동시성이 완료 지연을 만들 수 있음을 보여준다. 측정 범위는 HPC·접속 구간·VM을 포함한 종단 간 경로이며, 지연의 발생 지점을 KOREN 코어 장비 하나로 특정한 실험은 아니다.

이 병목을 반복 평가하기 위해 SHRiNK의 축소 실험 관점을 참고해 회선 용량과 부하 조건을 조정했다.[9] 충분한 학습 프로세스를 장시간 실행하면 CPU와 메모리 부족이 발생하므로, 32개 논리 클라이언트로 단기 제어 응답을 확인하고 8개로 줄여 장기 학습을 수행했다. 회선에 속도 제한과 변동을 적용해 적은 자원에서도 전송 경합과 복구 과정을 관찰했다.

기록의 대역폭 0.1배 조정과 클라이언트 수 32→8 축소는 각각 회선 조건과 계산 자원의 축소다. 실측에서 확인한 병목을 제어 가능한 조건으로 옮긴 것이며, 두 실행의 절대 시간을 직접 합산하지 않는다. 다음 표에 비교별 규모와 교란 조건을 명시했다.

나. 실험 조건과 라운드 완료 시간

표 3. 제어 응답 및 장기 학습의 실행 조건

| 항목 | 단기 제어 평가 | 장기 학습 평가 |
| --- | --- | --- |
| 공통 모델·배치 | ResNet-18 / CIFAR-10 분할 위치 2 / 배치 32 | ResNet-18 / CIFAR-10 분할 위치 2 |
| 규모·반복 | 32개 논리 클라이언트 24라운드×3시드 | 8개 논리 클라이언트 200라운드×2시드 |
| 실행 배치 | HPC CPU 클라이언트·V100 서버 KOREN VM 2대, 논리 중계 4개 | 동일 연구망 기반의 축소 실행 학습 품질까지 장기 관찰 |
| 교란·설정 | 정상 / 한 중계 1/4 용량 4개 클라이언트 연산 지연 / 용량 변동 | λ=18·70·280 실행별 조건은 E7·E8에 수록 |

단기 평가: 라운드당 4배치, 접속 상한 5/2 Mbps, 정상 중계 용량 각 56 Mbps, 폭 후보 0.5·0.75·1.0, λ=70, 라운드당 이동 최대 3개. 장기 평가도 라운드당 4배치를 사용했다.

그림 4. 고정 폭·단일 연결 기준선과 폭·경로 결합 구성의 평균 라운드 시간. 초기 4라운드 제외 후 세 시드 평균.

트래픽 몰림에서 109.51초가 62.87초로 줄어 42.6%, 연산 지연에서 79.12초가 47.26초로 줄어 40.3% 단축됐다. 몰림 조건의 평균 폭은 0.998로 대부분 유지했고, 연산 지연에서는 느린 클라이언트 4개의 폭을 0.75로 줄였다. 경로 혼잡과 계산 지연에 서로 다른 조치를 적용한 결과다.[11]

기준선은 단일 연결, 결합 구성은 두 연결을 사용하므로 수치는 전체 구성의 비교다. 응용 전송량 감소는 최대 3.12%로 시간 단축보다 작았다. 따라서 보낸 바이트 수와 함께 경합 및 가장 늦은 클라이언트의 완료 시간을 고려해야 한다. 연결 수를 맞춘 비교는 후속 검증에 포함한다.

다. 모델 축소와 학습 품질

폭 조절은 속도를 높이는 수단인 동시에 학습할 모델의 크기를 바꾸는 선택이다. 8클라이언트·200라운드 기록에서는 λ를 바꾸어 시간과 정확도의 관계를 확인했다. 시간은 초기 4라운드를 제외한 평균, 정확도는 마지막 50라운드의 평가 평균이며 각 값을 두 시드에 대해 평균했다. 평가에는 테스트셋의 앞 2,000개 표본을 사용했다.[11]

표 4. 축소 가중치에 따른 시간과 정확도

| 설정 | 라운드 시간 | 평균 폭 | 정확도 | 시간 단축 |
| --- | --- | --- | --- | --- |
| 기준선 | 19.11초 | 1.000 | 65.52% | — |
| λ=280 | 15.15초 | 1.000 | 65.22% | 20.7% |
| λ=70 | 12.90초 | 0.977 | 63.17% | 32.5% |
| λ=18 | 8.01초 | 0.832 | 53.59% | 58.1% |

λ=280에서는 폭을 유지하면서 시간이 20.7% 짧았고 정확도 차이는 약 −0.29%p였다. λ를 낮추면 더 적극적으로 모델을 축소해 시간이 줄지만 정확도 손실도 커졌다. 이 결과는 네트워크의 여유를 먼저 활용하고 모델 축소에는 비용을 두는 설계의 필요성을 보여준다. 운영 목표에 맞는 λ는 시간과 실제 학습 품질을 함께 보고 선택한다.

초기 고정 채널 방식의 정확도 문제를 보완하기 위해 FedRolex식 순환 추출을 구현했으며, 별도로 4클라이언트·300라운드×3시드의 두 폭 배정을 실행했다.[12] 이 실험은 학습할 부분을 순환시키는 구현과 집계가 작동하는지 확인한 근거다. 모델 선택 방법을 개선하면서도 스케줄러의 상태 수집·경로 평가·전송 실행 구조를 유지했다.

표 5. 모델 조절 방식과 제어 평가의 관계

| 24·200라운드 결합 실행 | 폭·경로 선택의 시간과 품질 | 해당 실행의 관측 결과 |
| 300라운드 순환 선택 | FedRolex식 부분 모델 추출·집계 | 별도 실행에서 구현 검증 |

24라운드 조건별 최종 정확도의 기준선 대비 차이는 정상 +4.63%p, 몰림 −0.50%p, 연산 지연 −1.20%p, 용량 변동 −2.85%p였다. 주 비교 로그에는 순환 선택의 활성화 기록이 없으므로, 표의 수치를 FedRolex 전환의 정확도 향상으로 해석하지 않는다. 같은 조건의 알고리즘 비교와 목표 정확도 도달 시간은 다음 검증 항목으로 남긴다.

라. 실제 Jetson 측정과 LoRA 공동 학습

실제 하드웨어에서도 학습 가능 자원은 고정돼 있지 않다. Jetson Orin Nano Super 8GB 한 대에서 Qwen2.5-0.5B의 LoRA 학습을 전력 모드별로 측정했다. 랭크 32, FP32, 배치 1, 시퀀스 길이 256을 사용하고 워밍업 이후 모드별 30스텝을 분석했다. 같은 장비와 모델에서도 15 W 모드의 스텝 시간 중앙값은 MAXN SUPER의 약 1.63배였다.[13]

표 6. Jetson 실측 연산 시간

| 전력 모드 | 스텝 시간 중앙값 | 측정 표본 |
| --- | --- | --- |
| MAXN SUPER | 554.1 ms | 30스텝 |
| 25 W | 608.9 ms | 30스텝 |
| 15 W | 903.7 ms | 30스텝 |

메모리 제약은 더 큰 모델에서 확인했다. CPU 기반 Qwen2.5-7B 전체 모델 LoRA 실행은 메모리 부족으로 중단됐고, 별도의 분할 실행은 클라이언트 최대 RSS 약 7.94 GB에서 10스텝을 완료했다. 이 결과는 큰 모델에서 학습 파라미터 축소와 계산 분할을 함께 적용할 필요를 보여준다.

공동 학습은 KOREN VM 두 대의 논리 클라이언트 세 개와 HPC 서버로 구성했다. Qwen2.5-0.5B를 두 번째 디코더 계층 뒤에서 분할하고 LoRA 랭크 16으로 16라운드×30스텝을 실행했다. 클라이언트는 데이터를 보유한 채 활성값과 기울기를 교환하고, 라운드 종료 후 학습 결과를 집계했다.[7,8,13]

표 7. LoRA 공동 학습의 자체 문답 평가

| 구성 | 정답 수 | 평가 조건 |
| --- | --- | --- |
| 미학습 모델 | 0 / 18 | 학습 사실의 질문 표현을 바꾼 자체 18문항 |
| 단독 학습 | 6 / 18 | 동일 자체 문항 |
| 연합 집계 두 방식 | 각 12 / 18 | 동일 자체 문항 |

CNN과 LoRA의 두 실험은 같은 목적을 서로 다른 모델에서 검토한다. CNN에서는 모델 크기와 전송 경로의 결합 효과를, LoRA에서는 자원 제한 아래의 분할 학습과 여러 클라이언트의 정보 반영을 확인했다. LoRA 랭크는 활성값의 은닉 차원을 줄이지 않으므로 CNN의 채널 비례식을 그대로 사용하지 않는다. 향후 모델별 비용 프로파일을 연결해 동일한 스케줄링 판단 구조로 확장한다.

2. KOREN 연동 및 활용 방안

KOREN은 실제 원격 경로에서 병목을 관찰하고, 같은 연결 기반에서 혼잡의 위치와 강도를 조절하며 대응을 비교하는 실험망으로 활용했다.[10] 안정적인 연구망에서도 동시 전송이 만드는 지연을 확인했다는 점과, 가상 시간 계산에 그치지 않고 실제 텐서를 전달하며 제어 응답을 측정했다는 점이 중요하다. 축소 실험은 이 관측을 사용 가능한 CPU·메모리 범위에서 반복 검증하기 위한 구성이다.

현재 제어 범위는 클라이언트 프로그램과 사용 권한이 있는 중계 호스트다. 기관이 다른 클라이언트와 엣지 사이에서는 운영자가 허용한 중계·주소·포트만 선택한다. SDN 연동에는 OS-Ken 기반 어댑터를 마련했으며, 제어 권한을 받은 스위치에 정책을 연결하는 구조다.[14] 본문의 시간 결과는 실제 중계 배정과 전송 실행에서 얻었다.

향후 KOREN 운영기관과 협의한 L2VPN 또는 T-SDN 구간을 연결하면, 허용 중계의 선택에 더해 망 내부의 경로와 서비스 설정도 정책에 반영할 수 있다. 이를 위해 모델 판단과 네트워크 집행을 분리했다. 기관별 중계 사용 권한, 인증 및 데이터 보호는 운영 환경에 맞게 설정하고, 추가 제어 권한은 실제 위임된 범위에 맞춰 확장한다.

3. 멘토 의견에 따른 개선사항 및 향후 진행방향

기존 개발 검토는 네트워크 과제로서의 기여, 혼잡제어와의 관계, 실제 환경 검증의 필요성을 지적했다.[12] 이를 반영해 목표를 “학습의 완료 시간을 줄이는 모델·경로 스케줄링”으로 구체화했다. 패킷 전송은 기존 통신 계층이 처리하고, AwareNet은 학습의 계산량과 허용 경로를 라운드 단위로 조정한다.

모델 축소로 생긴 정확도 문제에는 채널 순환 선택을 추가하고, 불필요한 축소를 줄이도록 λ를 도입했다. 경로 측면에서는 관측된 전송량을 곧바로 회선 용량으로 간주하지 않고 공유 상한과 전송 활동 시간을 함께 사용했다. 이처럼 학습 알고리즘의 개선과 네트워크 선택을 별도 모듈로 발전시키되, 실제 완료 시간으로 다시 연결했다.

후속 검증은 연결 수를 맞춘 경로 비교, 동일 조건의 고정·순환 채널 비교, 목표 정확도에 도달하는 시간 측정 순으로 진행한다. 이어 LoRA의 모델별 비용 프로파일과 관리 구간의 SDN 집행을 통합한다. 병원 등 기관 환경에서는 전체 시간과 함께 기관별 참여 정도와 모델 성능을 평가해, 특정 기관의 데이터가 지속적으로 덜 반영되는지 확인한다.

## Ⅳ. 결 론

1. 개발 최종 결과물

AwareNet은 모델 조절과 전송 경로 선택을 함께 수행하는 적응형 스케줄러를 구현했다. 모델 폭은 계산과 전송량을, 경로는 같은 데이터를 전달하는 시간을 바꾼다. 두 효과를 라운드 완료 시간으로 비교하고 모델 축소에 비용을 부여해, 혼잡과 계산 지연에 맞는 조치를 선택하도록 했다.

KOREN 실측에서 동시 전송에 따른 지연을 확인한 뒤 축소 환경에서 제어를 검증했다. 32클라이언트 구성의 평균 라운드 시간은 기준선보다 24.6~42.6% 짧았다. 8클라이언트 장기 평가에서는 폭을 유지한 설정으로 20.7% 단축과 약 −0.29%p의 정확도 차이를 관측했다. CNN의 채널 선택 개선, 실제 Jetson의 자원 측정, LoRA의 분할 공동 학습을 통해 모델 조절 모듈의 적용 범위도 살폈다.

2. 기술 구현에 따른 기대 효과

그림 5. 병원 등 여러 기관이 데이터는 현장에 보관하고 전역 모델을 함께 개선하는 적용 예시.

병원이나 제조 현장마다 계산 자원과 접속 환경이 다르다. 통신이 혼잡한 기관에는 허용된 여유 경로를 활용하고, 계산 부담이 큰 기관에는 적합한 학습 구성을 배정하면 공동 학습의 대기를 줄일 수 있다. 일시적인 자원 부족 때문에 일부 기관이 계속 작은 모델만 학습하는 상황도 운영 정책으로 점검할 수 있다.

기대 효과는 정해진 시간 안에 더 다양한 기관이 모델 갱신에 참여할 여건을 마련하는 것이다. 이를 통해 각 기관의 데이터가 반영된 전역 모델을 지속적으로 개선하는 네트워크 운용을 지원한다. 병원 적용은 향후 활용 시나리오이며, 현재 실증 범위는 KOREN의 CNN 학습과 Jetson·LoRA 실행이다.
