2. 아이디어 개발의 목적 및 필요성

연합학습은 각 기관에 데이터를 둔 채 학습 결과를 모아 하나의 모델을 개선하는 방법이다. 분할 연합학습은 계산을 서버와 나누어 클라이언트의 부담을 줄인다. 다만 학습 중간 결과를 자주 주고받아 통신이 느려지면 전체 학습도 지연된다. 본 프로젝트는 지연 원인에 맞춰 모델 크기와 전송 경로를 함께 조절한다.

3. 아이디어 개발의 내용 및 범위

AwareNet은 먼저 중계 경로를 바꾸어 지연을 줄일 수 있는지 살핀다. 그래도 지연이 크면 모델 축소로 얻는 시간 이득과 축소 비용을 비교한다. 회선 용량이 변한 직후에는 모델 크기를 유지해 두 설정이 동시에 크게 바뀌지 않게 한다. CNN으로 이 제어 방식을 평가하고, LoRA 언어모델로 분할 학습과 결과 집계를 확인했다.

4. 개 발 결 과

KOREN에서 동시 전송이 늘수록 지연이 커지는 현상을 확인하고, CPU와 메모리 한도에 맞춰 실험 규모를 줄였다. 32개 논리 클라이언트를 3개 시드로 평가한 결과, 트래픽 몰림과 연산 지연에서 라운드 시간이 각각 42.6%, 40.3% 짧아졌다.

별도의 8클라이언트·200라운드 평가에서는 채널 비율을 유지하면서 시간이 20.7% 줄었고, 정확도 차이는 약 −0.29%p였다. 두 비교 모두 기준 방식의 연결 1개와 AwareNet의 연결 2개를 포함한 전체 구성의 결과다.

5. 기 대 효 과

병원이나 제조기관에서 자원이 다른 클라이언트도 공동 학습에 참여하도록 돕는다. 각 기관의 대기 시간을 줄여 공동 모델을 꾸준히 개선하는 것이 기대 효과다. 실제 도입에는 기관별 사용 권한과 통신 보안을 함께 마련해야 한다.

Ⅰ. 서 론

1. 개발 목적 및 필요성

의료·제조 분야에서는 개인정보 보호와 기관별 관리 정책 때문에 데이터를 한곳에 모으기 어렵다. 연합학습(Federated Learning, FL)은 데이터를 각 클라이언트에 둔 채 학습 결과를 모아 공동 모델을 만든다.[1] 다만 연산 능력이나 메모리가 부족한 클라이언트는 전체 모델을 학습하기 어렵다.

분할 연합학습(Split Federated Learning, SFL)은 모델의 앞부분을 클라이언트가, 뒷부분을 서버가 학습해 계산 부담을 나눈다.[2] 이때 매 배치마다 중간 계산 결과인 활성값과 모델 갱신에 필요한 기울기를 주고받는다. 따라서 클라이언트의 계산 속도와 네트워크 상태가 모두 학습 시간에 영향을 준다.

본 프로젝트는 모든 클라이언트가 한 라운드를 마친 뒤 결과를 모으는 동기식 구조를 사용한다. 이 구조에서는 가장 늦게 끝나는 클라이언트가 전체 진행을 늦춘다.

모델의 일부만 사용하는 서브모델 학습은 계산량과 전송량을 줄이는 방법이다.[3,4] CNN에서는 사용하는 채널 수, 즉 모델 폭을 줄인다. 그러나 학습하는 모델이 작아지고 가중치의 갱신 기회도 달라져 정확도가 낮아질 수 있다.

통신 혼잡이 원인이라면 경로를 바꾸어 모델 크기를 유지할 여지가 있다. 반면 계산이 느리거나 모든 경로가 같은 포화 회선을 지나면 경로 변경만으로 지연을 줄이기 어렵다.

AwareNet은 이러한 차이를 고려해 모델 폭과 중계 경로를 함께 선택한다. 클라이언트의 연산 시간과 실제 전송 속도를 바탕으로 각 설정의 완료 시간을 예상한다. 경로 변경의 효과를 먼저 살피고, 모델 축소로 얻는 시간 이득이 충분할 때 폭을 줄인다. 이를 통해 학습 품질을 함께 확인하며 라운드 완료 시간을 단축하고자 한다.


<!-- page 7: 특징 -->

2. 특징(동일·유사 아이디어에 대한 차별성·독창성·혁신성)

같은 통신 지연이라도 다른 경로로 분산할 수 있는 경우와 공유 회선이 이미 포화된 경우는 다르게 대응해야 한다. AwareNet은 경로 변경으로 줄일 수 있는 시간을 먼저 계산하고, 그 결과를 모델 크기 선택에 반영한다.

가. 차별성: 모델 선택에 네트워크 경로를 결합

FjORD·FedRolex는 성능이 다른 클라이언트의 서브모델 학습을 다룬다. AdaptSFL·SuperSFL은 통신과 연산 자원에 맞춰 분할 연합학습을 조정한다.[3–6] AwareNet은 모델의 분할 위치를 고정한 상태에서 중계 경로와 경로별 전송 비율을 선택한다. 경로를 바꾼 뒤에도 모델 축소가 필요한지 판단하는 데 초점을 둔다.

표 1. 선행연구의 제어 대상과 AwareNet의 설계 초점

| 접근 | 주요 제어 대상 | 설계 초점 |
| --- | --- | --- |
| FjORD<br>FedRolex | 서브모델 크기·추출 | 성능이 다른 모델의 학습 |
| AdaptSFL<br>SuperSFL | 분할·집계 또는 서브네트워크 | 통신·연산 자원 적응 |
| AwareNet | 폭·중계·전송 비율 | 경로 개선 후 축소 판단 |

나. 독창성: 공유 회선과 설정 변경의 영향 반영

여러 연결이 같은 회선을 사용하면 각 연결이 쓸 수 있는 속도도 줄어든다. AwareNet은 중계의 공유 용량과 클라이언트의 접속 상한을 함께 계산해, 경로 변경과 폭 축소의 효과를 초 단위로 비교한다.

폭은 경로 변경을 마친 상태를 기준으로 선택한다. 또한 관측한 용량이 바뀐 라운드에는 폭을 유지한다. 경로를 옮기는 중의 일시적인 지연 때문에 모델을 지나치게 줄이지 않기 위해서다.

다. 실용성: 모듈 분리와 실제 환경의 검증

학습, 데이터 전송, 망 설정을 각각의 모듈로 나누어 사용 권한에 맞게 배치했다. KOREN에서는 실제 전송 시간과 CNN의 학습 정확도를 평가했다. Jetson에서는 장치의 연산 비용을 측정했고, 고정 랭크 LoRA로 언어모델의 분할 학습과 집계를 확인했다. 각 실험의 조건과 결과는 Ⅲ장에 제시한다.

목표는 성능이 다른 클라이언트가 함께 학습할 때 모델 품질을 확인하면서 라운드 완료 시간을 줄이는 것이다. 가장 늦은 클라이언트의 예상 시간과 모델 축소 비용을 합친 값 J로 설정을 비교한다. 사용할 수 있는 중계와 회선 용량 안에서 설정을 고르고, 시간과 정확도의 관계는 장기 학습으로 평가한다.

나. 세부 추진 내용 및 범위

그림 1. 스케줄러와 KOREN 실험 구성

시스템은 관측, 계획, 실행을 반복한다. 먼저 연산 시간과 전송 기록을 모은다. 이 기록으로 모델 크기와 중계 경로를 선택하고 다음 라운드에 적용한다. 실행 결과를 다시 수집하므로 이후 선택에 실제 완료 시간을 반영할 수 있다.

여기서 경로는 학습 데이터를 어느 중계 서버로 보낼지를 뜻한다. 학습 프로그램이 중계 선택과 전송을 담당하고, 관리 호스트는 실험에 필요한 회선 조건을 설정한다. OS-Ken 어댑터는 운영자가 제어를 허용한 SDN 구간에 연결하기 위한 확장 모듈이다. 이처럼 역할을 나누어 기관별 권한에 맞게 배치한다.

1) 모델 폭과 사용할 채널의 선택

CNN의 모델 폭은 한 계층에서 사용하는 채널 수다. 스케줄러는 전체 채널 중 사용할 비율을 정하고, 학습 모듈은 실제 사용할 채널을 고른다. 이 두 선택을 나누어 모델 크기 조절과 채널 선택 알고리즘을 각각 바꿀 수 있게 했다.

같은 채널만 반복해서 고르면 일부 가중치에 학습이 집중될 수 있다. FedRolex식 순환 선택은 라운드마다 채널 위치를 바꾸고, 학습 결과를 원래 가중치 위치에 맞춰 모은다.[4] 고정 선택과 순환 선택을 모두 구현했으며, 순환 선택과 집계는 별도 300라운드 실행으로 검증했다. CNN의 계층 수와 클라이언트·서버 분할 위치는 고정했다.

2) CNN과 LoRA의 적용 범위

CNN은 채널 수를 바꾸면 계산량과 중간 전송량이 함께 달라져 폭·경로 제어를 평가하기에 적합하다. 다른 알고리즘도 설정별 연산 시간, 전송량과 집계 방법을 제공하면 같은 구조에 연결할 수 있다. 전송 모듈은 특정 채널 선택 방법에 묶이지 않도록 설계했다.

표 2. 공통 시스템에 연결한 두 학습 구현

| 구분 | CNN 서브모델 학습 | LoRA 언어모델 학습 |
| --- | --- | --- |
| 자원 조절 변수 | 채널 비율·선택 위치 | 추가 학습 행렬의 랭크 |
| 전송량과의 관계 | 채널 수에 따라<br>활성값·기울기 크기 변화 | 랭크는 어댑터 집계량에 영향<br>분할 활성값 차원은 유지 |
| 검증 목적 | 폭·경로 제어의 시간·정확도<br>별도 채널 순환 선택 | 고정 랭크의 분할 실행<br>메모리 사용·연합 집계 |

LoRA는 원래 모델의 가중치를 고정하고 작은 추가 행렬인 어댑터를 학습하는 방법이다.[7,8] 이번 언어모델 실습은 랭크를 고정해 클라이언트의 어댑터를 모으고 서버의 뒷부분을 함께 갱신했다. CNN과 다른 모델에서도 분할 학습과 집계를 실행할 수 있는지 확인한 것이다. 랭크까지 동적으로 바꾸려면 랭크별 연산·전송 비용을 추가로 측정해야 한다.


<!-- page 10: 시간모형 -->

3) 완료 시간의 예측과 설정 선택

한 배치의 시간 τᵢ는 클라이언트 연산 Cᵢ, 활성값 전송 Uᵢ, 서버 처리 Sᵢ, 기울기 반환 Dᵢ의 합이다. 서버에서 기다리는 시간도 Sᵢ에 포함한다. 라운드당 배치 수를 B, 모델 배포·집계 시간을 T₀라 하면 전체 시간은 가장 늦은 클라이언트를 기준으로 계산한다.[2,5]


$$\tau_i=C_i+U_i+S_i+D_i\tag{1}$$


$$T_{\mathrm{round}}\approx T_0+\max_i(B\tau_i)\tag{2}$$

식 (3)은 폭 비율 wᵢ와 중계 배정 P에서의 시간을 예상한다. cᵢ와 bᵢ는 전폭 모델의 배치당 연산 시간(초)과 왕복 전송량(바이트)이다. Rᵢ는 실제 사용할 수 있는 전송률(bit/s), oᵢ는 고정 처리 시간과 예측 오차를 보정하는 값이다. γᵢ는 폭에 따라 연산 시간이 줄어드는 정도를 나타내며 기본값은 1.2다.


$$\hat T_i(w,P)=B[c_iw_i^{\gamma_i}+8b_iw_i/R_i(P)+o_i]\tag{3}$$

Rᵢ는 중계 용량을 나눠 쓰는 연결 수와 클라이언트의 접속 상한을 반영한다. 접속 회선이 같으면 연결 속도의 합을 제한하고, 독립 회선이면 각 연결을 제한한다. 이 값으로 경로 변경과 모델 축소가 각각 시간을 얼마나 줄이는지 비교한다.


$$J=\max_i\hat T_i+\frac{\lambda}{N}\sum_i(1-w_i)\tag{4}$$

N은 클라이언트 수다. λ는 모델 폭을 유지하려는 정도를 나타내며 단위는 초다. 값이 클수록 더 큰 시간 이득이 있어야 모델을 줄인다. 축소 전후 최대 시간 차이를 ΔT, 평균 폭 감소를 Δw̄라 하면 식 (5)를 만족할 때 축소한다. η=0.10을 두어 예상 시간 이득을 10% 낮춰 판단한다.


$$(1-\eta)\Delta T>\lambda\Delta\bar w\tag{5}$$

경로를 고를 때는 시간 합계와 N배의 최대 시간을 함께 평가한다. 선택한 경로에서 폭을 고를 때는 식 (4)·(5)를 적용한다. λ는 폭 감소에 부여한 비용이며, 정확도 변화는 Ⅲ장의 실제 학습 결과로 확인한다.

다. 참여구성원별 역할

• 성시준: 전체 설계·개발 총괄, 네트워크 제어, KOREN 구성·실측.
• 석태경: 분할 연합학습 파이프라인, 실험 설계·분석, 결과 시각화.

2. 단계별 세부 구현 계획

제어는 상태 측정, 설정 선택, 실행의 세 단계로 진행한다. 모델과 경로는 라운드 사이에 정하고, 배치 실행 중에는 정해진 설정으로 데이터를 보낸다. 전송 중인 데이터마다 설정을 다시 계산할 필요가 없도록 구성했다.

그림 2. 라운드 단위 제어 파이프라인과 피드백

가. 라운드별 제어 과정

표 3. 제어 단계별 입력과 출력

| 단계 | 입력 | 출력 |
| --- | --- | --- |
| 상태 측정 | 사전 연산 시간<br>전송량·소요 시간 | 연산·전송 특성<br>중계 용량 추정값 |
| 설정 선택 | 측정값·현재 배정<br>허용 경로·용량 상한 | 다음 라운드의 폭<br>중계 배정·분할비 |

1) 연산 시간과 전송 상태 측정

학습 전에 전체 채널을 사용해 순전파·역전파 시간 cᵢ와 왕복 전송량 bᵢ를 측정한다. 이 값을 폭 지수 γ의 기본값 1.2와 함께 식 (3)에 넣는다. 필요하면 다른 클라이언트를 쉬게 하고 단독 업로드도 측정한다. 이때 왕복 지연(RTT)을 뺀 전송 시간으로 접속 속도의 상한을 추정한다.

학습 중에는 연결별 전송량, 전송에 사용한 시간과 중계 배정을 기록한다. 최근 3라운드에서 중계를 충분히 사용한 관측값의 중앙값으로 용량을 추정한다. 예측 시간과 실제 시간의 차이도 보정한다. 다음 경로 후보에는 같은 보정값을 적용해 이전 경로의 혼잡 때문에 새 경로의 효과를 잘못 판단하는 일을 줄인다.[12]


<!-- page 12: 의사결정 -->

2) 경로 선택 후 모델 폭 조절

먼저 현재 폭을 유지하면서 허용된 중계 조합을 비교한다. 점수 G는 모든 클라이언트의 시간 합계와 가장 늦은 완료 시간을 함께 반영한다. 최대 시간에 N을 곱해, 여러 클라이언트가 조금 빨라지더라도 가장 느린 클라이언트가 더 늦어지는 선택을 억제한다.

경로 평가에는 관측 시간과 예측 시간의 비율을 보정값으로 사용한다. 이후 폭 평가에는 식 (3)의 시간 오차 보정값을 사용한다.


$$G(P\mid w)=\sum_i\hat T_i(w,P)+N\max_i\hat T_i(w,P)\tag{6}$$

다음은 경로 이동을 모두 마쳤다고 가정한 배정에서 폭을 고르는 단계다. 가장 늦은 클라이언트와 지연이 비슷한 집단의 폭을 한 단계 줄여 시간 이득 ΔT를 구한다. 식 (5)를 만족할 때 축소를 채택한다. 경로 이동 중에 생기는 일시적인 지연으로 모델 크기를 결정하지 않기 위해서다.

탐색량은 후보 수로 제한한다. 중계 K개를 두 연결에 배정할 때 클라이언트별 후보 C는 최대 K²개다. 전체 조합 Q=∏ᵢCᵢ가 20,000 이하이면 모두 비교한다. 그보다 많으면 전송량이 큰 클라이언트부터 배정하는 탐욕 방식으로 O(NC)회 평가한다.

라운드당 M개의 경로 이동을 고르는 데는 O(MNC)회 평가한다. 폭 후보가 L단계일 때 축소 반복은 최대 N(L−1)회이고, 반복마다 최대 N개 후보를 비교한다. 각 평가에는 공유 용량 계산이 추가된다.

3) 설정 적용과 결과 수집

서버는 RSTART 메시지로 라운드 번호, 폭, 모델 가중치, 중계 주소와 전송 비율을 각 클라이언트에 보낸다. 클라이언트는 해당 서브모델을 만들고 기존 연결을 재사용한다. 별도로 검증한 순환 선택 모듈은 채널 위치를 바꾸어 학습하고 원래 위치에 맞춰 결과를 모은다. 학습 모듈이 바뀌어도 전송 방식은 유지한다.

주 실험은 폭 0.5·0.75·1.0과 라운드당 최대 3개 경로 이동을 사용했다. 폭은 한 단계씩 바꾸며, 확대 조건은 두 라운드 연속 확인한다. 중계 용량 추정이 바뀐 라운드에는 폭을 유지한다.

경로별 전송 비율은 설정 용량과 공유 배정으로 계산하고, 경로 이동은 관측 용량으로 판단한다. 실행 결과는 다음 라운드의 측정값 갱신에 사용한다.

나. 여러 경로로 나눠 보내고 다시 합치는 과정

전송 모듈은 활성값과 기울기를 바이트열로 바꿔 조각으로 나눈다. 각 연결에는 예상 속도에 비례해 조각을 배분한다. 조각 크기는 전체 바이트를 연결 수의 16배로 나누되 64 KiB~1 MiB로 제한한다. 조각을 작게 나누면 배분이 세밀해지지만 부가 정보도 늘어나므로 하한을 둔다.

그림 3. 지속 TCP 연결의 텐서 분할·재조립

1) 전송 조각의 형식과 부가 정보

표 4. 구현된 응용 메시지 프레임

| 구역 | 형식·길이 | 내용 |
| --- | --- | --- |
| 고정 헤더 | !BII · 9바이트 | kind 1B · meta_len 4B<br>payload_len 4B |

전송 ID(tid)로 어느 텐서의 조각인지 구분한다. 조각 번호(seq)로 중복을 확인하고, 위치(off)와 길이(ln)로 저장할 구간을 정한다. 조각마다 9바이트 헤더와 JSON 정보가 추가된다. 연결별로 송신과 수신을 병렬 처리하며, 같은 소켓에 쓰는 작업에는 잠금을 두어 메시지가 섞이지 않게 한다.

2) 도착 순서가 바뀌어도 원래 텐서로 복원

수신부는 텐서 전체를 담을 버퍼를 마련하고 각 조각을 지정된 위치에 저장한다. 중복, 겹침과 길이 불일치를 검사하며 완료 신호가 먼저 와도 모든 조각을 기다린다. 전체 길이가 맞으면 수신 완료를 알리고 복원한 텐서를 학습에 넘긴다. 일부만 도착한 데이터로 계산하는 오류를 막는 절차다.


<!-- page 14: 재현테스트베드 -->

3) 전송 완료 확인과 학습 모듈 연결

송신부는 다음 데이터를 보내면서 앞선 전송의 완료 회신을 확인한다. 라운드가 끝나면 flush로 남은 회신까지 확인한다. 서버의 기울기 전송은 별도 작업 스레드가 맡아 다른 처리가 소켓 대기로 지연되는 시간을 줄인다. 연결은 재사용하고 송신 버퍼 크기는 제한해, 느린 연결에 데이터가 과도하게 쌓이지 않게 한다.

전송 모듈은 전송 ID와 바이트열을 다루고, 학습 모듈은 텐서의 모양·자료형과 가중치 위치를 관리한다. 배치마다 텐서를 복원하고 라운드마다 모델을 집계하는 역할도 나누었다. 현재 변환 과정은 연속 버퍼와 데이터 복사를 사용한다. 학습 알고리즘은 연결과 재조립 코드를 바꾸지 않고 교체할 수 있다.

다. 실험용 회선 설정과 실제 장치 측정

실험은 HPC의 클라이언트 프로세스와 V100 학습 서버, VM 2대에 둔 논리 중계 4개로 구성했다. Linux tc로 클라이언트의 접속 상한과 중계의 공유 용량을 따로 설정했다. 반환 방향에도 같은 상한을 적용했다.

속도 제한에는 HTB를 사용하고 VM의 수신 트래픽은 IFB를 거치게 했다. 설정에 따른 지연은 netem으로 주입했으며, 중계 큐는 fq_codel을 사용했다.[11,12]

접속과 중계의 상한을 나누면, 여러 연결이 같은 회선을 사용하더라도 전체 속도가 회선 용량을 넘지 않는 조건을 만들 수 있다. 로컬 실험도 두 단계 HTB로 같은 구조를 구성했다. KOREN의 주 비교는 연결별 독립 접속 조건이므로 결과에 기준 연결 1개와 AwareNet 연결 2개를 명시했다.

두 정책에는 라운드 기록에 맞춰 같은 부하 변화를 적용했다. 트래픽 몰림은 8라운드에 중계 용량을 56→14 Mbps로 줄이고 20라운드에 56 Mbps로 복구했다. 용량 변동은 7 Mbps 간격으로 낮추고 복구했다. 실행 조건, 시드, 사전 측정값과 라운드 로그를 보존해 설정과 결과를 대조할 수 있게 했다.[12,13]

Jetson Orin Nano Super 8GB에서는 전력 모드별 LoRA 학습 시간과 메모리 사용량을 따로 측정했다. KOREN 기록은 실제 통신 비용을, Jetson 기록은 장치의 연산 비용을 파악하는 데 사용했다. 모델과 실행 조건은 Ⅲ장에 제시한다.

KOREN VM 두 대와 HPC의 CPU·V100 서버를 연결해 실제 텐서를 전송했다. 별도로 Jetson Orin Nano Super 8GB 한 대에서 Qwen2.5-0.5B LoRA의 전력 모드별 연산 특성을 측정했다. 랭크 32, FP32, 배치 1, 시퀀스 길이 256을 고정하고 워밍업 이후 모드별 30스텝을 분석했다.[13]

2. KOREN 연동 및 활용 결과

가. KOREN을 선택한 이유와 실험에서 얻은 이점

KOREN의 사설 연구 환경은 외부 트래픽의 영향을 줄여 같은 조건에서 실험을 반복하는 데 유리했다. 참여 수, 중계 용량, 클라이언트의 계산 지연을 하나씩 바꾸며 정책을 비교했다. 망의 우연한 변화가 줄어들면 스케줄러가 설정 변화에 어떻게 대응하는지 더 명확히 살필 수 있다.[10]

원격 VM과 HPC를 함께 사용해 실제 통신과 학습을 연결할 수 있었다. VM 두 대에는 중계를, HPC에는 클라이언트와 V100 학습 서버를 배치했다. 이 구성으로 데이터가 전송 대기열을 거쳐 전달되고 원래 텐서로 복원되는 시간까지 측정했다. 계산과 통신이 서로의 대기 시간에 미치는 영향도 확인했다.

안정적인 연구망에서도 동시 전송이 늘면 지연은 커졌다. 8개와 32개 클라이언트의 배치 왕복 시간 중앙값은 각각 0.41초와 2.18초였다. 이 관측을 출발점으로 회선 용량과 부하 변화 시점을 정하고, CPU와 메모리 한도에 맞춰 축소 실험을 반복했다. 실제 경로에서 확인한 병목을 통제 가능한 조건으로 옮겨 대응 정책을 비교한 것이다.

나. T-SDN·L2VPN을 활용한 후속 확장

이번 실험은 할당된 VM·HPC와 중계 프로그램을 사용했다. T-SDN과 L2VPN은 향후 확장에 활용할 수 있다. KOREN 이용안내서는 전용회선의 자원 분리와 대역폭 보장, 여러 기관을 잇는 L2VPN 서비스를 소개한다.[10]

T-SDN으로 학습용 회선 자원을 확보하면 전송 경합을 줄이고 완료 시간을 더 안정적으로 예측할 수 있다. L2VPN은 여러 기관의 클라이언트와 중계를 하나의 논리망으로 연결하는 데 활용할 수 있다.

확보한 대역폭을 스케줄러에 반영하면 모델 폭을 줄이지 않고 학습할 여유가 생길 수 있다. 실제 효과는 할당된 용량과 공유 구간에 따라 달라진다. 후속 실험에서는 연결 수를 맞춘 뒤 라운드 시간의 중앙값·95백분위수와 목표 정확도 도달 시간을 비교한다. 망 설정은 운영기관이 허용한 범위에서 연동한다.

다. 실제 경로의 관측과 축소 실험

먼저 HPC에서 KOREN VM을 거치는 실제 텐서 전송을 측정했다. 접속과 중계의 상한을 4 Gbps 수준으로 높이고 동시 전송 수를 8~96개로 늘렸다. 낮은 속도 제한을 걸기 전에 실제 경로에서도 전송이 몰릴 때 지연이 생기는지 확인하기 위한 실험이다.[11]

그림 4. KOREN 종단 간 경로의 동시 전송 규모별 완료 시간

배치 왕복 시간의 중앙값은 8개에서 0.41초, 32개에서 2.18초로 늘었다. 양호한 망에서도 여러 클라이언트가 동시에 보내면 학습이 지연될 수 있다는 결과다. 이는 HPC와 접속 회선, VM을 모두 포함한 측정이므로 지연을 KOREN 코어 장비의 영향으로만 해석할 수는 없다.

이 현상을 반복해서 평가하기 위해 SHRiNK의 축소 실험 방식을 참고했다.[9] 많은 학습 프로세스를 오래 실행하면 CPU와 메모리가 부족해져, 32개 논리 클라이언트로 단기 제어를 확인하고 8개로 장기 학습을 수행했다. 회선 속도와 부하를 함께 조정해 제한된 자원에서도 혼잡과 복구 과정을 관찰했다.

대역폭을 0.1배로 조정한 조건과 클라이언트를 32→8개로 줄인 조건은 구분해 기록했다. 각각 회선과 계산 자원을 조정한 별도 실행이므로 시간도 따로 비교한다. 규모와 부하 조건은 다음 표에 정리했다.

그림 5. 조건별 평균 라운드 완료 시간

트래픽 몰림에서는 라운드 시간이 109.51초에서 62.87초로 줄어 42.6% 단축됐다. 이때 평균 폭은 0.998로 대부분 유지했다. 연산 지연에서는 느린 클라이언트 4개의 폭을 0.75로 줄였고, 시간이 79.12초에서 47.26초로 40.3% 짧아졌다. 두 상황에 서로 다른 설정을 적용한 결과다.[11]

기준 방식은 연결 1개, AwareNet은 2개를 사용한 전체 구성 비교다. 실제 전송량 감소는 최대 3.12%로 시간 단축 폭보다 작았다. 데이터를 적게 보내는 효과뿐 아니라 전송 경합과 가장 늦은 클라이언트의 대기 시간도 함께 봐야 한다. 연결 수를 맞춘 비교는 후속 실험에서 확인한다.

멘토 의견은 개발 목표와 실증 범위를 구체화하는 계기가 됐다. 기존 중간보고서의 7월 12일, 7월 30일, 8월 6일 기록은 클라이언트 참여, 혼잡제어와의 경계, 실제 환경 검증, 관측값의 지속성에 대한 검토를 담고 있다.[12]

클라이언트와 엣지의 운영기관이 다르면 허용된 중계 주소와 포트 안에서 연결을 선택한다. SDN 설정은 제어 권한을 위임받은 구간에 적용한다. 활성값을 교환할 때도 정보 노출 가능성을 고려해야 하므로 인증, 암호화와 접근통제를 기관의 운영 정책에 맞춰 마련해야 한다.

후속 실험에서는 연결 수를 맞춘 경로 비교, 같은 조건의 고정·순환 채널 비교, 목표 정확도 도달 시간을 차례로 평가한다. LoRA는 랭크별 연산 시간과 전송량을 측정한 뒤 스케줄러에 연결한다.

4. 결과물의 통합 및 시험/검증 결과

가. 장기 학습과 품질 검증

모델 폭을 줄이면 학습이 빨라질 수 있지만 정확도도 달라진다. 이를 확인하기 위해 8클라이언트·200라운드 실험에서 λ를 바꾸었다. 시간은 초기 4라운드를 뺀 평균, 정확도는 마지막 50라운드의 평균이며 두 시드의 결과를 다시 평균했다. 평가에는 테스트셋의 앞 2,000개 표본을 사용했다.[11]

표 8. 축소 가중치에 따른 시간과 정확도

| 설정 | 라운드 시간 | 평균 폭 | 정확도 | 시간 단축 |
| --- | --- | --- | --- | --- |
| 기준선 | 19.11초 | 1.000 | 65.52% | — |
| λ=280 | 15.15초 | 1.000 | 65.22% | 20.7% |
| λ=70 | 12.90초 | 0.977 | 63.17% | 32.5% |
| λ=18 | 8.01초 | 0.832 | 53.59% | 58.1% |

λ=280에서는 폭을 유지한 채 시간이 20.7% 짧아졌고 정확도 차이는 약 −0.29%p였다. λ를 낮추면 모델을 더 줄여 시간이 짧아졌지만 정확도 손실도 커졌다. 따라서 λ는 원하는 속도와 실제 학습 품질을 함께 보고 선택해야 한다. 이 결과는 경로 변경의 여유를 먼저 살피고 모델 축소를 신중히 적용할 필요성을 보여준다.

채널 선택 개선은 별도의 4클라이언트·300라운드×3시드에서 검증했다.[12] 이 실행은 FedRolex식 순환 추출과 집계의 구현 근거다.

시연 화면에서는 클라이언트별 학습 손실과 정확도, 생성된 답변을 볼 수 있다. KOREN 기록에서는 경로와 폭이 바뀐 시점을 확인할 수 있다. 두 실행의 조건과 출처를 구분해 표시했으며, 이 화면을 연속 녹화해 시연 영상으로 만들었다.

Ⅳ. 결 론

1. 개발 최종 결과물

AwareNet은 경로를 바꾸어 줄일 수 있는 지연을 먼저 살핀다. 이후에도 지연이 크면 모델 축소의 시간 이득과 비용을 비교해 폭을 조절한다. 공유 회선의 용량을 함께 계산하고, 용량이 변한 직후에는 폭을 유지한다. 일시적인 통신 혼잡 때문에 모델을 불필요하게 줄이는 상황을 완화하려는 설계다.

KOREN에서 동시 전송에 따른 지연을 확인한 뒤 축소 실험으로 제어를 평가했다. 32클라이언트 구성은 평균 라운드 시간이 24.6~42.6% 짧아졌다. 8클라이언트 장기 평가에서는 폭을 유지하면서 20.7% 단축과 약 −0.29%p의 정확도 차이를 확인했다. Jetson의 실제 연산 측정과 LoRA 공동 학습으로 다른 장치와 모델의 적용 가능성도 살폈다.

2. 기술 구현에 따른 기대 효과

그림 6. 여러 기관의 전역 모델 공동 개선 활용 예시

병원이나 제조 현장마다 계산 자원과 접속 환경이 다르다. 통신이 혼잡하면 여유 있는 중계 경로를 이용하고, 계산 부담이 크면 모델 크기를 조절해 공동 학습의 대기를 줄일 수 있다. 이 과정에서 일부 기관이 계속 작은 모델만 학습하지 않는지도 살펴야 한다.

이러한 스케줄링은 더 다양한 기관이 정해진 시간 안에 모델 갱신에 참여할 여건을 만든다. 각 기관의 데이터가 반영된 공동 모델을 꾸준히 개선하도록 돕는 것이 기대 효과다. 병원 적용은 향후 활용 시나리오이며, 현재는 KOREN의 CNN 학습, Jetson·LoRA 실행과 공개 데이터 시연으로 검증했다.
