2. 아이디어 개발의 목적 및 필요성

데이터를 기관 밖으로 모으기 어려운 환경에서 연합학습은 각 클라이언트의 모델 갱신을 모아 전역 모델을 구축한다. 분할 연합학습은 모델의 연산을 서버와 나누어 클라이언트의 자원 부담을 줄이지만, 배치마다 활성값과 기울기를 교환하므로 통신 지연에 민감하다. 본 프로젝트는 연산 병목과 네트워크 병목에 맞춰 모델 축소와 전송 경로를 함께 조절한다.

3. 아이디어 개발의 내용 및 범위

AwareNet은 허용 중계의 경로 조정으로 줄일 수 있는 지연을 먼저 평가한 뒤, 그 배정에서도 남는 지연의 감소와 모델 축소 비용을 비교한다. 공유 접속·중계 용량을 반영하고 관측 용량이 바뀐 라운드에는 폭을 유지해 과도한 동시 조정을 억제한다. 선택한 설정은 CNN 서브모델과 다중 연결 텐서 전송에 적용하며, 고정 랭크 LoRA는 분할 실행·집계의 확장 실습으로 검증했다.

4. 개 발 결 과

KOREN의 실제 종단 간 경로에서 동시 전송에 따른 지연을 확인한 뒤, CPU·메모리 제약 안에서 축소 실험을 수행했다. 32개 논리 클라이언트·3시드 평가에서 트래픽 몰림과 연산 지연 조건의 라운드 시간이 각각 42.6%, 40.3% 짧았다. 별도의 8클라이언트·200라운드 평가에서는 채널 비율을 유지한 설정에서 20.7% 단축과 약 −0.29%p의 정확도 차이를 관측했다. 수치는 기준 1개 연결과 결합 구성 2개 연결을 포함한 전체 구성 비교다.

5. 기 대 효 과

병원·제조기관처럼 데이터와 자원이 분산된 환경에서 공동 학습의 대기를 줄이고 다양한 클라이언트가 전역 모델 갱신에 참여하도록 지원한다. 실제 적용에서는 기관별 권한, 통신 보안과 목표 정확도를 함께 관리한다.

Ⅰ. 서 론

1. 개발 목적 및 필요성

의료·제조 분야에서는 데이터 프라이버시와 기관별 관리 정책 때문에 원자료를 한곳에 모으기 어렵다. 연합학습(Federated Learning, FL)은 데이터를 클라이언트에 보관하면서 모델 갱신을 집계해 공동 모델을 구축하는 접근법이다.[1] 그러나 전체 모델을 학습하는 데 필요한 연산량과 메모리는 자원이 제한된 클라이언트의 참여를 어렵게 한다.

분할 연합학습(Split Federated Learning, SFL)은 이러한 부담을 줄이기 위해 모델의 앞부분을 클라이언트에, 뒷부분을 서버에 배치하고 연합 집계를 결합한다.[2] 대신 배치마다 중간 활성값(activation)과 기울기(gradient)를 교환한다. 따라서 이질적인 연산 성능뿐 아니라 네트워크 병목에 따른 통신 지연도 학습 속도에 영향을 준다. 동기식 구조에서는 가장 늦게 완료되는 클라이언트, 즉 스트래글러(straggler)가 전체 라운드 시간을 결정한다.

모델 폭(width)을 조절하는 서브모델(submodel) 학습은 연산량과 전송량을 줄이는 방법이다.[3,4] 다만 모델 표현력과 파라미터 갱신 빈도가 달라져 정확도가 낮아질 수 있다. 네트워크 경합 때문에 지연된 클라이언트까지 일괄 축소하면, 전송 경로를 조정해 해소할 수 있는 지연에도 모델 용량을 줄이게 된다. 반대로 클라이언트의 연산 자원이 부족하거나 대체 경로도 공유 회선의 상한에 묶여 있으면 경로 전환만으로 지연을 충분히 줄이기 어렵다.

본 프로젝트는 연산 병목과 네트워크 병목에 필요한 조치가 다르다는 점에 주목한다. AwareNet은 클라이언트 연산 시간과 경로별 실효 전송률을 관측하고, 모델 폭과 허용 중계 경로를 바꿀 때의 예상 완료 시간을 비교한다. 네트워크의 여유를 활용하면서 모델 축소에는 비용을 부여해 불필요한 축소를 줄인다. 목표는 학습 품질을 함께 확인하며 동기식 라운드의 완료 시간을 단축하는 것이다.


<!-- page 7: 특징 -->

2. 특징(동일·유사 아이디어에 대한 차별성·독창성·혁신성)

모델 축소와 경로 조정은 모두 학습 시간을 줄이지만 모델에 미치는 영향은 다르다. AwareNet은 경로를 바꾼 뒤에도 모델 축소가 필요한지를 판단하는 데 초점을 둔다. 네트워크 혼잡을 모델 용량 감소로 일괄 처리하지 않도록, 두 제어의 순서와 채택 조건을 함께 설계했다.

가. 차별성: 모델 선택에 경로의 개선 가능성을 반영

FjORD·FedRolex는 자원에 맞는 서브모델 학습을, AdaptSFL·SuperSFL은 통신·연산 자원에 따른 분할 학습 구성을 다룬다.[3–6] AwareNet은 허용 중계의 배정까지 제어 변수에 포함한다. 현재 모델을 유지한 경로 후보와 모델을 줄인 후보를 비교해, 네트워크 자원으로 학습 부담을 보완할 수 있는 범위를 찾는다.

표 1. 선행 접근과 본 프로젝트의 주요 제어 변수

| 접근 | 주요 제어 변수 |
| FjORD·FedRolex | 서브모델 크기·학습 파라미터 선택 |
| AdaptSFL·SuperSFL | 분할·집계 구성 또는 자원별 서브네트워크 |
| AwareNet | 서브모델 크기·허용 중계 배정·전송 비율 |

나. 설계 기여: 경로 조정 후의 시간으로 축소 여부를 판단

연결을 늘려도 공유 회선이 포화되면 전송률은 충분히 증가하지 않는다. 스케줄러는 접속·중계 용량을 함께 반영한 예상 시간으로 경로를 평가하고, 그 배정에서도 남는 지연의 감소가 폭 축소 비용보다 클 때 축소를 선택한다. 관측 용량이 변한 라운드에는 폭을 유지해 일시적인 혼잡과 모델 축소가 동시에 증폭되는 것을 억제한다.

다. 실용성: 권한이 있는 종단·중계에서 제어를 실행

클라이언트 프로그램과 허용 중계 연결에서 결정을 집행하므로, 여러 기관이 코어 라우터의 제어권을 공유하지 않아도 적용할 수 있다. KOREN에서는 실제 텐서 전송과 제어 선택을 기록하고, 장기 학습에서는 시간 단축과 정확도의 관계를 평가했다. Jetson 측정과 LoRA 실습은 장치 비용과 다른 학습 모듈의 분할 실행을 검토하는 근거로 연결했다.

Ⅱ. 아이디어 개발 추진 내용과 범위

1. 개발 목표 및 추진 내용

가. 개발 목표

개발 목표는 이질적인 클라이언트가 참여하는 동기식 분할 연합학습에서 모델 축소를 억제하면서 라운드 완료 시간을 단축하는 것이다. 제어 변수는 클라이언트별 폭 비율과 허용 중계 배정이다. 예상 최대 완료 시간과 평균 폭 감소 비용을 함께 최소화하도록 후보를 비교하고, 학습 정확도는 별도 평가로 확인한다.

나. 세부 추진 내용 및 범위

그림 1. 스케줄러와 KOREN 실험 구성

시스템은 관측부, 계획부, 실행부의 폐루프로 구성한다. 관측부는 연산 프로파일과 연결별 전송 기록을 모은다. 계획부는 공유 회선의 상한 아래에서 모델 크기와 중계 배정을 선택한다. 실행부는 다음 라운드에 서브모델과 연결별 조각 비율을 적용하고 실제 완료 시간을 다시 관측부에 전달한다.

응용 계층의 오버레이 경로는 사용할 중계 호스트를 뜻한다. 이 경로와 텐서 전송은 학습 프로그램이 제어하고, 관리 호스트의 트래픽 제어는 반복 실험의 회선 조건을 집행한다. OS-Ken 어댑터는 운영자가 권한을 부여한 SDN 구간에 연결하는 확장 인터페이스다. 학습·전송·망 집행을 분리해 기관별 권한 범위에 맞춰 배치한다.


<!-- page 9: 모델조절 -->

서브모델의 크기와 학습 파라미터 선택

모델 폭은 한 계층이 사용하는 유닛 수이며, CNN에서는 채널 수로 표현한다. AwareNet의 계획부는 사용할 채널의 비율을 정하고 학습 모듈은 실제 채널 인덱스를 선택한다. 따라서 스케줄러가 결정하는 서브모델의 크기와 학습 알고리즘이 결정하는 갱신 위치를 독립적으로 바꿀 수 있다.

고정 선택은 같은 폭에서 같은 채널을 반복 사용하므로, 작은 서브모델만 학습하는 클라이언트의 갱신이 특정 파라미터에 집중될 수 있다. FedRolex식 순환 선택은 라운드마다 채널 인덱스를 이동하고 원래 위치에 맞춰 갱신을 집계한다.[4] 본 구현은 고정·순환 선택을 지원하며, 순환 추출과 집계는 별도 300라운드 실행으로 검증했다. CNN의 계층 수와 클라이언트·서버 분할 위치는 고정한다.

CNN과 LoRA를 연결하는 모듈 경계

CNN은 채널 수를 바꿀 때 연산량과 분할 활성값 크기가 함께 변하므로 결합 제어를 평가하는 기준 모델로 사용한다. 새 학습 알고리즘을 적용하려면 모델 설정별 연산 시간, 전송 바이트와 집계 규칙을 제공하면 된다. 이 인터페이스를 두어 특정 채널 선택 방법에 전송 구조가 종속되지 않도록 했다.

표 2. 공통 시스템에 연결한 두 학습 구현

| 구분 | CNN 서브모델 학습 | LoRA 언어모델 학습 |
| 자원 조절 변수 | 채널 비율·선택 위치 | 추가 학습 행렬의 랭크 |
| 전송량과의 관계 | 채널 수에 따라
활성값·기울기 크기 변화 | 랭크는 어댑터 집계량에 영향
분할 활성값 차원은 유지 |
| 검증 목적 | 폭·경로 제어의 시간·정확도
별도 채널 순환 선택 | 고정 랭크의 분할 실행
메모리 사용·연합 집계 |

LoRA는 기반 가중치를 고정하고 저랭크 행렬을 학습한다.[7,8] 언어모델 실습에서는 고정 랭크의 앞부분 어댑터를 집계하고 서버의 뒷부분을 공동 갱신했다. 이 결과는 학습 모듈의 확장 근거이며, CNN에서 측정한 동적 폭·경로 제어와는 검증 목적이 다르다. 랭크를 동적으로 선택하려면 랭크별 비용 프로파일을 추가한다.


<!-- page 10: 시간모형 -->

완료 시간 모형과 폭 축소의 채택 조건

클라이언트 i의 한 배치 시간은 연산 Cᵢ, 활성값 전송 Uᵢ, 서버 처리 Sᵢ, 기울기 반환 Dᵢ로 구성한다. B는 라운드당 배치 수, T₀는 모델 배포·집계 시간이다. 서버 대기를 Sᵢ에 포함하면 동기식 라운드 시간은 다음과 같이 나타낼 수 있다.[2,5]

폭 비율 wᵢ와 중계 배정 P의 예상 시간을 식 (3)으로 계산한다. cᵢ와 bᵢ는 전폭의 배치당 연산 초와 왕복 전송 바이트, Rᵢ는 배정에 따른 실효 전송률(bit/s), oᵢ는 고정 처리·관측 잔차다. γᵢ는 폭에 따른 연산 시간의 지수이며 프로파일의 기본값은 1.2다.

Rᵢ는 중계 용량을 공유하는 흐름의 몫과 접속 상한으로 정한다. 공유 접속이면 연결들의 합에 상한을, 독립 접속이면 각 연결에 상한을 적용한다. 이 계산으로 경로 변경의 시간 이득과 모델 축소의 시간 이득을 같은 단위에서 비교한다.

N은 클라이언트 수이고 λ는 평균 폭 감소에 부여하는 비용으로 단위는 초다. λ가 크면 더 큰 시간 이득이 있어야 축소를 선택한다. 축소 전후 최대 시간 차이를 ΔT, 평균 폭 감소를 Δw̄라 두면 기본 비용 정책의 채택 조건은 식 (5)다. η=0.10은 예측 이득을 보수적으로 평가하는 여유율이다.

경로 단계는 시간 합계와 N배의 최대 시간을 더한 점수로 후보를 평가한다. 폭 단계는 목표 경로 배정에서 식 (4)·(5)를 적용한다. λ는 정확도 손실을 직접 예측하는 계수가 아니라 폭 보존 비용이며, 설정별 정확도 변화는 Ⅲ장의 장기 학습으로 검증한다.

다. 참여구성원의 역할

성시준은 전체 설계와 개발을 총괄하고 네트워크 제어, KOREN 테스트베드 구성과 실측을 담당했다. 석태경은 분할 연합학습 파이프라인, 실험 설계·분석과 결과 시각화를 담당했다.

2. 단계별 세부 구현 계획

가. 계측·계획·적용의 순환 제어

1단계에서는 사전 진단으로 클라이언트의 전폭 연산 시간과 왕복 텐서 크기를 측정한다. 연산 프로파일은 계획의 기준으로 유지하고, 실행 중에는 전송 바이트·활동 시간과 당시 경로 배정을 함께 기록한다. 관측부는 최근 기록으로 중계의 실효 용량과 전송 시간의 잔차를 추정한다. 측정값, 설정값과 기본값의 출처를 구분해 사용한다.

2단계에서는 현재 폭을 유지한 채 허용 중계 조합을 평가한다. 이때 계산한 목표 배정의 완료 시간으로 폭 축소의 이득을 판단하므로, 경로 이동이 아직 진행 중인 클라이언트를 즉시 축소하는 상황을 줄인다. 폭 단계는 최대 지연에 영향을 주는 클라이언트와 근접한 지연 집단을 함께 검토하고 식 (5)의 조건을 만족하는 한 단계 축소를 선택한다.

중계 K개를 두 연결에 배정하면 클라이언트별 경로 후보 수는 최대 O(K²)다. 전체 배정 조합이 2만 개 이하이면 전수 평가하고, 더 큰 경우 전송량이 큰 클라이언트부터 탐욕적으로 배정한다. 이동 수를 제한한 적용 후보도 다시 평가한다. 이 탐색 구조로 전체 조합의 증가를 제한하면서 라운드 단위 결정을 수행한다.

3단계에서는 선택한 폭과 중계 배정을 다음 라운드에 적용한다. 주 실험은 폭 후보 0.5·0.75·1.0, 라운드당 이동 최대 3개를 사용했다. 폭은 한 단계씩 변경하고 복귀는 두 라운드 연속 확인한다. 관측 용량이 변한 라운드에는 폭 변경을 보류한다. 적용 후의 실제 시간을 기록해 다음 계획에서 예측 오차를 보정한다.

연결별 전송 비율은 설정 용량과 공유 배정으로 계산하고, 관측한 중계 용량은 경로 이동 판단에 사용한다. 분할비를 바꾼 효과를 다시 망 용량 변화로 해석하는 피드백을 줄이기 위한 구분이다. 규칙 기반 계획은 라운드 경계에서 실행하며, 각 결정과 관측값을 로그에 남겨 재현·비교할 수 있게 했다.[12]

나. 다중 연결의 텐서 분할·재조립

전송 모듈은 활성값과 기울기를 직렬화한 바이트열을 조각으로 나누고 지속 TCP 연결에 병렬 배분한다. 연결을 배치마다 다시 여는 비용을 줄이고, 각 연결의 예상 전송률에 비례해 조각 할당량을 정한다. 조각 크기는 텐서 크기와 연결 수로 정하며, 연결별 작업 스레드가 할당된 조각을 전송한다.

그림 2. 다중 연결의 텐서 분할과 재조립

메시지는 종류 1바이트, 메타데이터 길이 4바이트, 페이로드 길이 4바이트의 고정 헤더 뒤에 JSON 메타데이터와 데이터를 둔다. 조각 메타데이터에는 전송 ID, 클라이언트 ID, 조각 번호, 바이트 위치·길이와 전체 길이를 기록한다. 수신부는 도착 순서와 관계없이 해당 위치에 저장하고 중복·겹침·길이 불일치를 검사한다.

완료 신호가 데이터보다 먼저 도착해도 전체 조각이 모일 때까지 텐서를 학습 모듈에 넘기지 않는다. 수신부는 전체 바이트 수를 확인해 완료 회신을 보내고, 송신부는 후속 전송과 라운드 종료 시 회신을 확인한다. 이 구조는 연결 간 순서 역전을 처리하면서 전송마다 완료 회신을 기다리는 왕복 지연을 줄인다.

재조립은 배치 단위로 학습 입력을 복원하고, 연합 집계는 라운드 단위로 서브모델의 파라미터 위치를 맞춰 전역 모델을 갱신한다. 두 모듈은 완성된 텐서와 모델 갱신을 각각 주고받는다. 반복 실험의 대역폭·지연 조건은 관리 호스트의 Linux 트래픽 제어로 설정하고 실행 인자와 함께 보존한다.

Ⅲ. 아이디어 개발 진행 내용 및 결과

1. 개발 수행 현황 및 최종 결과물

가. 하드웨어 부분

KOREN VM 두 대와 HPC의 CPU·V100 서버를 연결해 실제 텐서를 전송했다. 별도로 Jetson Orin Nano Super 8GB 한 대에서 Qwen2.5-0.5B LoRA의 전력 모드별 연산 특성을 측정했다. 랭크 32, FP32, 배치 1, 시퀀스 길이 256을 고정하고 워밍업 이후 모드별 30스텝을 분석했다.[13]

표 3. Jetson의 전력 모드별 스텝 시간 중앙값

| 전력 모드 | 스텝 시간 | 표본 |
| MAXN SUPER | 554.1 ms | 30스텝 |

15 W 모드의 중앙값은 MAXN SUPER의 약 1.63배였다. 같은 장비에서도 연산 시간이 달라지므로 스케줄러가 고정 장치 등급 대신 관측한 연산 시간을 사용할 필요가 있다. CPU 기반 Qwen2.5-7B 전체 모델 LoRA는 메모리 부족으로 중단됐고, 별도 분할 실행은 클라이언트 최대 RSS 약 7.94 GB에서 10스텝을 완료했다.

나. 소프트웨어 부분

완성한 모듈은 CNN 서브모델 추출·집계, 연산·통신 관측, 폭·경로 계획, 지속 TCP 전송, 텐서 재조립, 실행 로그와 비교 결과 조회 화면이다. FedRolex식 채널 순환 선택은 별도 300라운드 실행으로 검증했다. 전송 제어와 모델 선택을 분리해 학습 알고리즘의 변경을 수용하도록 구성했다.

LoRA 공동 학습은 KOREN VM 두 대의 논리 클라이언트 세 개와 HPC 서버에서 실행했다. Qwen2.5-0.5B를 두 번째 디코더 계층 뒤에서 분할하고 랭크 16, 16라운드×30스텝으로 학습했다. 자체 18문항에서 미학습 0개, 단독 학습 6개, 두 연합 집계 방식은 각각 12개가 정답이었다.[13]

2. KOREN 연동 및 활용 결과

가. 실경로 관측과 축소 실험

KOREN과 같은 연구망에서도 여러 클라이언트가 같은 시점에 데이터를 보내면 종단 간 전송 구간에 경합이 생긴다. 본 프로젝트는 HPC에서 KOREN VM을 경유하는 실제 텐서 전송을 먼저 측정했다. 접속·중계 상한을 4 Gbps 수준으로 높인 조건에서 동시 전송 수를 8~96개로 늘려, 낮은 인위적 제한에 앞서 실제 경로에서 생기는 지연을 확인했다.[11]

그림 3. KOREN 종단 간 경로의 동시 전송 규모별 완료 시간

배치 왕복 중앙값은 8개에서 0.41초, 32개에서 2.18초로 늘었다. 이 관측은 양호한 연구망에서도 학습 트래픽의 동시성이 완료 지연을 만들 수 있음을 보여준다. 측정 범위는 HPC·접속 구간·VM을 포함한 종단 간 경로이며, 지연의 발생 지점을 KOREN 코어 장비 하나로 특정한 실험은 아니다.

이 병목을 반복 평가하기 위해 SHRiNK의 축소 실험 관점을 참고해 회선 용량과 부하 조건을 조정했다.[9] 충분한 학습 프로세스를 장시간 실행하면 CPU와 메모리 부족이 발생하므로, 32개 논리 클라이언트로 단기 제어 응답을 확인하고 8개로 줄여 장기 학습을 수행했다. 회선에 속도 제한과 변동을 적용해 적은 자원에서도 전송 경합과 복구 과정을 관찰했다.

기록의 대역폭 0.1배 조정과 클라이언트 수 32→8 축소는 각각 회선 조건과 계산 자원의 축소다. 실측에서 확인한 병목을 제어 가능한 조건으로 옮긴 것이며, 두 실행의 절대 시간을 직접 합산하지 않는다. 다음 표에 비교별 규모와 교란 조건을 명시했다.

기준선은 단일 연결, 결합 구성은 두 연결을 사용하므로 수치는 전체 구성의 비교다. 응용 전송량 감소는 최대 3.12%로 시간 단축보다 작았다. 따라서 보낸 바이트 수와 함께 경합 및 가장 늦은 클라이언트의 완료 시간을 고려해야 한다. 연결 수를 맞춘 비교는 후속 검증에 포함한다.

멘토 의견은 개발 목표와 실증 범위를 구체화하는 계기가 됐다. 기존 중간보고서의 7월 12일, 7월 30일, 8월 6일 기록은 클라이언트 참여, 혼잡제어와의 경계, 실제 환경 검증, 관측값의 지속성에 대한 검토를 담고 있다.[12]

| 시뮬레이션만으로는 실증이 부족하다 | KOREN 실제 전송과 Jetson 장비 측정을 수행 |
| 관측 가치가 지속되는가, LoRA가 초점을 흐린다 | 상태를 반복 관측하고 CNN 제어 평가와 LoRA 확장 실습을 구분 |

개발 과정에서는 모델 축소의 정확도 문제를 검토해 채널 순환 선택을 추가했고, 모델 크기를 보존하도록 축소 비용 λ를 도입했다. 경로 선택에는 관측한 전송량과 활동 시간, 공유 접속 상한을 함께 반영했다. 병목의 원인을 확정적으로 분류하기보다 후보 설정에서 예상되는 완료 시간을 비교하는 방식으로 구현했다.

관리 권한도 구분했다. 클라이언트와 엣지 운영기관이 다른 경우에는 허용된 중계 주소와 포트 안에서 연결을 선택한다. 실제 SDN 집행은 권한을 위임받은 구간에 연결한다. 활성값 교환 자체가 프라이버시 보장을 완성하지 않으므로 인증·암호화·접근통제는 운영 정책과 함께 구성해야 한다.

후속 검증은 연결 수를 동일하게 맞춘 경로 비교, 동일 조건의 고정·순환 채널 비교, 목표 정확도 도달 시간의 순서로 진행한다. LoRA에는 랭크별 연산·전송 프로파일을 별도로 측정해 스케줄링 입력으로 연결한다.


<!-- page 17: 학습품질 -->

4. 결과물의 통합 및 시험/검증 결과

가. 장기 학습과 품질 검증

폭 조절은 속도를 높이는 수단인 동시에 학습할 모델의 크기를 바꾸는 선택이다. 8클라이언트·200라운드 기록에서는 λ를 바꾸어 시간과 정확도의 관계를 확인했다. 시간은 초기 4라운드를 제외한 평균, 정확도는 마지막 50라운드의 평가 평균이며 각 값을 두 시드에 대해 평균했다. 평가에는 테스트셋의 앞 2,000개 표본을 사용했다.[11]

표 6. 축소 가중치에 따른 시간과 정확도

| 설정 | 라운드 시간 | 평균 폭 | 정확도 | 시간 단축 |
| 기준선 | 19.11초 | 1.000 | 65.52% | — |
| λ=280 | 15.15초 | 1.000 | 65.22% | 20.7% |
| λ=70 | 12.90초 | 0.977 | 63.17% | 32.5% |
| λ=18 | 8.01초 | 0.832 | 53.59% | 58.1% |

λ=280에서는 폭을 유지하면서 시간이 20.7% 짧았고 정확도 차이는 약 −0.29%p였다. λ를 낮추면 더 적극적으로 모델을 축소해 시간이 줄지만 정확도 손실도 커졌다. 이 결과는 네트워크의 여유를 먼저 활용하고 모델 축소에는 비용을 두는 설계의 필요성을 보여준다. 운영 목표에 맞는 λ는 시간과 실제 학습 품질을 함께 보고 선택한다.

채널 선택 개선은 별도의 4클라이언트·300라운드×3시드에서 검증했다.[12] 이 실행은 FedRolex식 순환 추출과 집계의 구현 근거다.

표 7. 모델 조절 방식과 제어 평가의 관계

| 실험 계열 | 주요 목적 | 해석 범위 |
| 24·200라운드 결합 실행 | 폭·경로 선택의 시간과 품질 | 해당 실행의 관측 결과 |
| 300라운드 순환 선택 | FedRolex식 서브모델 추출·집계 | 별도 실행에서 구현 검증 |
| LoRA 언어모델 실행 | 다른 모델에서 분할·연합 실행 | 모델 모듈 확장의 실습 근거 |

24라운드 최종 정확도 차이는 정상 +4.63%p, 몰림 −0.50%p, 연산 지연 −1.20%p, 용량 변동 −2.85%p였다. 이 비교에는 순환 선택 활성화 기록이 없어, FedRolex의 별도 구현 검증과 구분한다.


<!-- page 18: 시연검증 -->

나. CNN과 LoRA의 학습·추론 시연

최종 결과물의 활용 흐름은 공개 X-ray 분류와 가상 기업의 업무 문답으로 구성했다. 2026년 9월 29일 RTX 3080 한 대에서 세 논리 클라이언트를 순차 실행하고, 학습 로그·집계 결과·저장 모델의 추론 출력을 보존했다. 이 로컬 시연은 앞의 KOREN 실험과 데이터·학습 조건이 다른 별도 실행이다.[15]

CNN은 같은 시험 영상의 학습 전·후 예측을 비교하고 저장 모델을 다시 불러와 624개 예측의 일치를 확인했다. LoRA는 운영·고객지원·보안 규정을 나누어 학습한 뒤 동일한 질문의 답변을 비교했다. 평가는 학습한 규정을 다른 표현으로 묻는 자체 문항이며 일반적인 업무 문답 성능을 대표하지 않는다. 병원 시연 역시 공개 연구용 영상의 분류 예시다.

기록 조회 화면은 클라이언트별 손실, 집계 정확도, 실제 생성 답변과 KOREN 원로그의 경로·폭 변경을 표시한다. 로컬 학습과 과거 KOREN 실측을 화면에서 구분하고, 비교 조건과 자료 출처를 함께 제공한다. 시연 영상은 이 화면의 연속 기록으로 구성한다.

Ⅳ. 결 론

1. 개발 최종 결과물

AwareNet은 허용 중계 경로로 줄일 수 있는 지연을 먼저 평가하고, 그 배정에서도 남는 지연의 감소가 폭 축소 비용보다 클 때 모델을 조절하는 스케줄러다. 공유 용량을 반영한 후보 평가와 용량 변화 시 폭 유지 규칙을 결합해, 네트워크의 일시적인 혼잡 때문에 모델이 불필요하게 축소되는 상황을 줄이도록 설계했다.

KOREN 실측에서 동시 전송에 따른 지연을 확인한 뒤 축소 환경에서 제어를 검증했다. 32클라이언트 구성의 평균 라운드 시간은 기준선보다 24.6~42.6% 짧았다. 8클라이언트 장기 평가에서는 폭을 유지한 설정으로 20.7% 단축과 약 −0.29%p의 정확도 차이를 관측했다. CNN의 채널 선택 개선, 실제 Jetson의 자원 측정, LoRA의 분할 공동 학습을 통해 모델 조절 모듈의 적용 범위도 살폈다.

2. 기술 구현에 따른 기대 효과

그림 5. 여러 기관의 전역 모델 공동 개선 활용 예시

병원이나 제조 현장마다 계산 자원과 접속 환경이 다르다. 통신이 혼잡한 기관에는 허용된 여유 경로를 활용하고, 연산 부담이 큰 기관에는 적합한 학습 구성을 배정하면 공동 학습의 대기를 줄일 수 있다. 일시적인 자원 부족 때문에 일부 기관이 계속 작은 모델만 학습하는 상황도 운영 정책으로 점검할 수 있다.

기대 효과는 정해진 시간 안에 더 다양한 기관이 모델 갱신에 참여할 여건을 마련하는 것이다. 이를 통해 각 기관의 데이터가 반영된 전역 모델을 지속적으로 개선하는 네트워크 운용을 지원한다. 병원 적용은 향후 활용 시나리오이며, 현재 실증은 KOREN의 CNN 학습, Jetson·LoRA 실행과 공개 데이터 기반 로컬 시연까지 수행했다.
