데이터를 기관 밖으로 모으기 어려운 환경에서 연합학습은 각 클라이언트의 모델 갱신을 모아 전역 모델을 구축한다. 분할 연합학습은 모델의 연산을 서버와 나누어 클라이언트의 자원 부담을 줄이지만, 배치마다 활성값과 기울기를 교환하므로 통신 지연에 민감하다. 본 프로젝트는 연산 병목과 네트워크 병목에 맞춰 모델 축소와 전송 경로를 함께 조절한다.

3. 아이디어 개발의 내용 및 범위

AwareNet은 연산 시간, 전송량, 경로별 실효 전송률을 관측해 다음 라운드의 서브모델 크기와 허용 중계 경로를 결정한다. 예상 완료 시간에 모델 축소 비용을 더해 불필요한 채널 축소를 억제한다. CNN 채널 선택, 다중 연결의 텐서 분할·재조립, 연합 집계를 구현하고 LoRA 분할 학습으로 모델 확장 가능성을 확인했다.

4. 개 발 결 과

KOREN의 실제 종단 간 경로에서 동시 전송에 따른 지연을 확인한 뒤, CPU·메모리 제약 안에서 축소 실험을 수행했다. 32개 논리 클라이언트·3시드 평가에서 트래픽 몰림과 연산 지연 조건의 라운드 시간이 각각 42.6%, 40.3% 짧았다. 별도의 8클라이언트·200라운드 평가에서는 채널 비율을 유지한 설정에서 20.7% 단축과 약 −0.29%p의 정확도 차이를 관측했다. 수치는 기준 1개 연결과 결합 구성 2개 연결을 포함한 전체 구성 비교다.

5. 기 대 효 과

Ⅰ. 서 론

1. 개발 목적 및 필요성

의료·제조 분야에서는 데이터 프라이버시와 기관별 관리 정책 때문에 원자료를 한곳에 모으기 어렵다. 연합학습(Federated Learning, FL)은 데이터를 클라이언트에 보관하면서 모델 갱신을 집계해 공동 모델을 구축하는 접근법이다.[1] 그러나 전체 모델을 학습하는 데 필요한 연산량과 메모리는 자원이 제한된 클라이언트의 참여를 어렵게 한다.

분할 연합학습(Split Federated Learning, SFL)은 이러한 부담을 줄이기 위해 모델의 앞부분을 클라이언트에, 뒷부분을 서버에 배치하고 연합 집계를 결합한다.[2] 대신 배치마다 중간 활성값(activation)과 기울기(gradient)를 교환한다. 따라서 이질적인 연산 성능뿐 아니라 네트워크 병목에 따른 통신 지연도 학습 속도에 영향을 준다. 동기식 구조에서는 가장 늦게 완료되는 클라이언트, 즉 스트래글러(straggler)가 전체 라운드 시간을 결정한다.

모델 폭(width)을 조절하는 서브모델(submodel) 학습은 연산량과 전송량을 줄이는 방법이다.[3,4] 다만 모델 표현력과 파라미터 갱신 빈도가 달라져 정확도가 낮아질 수 있다. 네트워크 경합 때문에 지연된 클라이언트까지 일괄 축소하면, 전송 경로를 조정해 해소할 수 있는 지연에도 모델 용량을 줄이게 된다. 반대로 클라이언트의 연산 자원이 부족하거나 대체 경로도 공유 회선의 상한에 묶여 있으면 경로 전환만으로 지연을 충분히 줄이기 어렵다.

본 프로젝트는 연산 병목과 네트워크 병목에 필요한 조치가 다르다는 점에 주목한다. AwareNet은 클라이언트 연산 시간과 경로별 실효 전송률을 관측하고, 모델 폭과 허용 중계 경로를 바꿀 때의 예상 완료 시간을 비교한다. 네트워크의 여유를 활용하면서 모델 축소에는 비용을 부여해 불필요한 축소를 줄인다. 목표는 학습 품질을 함께 확인하며 동기식 라운드의 완료 시간을 단축하는 것이다.


<!-- page 7: 특징 -->

2. 특징(동일·유사 아이디어에 대한 차별성·독창성·혁신성)

자원 이질성에 대응하는 선행연구는 모델 구성과 학습 절차를 조정한다. FjORD는 Ordered Dropout으로 클라이언트에 맞는 폭의 서브모델을 추출하고, FedRolex는 학습할 파라미터를 순환 선택한다.[3,4] AdaptSFL은 분할 위치와 클라이언트 집계 주기를, SuperSFL은 자원별 서브네트워크와 기울기 결합을 다룬다.[5,6] AwareNet은 이 문제를 실제 전송 경로의 상태와 연결해 다룬다.

표 1. 선행 접근과 본 프로젝트의 제어 대상

| 접근 | 주요 제어 대상 |
| FjORD·FedRolex | 서브모델의 크기 및 파라미터 선택 |
| AdaptSFL·SuperSFL | 자원 적응형 분할 학습과 집계 구성 |
| AwareNet | 서브모델 크기와 허용 중계 경로를 완료 시간으로 비교 |

핵심 구현은 학습 모듈과 전송 모듈 사이의 스케줄러다. 모델 설정에 따른 연산 시간·전송량과 경로 배정에 따른 실효 전송률을 같은 시간 단위로 평가한다. 공유 접속 구간의 상한을 반영하므로 연결을 추가한 만큼 용량이 선형 증가한다고 가정하지 않는다. 선택한 설정은 실제 텐서 전송에 적용하고, 관측 결과를 다음 라운드에 반영한다.

학습 알고리즘은 교체할 수 있도록 분리했다. CNN에서는 채널 선택으로 폭을 조절하고, 별도의 LoRA 구현에서는 분할 실행과 어댑터 집계를 확인했다. 두 모델의 비용 특성은 구분한다. KOREN 종단 간 실측, 축소 반복 실험, 실제 Jetson의 연산 측정은 이러한 설계를 검토하는 근거다.

가. 개발 목표

개발 목표는 계산 자원과 네트워크 상태가 다른 클라이언트가 함께 학습할 때 발생하는 라운드 대기를 줄이는 것이다. 입력은 연산 시간, 텐서 크기, 연결별 전송 시간이며 출력은 다음 라운드의 채널 비율, 중계 배정과 전송 조각의 배분이다.

나. 세부 추진 내용 및 범위

그림 1. 스케줄러와 KOREN 실험 구성

클라이언트는 모델 앞부분을 실행하고 서버와 활성값·기울기를 교환한다. 중계 호스트는 텐서 조각을 전달하며, 서버는 조각을 재조립한 뒤 학습을 진행한다. 라운드 종료 후 모델 갱신을 집계한다. 관측·계획·실행의 순환으로 모델 구성과 통신 상태를 연결한다.

제어 대상은 클라이언트 프로그램과 사용 권한이 있는 중계 호스트다. 허용 중계 선택은 응용 계층의 경로 조정이며, KOREN 코어 라우팅을 변경한 실험과 구분한다. OS-Ken 어댑터는 운영자가 권한을 부여한 SDN 구간을 연결하기 위한 확장 모듈이다.

모델 폭과 채널 선택

초기 구현은 FjORD 계열의 앞쪽 채널 선택으로 클라이언트의 연산 부담을 줄였다. 이 방식에서는 작은 모델을 쓰는 클라이언트가 같은 부분만 반복 학습하므로, 해당 클라이언트의 데이터가 반영되는 파라미터가 제한될 수 있다. 기존 정확도 검토를 바탕으로 FedRolex식 채널 순환 선택을 추가했다. 순환 선택은 서브모델의 크기를 유지하면서 라운드마다 학습할 채널을 바꾸어 전역 모델의 학습 기회를 분산한다.[3,4,12]

CNN에서 모델 폭은 계층별 채널 수다. 이번 개선은 같은 폭의 서브모델에 포함할 채널을 순환 선택하도록 바꾼 것이다. 계층 수인 깊이와 클라이언트·서버의 계산 경계인 분할 위치는 구분한다. CNN 평가에서는 계층 구조와 분할 위치를 고정하고 채널 수와 선택 위치를 조절했다.

CNN과 LoRA의 적용 범위

CNN은 채널 수를 바꾸었을 때 계산량과 전송량의 관계가 명확해 결합 제어를 평가하기에 적합하다. 예를 들어 같은 배치와 공간 크기에서 활성값의 채널 수를 128개에서 96개로 줄이면 활성값 크기도 25% 감소한다. 이 관계를 이용해 경로 변경과 모델 축소의 시간 이득을 비교했다. CNN은 스케줄러를 검증하는 구체적인 모델이며, 적용 범위를 정하는 전제는 아니다.

LoRA는 큰 언어모델의 학습 파라미터를 줄이는 방법으로, CNN과 다른 모델에서도 자원이 제한된 클라이언트의 공동 학습을 구성할 수 있는지 확인하기 위해 사용했다.[7,8] 두 구현은 분할 실행과 연합 집계라는 공통 구조를 사용한다. LoRA 실험은 고정 랭크로 수행했으며, 같은 동적 제어를 확대 적용하려면 랭크별 계산·통신 특성을 별도로 측정해 스케줄러에 연결한다.


<!-- page 10: 시간모형 -->

라운드 완료 시간과 선택 기준

동기식 분할 연합학습의 한 배치 시간은 클라이언트 계산 Cᵢ, 활성값 전송 Uᵢ, 서버 처리 Sᵢ, 기울기 반환 Dᵢ의 합이다.[2,5] 각 항은 초 단위이고 서버 처리에는 대기 시간도 포함한다. 클라이언트 i의 배치 평균을 τᵢ, 라운드당 배치 수를 B, 모델 배포·집계 등의 시간을 T₀라고 하면 다음처럼 정리할 수 있다.

모델 설정 mᵢ와 경로 배정 P가 정해지면, 연산 시간과 전송 시간을 측정 프로파일로 예측한다. 아래 식에서 bᵢ는 한 배치의 왕복 전송 바이트, Rᵢ는 해당 배정에서 예상하는 실효 전송률이다. oᵢ는 서버 처리 등 나머지 시간이다. mᵢ를 바꾸면 계산량과 전송량이, P를 바꾸면 Rᵢ가 달라지므로 두 변수를 함께 평가한다.

CNN 구현은 모델 설정을 폭 비율 w로 나타내고 연산 시간은 cᵢwᵞ, 전송량은 bᵢw로 근사한다. γ는 폭에 따른 계산량 변화를 나타내는 지수다. 경로 배정은 공유 접속 회선과 중계 용량을 함께 고려한다. 다른 모델에는 해당 모델의 계산·전송 프로파일을 적용한다. N개 클라이언트의 폭 선택은 다음 비용으로 평가한다.

λ는 모델 폭을 보존하는 정도를 정하는 가중치다. 단위는 초이며, 값이 클수록 모델 축소에 더 큰 시간 이득을 요구한다. 32개 중 4개의 폭을 1.0에서 0.75로 줄이면 평균 폭 감소는 0.03125다. λ=70일 때 축소 비용은 약 2.19초이므로, 그보다 큰 완료 시간 감소가 있는지 비교한다. 정확도 손실은 이 값으로 환산했다고 가정하지 않고 학습 평가로 확인한다.

계획부는 현재 폭에서 경로 후보를 먼저 평가하고 남는 지연에 폭 조절을 적용한다. 경로 단계는 시간 합계와 N배의 최대 시간을 함께 반영해 가장 늦은 클라이언트의 영향을 높인다. 폭이 바뀌면 전송량도 변하므로 경로를 다시 확인한다. 유한한 후보를 단계적으로 탐색해 실제 라운드에 적용할 설정을 정한다.[12]

다. 참여구성원의 역할

성시준은 팀장으로서 네트워크 제어와 KOREN 인프라 구성, 망 실측 및 개발 총괄을 맡았다. 석태경은 분산학습 파이프라인, 실험 설계·분석과 시각화를 맡았다. 이 역할 구분은 기존 중간보고서와 개발 기록을 기준으로 정리했다.[12]

2. 단계별 세부 구현 계획

1단계는 모델 크기별 연산 시간·전송량과 연결별 실효 전송률을 측정하는 과정이다. 2단계에서는 후보 경로를 평가한 뒤 모델 폭 변경의 시간 이득과 축소 비용을 비교한다. 3단계에서는 선택한 서브모델과 전송 배정을 실행하고 관측 결과를 다음 라운드의 계획에 반영한다.

그림 2. 다중 연결의 텐서 분할과 재조립

텐서 조각에는 전송 식별자와 위치를 부여한다. 수신 측은 모든 조각을 원래 순서로 복원한 후 학습을 진행한다. 연합 집계는 라운드 종료 후 파라미터 위치를 맞춰 수행한다. 따라서 전송 조각의 재조립과 모델 집계는 서로 다른 단계다.

라운드 단위의 규칙 기반 탐색은 유한한 후보를 비교하므로 계산 비용과 선택 이유를 확인하기 쉽다. 패킷 전달·재전송은 TCP가 처리한다. PyTorch 학습과 지속 TCP 연결을 통합했으며, 반복 실험의 회선 제한은 관리 호스트의 Linux 트래픽 제어로 적용했다.

Ⅲ. 아이디어 개발 진행 내용 및 결과

1. 개발 수행 현황 및 최종 결과물

가. 하드웨어 부분

KOREN VM 두 대와 HPC의 CPU·V100 서버를 연결해 실제 텐서를 전송했다. 별도로 Jetson Orin Nano Super 8GB 한 대에서 Qwen2.5-0.5B LoRA의 전력 모드별 연산 특성을 측정했다. 랭크 32, FP32, 배치 1, 시퀀스 길이 256을 고정하고 워밍업 이후 모드별 30스텝을 분석했다.[13]

표 3. Jetson의 전력 모드별 스텝 시간 중앙값

| 전력 모드 | 스텝 시간 | 표본 |
| MAXN SUPER | 554.1 ms | 30스텝 |

15 W 모드의 중앙값은 MAXN SUPER의 약 1.63배였다. 같은 장비에서도 연산 시간이 달라지므로 스케줄러가 고정 장치 등급 대신 관측한 연산 시간을 사용할 필요가 있다. CPU 기반 Qwen2.5-7B 전체 모델 LoRA는 메모리 부족으로 중단됐고, 별도 분할 실행은 클라이언트 최대 RSS 약 7.94 GB에서 10스텝을 완료했다.

나. 소프트웨어 부분

완성한 모듈은 CNN 서브모델 추출·집계, 연산·통신 관측, 폭·경로 계획, 지속 TCP 전송, 텐서 재조립, 실행 로그와 비교 결과 조회 화면이다. FedRolex식 채널 순환 선택은 별도 300라운드 실행으로 검증했다. 전송 제어와 모델 선택을 분리해 학습 알고리즘의 변경을 수용하도록 구성했다.

LoRA 공동 학습은 KOREN VM 두 대의 논리 클라이언트 세 개와 HPC 서버에서 실행했다. Qwen2.5-0.5B를 두 번째 디코더 계층 뒤에서 분할하고 랭크 16, 16라운드×30스텝으로 학습했다. 자체 18문항에서 미학습 0개, 단독 학습 6개, 두 연합 집계 방식은 각각 12개가 정답이었다.[13]

2. KOREN 연동 및 활용 결과

가. 실경로 관측과 축소 실험

KOREN과 같은 연구망에서도 여러 클라이언트가 같은 시점에 데이터를 보내면 종단 간 전송 구간에 경합이 생긴다. 본 프로젝트는 HPC에서 KOREN VM을 경유하는 실제 텐서 전송을 먼저 측정했다. 접속·중계 상한을 4 Gbps 수준으로 높인 조건에서 동시 전송 수를 8~96개로 늘려, 낮은 인위적 제한에 앞서 실제 경로에서 생기는 지연을 확인했다.[11]

그림 3. KOREN 종단 간 경로의 동시 전송 규모별 완료 시간

배치 왕복 중앙값은 8개에서 0.41초, 32개에서 2.18초로 늘었다. 이 관측은 양호한 연구망에서도 학습 트래픽의 동시성이 완료 지연을 만들 수 있음을 보여준다. 측정 범위는 HPC·접속 구간·VM을 포함한 종단 간 경로이며, 지연의 발생 지점을 KOREN 코어 장비 하나로 특정한 실험은 아니다.

이 병목을 반복 평가하기 위해 SHRiNK의 축소 실험 관점을 참고해 회선 용량과 부하 조건을 조정했다.[9] 충분한 학습 프로세스를 장시간 실행하면 CPU와 메모리 부족이 발생하므로, 32개 논리 클라이언트로 단기 제어 응답을 확인하고 8개로 줄여 장기 학습을 수행했다. 회선에 속도 제한과 변동을 적용해 적은 자원에서도 전송 경합과 복구 과정을 관찰했다.

기록의 대역폭 0.1배 조정과 클라이언트 수 32→8 축소는 각각 회선 조건과 계산 자원의 축소다. 실측에서 확인한 병목을 제어 가능한 조건으로 옮긴 것이며, 두 실행의 절대 시간을 직접 합산하지 않는다. 다음 표에 비교별 규모와 교란 조건을 명시했다.

기준선은 단일 연결, 결합 구성은 두 연결을 사용하므로 수치는 전체 구성의 비교다. 응용 전송량 감소는 최대 3.12%로 시간 단축보다 작았다. 따라서 보낸 바이트 수와 함께 경합 및 가장 늦은 클라이언트의 완료 시간을 고려해야 한다. 연결 수를 맞춘 비교는 후속 검증에 포함한다.

3. 멘토 의견에 따른 개선사항

멘토 의견은 개발 목표와 실증 범위를 구체화하는 계기가 됐다. 기존 중간보고서의 7월 12일, 7월 30일, 8월 6일 기록은 클라이언트 참여, 혼잡제어와의 경계, 실제 환경 검증, 관측값의 지속성에 대한 검토를 담고 있다.[12]

표 5. 멘토 의견과 반영 내용

| 기존 기록의 의견 | 반영 내용 |
| 미선택 클라이언트의 기여를 어떻게 볼 것인가 | 참여 배제보다 클라이언트의 학습 부담과 완료 시간 조정에 집중 |
| 혼잡제어와의 경계가 불분명하다 | TCP의 패킷 제어와 라운드 단위 모델·중계 선택을 분리 |
| 시뮬레이션만으로는 실증이 부족하다 | KOREN 실제 전송과 Jetson 장비 측정을 수행 |
| 관측 가치가 지속되는가, LoRA가 초점을 흐린다 | 상태를 반복 관측하고 CNN 제어 평가와 LoRA 확장 실습을 구분 |

개발 과정에서는 모델 축소의 정확도 문제를 검토해 채널 순환 선택을 추가했고, 모델 크기를 보존하도록 축소 비용 λ를 도입했다. 경로 선택에는 관측한 전송량과 활동 시간, 공유 접속 상한을 함께 반영했다. 병목의 원인을 확정적으로 분류하기보다 후보 설정에서 예상되는 완료 시간을 비교하는 방식으로 구현했다.

관리 권한도 구분했다. 클라이언트와 엣지 운영기관이 다른 경우에는 허용된 중계 주소와 포트 안에서 연결을 선택한다. 실제 SDN 집행은 권한을 위임받은 구간에 연결한다. 활성값 교환 자체가 프라이버시 보장을 완성하지 않으므로 인증·암호화·접근통제는 운영 정책과 함께 구성해야 한다.

후속 검증은 연결 수를 동일하게 맞춘 경로 비교, 동일 조건의 고정·순환 채널 비교, 목표 정확도 도달 시간의 순서로 진행한다. LoRA에는 랭크별 연산·전송 프로파일을 별도로 측정해 스케줄링 입력으로 연결한다.

4. 결과물의 통합 및 시험/검증 결과

가. 장기 학습과 품질 검증

폭 조절은 속도를 높이는 수단인 동시에 학습할 모델의 크기를 바꾸는 선택이다. 8클라이언트·200라운드 기록에서는 λ를 바꾸어 시간과 정확도의 관계를 확인했다. 시간은 초기 4라운드를 제외한 평균, 정확도는 마지막 50라운드의 평가 평균이며 각 값을 두 시드에 대해 평균했다. 평가에는 테스트셋의 앞 2,000개 표본을 사용했다.[11]

표 6. 축소 가중치에 따른 시간과 정확도

| 설정 | 라운드 시간 | 평균 폭 | 정확도 | 시간 단축 |
| 기준선 | 19.11초 | 1.000 | 65.52% | — |
| λ=280 | 15.15초 | 1.000 | 65.22% | 20.7% |
| λ=70 | 12.90초 | 0.977 | 63.17% | 32.5% |
| λ=18 | 8.01초 | 0.832 | 53.59% | 58.1% |

λ=280에서는 폭을 유지하면서 시간이 20.7% 짧았고 정확도 차이는 약 −0.29%p였다. λ를 낮추면 더 적극적으로 모델을 축소해 시간이 줄지만 정확도 손실도 커졌다. 이 결과는 네트워크의 여유를 먼저 활용하고 모델 축소에는 비용을 두는 설계의 필요성을 보여준다. 운영 목표에 맞는 λ는 시간과 실제 학습 품질을 함께 보고 선택한다.

채널 선택 개선은 별도의 4클라이언트·300라운드×3시드에서 검증했다.[12] 이 실행은 FedRolex식 순환 추출과 집계의 구현 근거다.

표 7. 모델 조절 방식과 제어 평가의 관계

| 실험 계열 | 주요 목적 | 해석 범위 |
| 24·200라운드 결합 실행 | 폭·경로 선택의 시간과 품질 | 해당 실행의 관측 결과 |
| 300라운드 순환 선택 | FedRolex식 서브모델 추출·집계 | 별도 실행에서 구현 검증 |
| LoRA 언어모델 실행 | 다른 모델에서 분할·연합 실행 | 모델 모듈 확장의 실습 근거 |

24라운드 최종 정확도 차이는 정상 +4.63%p, 몰림 −0.50%p, 연산 지연 −1.20%p, 용량 변동 −2.85%p였다. 이 비교에는 순환 선택 활성화 기록이 없어, FedRolex의 별도 구현 검증과 구분한다.

나. CNN과 LoRA의 학습·추론 시연

최종 결과물의 활용 흐름은 공개 X-ray 분류와 가상 기업의 업무 문답으로 구성했다. 2026년 9월 29일 RTX 3080 한 대에서 세 논리 클라이언트를 순차 실행하고, 학습 로그·집계 결과·저장 모델의 추론 출력을 보존했다. 이 로컬 시연은 앞의 KOREN 실험과 데이터·학습 조건이 다른 별도 실행이다.[15]

Ⅳ. 결 론

1. 개발 최종 결과물

AwareNet은 모델 조절과 전송 경로 선택을 함께 수행하는 적응형 스케줄러를 구현했다. 모델 폭은 계산과 전송량을, 경로는 같은 데이터를 전달하는 시간을 바꾼다. 두 효과를 라운드 완료 시간으로 비교하고 모델 축소에 비용을 부여해, 혼잡과 계산 지연에 맞는 조치를 선택하도록 했다.

KOREN 실측에서 동시 전송에 따른 지연을 확인한 뒤 축소 환경에서 제어를 검증했다. 32클라이언트 구성의 평균 라운드 시간은 기준선보다 24.6~42.6% 짧았다. 8클라이언트 장기 평가에서는 폭을 유지한 설정으로 20.7% 단축과 약 −0.29%p의 정확도 차이를 관측했다. CNN의 채널 선택 개선, 실제 Jetson의 자원 측정, LoRA의 분할 공동 학습을 통해 모델 조절 모듈의 적용 범위도 살폈다.

2. 기술 구현에 따른 기대 효과

그림 5. 여러 기관의 전역 모델 공동 개선 활용 예시

병원이나 제조 현장마다 계산 자원과 접속 환경이 다르다. 통신이 혼잡한 기관에는 허용된 여유 경로를 활용하고, 연산 부담이 큰 기관에는 적합한 학습 구성을 배정하면 공동 학습의 대기를 줄일 수 있다. 일시적인 자원 부족 때문에 일부 기관이 계속 작은 모델만 학습하는 상황도 운영 정책으로 점검할 수 있다.

기대 효과는 정해진 시간 안에 더 다양한 기관이 모델 갱신에 참여할 여건을 마련하는 것이다. 이를 통해 각 기관의 데이터가 반영된 전역 모델을 지속적으로 개선하는 네트워크 운용을 지원한다. 병원 적용은 향후 활용 시나리오이며, 현재 실증은 KOREN의 CNN 학습, Jetson·LoRA 실행과 공개 데이터 기반 로컬 시연까지 수행했다.
