2. 아이디어 개발의 목적 및 필요성

기관별 데이터 관리 정책 때문에 원자료를 모으기 어려운 환경에서 연합학습은 공동 모델을 만드는 방법이다. 자원이 부족한 클라이언트는 분할 연합학습으로 계산을 서버와 나눌 수 있지만, 매 배치의 활성값·기울기 교환이 통신 병목을 만든다. AwareNet은 경로와 분할 전송의 여유를 먼저 활용하고, 남은 부담에 모델 축소를 적용한다.

3. 아이디어 개발의 내용 및 범위

AwareNet은 모델 폭, 중계 경로와 텐서 분할 전송을 함께 조절한다. 텐서를 조각으로 나누어 연결별 예상 전송률에 맞춰 배분하고, 중계 배정으로 줄일 수 있는 지연을 먼저 평가한다. 남는 지연에는 모델 축소의 시간 이득과 비용을 비교한다. 용량 변화 직후에는 폭을 유지한다. CNN의 시간·정확도와 LoRA의 분할 학습·집계·전송을 평가했다.

4. 개 발 결 과

Ⅰ. 서 론

1. 개발 목적 및 필요성

의료·금융·제조 분야에서는 개인정보 보호와 기관별 관리 정책 때문에 원자료를 한곳에 모으기 어렵다. 연합학습(Federated Learning, FL)은 각 기관에 데이터를 둔 채 모델 갱신을 모아 공동 모델을 만든다.[1] 그러나 연산·메모리 자원이 부족한 클라이언트는 전체 모델을 학습하기 어렵다. 본 프로젝트는 공동 학습과 중계 사용에 합의한 기관 간 협력 환경을 대상으로 한다.

분할 연합학습(Split Federated Learning, SFL)은 분할 계층을 기준으로 모델 앞부분을 클라이언트가, 뒷부분을 서버가 학습한다.[2] 계산 부담을 나누는 대신 매 미니배치마다 활성값과 기울기를 교환한다. 따라서 연산을 서버로 옮겨도 전송이 지연되면 다음 계산을 시작할 수 없다. 이처럼 연산 부담을 줄일수록 통신의 역할이 커지는 구조가 본 프로젝트의 출발점이다.

본 프로젝트는 같은 라운드의 갱신을 모아 집계하는 동기식 구조를 채택했다. 갱신 시점과 모델 버전을 맞추기 쉽고, 오래된 갱신이 뒤늦게 반영되는 문제를 줄일 수 있기 때문이다. 이 구조에서는 가장 늦은 클라이언트인 스트래글러(straggler)가 전체 라운드 시간을 결정한다.

서브모델 학습은 모델의 일부만 사용해 계산량과 전송량을 줄인다.[3,4] CNN에서는 채널 수로 모델 폭(width)을 조절한다. 다만 폭을 줄이면 표현 용량과 가중치 갱신 기회가 달라져 정확도가 낮아질 수 있다. 중요한 것은 축소 방법을 고르는 데 그치지 않고, 축소가 필요한 상황을 구분하는 일이다.

한 중계의 혼잡이 원인이라면 여유 있는 중계로 전송을 분산해 모델 크기를 유지할 수 있다. 반대로 계산이 느리거나 모든 경로가 같은 포화 회선을 지나면 경로 전환의 이득이 작다. AwareNet은 기관이 허용한 중계 연결을 선택하는 응용 계층 제어로 이 두 상황에 대응한다.

AwareNet은 모델 폭, 중계 경로, 텐서 분할 전송을 함께 조절한다. 큰 텐서를 연결별 예상 속도에 맞춰 나누고, 경로 조정 후의 완료 시간을 먼저 계산한다. 남은 지연에 대해 시간 이득이 폭 축소 비용보다 클 때 모델을 줄인다. 목표는 통신으로 해소할 수 있는 지연 때문에 모델을 불필요하게 축소하지 않는 것이다.

2. 특징(동일·유사 아이디어에 대한 차별성·독창성·혁신성)

AwareNet의 설계 초점은 네트워크 조정으로 확보할 수 있는 여유를 모델 크기 결정에 반영하는 데 있다. 경로 배정과 텐서 분할을 먼저 평가하고, 남는 지연에 폭 축소를 적용하는 순서로 두 제어를 연결했다.

가. 차별성: 모델 선택에 네트워크 경로를 결합

FjORD·FedRolex는 이질적인 모델의 크기와 추출 방법을, AdaptSFL은 분할 위치와 집계 주기를, SuperSFL은 자원별 서브네트워크와 기울기 결합을 다룬다.[3–6] AwareNet은 이 학습 기법들과 연결할 수 있는 전송 제어에 초점을 둔다. 허용된 중계와 공유 용량을 반영해 분할 전송을 배정한 뒤 모델 축소 여부를 결정한다.

나. 독창성: 공유 회선과 설정 변경의 영향 반영

논리 연결을 늘려도 같은 물리 회선을 사용하면 전체 전송 용량은 늘지 않는다. AwareNet은 중계 공유 용량과 클라이언트 접속 상한을 함께 계산한다. 예상 완료 시간과 평균 폭 감소 비용을 초 단위로 통일해, 경로 전환과 모델 축소의 이득을 같은 기준에서 비교한다.

폭 선택에는 경로 재배정 후의 예상 시간을 사용한다. 관측 용량이 변한 라운드에는 폭을 유지하고, 폭 확대는 두 라운드 연속 조건을 확인한다. 상태 전환 중의 관측값으로 모델을 과도하게 줄이거나 설정이 반복해서 바뀌는 현상을 완화하기 위한 장치다.

다. 실용성: 모듈 분리와 목적별 실증

학습·전송·망 설정 모듈을 분리하고 검증도 목적에 맞춰 구성했다. KOREN에서는 실제 전송 경합과 CNN 제어를, Jetson에서는 장치의 연산·전력을, Qwen·LoRA에서는 분할 공동 학습과 어댑터 전송을 확인했다. 이 세 기록을 통해 네트워크 효과, 장치 비용, 언어모델 적용 가능성을 각각 설명한다.

Ⅱ. 아이디어 개발 추진 내용과 범위

1. 개발 목표 및 추진 내용

가. 개발 목표

개발 목표는 모델 축소를 신중히 적용하면서 동기식 SFL의 라운드 완료 시간을 줄이는 것이다. 가장 늦은 클라이언트의 예상 시간과 평균 폭 감소 비용을 결합한 J를 정의하고, 허용 중계와 회선 용량 안에서 J를 낮추는 설정을 찾는다. 시간 단축과 학습 품질은 단기 제어·장기 학습으로 나누어 평가한다.

나. 세부 추진 내용 및 범위

그림 1. 스케줄러와 KOREN 실험 구성

AwareNet은 관측 → 계획 → 실행 → 피드백의 제어 루프로 동작한다. 연산 시간과 전송 기록에서 다음 라운드의 폭·중계·분할비를 정하고, 실제 완료 시간으로 예측을 보정한다. 계획은 라운드 경계에서 수행하고 텐서 전송은 별도 모듈이 처리한다.

제어 범위는 사전에 허용된 종단과 중계 프로그램이다. 실제 KOREN 경로에서 데이터를 전송하면서 응용 계층의 연결을 선택한다. CPU·메모리 한도 안에서 혼잡을 반복 재현하기 위해 SHRiNK의 축소 실험 관점을 참고하고, 관리 호스트의 대역폭·지연 조건을 조정했다.[9] 망 내부의 제어는 후속 T-SDN 연동으로 확장한다.

1) 모델 폭과 사용할 채널의 선택

스케줄러는 사용할 채널 비율을 정하고 학습 모듈은 해당 비율의 채널을 추출한다. 모델 크기 결정과 추출 방식을 분리해 고정 선택·순환 선택을 교체할 수 있도록 했다. 주 CNN 실험은 분할 위치 2와 계층 수를 고정하고 채널 비율을 조절한다.

같은 채널만 반복해서 고르면 일부 가중치에 학습이 집중될 수 있다. FedRolex식 순환 선택은 라운드마다 채널 위치를 바꾸고 원래 가중치 위치에 맞춰 집계한다.[4] 고정 선택과 순환 선택을 구현했으며, 별도 300라운드 실행과 추가 데이터셋에서 추출·집계 동작을 확인했다. 폭과 채널은 각각 크기와 선택 단위를 뜻한다.

2) CNN과 LoRA의 적용 범위

CNN은 채널 비율에 따라 연산 시간과 활성값 전송량이 함께 변하므로 결합 제어의 주 평가 모델로 사용했다. LoRA는 언어모델의 분할 학습과 전송 계층을 연결하는 개념 검증(PoC)으로 구성했다. 다른 모델도 설정별 연산·전송 비용과 집계 방법을 제공하면 이 구조에 연결할 수 있다.

LoRA는 원래 가중치를 고정하고 작은 저랭크 어댑터를 학습한다.[7,8] Qwen2.5-0.5B·랭크 16에서 분할 공동 학습을 수행했고, 별도 중계 배정 비교에서 어댑터 업로드 시간을 19.3% 줄였다.[16] 이는 언어모델에도 전송 제어를 적용할 수 있는 근거다. 랭크 조절은 활성값의 차원과 다른 변수이며 동적 결합은 후속 과제로 둔다.

• 성시준: 전체 설계·개발 총괄, 네트워크 제어, KOREN 구성·실측.
• 석태경: 분할 연합학습 파이프라인, 실험 설계·분석, 결과 시각화.

3) 완료 시간의 예측과 설정 선택

한 배치의 시간 τᵢ는 클라이언트 연산 Cᵢ, 활성값 전송 Uᵢ, 서버 처리 Sᵢ, 기울기 반환 Dᵢ의 합이다. 서버에서 기다리는 시간도 Sᵢ에 포함한다. 라운드당 배치 수를 B, 모델 배포·집계 시간을 T₀라 하면 전체 시간은 가장 늦은 클라이언트를 기준으로 계산한다.[2,5]

$$\tau_i=C_i+U_i+S_i+D_i$$

$$T_{round}\approx T_0+\max_i(B\tau_i)$$

식 (3)에서 cᵢ·bᵢ는 전폭의 배치당 연산 시간(초)·왕복 텐서량(바이트), Rᵢ는 실효 전송률(bit/s), oᵢ는 고정 처리·오차 보정값이다. γᵢ는 폭에 따른 연산 시간의 변화 정도다. FLOPs와 달리 실행 시간에는 메모리·커널 비용도 작용하므로 실측 기반 보정을 사용하며, 주 실행의 γᵢ 기본값은 1.2다.

$$\hat T_i=B[c_iw_i^{\gamma_i}+8b_iw_i/R_i(P)+o_i]$$

분할 위치 2에서 활성값의 공간 크기·자료형을 고정하면 텐서량은 채널 수에 비례하므로 8bᵢwᵢ로 비트량을 근사한다. Rᵢ는 중계 공유 용량과 접속 상한을 반영한다. 같은 접속 회선은 연결 속도의 합을 제한하고, 독립 접속은 연결별로 제한한다.

$$J=\max_i\hat T_i+\frac{\lambda}{N}\sum_i(1-w_i)$$

N은 클라이언트 수, λ(람다)는 폭 보존에 부여하는 가중치다. 평균 폭 감소량에 λ를 곱한 비용을 시간과 더하므로 단위는 초다. 큰 λ는 폭 유지에, 작은 λ는 시간 단축에 비중을 둔다. 이 항은 정확도 손실의 직접 예측값이 아니라 모델 축소를 억제하는 비용이다.

최대 예상 시간의 감소를 ΔT, 평균 폭 감소를 Δw̄라 한다. η=0.10은 일시적 잡음과 예측 오차를 고려한 안전 여유다. 시간 이득을 10% 낮춰 평가한 뒤에도 축소 비용보다 클 때 폭을 줄인다.

$$(1-\eta)\Delta T>\lambda\Delta\bar w$$

예를 들어 λ=70초에서 평균 폭을 0.1 줄이면 비용은 7초다. 10% 안전 여유를 적용한 시간 이득이 7초를 넘어야 채택한다. 실제 정확도와의 관계는 λ별 장기 학습 결과로 확인한다.

경로는 시간 합계와 N배의 최대 시간을 함께 평가해 고른다. 선택한 경로에서 폭을 비교할 때 식 (4)·(5)를 적용한다.

2. 단계별 세부 구현 계획

제어 파이프라인은 프로파일링, 설정 선택, 실행·피드백으로 구성한다. 모델과 경로는 라운드 사이에 정하고 배치 실행 중에는 선택한 설정으로 전송한다. 결정 주기를 패킷 처리와 분리해, 측정에 따른 적응과 전송 처리 속도를 함께 확보했다.

나. 경로 탐색과 선택적 모델 축소

현재 폭에서 경로 후보를 비교하는 점수 G는 시간 합계와 N배의 최대 시간을 더한다. G/N은 평균 시간과 최대 시간의 합이므로 전체 효율과 스트래글러 지연을 같은 비중으로 반영한다. 작은 이득을 얻으려다 가장 늦은 클라이언트를 더 지연시키는 선택을 억제하는 기준이다.

경로 평가에는 관측 시간과 예측 시간의 비율을 보정값으로 사용한다. 이후 폭 평가에는 식 (3)의 시간 오차 보정값을 사용한다.

$$G(P\mid w)=\sum_i\hat T_i+N\max_i\hat T_i$$

다음은 경로 이동을 모두 마쳤다고 가정한 배정에서 폭을 고르는 단계다. 가장 늦은 클라이언트와 지연이 비슷한 집단의 폭을 한 단계 줄여 시간 이득 ΔT를 구한다. 식 (5)를 만족할 때 축소를 채택한다. 경로 이동 중에 생기는 일시적인 지연으로 모델 크기를 결정하지 않기 위해서다.

탐색량은 후보 수로 제한한다. 중계 K개를 두 연결에 배정할 때 클라이언트별 후보 C는 최대 K²개다. 전체 조합 Q=∏ᵢCᵢ가 20,000 이하이면 모두 비교한다. 그보다 많으면 전송량이 큰 클라이언트부터 배정하는 탐욕 방식으로 O(NC)회 평가한다.

라운드당 M개 이동을 선택하는 과정은 O(MNC)회 후보를 평가한다. M=3은 한 번에 바뀌는 배정 수를 제한해 경로 전환의 요동을 줄인다. 폭 후보 L단계의 축소 반복은 최대 N(L−1)회다. 이는 후보 평가 횟수이며, 각 후보의 공유 용량 계산 비용이 추가된다.

설정 적용과 결과 수집

서버는 RSTART 메시지로 라운드 번호, 폭, 모델 가중치, 중계 주소와 전송 비율을 각 클라이언트에 보낸다. 클라이언트는 해당 서브모델을 만들고 기존 연결을 재사용한다. 별도로 검증한 순환 선택 모듈은 채널 위치를 바꾸어 학습하고 원래 위치에 맞춰 결과를 모은다. 학습 모듈이 바뀌어도 전송 방식은 유지한다.

주 실험은 폭 0.5·0.75·1.0과 라운드당 최대 3개 경로 이동을 사용했다. 폭 확대는 두 라운드 연속 조건을 만족할 때 적용하고, 관측 용량 변화 직후에는 폭을 동결한다. 이동 수 제한과 유지 조건을 함께 적용해 설정 변경을 완만하게 만든다.

경로별 전송 비율은 설정 용량과 공유 배정으로 계산하고, 경로 이동은 관측 용량으로 판단한다. 실행 결과는 다음 라운드의 측정값 갱신에 사용한다.

다. 다중 경로 텐서 분할과 재조립

큰 텐서를 한 연결에 맡기면 그 연결의 지연이 배치 전체의 대기가 된다. 전송 모듈은 연결별 예상 속도에 비례해 조각을 배분한다. 조각 크기는 전체 바이트를 연결 수의 16배로 나누고 64 KiB~1 MiB로 제한한다. 작은 조각의 반복 처리 비용과 큰 조각이 느린 연결에 남는 대기 사이를 절충한 설정이다.

전송 ID(tid)는 텐서를, 조각 번호(seq)는 조각을 구분한다. 위치(off)·길이(ln)로 저장 구간을 정한다. 조각마다 9바이트 헤더와 가변 JSON 메타데이터를 붙인다. 지속 TCP 연결마다 송·수신 스레드를 두고 소켓 쓰기에는 잠금을 사용한다. 헤더 비용은 메타데이터 길이와 조각 크기에 따라 달라진다.

2) 도착 순서가 바뀌어도 원래 텐서로 복원

수신부는 전체 크기의 버퍼를 미리 확보하고 각 조각을 지정 위치에 기록한다. 도착 순서가 달라도 원래 순서를 복원하며 중복·겹침·길이 오류를 검사한다. 모든 조각이 모이면 학습 모듈에 텐서를 전달한다. 분할 배분은 특정 연결에 남는 전송 부담을 줄이는 수단이고, 다음 계산은 텐서 전체 수신 후 시작한다.

3) 전송 완료 확인과 학습 모듈 연결

송신부는 다음 데이터를 보내면서 앞선 전송의 완료 회신을 확인한다. 라운드가 끝나면 flush로 남은 회신까지 확인한다. 서버의 기울기 전송은 별도 작업 스레드가 맡아 다른 처리가 소켓 대기로 지연되는 시간을 줄인다. 연결은 재사용하고 송신 버퍼 크기는 제한해, 느린 연결에 데이터가 과도하게 쌓이지 않게 한다.

전송 ID·바이트열을 다루는 전송 계층과 텐서 모양·가중치 위치를 다루는 학습 계층을 분리했다. 매 배치의 조각 재조립과 라운드 종료 시 모델 집계도 독립적으로 수행한다. 현재 구현은 연속 버퍼와 복사를 사용하며, 학습 알고리즘을 바꿔도 연결·재조립 모듈을 재사용할 수 있다.

라. 실험용 회선 설정과 실제 장치 측정

실험은 HPC의 클라이언트 프로세스와 V100 학습 서버, VM 2대에 둔 논리 중계 4개로 구성했다. Linux tc로 클라이언트의 접속 상한과 중계의 공유 용량을 따로 설정했다. 반환 방향에도 같은 상한을 적용했다.

HTB로 접속·중계의 대역폭을 설정하고 IFB로 수신 방향을 제한했다. netem은 추가 지연을, fq_codel은 큐 관리를 담당한다. 실제 KOREN 전송 위에 통제 가능한 부하 조건을 더해 정책을 반복 비교했다.[11,12]

접속과 중계의 상한을 나누면, 여러 연결이 같은 회선을 사용하더라도 전체 속도가 회선 용량을 넘지 않는 조건을 만들 수 있다. 로컬 실험도 두 단계 HTB로 같은 구조를 구성했다. KOREN의 주 비교는 연결별 독립 접속 조건이므로 결과에 기준 연결 1개와 AwareNet 연결 2개를 명시했다.

두 정책에는 라운드 기록에 맞춰 같은 부하 변화를 적용했다. 트래픽 몰림은 8라운드에 중계 용량을 56→14 Mbps로 줄이고 20라운드에 56 Mbps로 복구했다. 용량 변동은 7 Mbps 간격으로 낮추고 복구했다. 실행 조건, 시드, 사전 측정값과 라운드 로그를 보존해 설정과 결과를 대조할 수 있게 했다.[12,13]

Jetson Orin Nano Super 8GB에서는 전력 모드별 LoRA 학습 시간과 메모리 사용량을 따로 측정했다. KOREN 기록은 실제 통신 비용을, Jetson 기록은 장치의 연산 비용을 파악하는 데 사용했다. 모델과 실행 조건은 Ⅲ장에 제시한다.

15 W 모드에서는 한 스텝이 MAXN SUPER보다 약 1.63배 오래 걸렸다. 같은 장비도 설정에 따라 속도가 달라지므로 실제 연산 시간을 측정해 스케줄링에 반영할 필요가 있다.

입력 전력(VDD_IN) 평균은 MAXN SUPER 11.969 W, 25 W 모드 10.985 W, 15 W 모드 8.852 W였다. 15 W 모드의 스텝 중앙값은 MAXN SUPER의 약 1.63배였다. 동일 모델에서도 전력 모드가 연산 비용을 바꾼다는 실측 근거이며, 장치별 비용 모델의 후속 보정에 활용할 수 있다.[13]

나. 소프트웨어 부분

CNN 서브모델 선택·집계, 연산·전송 측정, 폭·경로 계획, 지속 TCP 분할 전송·재조립을 구현했다. FedRolex식 채널 순환 선택은 별도 300라운드 실행으로 검증했다. 학습 엔진과 전송 모듈을 분리해 CNN의 결합 제어와 LoRA의 공동 학습·어댑터 전송을 같은 시스템 구조에서 다루었다.

LoRA 공동 학습은 KOREN VM 두 대의 논리 클라이언트 세 개와 HPC 서버에서 실행했다. Qwen2.5-0.5B·랭크 16·16라운드×30스텝에서 자체 18문항 중 단독 학습은 6개, 연합 집계는 12개를 맞혔다.[13] 별도 6라운드 전송 실험은 중계 배정을 조절해 어댑터 업로드 평균을 20.74초에서 16.75초로 줄였다. 랭크는 16으로 고정했다.[16]

2. KOREN 연동 및 활용 결과

가. KOREN의 활용

KOREN은 원격 자원 사이에서 실제 학습 트래픽을 주고받는 연구망으로 활용했다. 동일한 연구 환경에서 정책을 반복 비교하고, 관리 호스트의 전송·수신 기록을 함께 확보할 수 있었다. 로컬 메모리 전달로는 포함할 수 없는 전송 대기·소켓 처리·텐서 복원까지 측정한 점이 중요하다.[10]

VM 두 대에 중계를, HPC에 클라이언트와 V100 학습 서버를 배치했다. 클라이언트 프로그램이 중계와 분할비를 바꾸어 실제 TCP 전송을 분산했다. 기관 간 연결·중계 사용에 합의한 범위에서 적용하는 구조이며, 관측 대상은 관리 호스트와 종단 간 전송이다.

양호한 연구망에서도 동시 전송 8개와 32개의 배치 왕복 중앙값은 0.41초와 2.18초로 달라졌다. 이 관측을 바탕으로 공유 회선의 경합을 모델에 포함하고, 자원 한도 안에서 용량·교란 시점을 통제하는 비교 실험을 설계했다. KOREN은 실제 전송 특성과 반복 가능한 조건을 연결하는 기반이었다.

나. T-SDN·L2VPN을 활용한 후속 확장

후속 단계에서는 관리 권한이 있는 스위치에 소프트웨어 SDN을 적용하고, OS-Ken 어댑터로 전달 규칙의 설치·확인을 연결한다.[14] 현재의 중계 선택 인터페이스를 유지하면서 하부 경로 정보를 확장하는 방향이다. 스위치 규칙과 스케줄러의 동시 동작을 먼저 검증한다.

KOREN T-SDN·L2VPN은 이용 조건을 협의해 적용할 후속 방안이다.[10] L2VPN으로 기관별 클라이언트와 중계를 논리망에 연결하고, T-SDN에서 제공받는 경로·회선 자원을 스케줄러에 반영한다. 제공 인터페이스·권한·용량 조건을 확인한 뒤 연동한다.

확보한 전송 여유를 모델 폭 유지에 활용하는 것이 확장 목적이다. 같은 연결 수·학습 조건에서 평균·95백분위 완료 시간과 목표 정확도 도달 시간을 비교한다. L2VPN의 논리 연결과 대역폭 보장은 별도로 확인한다.

다. 실제 경로의 관측과 축소 실험

먼저 별도의 속도 제한을 설정하지 않고 HPC에서 KOREN VM을 거치는 텐서 전송을 측정했다. 동시 전송 수를 8~96개로 늘려 실제 경로에서 전송이 집중될 때 완료 시간이 어떻게 변하는지 확인했다. 이 측정은 이후 부하 조건을 축소해 반복 비교하는 실험의 출발점이다.[11]

그림 4. KOREN 종단 간 경로의 동시 전송 규모별 완료 시간

배치 왕복 시간의 중앙값은 8개에서 0.41초, 32개에서 2.18초로 늘었다. 양호한 망에서도 여러 클라이언트가 동시에 보내면 학습이 지연될 수 있다는 결과다. 이는 HPC와 접속 회선, VM을 모두 포함한 측정이므로 지연을 KOREN 코어 장비의 영향으로만 해석할 수는 없다.

CPU·메모리 자원 때문에 많은 학습 프로세스를 장시간 실행하기 어려워 SHRiNK의 축소 실험 관점을 참고했다.[9] 32개 논리 클라이언트로 단기 제어를, 8개로 장기 학습을 평가했다. 대역폭과 부하를 조절해 작은 규모에서도 혼잡·복구에 대한 제어 반응을 관찰했다.

대역폭을 0.1배로 조정한 조건과 클라이언트를 32→8개로 줄인 조건은 구분해 기록했다. 각각 회선과 계산 자원을 조정한 별도 실행이므로 시간도 따로 비교한다. 규모와 부하 조건은 다음 표에 정리했다.

트래픽 몰림에서는 평균 폭 0.998을 유지하며 109.51초에서 62.87초로 42.6% 단축했다. 연산 지연에서는 느린 클라이언트 4개의 폭을 0.75로 줄여 79.12초에서 47.26초로 40.3% 단축했다. 통신 경합에는 전송 배정을, 연산 부족에는 선택적 축소를 사용하는 설계 의도가 실행 기록에 나타났다.[11]

기준 방식은 연결 1개, AwareNet은 2개를 사용한 전체 구성 비교다. 실제 전송량 감소는 최대 3.12%였다. 추가 로컬 진단에서는 연결 2개를 맞추고 4조건·6정책·3반복을 비교했다. 혼합 병목에서 결합 정책은 독립 제어와 비슷한 시간에 더 큰 평균 폭을 유지했다.[16]

3. 멘토 의견에 따른 개선사항

멘토 의견은 개발 목표와 실증 범위를 구체화하는 계기가 됐다. 기존 중간보고서의 7월 12일, 7월 30일, 8월 6일 기록은 클라이언트 참여, 혼잡제어와의 경계, 실제 환경 검증, 관측값의 지속성에 대한 검토를 담고 있다.[12]

모델 축소에 따른 정확도 문제를 검토하며 채널 순환 선택과 축소 비용 λ를 추가했다. 경로 선택에는 실제 전송량과 소요 시간, 공유 회선의 상한을 반영했다. 각 설정에서 얼마나 빨리 학습을 마칠 수 있는지 비교하는 방식으로 구현했다.

운영기관이 다른 클라이언트와 중계는 허용된 주소·포트로 연결한다. 현재의 중계 선택은 응용 프로그램에서 수행하며, 스위치 규칙 변경은 권한 협의와 별도 연동 검증이 필요한 후속 작업이다. 기관의 운영 정책에 맞춰 인증·암호화·접근통제를 갖추고 활성값의 정보 노출 위험을 평가한다.

다음 검증은 텐서 분할 자체의 효과에 집중한다. 모델·경로·연결 수를 고정하고 텐서 통째 전송, 균등 분할, 전송률 비례 분할을 비교한다. 텐서 완료 시간의 95백분위수와 마지막 조각 대기를 측정한다. 이어 목표 정확도 도달 시간과 LoRA의 동적 모델 조절을 평가한다.

4. 결과물의 통합 및 시험/검증 결과

가. 장기 학습과 품질 검증

λ는 모델을 얼마나 신중하게 줄일지 정하는 값이다. 큰 값은 폭 유지에, 작은 값은 시간 단축에 더 비중을 둔다. 8클라이언트·200라운드 실험에서 λ를 바꾸어 시간과 정확도를 비교했다. 시간은 초기 4라운드를 뺀 평균, 정확도는 마지막 50라운드의 평균이며 두 시드의 결과를 다시 평균했다. 평가에는 테스트셋의 앞 2,000개 표본을 사용했다.[11]

나. CNN과 LoRA의 학습·추론 시연

활용 시연은 AwareNet 안에서 공개 X-ray 분류와 가상 기업의 업무 문답을 학습하고, 클라이언트별 결과를 집계한 뒤 공동 모델로 예측하는 흐름으로 구성했다. 실행 로그·집계 결과·저장 모델의 추론 출력을 보존했다. 시연 데이터와 학습 조건은 앞의 KOREN 실험과 구분한다.[15]

| 결과 | 시험 정확도 87.02%<br>543/624 일치, 오분류 81장 | 기본 0/18 · 단독 6/18<br>연합 18/18 |

CNN은 같은 시험 영상의 학습 전·후 예측을 비교했다. 저장 모델을 다시 불러왔을 때도 624개 예측이 일치했다. LoRA는 세 부서의 규정을 나눠 학습한 뒤 같은 질문에 대한 답을 비교했다. 학습한 규정을 다른 표현으로 묻는 자체 평가이므로 일반 업무 성능으로 넓혀 해석하기는 어렵다. 병원 사례도 공개 연구용 영상의 분류 시연이다.

시연은 저장된 실제 학습·추론 로그를 시간 압축해 재생한다. CNN·LoRA의 기록 시간과 재생 표시를 함께 제공하고, 추론 답변에는 실제 생성 시간을 표기한다. KOREN 화면은 용량 축소·복구 시점과 중계 배정 변화를 강조한다. 마지막에는 공개 코드와 원자료 주소를 제시한다.

다. 모델별 실험과 원자료

ResNet-18은 CNN 계열의 모델이며, LoRA는 Qwen 언어모델에 적용한 학습 기법이다. 모델 이름과 조절 대상을 구분하고, 학습 성능·전송 제어·장치 측정을 아래와 같이 연결했다. 실험마다 데이터와 평가 범위가 다르므로 각 행의 조건 안에서 비교한다.

표 11. 모델과 학습 기법별 실험 총괄

| 모델·학습 기법 | 데이터·조건 | 비교 결과 | 근거 |

라. 기능을 켜고 끈 실제 학습 비교

기존 CIFAR-10 실험에서 폭 조절, 중계 배정, 다중 연결 분할 전송을 선택적으로 활성화했다. 8클라이언트·24라운드·3시드, 중계 용량 125 Mbps×4의 기록을 재집계했다. 이 실험은 10초 목표를 사용하는 이전 제어 방식으로, 앞의 λ 기반 평가와 구분한다.

표 12. 기능 활성화에 따른 시간과 모델 폭

| 설정 | 폭 | 경로 | 분할 | 시간(초) | 평균 폭 |

| --- | --- | --- | --- | --- | --- |

| 기준 방식 | 끔 | 고정 | 끔 | 18.95 | 1.000 |

| 폭만 | 켬 | 고정 | 끔 | 9.36 | 0.568 |

| 경로+분할 | 끔 | 켬 | 켬 | 14.48 | 1.000 |

| 폭+경로 | 켬 | 켬 | 끔 | 9.22 | 0.813 |

| 폭+경로+분할 | 켬 | 켬 | 켬 | 9.29 | 0.927 |

시간과 평균 폭은 초기 10라운드를 제외한 평균을 계산한 뒤 세 시드를 평균했다. 평균 폭은 라운드 로그의 plan 값을 사용했다. 각 실행의 설정 파일과 24개 라운드 원기록을 함께 공개했다.[17]

폭만 조절한 구성은 9.36초·평균 폭 0.568이었다. 전체 구성은 비슷한 시간인 9.29초에 평균 폭 0.927을 유지했다. 폭+경로 구성도 9.22초·폭 0.813이었다. 같은 시간 목표를 맞추더라도 전송 선택지를 함께 활용하면 모델을 덜 줄일 수 있다는 근거다.

분할 활성화는 연결 수도 바꾸므로 이 표는 기능 구성 간 비교다. 텐서 조각 크기만의 효과는 별도 비교가 필요하다. 모델 품질은 앞의 장기 학습 평가에서 별도로 확인한다.

같은 연결 수의 보조 검증

별도의 로컬 TCP 진단은 모든 정책에 연결 2개를 적용해 고정·정적 분산·경로만·폭만·독립·결합을 4조건×3회 비교했다. 혼합 병목에서 독립 제어는 0.927초·평균 폭 0.667, 결합 제어는 0.934초·0.833이었다. 이 기록은 소켓 전송과 제어 판단을 확인하는 보조 자료다.[16]

Ⅳ. 결 론

1. 개발 최종 결과물

AwareNet은 네트워크 조정으로 얻을 수 있는 여유를 먼저 평가하고 모델 축소를 결정하는 SFL 스케줄러다. 큰 텐서를 연결별 처리 속도에 맞춰 나누고 공유 회선 상한을 반영한다. 용량 변화 직후 폭 유지와 단계적 설정 변경을 통해 일시적인 지연에 과도하게 반응하지 않도록 구성했다.

KOREN의 32클라이언트 비교에서는 라운드 시간을 24.6~42.6% 줄였다. 별도 장기 학습의 λ=280에서는 폭을 유지하며 20.7% 단축과 약 −0.29%p 정확도 차이를 확인했다. 기능 비교는 비슷한 시간에 더 큰 폭을 유지하는 효과를, LoRA 전송은 언어모델 적용 기반을 보여주었다.

2. 기술 구현에 따른 기대 효과

그림 6. 여러 기관의 전역 모델 공동 개선 활용 예시

병원·제조·금융기관은 서로 다른 연산 장비와 접속 회선을 사용한다. 기관 간 협약과 통신 보안을 갖춘 환경에서, 혼잡에는 전송 분산을 적용하고 연산 부담에는 모델 조절을 적용할 수 있다. 여러 기관이 정해진 시간 안에 공동 모델 갱신에 참여하도록 돕는 것이 기대 효과다.

향후에는 기관별 데이터 특성과 자원 차이를 함께 반영해 학습 기회를 배분하고, T-SDN·L2VPN 연동으로 활용 가능한 전송 자원을 넓힌다. 현재의 KOREN 제어 검증, Jetson 프로파일, CNN·LoRA 실습은 이러한 다기관 공동 학습 시스템을 확장하기 위한 구현·측정 기반이다.
