- 이 조절 수단을 실측 근거로 제어하는 것이 과제의 본질

## 5장. 초기 설계 — 가치 기반 대역폭 할당

- 흐름도 3단계: ① 참여자별 데이터 가치를 loss 로 평가 → ② 가치 순으로 대역폭 배정
  → ③ 게이트웨이 큐(HTB)가 비율을 집행
- 성과 박스(강조): 집행 계층 검증 완료 — 한 회선(45Mbps)에 흐름 3개 경합, 큐 비율
  8:1:1 지정 → 실측 처리량 **7.93:1.01:1.00** (집행 정확도 96~100%)
- 복선 문장: "큐 정책으로 대역폭을 원하는 비율로 나눌 수 있다"는 검증 완료 —
  문제는 장치가 아니라 **적용할 수 있는 환경**이었습니다

## 6장. 한계점 ① 자기상관성 — 가치 평가의 피드백 루프

- 순환 다이어그램 3상자 + 점선 복귀 화살표:
  [loss 가 높다 = "가치가 높다" 판정] → [대역폭을 더 받아 더 많이·더 먼저 학습] →
  [그 데이터에 익숙해져 loss 하락, 다른 참여자의 loss 는 상대적 상승] → (점선) 처음으로
- 화살표 아래: 판정 기준(loss)이 다시 처음으로 — 판정이 스스로 만든 결과를 근거로
  삼는 피드백 루프
- 하단 박스 "왜 치명적인가": 가치 순위가 안정되지 않아 배정이 진동하고, "누구에게 더
  줄까"의 정답이 존재하지 않게 됨. loss 편향 선택이 수렴점을 틀어지게 한다는 이론
  결과도 있음 (Power-of-Choice 2020 — 24장 참고 문헌)

## 7장. 한계점 ② DiffServ 방식 우선순위 — 자원 편중과 과적합

좌 카드 (시도한 것):
- 트래픽에 등급 태그를 붙여 가치 높은 순서대로 대역폭을 채움 (DiffServ 의 차등
  서비스 개념) / 태그 근거는 loss 기반 가치 / 구현은 큐 우선순위로 가능(집행 검증됨)

우 카드 (부딪힌 것 — 과적합, 주황 강조):
- 상위 등급 참여자에게 학습 기회 편중 → 모델이 그 데이터에 과잉 적응(overfitting)
- 연합학습의 목적은 "모두의 데이터를 고루 반영" — 특정 참여자 편중은 목적과 충돌
- 네트워크 QoS 에서는 옳은 원리가 학습에서는 편향 장치가 됨 — 학습은 "고른 반영"이
  품질 조건

## 8장. 한계점 ③ 워터필링 — 공정성과 속도의 트레이드오프

- 3행 표: [보장을 늘리면 → 느린 참여자에게도 대역폭이 가야 해 빠른 쪽 대기, 라운드
  시간 증가] / [보장을 줄이면 → 자원 편중으로 복귀, 과적합 재발] / [중간을 찾으면 →
  환경마다 최적점이 달라 튜닝 상수가 됨 — "상수 없는 설계" 원칙과 충돌]
- 결론 박스: 속도와 공정성이 같은 자원(대역폭)을 두고 경합하는 트레이드오프 — 한
  자원 안의 재분배로는 둘 다 얻을 수 없음
- 전환 문장(초록 강조): → 그래서 조절 대상을 바꿨습니다: 대역폭(총량 고정)이 아니라
  학습량(줄여도 품질이 점진 하락)을 조절하면, 이 트레이드오프가 사라집니다

## 9장. 한계점 ④ 물리적 한계 — 실측과 조사

카드 3개:
1. 재분배 무효 (실측): 같은 회선 안 재분배 후 완료 시각 32.0초 대 34.7초(오차 범위).
   현대 TCP 는 남는 대역폭을 놀리지 않아 개입 전에 이미 물리 하한
2. 전송 시점 조절 무효 (실측): 느린 쪽은 못 당기고 빠른 쪽만 52% 지연
3. 공용 회선의 부재 (조사): Gboard·EXAM·MELLODDY 전부 참여자 공용 회선 없음 —
   배분할 대상 자체가 없었음
- 하단: 가설을 세우고 → 실측하고 → 기각을 기록했습니다. 이 이력 자체가 산출물

## 10장. 설계 변경 전후 비교 표

| | 전 (중간보고서까지) | 현 (변경 후) |
|---|---|---|
| 조절 대상 | 대역폭 할당량 (총량 고정→트레이드오프) | 학습량(폭)과 접속 경로 |
| 판정 근거 | loss 기반 가치 (자기상관성) | 시간 실측만 — 계산·전송 이동평균 |
| 네트워크 역할 | 제어 대상 (VXLAN·큐 배분) | 측정 대상 + 접속 지점 선택 |
| 공정성 | 보장을 섞을수록 느려짐 | 최소 폭 25% — 아무도 배제하지 않음 |
| 상수 | 등급·보장 수위 튜닝 필요 | 문턱 상수 0 — 중앙값×1.2, 계측 오차 10%만 |

## 11장. SDN 개념의 재적용

좌 (교과서 정의): 제어 평면·데이터 평면 분리 / 제어부가 망 전체 상태를 한눈에
관측(전역 관측) / 관측을 근거로 규칙을 내려보냄(프로그래머블 제어)

우 (AwareNet 대응 — 같은 원리, 다른 대상): 결정(컨트롤러)·학습(기기) 분리 / 모든
기기의 계산·전송 속도를 실측으로 관측 / 역할 하달 — 전체 폭·축소 폭·다른 경로 /
결과: 속도(라운드 시간)와 학습 상황(배제 0)이 함께 개선

하단: 가상 망을 구성하는 SDN 이 아니라, 망 전체를 관측해 제어하는 SDN — 과제명의
SDN 은 이 의미로 유지

## 12장. 시스템 구성 (그림 1)

- 아키텍처 그림: 기기 3대(회선 각자, "데이터 밖으로 안 나감", 폭 100/100/25%) →
  중간 결과 업로드/기울기 수신 → 서버(① 모델 뒷부분 계산+취합 ② 측정 수집 —
  별도 장치 없이 학습 트래픽 그대로 ③ 컨트롤러 — 예측→기준선 비교→늦을 기기만
  폭 한 단계 축소) → 다음 라운드 폭 지시(체크인 응답에 동봉)
- 말 포인트: 측정·결정·집행이 한 바퀴로 도는 폐루프

## 13장. 핵심 개념 ① 모델 분할과 학습량(폭) (그림 2)

- 그림: 층 6개, 절단 계층(cut layer) 왼쪽은 기기 계산·오른쪽은 서버 계산. 각 층의
  앞쪽 25%가 칠해져 "폭 25%가 쓰는 부분" — 모든 층의 앞쪽 25%, 느린 기기의
  데이터도 이 부분을 통해 매 라운드 전체 모델에 반영
- 부제: 기기는 모델 앞부분만 계산해 중간 결과를 올리고(분할 학습), 느린 기기는 층의
  일부 폭만 학습 (Ordered Dropout — 항상 앞쪽부터라 기여가 보존됨)

## 14장. 핵심 개념 ② 컨트롤러의 결정 순서 (그림 3)

- 그림: 측정(기기별 계산·전송 시간, 지수이동평균) → 예측(전체 폭일 때 완료 시간)
  → 기준선(중앙값×1.2 — "보통 기기의 1.2배까지 기다림") → 조치(넘는 기기만 폭 한
  단계 축소, 최소 25% 보장)
- 그림 아래 2단 규칙:
  - 1단 — 여유 있는 접속 경로가 있으면 이동 (정확도 손실 없음, 이득이 계측 오차
    10%를 넘고 2라운드 연속일 때만)
  - 2단 — 경로로 부족하면 그 기기의 학습량(폭)만 한 단계 축소 · 최소 폭 25% (배제 없음)
- 말 포인트: 모두 비슷하면 아무도 기준선을 안 넘으므로 개입 0회 (균질 실험으로 검증)

## 15장. 현행 설계 개념도 (그림 7)

- 그림: 기기 4대(폭 게이지: 100/100/75/100%) · 경로 2개(넓은 길 40Mbps/좁은 길
  20Mbps) · 기기 3만 좁은 길로 이동(점선 = 원래 자리) · 집계 서버 · 컨트롤러
  (측정 수신 → 지시 ① 경로 / 지시 ② 폭(모자랄 때만))
- 말 포인트: 기기 3만 옮기고, 그래도 늦는 만큼만 폭 75% — 나머지 셋은 안 건드림

## 16장. 실험 결과 요약 (숫자 카드 4개)

| 숫자 | 항목 | 조건 |
|---|---|---|
| **−40%** | 학습량 조절 — 이질 환경 라운드 시간 | 기기 4대, 회선 20~80Mbps |
| **−21%** | 학습량×경로 공동 결정 — 병목 환경 | 학습량 손실 0, 경로 이동만으로 |
| **−29%** | 언어모델 실험 — 어댑터 업로드 구간 | 실제 0.5B 모델 3기관, 실소켓 |
| **2~3%p** | 예측 오차 (계획 대비 실측) | CNN 3% · 언어모델 2%p |

하단 2줄: 안정성 — 성능 차이 없는 환경에서 개입 0회(2회 실측) / 목표 정확도 도달
시간(time-to-accuracy) — 병목 환경 20% 도달 304→179초 (−41%)

## 17장. 온라인 공동 결정 — 동작 실측 (그림 6)

- 그림: 라운드별 완료 시간 곡선 2칸 — 좌(여유 환경 100/20M): 13.1→11.8초(10% 단축),
  우(병목 환경 30/10M): 42.6→33.7초(21% 단축). 기준선(전원 빠른 경로)은 평평,
  공동 결정은 첫 이동 후 뚝 떨어져 유지
- 캡션: 전체 기기를 빠른 경로에 배치하고 시작 → 첫 측정 후 1대만 이동, 이후 안정
  (진동 없음) — 병목이 심할수록 개선 폭이 커짐

## 18장. 언어모델 실험 — 3개 기관 연합과 경로 조절

좌 (지식 공유 검증, 동일 채점 기준): 기본 모델 0%(학습 전 — 알 수 없는 사실) /
한 기관 단독 36%(자기 데이터만) / **3개 기관 연합 71%**(서로의 지식이 전달됨)

우 (경로 조절 실측 — 어댑터 트래픽):
- 기준(전원 40Mbps) 업로드 20.5초 → 공동 결정(1대를 20Mbps 로 분산) 14.7초 (−29%)
- 예측 33% 대 실측 31% — 오차 2%p
- 추가 확인: 이득이 정확히 0인 환경에서는 6라운드 내내 개입하지 않음(안정성) /
  예측-실측 불일치가 테스트베드 결함(수신 직렬화)을 발견해 수정
- 의미: CNN(활성값)과 언어모델(어댑터) — 성질이 다른 두 트래픽에서 같은 규칙 동작

## 19장. 결정 알고리즘의 신뢰성 — 3단계 검증

1. **단위 테스트 10종**: 성능 같으면 이동 없음 · 명확한 이득이면 1대만 · 차이 작으면
   유지 · 느린 경로 배정 기기는 학습량 축소 — 규칙별 테스트 등록, 전부 통과
2. **난수 시뮬레이션 1000회**: 기기 수·경로·속도 난수 생성 + 측정 잡음 ±10% →
   규칙 위반 0건 (진동·과잉 이동·성능 악화 없음), 예측 개선 중앙값 +30%
3. **발견·수정 결함 2건** (주황 강조): 측정 잡음 1회 반응 → 같은 결정 2라운드
   연속일 때만 적용 / 왕복 진동 1건 → 복귀 이동은 3라운드 연속 요구 (상수 추가 없음)

하단: 난수 시뮬레이션이 실장비보다 먼저 결함을 발견 — 실WAN 에서 났다면 원인 규명이
어려웠을 문제들

## 20장. 실험 계획 — 표준 검증 절차 4단계

| 단계 | 내용 | 상태 |
|---|---|---|
| ① 난수 시뮬레이션 | 1000회 실행, 규칙 위반 0건 | 완료 |
| ② 트래픽 제어(tc) 테스트베드 | 학습량 −40% · 경로 −21% · 언어모델 −29% | 완료 |
| ③ 실기기 (젯슨) | 연산이 실제로 느린 기기에서 학습량 축소 경향 재현 — PC 2대+젯슨 1대 | 계획 |
| ④ 실WAN (KOREN) | K-W1 사전 진단 실WAN 검증(판교 VM, 즉시 가능) · K-W2 학습량 조절 재현(실제 회선이 다른 기기들) · K-W3 접속 지점 배정 — 집계 서버 2곳(판교+HPC V100) 중 선택을 학습량과 함께 | V100 VM 확보 |

- 부제: FjORD 는 ①만, PiPar·FedAdapt 는 ②③, FEDn 은 ④ — 한 논문이 모두 수행하지는
  않는 절차를 순서대로 수행
- 하단(평가 기준, 사전 등록): 실WAN 은 수치 일치가 아니라 경향 재현 — 느린 기기만
  학습량이 줄고 라운드 시간이 단축

## 21장. 연합학습의 역할 — 현재는 검증 플랫폼, 기법은 범용

좌 (현재): 연합학습은 "기기마다 속도가 다르고 트래픽이 라운드 경계마다 집중되는"
조건을 실제로 만들어 주는 환경 / 이 환경에서 측정→결정→집행 절차를 실측 검증 완료

우 (다음): 분할 학습 — 활성값 트래픽(CNN 실험 확인) / 언어모델 — 어댑터 트래픽
(−29% 실측) / 서버에 모으면 더 빠를 수 있으나 데이터가 못 나가는 전제(병원·제약)
에서는 이 방식뿐 — 증명 목표는 범용성 (다음 장)

## 22장. 범용성 — 어떤 트래픽까지 적용 가능한가

- 기준: "모든 트래픽"이 아니라 **"양을 줄여도 품질이 점진적으로 떨어지는 트래픽"**
  이라는 분류 전체
- 적용 가능: 분산 학습 전반(성질 다른 두 트래픽에서 실측) / 영상 스트리밍(적응형
  화질 ABR 이 같은 원리의 상용 선례) / 센서·관측 데이터(샘플링 주기)
- 적용 불가(주황): 파일 전송·금융 거래 — 내용이 1비트도 깨지면 안 됨. 원리적으로
  불가하며 한계가 아니라 분류 기준
- 정리(강조): 일반 네트워크 전체로의 확장은 표준 기술(QoS)의 재확인이 되므로 하지
  않되, "양을 줄일 수 있는 트래픽" 분류에 대한 범용성은 실측으로 증명한다
- (구두 보충용) 이질 분산학습의 낙오자(straggler) 문제로 일반화 가능 — 연합학습은
  한정이 아니라 이 문제가 가장 심한 무대

## 23장. 예상 질문과 준비된 답변

- Q1 모델을 주고받는 것인가? → 데이터는 절대 안 움직임. CNN: 모델 앞부분만 계산해
  중간 결과(활성값)를 올림. 언어모델: 어댑터(전체의 1% 미만, 35MB)만 왕복, 서버가
  평균해 반환
- Q2 loss 로 가치를 나눈다면 loss 는 누가 계산하나? → 그 설계는 기각(자기상관성 —
  6장). 현재는 가치 판단 없이 시간 실측만. 한다면 기기 로컬 계산·보고(Oort 계열)가
  표준이나 피드백 루프 문제로 미채택
- Q3 컨트롤러는 무엇을 아는가? → 기기별 계산·전송 시간과 업로드 크기(실측
  이동평균)뿐, 데이터 내용은 모름. 시작 전 0.8초 사전 진단으로 첫 라운드부터 배정

## 26장. 과제명 변경안과 사유 문안

- 변경안(확정): AwareNet — 학습은 더 빠르게, 참여는 빠짐없이: 기기마다 알맞은
  학습량과 접속 경로를 정하는 연합학습 네트워크 (KOREN 실측 기반)
- 사유 문안(신청서용): "본 과제는 당초 KOREN 의 SDN 제어 기능을 활용해 회선을 측정·제어하는 것을 계획하였습니다. 그러나 수행 과정에서 현실적인 제약으로 해당 기능(L2VPN 개통, T-SDN OpenAPI 등)을 제공받기 어렵다는 것을 확인하였습니다. 이에 OVS(Open vSwitch)로 가상 경로를 직접 구성해 SDN 제어를 대신하는 방안도 검토하였으나, 이는 저희가 만든 가상 환경 안에서만 성립하고 실제 운영 환경으로 이어질 수 없다고 판단하여 채택하지 않았습니다. 이에 따라 과제의 초점을 연합학습의 학습 환경 — 학습 트래픽의 측정과 기기별 학습량·접속 경로의 조절 — 으로 옮겼습니다. SDN 의 개념이 사라진 것은 아니며, 중앙 제어부가 망 전체를 관측해 기기의 접속 지점을 바꾸는 재접속의 형태로 이어집니다. 이러한 변경 내용을 과제명에 반영하여 정정하고자 합니다."
- 절차: ① 사무국 변경 가능 여부 확인(선행) ② 가능 시 신청 ③ 불가 시 등록명 유지 +
  부제 병기
