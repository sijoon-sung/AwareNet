## 1. 실험 조건을 어떻게 정할 것인가

**상황** — 본 방식의 효과는 실험 조건에 크게 좌우된다. 병목의 위치, 기기 성능 차이, 회선
대역폭에 따라 개선 폭이 달라지고, 조건을 유리하게 잡으면 결과는 좋게 나올 수밖에 없다.
예비 실험은 임의로 정한 값(기기 4~8대, 회선 20~80Mbps 등)에서 한 것이라 근거가 약하다.

**정해야 할 것 세 가지**
1. 병목의 위치 — 기기 연산 / 기기별 접속 회선 / 서버 앞 공유 구간. 본 방식은 회선 병목에서
   효과가 나고, 연산 병목에서는 학습량 축소만 듣는다. 실증의 주된 조건을 어느 병목으로 둘지.
2. 기기 성능의 모사 — 실기기는 PC·V100 서버·젯슨 3종. 나머지는 모사해야 하며 지금까지는
   FedScale 논문의 실측 분포(연산 속도·대역폭)를 따랐다. 그대로 쓸지, 실기기 3종을 기준점으로
   두고 사이를 분포로 채울지.
3. 게이트웨이(서버 앞) 회선 대역폭 — 기기 수와 모델 크기에 비해 넉넉하면 어느 방식이나 같고,
   좁으면 본 방식이 유리하게 나온다. 값의 근거: KOREN 실측값 / 공개 측정 데이터 / 기기 수 대비
   비율.

**우리 생각** — (가) 조건을 한 점이 아니라 범위로 훑어 효과가 나는 구간과 사라지는 구간을
곡선으로 함께 보인다 (나) 조건 값의 출처를 실측·공개 데이터로 고정하고 실험 전에 등록한다
(다) 변동이 없는 조건에서는 개입 0회로 기존 방식과 같음을 보인다. 비교 대상은 아무 조절 없음 /
처음 한 번만 재고 고정 두 가지.

**여쭙는 것** — 조건에 따라 결과가 달라지는 실험을 어떻게 보여야 하는가. 위 세 가지로
충분한지, 다른 정석이 있는지. 비교 대상 두 가지가 적절한지.

## 2. 학습량×경로의 공동 최적화 정식화 — "단순 결합"으로 보이지 않으려면

**상황** — 학습량 조절과 경로 조정이 기능 두 개의 결합으로 보일 위험. 따로 결정하면
틀린다는 것은 관측했다(경로만 놓고 최적이던 배정이 학습량을 함께 조절하자 뒤집힘).

**정식화 (초안)** — 기기 i 의 폭 w_i, 접속 지점 a_i 에 대해

    T(w, a) = R(w) × max_i [ C_i·w_i^γ + w_i·B_i / φ_i(a) ] + Σ δ·(a_i 변경)

R(w) = 목표 정확도 도달 라운드 수, C_i = 연산, B_i = 업로드 바이트, φ_i(a) = 배정 a 에서의
실효 대역(경로를 공유하는 다른 기기들의 w 에 의존 — 비분리성). 이동 채택 조건 "(라운드당 절감)
× (남은 라운드) > 전환 비용 δ"가 수식의 귀결. 해법은 교대 최적화(무선 FL 수렴 시간 최소화
계열, 분할학습 절단층×자원배분 계열의 표준). 남은 재료: R(w) 적합용 폭별 정확도 궤적 부족 →
전용 예비 실험(폭 4수준 × 3시드 × 30라운드).

**여쭙는 것** — ① 이 정식화가 "단순 결합" 지적에 충분한 답인지 ② R(w)를 이론 상계 없이 실측
적합으로 넣는 것이 용인되는지 ③ 차별점을 어디에 둘지 — 후보: 변수 조합 / 실측만으로 하는 온라인 결정 /
실망 검증 (학술 발표가 아니라 대회 심사의 차별점 수준).

## 3. 경로 수단 — 분할 전송이 주력, 두 번째 경로는 우리가 만들 수 없다

**상황** — 주력은 분할 전송(TCP 멀티패스 방식: 조각으로 나눠 두 출구로, 먼저 한가해진 출구가 다음
조각). 접속 지점 변경은 조각 전부를 다른 접속 지점으로 보내는 특수한 경우 — 완전히 다른 수단이
아니다.

**문제** — 두 번째 출구(또는 접속 지점)가 실제로 있어야 하고 한가한 쪽이 조각을 가져가야
성립하는데, 이는 배치가 정하는 것이라 우리가 강제할 수 없다. 실증에서는 우리가 두 경로를 만들어
둔다(tc 에뮬레이션, 두 호스트) → "직접 만든 조건" 지적 가능. 두 번째 경로가 다른 서버로 가면
서버 간 동기화 비용(CNN 서버 뒷단 42MB ≈ 6.5초/라운드, LoRA 어댑터 35MB ≈ 5.1초) 발생.

**여쭙는 것** — ① 성립 조건(출구 2개 기기, 접속 지점 다수 배치)의 제시 방법 ② 접속 지점은 한 곳,
출구만 둘로 할지 / 동기화 비용까지 식에 넣고 다른 접속 지점으로도 조각을 보낼지.

## 4. 실증 규모와 편차·변동

**상황** — 실학습 8대까지(예비). 결정 루프 100대는 완전탐색이 5대부터 조합 폭발. 기기 성능·
네트워크 분포는 임의. 많은 연구는 기기 성능을 고정으로 본다.

**시안** — 규모: 실학습 16대(PC 8 + V100 8, 호스트 간 실제 망) + 결정 루프 100대(교대 최적화
근사, N≤4 최적 대비 오차 검증). 기기 성능: 3계층 실측 기준점 + FedScale 보간. 네트워크: KOREN
실측 상단 + 공개 데이터 하단, 변동 패턴은 장기 로그의 자기상관 특성 재현. **연산 능력: 기본
고정(관행), 변동(젯슨 전력 모드·배경 부하)은 부가 실험** (2026-09-02 팀 결정). 고정 가정 방어:
망은 변한다(장기 로그 자기상관 +0.4~0.87, 급락 실험) — 변동 없으면 개입 0회로 정적과 동일.

**여쭙는 것** — 규모 목표선·두 호스트 분산의 인정 가능성. 편차 방식의 타당성. 망 변동은 어느
기간·무슨 지표로 보여야 하는지.

## 5. 이분법(켜기/끄기) 대신 조건의 정밀 모델링

**상황** — 여러 결정이 "조건이 맞으면 켠다"(분할 전송: 출구 2개면 켬 / 파이프라인 켜고 끔). 경로
이동은 규칙 → 경제성 모델("이득 − 비용")로 바꿔 더 깔끔해졌다.

**우리 생각** — 각 수단의 이득을 조건의 함수로 목적식에 넣어 항상 최적을 계산. 결정론(기대값 +
계측 오차 여유)으로 시작. 잡음이 큰 항(무선 출구 속도, 남은 라운드 추정)은 분포로 다루면 더
정밀해질 여지.

**여쭙는 것** — ① 결정론 모델로 충분한지 ② 확률 모델이 필요한 지점이 있는지 ③ 있다면 어느
수단부터.
