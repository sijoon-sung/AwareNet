# 방향 결정 브리프 — 양희철 교수님 미팅용 (다음 주)

> 목적: 챌린저데이 멘토링(2026-08-28, 구판 hwpx 기준 의견)을 받아 방향을 확정한다.
> 미팅 진행 방식: 별도 설명 자료 없이 **고친 최종본을 처음부터 쭉 설명**하고,
> 이 브리프는 갈림길 결정용 보조 자료로만 쓴다.

## 1. 현재 위치 (중간보고서 이후 바뀐 것)

중간보고서(8/17)는 **선별층·배분층**(학습 가치 기반 대역 배분) 설계였다. 이후 실전
배치 조사에서 **실제 연합학습에는 클라이언트들이 다투는 공유 병목 자체가 없음**
(구글·EXAM·MELLODDY 전수 확인)을 확인하고, 8월 말 방향을 전환했다:

**현 설계 = AwareNet 폭 컨트롤러**: 망·기기를 실측해 클라이언트별 학습 폭
(CNN 채널 / LLM LoRA rank)을 배정하는 분할연합학습 스케줄러.
- 검증 완료: 마감선 규칙(중앙값 3판, 유닛 8/8·시뮬 6/6), 이질 환경 makespan
  −40%(3방향 정합), 교란 ≤2라운드 회복, 폭×경로 공동 최적화(예측 오차 3%),
  LLM 지식주입 0→72%·3기관 연합 67%, 파이프라인·시차 계획기(시험 5종),
  카나리아 유출 실측, 폐루프 라이브 데모 2종
- 문서: 방향 전환 근거·금지 주장·보안 입장 전부 사전 등록 (9·14·15번 문서)

## 2. 챌린저데이 멘토 의견 (구판 hwpx 기준)

멘토의 논리 흐름을 그대로 옮기면: "연합학습에서 네트워크가 트래픽을 인지하지
못하는 문제를 풀겠다고 시작했고, 배분층에서 효과가 나왔다. 그렇다면 이 장치가 꼭
연합학습에서만 되는 것인가? 도메인을 한정하지 말고 전체 네트워크에 적용하라."
학습 폭 이야기에는 관심을 보이지 않았다.

정리하면 세 가지다: ① 보고서가 어렵다 — 모르는 사람이 알아듣게 ② 이것은
네트워크 과제다 — AI 쪽에 매달리지 말라 ③ 트래픽 인지·배분 장치를 연합학습
너머 일반 트래픽으로 넓혀라.

## 3. 전과 현 — 무엇을 바꾸려는가 (교수님께 보여드릴 핵심 대비)

| | 전 (중간보고서까지) | 현 (바꾸려는 방향) |
|---|---|---|
| 한 줄 목표 | 학습 가치를 반영해 **회선(대역폭)을 배분**하는 SDN 계층 | 망·기기를 실측해 **학습량(폭)을 배분**하는 컨트롤러 |
| 네트워크의 역할 | 제어 대상 (VXLAN 토폴로지·큐 배분) | 측정 대상 (제어하지 않음) |
| 연합학습의 역할 | 응용 (트래픽을 만드는 쪽) | 본체 |
| SDN | 본체 | 사실상 소멸 — 경로/접속 지점 배정만 흔적으로 남음 (그것도 아직 모의 검증) |
| 바꾸는 근거 | — | 실제 연합학습에는 공용 회선이 없음(배치 조사) + 같은 회선 안 재분배는 효과 없음(실측) |

## 3-1. 두 방향의 한계 (정직하게 — 둘 다 한계가 있다)

**연합학습에 치중(현 방향)의 한계**: 네트워크 과제로서의 필요성이 약해진다.
학습 폭(Ordered Dropout)과 SDN 제어는 물리적으로 섞이지 않는다 — 유일한 접점은
경로/접속 지점 배정인데 아직 모의 검증뿐이다. 과제 제목("KOREN SDN 기반")과의
거리가 생긴다.

**네트워크에 집중(외부 멘토 제안)의 한계**: 연합학습을 버려야 한다. 그런데 원래
목표는 "연합학습에 특화된 네트워크"를 만드는 것이었다 — 과제 제목이 일반 SDN
과제처럼 읽혀 오해를 산 면이 있다. 일반 트래픽 배분은 이미 표준 기술(QoS·5G
슬라이싱)이 있어 새로움도 약하다.

## 3-1-가. 발전안 ① — 연합학습 치중을 유지하면서 SDN(폭↔망)을 잇는 세 방안

한계였던 "폭(OD)과 SDN이 물리적으로 안 섞임"을 줄이는 연결 지점이 셋 있다.
셋 다 새 시스템이 아니라 이미 있는 부품을 잇는 것이다.

1. **큐 우선순위를 세 번째 조절 수단으로.** 지금 컨트롤러의 단계는 "폭 축소 →
   (부족하면) 양자화"인데, 여기에 "(관리형 망이라면) 게이트웨이 큐에서 그 기기의
   업로드 우선순위 상향"을 추가한다. 학습 손잡이(폭)와 망 손잡이(큐)를 **같은 마감
   규칙이 함께 산출** — 중간보고서의 큐 집행 실증(8:1:1)이 그대로 집행층이 된다.
   성립 조건(기관 게이트웨이 = 병목 큐를 우리가 소유)은 명시한다.
2. **폭×경로 동시 결정의 실WAN 승격.** 이미 통과한 폭×경로 동시 결정(현재는 모의)
   을 KOREN 다지점에서 실제 경로로 실증한다. SDN 으로 연합학습 경로를 배정하는
   선행(SmartFLow, arXiv 2509.00603)이 있으므로 "최초"는 금지 — 우리 차별점은
   경로를 폭과 **함께** 정한다는 것(선행은 경로만).
3. **전송 시차의 망층 집행.** 라운드 경계에 전송이 몰리는 문제(실측: 13대 동시
   업로드에 지연 5배)를 컨트롤러가 산출한 시차로 푸는데, 이 시차를 앱 계층이
   아니라 게이트웨이 큐로 집행하면 망층 기여가 된다.

→ 셋을 합치면 "하나의 컨트롤러가 학습 손잡이(폭)와 망 손잡이(큐·경로·시차)를 같은
규칙으로 함께 결정"이 되어, 과제 제목의 SDN 이 본문으로 돌아온다.

## 3-1-나. 발전안 ② — 네트워크 집중을 "일반"이 아니라 "연합학습 특화"로

멘토 제안을 그대로 하면(일반 트래픽 배분) 표준 기술의 재확인이 되지만, 범위를
**"연합학습의 트래픽 구조를 아는 네트워크"**로 좁히면 새로움이 살아난다. 연합학습
트래픽에는 일반 트래픽에 없는 구조가 있다 — 라운드 경계의 다대일 몰림, 마감,
주기적 벌크 전송, 참여자 집합의 변동. 이 구조를 아는 망 제어는 실제 연구
영역이다(망 내 집계+경로 스케줄링 SECON 2024 · SDN 기반 기관 간 FL 경로 배정
SmartFLow · 혼잡 인지 집계 스케줄링). 이 판이라면 연합학습을 버리는 것이 아니라
**"특화 대상"으로 유지**된다 — 원래 목표였던 "연합학습에 특화된 네트워크"라는
문장과 정확히 일치하고, 제목의 오해도 해소된다. 대가: 폭/언어모델의 비중 축소.

## 3-1-다. 부품 구분표 — 일반 네트워크에서도 되는 것 / 연합학습에서만 되는 것

| 일반 네트워크에서도 되는 것 (조절: 언제·어디로·누구 먼저) | 연합학습에서만 되는 것 (조절: 얼마나) |
|---|---|
| 큐 우선순위·배분 (누구 먼저) | **학습 폭(OD) 조절** — 보내는 양 자체를 줄여도 결과가 성립 |
| 전송 시차 — 몰림 회피 (언제) | LoRA 랭크 조절 (언어모델판) |
| 경로/접속 지점 배정 (어디로) | 어댑터만 모아 평균하는 연합 집계 |
| 마감 기준선 — 중앙값×1.2 (얼마나 기다릴지) | 시간↔정확도 거래의 판단 |
| 파이프라이닝 — 기다림 숨기기 | 최소 폭 참여 보장 (배제 없는 학습) |
| 인밴드 측정 (상황 인지) | |

가르는 본질: 일반 트래픽은 내용이 깨지면 안 되므로(파일은 반만 보내면 무용)
타이밍과 경로만 조절할 수 있다. 학습 트래픽은 **양을 줄여도 품질이 점진적으로만
떨어지므로** 네 번째 손잡이("얼마나")가 생긴다 — 우리 폭 조절이 그 자리다.

미팅 설명 문장: "왼쪽은 표준 기술과 겹치는 영역이라 저희 새로움이 아닙니다.
저희의 새로움은 학습에서만 열리는 오른쪽 층에 있고, 그래서 연합학습을 유지합니다.
다만 왼쪽 부품들도 저희가 만들었으므로, 이를 SDN 접점으로 살리는 것(발전안 ①)이
남은 선택입니다."

## 3-1-라. 관찰 — 두 발전안은 같은 곳으로 수렴한다

발전안 ①과 ②는 같은 부품(큐 우선순위·경로 배정·전송 시차·마감 규칙)을 쓴다.
차이는 하나뿐이다 — **폭(학습량 조절)과 언어모델을 본체로 두느냐, 축소하느냐.**
따라서 교수님께 드릴 질문이 단순해진다.

## 3-2. 교수님께 여쭙고 싶은 것

두 방향의 수렴점("연합학습 트래픽을 아는 네트워크 제어")을 전제로, **폭·언어모델의
비중을 어디에 둘지** 교수님의 생각을 듣고 싶다 — ① 본체 유지(발전안 ①: 폭이 중심,
망 손잡이를 연결) ② 축소(발전안 ②: 망 제어가 중심, 학습은 특화 대상) ③ 그 사이.
