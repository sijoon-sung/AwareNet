# 검증 매트릭스 — 무엇이 무엇을 증명하고, 언제 도는가 (11번 문서)

> 진입점 하나: `bash scripts/run_tests.sh {fast|full|rig}`.
> 원칙: 시험 이름 = 증명하는 주장. 통과 못 하면 해당 주장을 발표·보고서에서 내린다.

## 3. RIG — 실증·발표 전, sudo·tc·GPU, ~15분 + 수동 리허설

| 시험 | 증명하는 주장 |
|---|---|
| **리그 자가 검사 (`scripts/measurement/rig_selftest.py --cond <조건>`)** | 리그가 조건 원장의 물리대로 동작한다 — A 단독 처리량 ≈ min(접속 상한, 경로) · B 동시 처리량 ≈ 물 채우기 균등 몫 · C 왕복 지연 ≈ 2×편도. **실패하면 드라이버가 실험을 걸지 않는다** (5판 1차 2026-09-06: 접속 회선이 가중치로 동작한 결함의 재발 방지) | 리그 위 모든 실측 |
| 조건1 스크리닝 (rerun_R_quick cond1) | 실물 리그에서 균질 무개입 — 계측·규칙·리그의 통합 건전성 |
| M4 축약판 (run_m1 3라운드) | 경로 리그(paths.sh) 가동성 + 균질 무개입 |
| **수동 리허설 목록** | ① 폐루프 라이브: 기동→R3 대기→c3 조임→회복 배지 확인→복구→전폭 복귀 확인 ② 삼면비교 채팅: 기동→제안 질문 3개→베이스/튜닝 대조 확인 ③ 재생 데모: make_demo 재생성→그리드 확인 |

## 4. 운영 수칙

- 커밋 전 FAST 는 무조건. FULL 은 실험 착수 전·러너 수정 후. RIG 는 시연 전날+당일.
- 새 기능은 **시험을 먼저 등록**하고(이 표에 행 추가) 구현한다 — 사전 등록 문화의 코드판.
- 시험 실패 → 해당 주장을 발표·보고서에서 즉시 강등 (R5-Q 양자화 동결이 선례).
- 배포(deploy/remote push.bat)는 원격 스모크 3종이 내장돼 있다 — 그것이 원격판 FAST.
