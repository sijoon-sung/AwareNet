**왜 0인가.** TCP 공정 분배(물 채우기)에서 두 경로를 연 기기는 두 경로 모두의 "사용자"로 세어져 남들 몫을 그만큼 가져간다.
동질 집단에서 분할은 통째 이동과 총비용이 같거나(라운드 시간 동일) 약간 나쁘다. 분할이 이기는 자리는 접속이 작은 기기들이
경로를 못 채워 **남는 용량**이 있을 때뿐이고 그 이득도 몇 %다. 즉 **접속 회선이 한 가닥인 물리 모형에서는 분할 전송이
전송 시간을 줄이지 못한다.** (MPTCP 가 coupled congestion control 로 "한 경로 흐름보다 더 갖지 않게" 하는 이유와 같은 현상.)
분할이 크게 이기는 물리 모형은 **기기가 접속 회선을 2개(유선+무선) 가질 때** — 그때 실효율 = a_A + a_B. 이 선택은 사용자 결정 사항.

### HPC 스모크(h5xm mp, 2R)가 잡은 결함 4 — 조각 크기 고정의 꼬리 지연
두 출구를 연 c3(혼자 경로 2, 예상 64 Mbps)가 한 출구만 쓴 기기들보다 느렸다(전송 8.3s vs 4.8s). 즉시 내보내기로 페이로드가
2MB 가 되자 1MB 고정 조각이 2개뿐 → 느린 출구(19 Mbps)가 1MB 를 잡는 순간 완료가 0.43s 에 묶임(빠른 출구 혼자 0.37s).
MPTCP 의 head-of-line 문제와 같은 현상. → 조각 크기 = clamp(페이로드/(8×연결 수), 64KB, 1MB) + 꼬리 규칙(남이 더 빨리
끝낼 수 있으면 느린 연결은 조각을 안 집음, 연결별 속도는 EWMA 0.5). 시험: 옛 규칙 재현 0.44s > 혼자 0.36s, 새 규칙 0.27s(이상 0.26s).
리그 자가 검사 h5x: A 45~48/50, B 36~37/37.5, C 30.4ms, D 62~64/70 (A 46 + B 17.5) 통과. 자가 검사 위생: 송신 버퍼 256KB, 검사 간 2s 배출.
