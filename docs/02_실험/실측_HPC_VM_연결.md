## 4. 처리량 — 아직 못 잼, 조건

HPC → VM 처리량은 VM 에 iperf3 서버(예: 12005)를 띄워야 잴 수 있다. 서버를 띄우려면 VM 로그인이 필요한데
집·HPC 에서는 26022 가 막혀 있고 22 에는 sshd 가 없다. 두 가지 중 하나를 하면 바로 잰다:
① 연구실에서 `bash scripts/measurement/hpc_vm_link.sh iperf` ② 연구실에서 두 VM sshd 에 `Port 22` 추가 후 어디서든.

## 5. 실험에 주는 뜻

- 실험 트래픽은 지금도 흐른다: **VM 에 집계 서버(12000번대)를 띄우면 HPC 클라이언트가 붙는다.** 코드 수정 없음(`--port`).
- HPC 를 집계 서버로 쓰려면(GPU 뒷부분 계산) 클라이언트가 HPC 로 들어와야 하는데 그 방향이 불가 → HPC 에서 VM1 로 역방향 SSH 터널(HPC → VM1:22)을 걸고 클라이언트는 VM1:포트 로 붙는 형태. 이것도 VM1 sshd 의 22 가 전제.
- 결론: 다음에 연구실에서 할 일 한 가지 = 두 VM sshd 에 `Port 22` 추가. 그 뒤로는 집·HPC 어디서든 서버 기동·측정·터널이 된다.

## 6. HPC 운영 측 답변 (2026-09-03)

- KOREN VM IP(116.89.187.190, .189)는 HPC 쪽 접속 허용 목록에 **등록됨**.
- **공인 IP 로의 포트 포워딩은 불가.** 대신 포털 자료실의 **리눅스용 접속 프로그램**을 KOREN VM 에 설치하면
  런처와 같은 방식(10000~15000 포트)으로 VM → HPC 접속이 가능하다고 안내.
- 따라서 VM → HPC 방향은 "리눅스 접속 프로그램을 VM2 에 설치 → VM2 클라이언트가 HPC 집계 서버(12001)에 접속"으로 푼다.
  역방향 SSH 터널은 대안으로만 남긴다.
- 할 일: 자료실에서 리눅스 접속 프로그램(파일·설치 안내) 받기 → VM2 에 설치 → VM2 에서 `nc -zv 10.246.246.33 12001` 로 확인.

## 7. VM → HPC 접속 방법 (가이드 확인, 2026-09-03)

넷챌린지캠프용 가이드 v3.0 §3.4 "직접연결 및 포트포워딩":
- 리눅스에서는 웹 브라우저 없이 **CLI 접속 프로그램 `hirun`** 으로 로그인·접속한다. 포털 [사용자 지원 → 자료실 → "리눅스 프로그램"(18번)] 게시글에서 내려받는다.
- 필수 패키지: Ubuntu `apt-get install -y proxychains4` (CentOS 는 proxychains-ng). hirun 이 proxychains 로 SOCKS 게이트웨이를 태운다 (윈도우의 ProxyCap 과 같은 역할).
- 모든 HPC VM 은 10000~15000 포트로 외부와 통신할 수 있고, 포트 설정은 HPC VM 안에서 한다.
- 사용 예: `./hirun -u '$ID' -p '$PW' -c 'ssh -p 11000 $ID@$IP'` — `-c` 뒤의 명령이 터널을 타고 실행된다.

우리 배치에 적용: KOREN VM2 에 proxychains4 + hirun 설치 → VM2 에서 `./hirun -u ID -p PW -c 'python sfl/fed_client.py --server 10.246.246.33:12001 ...'`
→ 클라이언트 트래픽이 HPC 집계 서버(12001)로 간다. 확인: `./hirun -u ID -p PW -c 'nc -zv 10.246.246.33 12001'`.
ID·비밀번호는 포털 계정이므로 사용자가 직접 입력한다.

주의: 내려받은 `pcap536_x86.zip` 은 **윈도우용 ProxyCap 설치본**이라 VM 에는 쓰지 않는다 (PC 에는 이미 설치됨).
