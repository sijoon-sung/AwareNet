# KOREN·Jetson 실측값 주입 재현 실험

2026-09-23 · `awarenet` · **결과 종류: 기존 실측값을 사용한 시간 모형 및 로컬 TCP 주입 실험**

## 1. 결과 요약

새 KOREN 접속 없이 기존 원시 기록을 복구해 재현 실험을 실행했다. 젯슨 전력 모드별 90개 스텝과 KOREN 8개 논리 클라이언트의 전송 시각을 사용했다. 원본 측정값, 그 값을 변환한 가정, 이번 재현 결과를 아래에서 구분한다.

대표 조건은 젯슨 전체 학습 시간의 절반을 전송 이후 계산으로 배치하고, 나머지 절반 뒤에 전송이 준비되는 모형이다. 이 절반이라는 비율은 측정값이 아니라 민감도 분석의 중간값이다.

| 결과 종류 | 조각 순환 전송 RR | 조건부 전송 순서 | 시드/샘플별 감소율 평균 |
|---|---:|---:|---:|
| 실측값 주입 시간 모형, 원래 속도 계수 | 1.745초 | 1.571초 | **9.97%** |
| 같은 대표 조건을 로컬 TCP에 주입, 5쌍 | 1.753초 | 1.579초 | **9.91%** |
| 회선 계수만 0.1배로 낮춘 시간 모형 | 10.891초 | 10.717초 | **1.60%** |

위 시간은 **전송 준비와 전송 및 그 뒤 계산이 끝나는 모형 구간**이다. 전체 SFL 라운드·정확도 도달 시간·새 KOREN 현장 성능이 아니다. 로컬 TCP에서는 측정된 시간을 대기 시간으로 주입했고 학습 모델을 실행하지 않았다.

### 실제 기록값

장비: Jetson Orin Nano Super 8GB. 원본 환경 기록은 Jetson Linux R39.2.1, CUDA 13.2, torch 2.12.0+cu132다. 이번 PC 환경을 뜻하지 않는다.

워크로드: **Qwen2.5-0.5B, LoRA r=32, q_proj/v_proj, fp32, batch=1, sequence=256**. 워밍업 3회 제외, 전력 모드별 30스텝.

| 전력 모드 | 중앙값 | 평균 | 기록된 표준편차 | 표본 수 |
|---|---:|---:|---:|---:|
| MAXN SUPER | 554.1ms | 556.1ms | 3.9ms | 30 |
| 25W | 608.9ms | 610.1ms | 2.3ms | 30 |
| 15W | 903.7ms | 903.6ms | 3.5ms | 30 |

평균과 중앙값을 만들어 넣지 않고 `step_times_ms` 배열의 기록을 그대로 읽었다. 하나의 젯슨에서 모드를 바꿔 측정한 자료다. 8개 논리 기기로 복제해 사용했다고 해서 실물 젯슨 8대를 측정한 것은 아니다.

원본 측정 코드를 확인하면 스텝 시간에는 **forward + loss.backward + optimizer.step + CUDA 동기화**가 포함된다. SFL의 분할점 이후/이전 계산 시간으로 분해되어 있지 않다. 따라서 554.1ms를 “기울기 수신 후 역전파 실측값”으로 이름만 바꿔 사용하지 않았다.

[메모리 원기록](../../_archive/v2/jetson/results/jetson_memory_envelope.md)도 남아 있다. batch=2·seq=512에서는 forward, batch=2·seq=256에서는 backward에서 실패했고, batch=1·seq=256에서 30스텝이 성공했다. 이런 제약은 기록의 범위 안에서 근거로 사용할 수 있다.

## 3. KOREN 입력값을 복원한 방법

원시 파일:

- [8기기 batch 패턴](../../out/line_scale_detail/n8_s1.0_tcp_batch_1788881912.json), 2026-09-09 00:38:32 KST 기록.
- [8기기 burst 패턴](../../out/line_scale_detail/n8_s1.0_tcp_burst_1788881939.json), 2026-09-09 00:38:59 KST 기록.
- 수집 코드: [line_scale.py](../../scripts/measurement/line_scale.py). HPC→KOREN VM→역터널→HPC의 echo 전송이다.

각 클라이언트가 배치당 **4.2MB를 올리고 같은 크기를 받는다**. 4배치×3구간, 논리 출구 2개다. 데이터 생성에는 학습 모델이 없다. 이번 주입 페이로드는 이 기록의 `dn_mb=4.2`에서 가져왔다.

기존 요약의 `aggregate_mbps`는 `N × 기기당 중앙 처리량`이므로 진짜 공통 시간축의 총처리량으로 사용하지 않았다. 동기화된 burst 구간에 대해 다음과 같이 다시 계산했다.

```text
구간 바이트 = 8기기 × 4배치 × (4.2MB 업로드 + 4.2MB 반환)
공통 시간 = 가장 늦은 종료 시각 − 가장 이른 시작 시각
서비스 속도 계수 = 구간 바이트 × 8 / 공통 시간
```

| burst 구간 | 실제 기록의 공통 시간 | 유도한 서비스 속도 계수 | 사용 |
|---|---:|---:|---|
| 0 | 7.605초 | 282.761Mbps | 계획기의 예측값 보정 |
| 1 | 8.195초 | 262.404Mbps | 평가 환경에 주입 |
| 2 | 8.064초 | 266.667Mbps | 평가 환경에 주입 |

이 계수는 왕복 페이로드·터널·프로토콜·경합의 영향을 포함한 **서비스 시간 환산값**이다. 물리 링크 속도나 단방향 내려받기 대역폭을 직접 잰 값은 아니다. 이것을 단일 출구의 페이로드 직렬화 속도로 사용하는 것은 이번 시간 모형의 가정이다. RTT를 별도로 더하면 기존 지연을 중복 반영할 수 있어 추가하지 않았다.

### 보정값의 제한도 검사

구간 0으로 구간 1·2의 공통 시간을 예측하면 각각 **7.20%, 5.69% 짧게 예측**한다. 입력으로 쓰는 범위의 시간 변동이 있다는 뜻이며 실제 망과 모형의 완전한 일치를 뜻하지 않는다.

batch 패턴을 같은 방식으로 억지로 환산하면 첫 구간에서 뒤 구간을 29.1~30.5% 짧게 예측한다. 또한 기기별 배치 인덱스 구간이 시간상 겹치므로 독립 용량 측정으로 볼 수 없다. **이를 주 정책의 서비스 속도 입력으로 쓰지 않았다.** 자료는 보정 실패 근거로 함께 보존했다.

## 4. 주입 규칙과 확인되지 않은 가정

| 항목 | 사용한 값 | 근거 종류 |
|---|---|---|
| 기기 전체 학습 스텝 | 각 전력 모드의 `step_times_ms` | 실제 원시 기록 |
| 전력 모드 구성 | MAXN 4개 + 25W 2개 + 15W 2개 | 논리 기기 구성 가정 |
| 기기별 페이로드 | 4,200,000바이트 | KOREN echo 측정 워크로드 |
| 공유 서비스 속도 | 위 burst 구간의 환산 계수 | 실측 기록에서 유도 |
| 전송 뒤 계산 비율 α | 0.25 / 0.50 / 0.75 | **SFL 분해 실측이 없어 둔 민감도 가정** |
| 전송 준비 시각 | 모두 0 또는 `(1−α) × 전체 스텝` | 도착 모형 가정 |
| 전송 후 계산 | `α × 전체 스텝` | 전체 스텝을 분할한 가정 |
| 속도 배율 | 1.0 / 0.1 | 원래 계수 / 합성 병목 민감도 |
| 조각 | 64KiB | 실험 설계 |
| 계산 시간 예측 범위 | 앞 10개 표본의 min/max에 ±5% | 과거 표본 기반 경험 범위, 신뢰구간 아님 |
| 완료 예측 오차 여유 | 10ms | 설계값, 실망에서 보장된 오차 상한 아님 |

이 모형은 **Qwen의 전체 계산 기록과 KOREN echo의 페이로드를 결합한 혼합 워크로드**다. 측정 당시의 Qwen SFL 분할 학습을 복제했다고 해석하지 않는다. 모델 폭이나 페이로드를 정책별로 줄이지 않았다.

젯슨 표본 0~9만 예측에 사용하고 10~29를 평가했다. KOREN 구간 0만 계획기에 주고 실제 전송 시간은 구간 1·2의 계수로 계산했다. 같은 평가 사례의 모든 정책은 동일한 바이트·도착 시각·계산 시간·속도를 받는다.

8개 논리 기기는 같은 장비의 전력 모드별 기록을 재사용한다. 같은 모드의 기기들은 같은 스텝 표본을 사용했다. 표본을 독립 측정으로 부풀리거나 임의 가우시안 잡음을 추가하지 않았다.

## 5. 모형 결과: 어떤 가정에서 이득이 생기는가

3개 계산 비율×2개 도착 모형×2개 속도 배율×2개 네트워크 평가 구간×20개 젯슨 평가 스텝 = **480개 짝지은 사례**. RR·FIFO·SJF·긴 계산 우선·조건부 개입의 5정책을 비교했다. 각 행은 40사례 평균이다. 480회 독립 현장 측정이라는 뜻은 아니다.

### 계산을 마친 기기부터 준비되는 경우

| 속도 배율 | 전송 후 계산 비율 α | RR | 조건부 개입 | 감소율 평균 |
|---|---:|---:|---:|---:|
| 1.0 | 0.25 | 1.658초 | 1.571초 | 5.25% |
| 1.0 | 0.50 | 1.745초 | 1.571초 | **9.97%** |
| 1.0 | 0.75 | 1.832초 | 1.571초 | 14.25% |
| 0.1 | 0.25 | 10.804초 | 10.717초 | 0.81% |
| 0.1 | 0.50 | 10.891초 | 10.717초 | **1.60%** |
| 0.1 | 0.75 | 10.978초 | 10.717초 | 2.38% |

모두 준비된 큐에서는 원래 속도·α=0.5일 때 1.467→1.294초, 11.84%다. 이 조건의 FIFO/SJF도 7.60% 개선하므로 단순 정책의 효과를 빼고 해석해야 한다. 반면 계산을 마친 순서로 준비되는 대표 조건의 FIFO/SJF는 RR과 같은 완료 시간을 보였다.

조건부 개입은 이번 범위에서는 모든 사례에서 개입했고 RR 대비 악화가 없었다. 변화가 작은 전력 모드별 실측 표본을 사용한 결과이지, 앞선 급변 반례가 해결된 것은 아니다. 준비가 드물게 겹치는 조건이나 갑작스러운 성능 역전은 [앞선 실패 실험](../04_설계기록/핵심기여_설계실험_반복검토_2026-09-22.md)의 제한을 유지한다.

**0.1배는 기존 32대↔8대 축소와 동등하다는 주장이 아니다.** 이번에는 기기 수·계산량·페이로드를 그대로 두고 속도 계수만 줄였다. 이 경우 네트워크 시간이 지배적이 되어 순서 변경으로 겹칠 수 있는 계산의 상대 비중이 작아졌다.

## 6. 실제 로컬 TCP 주입 결과

대표 조건 α=0.5·계산 준비 도착·KOREN 구간 1의 계수 262.404Mbps를 사용했다. 젯슨 평가 표본 10~14로 5쌍씩, 정책 3종으로 **총 15회** 로컬 TCP 실행을 했다. 정책 실행 순서는 표본별로 섞었다.

| 정책 | 평균 구간 완료 | RR 대비 감소율 평균 | 표본별 감소율 범위 |
|---|---:|---:|---:|
| RR | 1.7532초 | — | — |
| FIFO | 1.7533초 | −0.005% | −0.013~0.003% |
| 조건부 개입 | 1.5795초 | **9.9086%** | 9.7812~10.0260% |

모든 실행에서 **33,600,000바이트**를 보냈고 클라이언트별 수신 SHA-256가 모두 일치했다. 이는 같은 입력 바이트와 주입 시간에서 전송 순서의 영향을 확인한 것이다.

이번 TCP 페이로드는 재현용 바이트 패턴이다. 계산은 원시 시간에 기반한 sleep으로 주입했다. **실제 Qwen/SFL 역전파, 모델 정확도, 실물 젯슨의 동작을 측정한 실행이 아니다.** 앞선 PyTorch 수치 정합 실험과는 별도이며 그 결과를 이번 실행의 학습 정확도 증거로 붙이지 않는다.

## 7. 이번 결과로 연구 기여를 어떻게 수정할까

1. 이전 합성 큐 실험의 약 29%보다, 이번 실측값 주입의 대표 결과는 약 10%다. 보고서의 대표 수치를 이번 조건으로 교체할 수 있으나 반드시 “실측값 주입 재현”을 붙인다.
2. 결과는 계산 분해 비율에 따라 약 5~14%로 바뀐다. 정확한 SFL 기기 계산 분해를 측정하지 않은 현재 상태에서 9.97% 한 점을 보편적인 효과로 확정할 수 없다.
3. 강한 네트워크 병목에서는 약 1.6%다. 전송 순서만으로 심한 병목을 해결한다는 주장은 약하다. 피할 수 있는 혼잡은 기존 경로 변경이 담당하고, 순서 제어는 통신과 계산을 겹칠 여지가 있을 때 보완하는 방향이 적절하다.
4. 새 현장 실험 없이도 결과를 재현하고 설계를 비교할 수 있도록 입력 원장·원자료 해시·구간 분리·모든 민감도 결과를 보존했다. 현 단계의 검증 방식은 **실측 기반 모형 검토와 로컬 주입 실행**이다.

보고서에 사용할 문장:

> 기존 KOREN echo 전송 기록과 Jetson Orin Nano Super의 전력 모드별 학습 시간 기록을 사용해 8개 논리 기기의 시간 모형을 구성하였다. 학습 시간의 절반을 반환 이후 계산으로 배치한 가정에서 조건부 기울기 반환 순서는 순환 전송 대비 모형상 9.97%, 동일 입력의 로컬 TCP 시간 주입 실행에서 9.91%의 구간 완료 시간 감소를 보였다. 이는 신규 KOREN 현장 학습 결과가 아니며, SFL 계산 분해 비율과 단일 공유 출구의 서비스 모형에 의존한다.
