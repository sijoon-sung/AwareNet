## 1. 실행 순서 — 게이트 통과 순, 앞이 죽으면 뒤는 안 한다

### G-L1 지식주입 파일럿 — 로컬 4060, GPU 신청 불필요 ✅ **PASS (2026-08-26 밤)**

**판정: 베이스 0% → 66.7% (Δ +66.7%p, 게이트 +40%p) — 6차 만에 통과.** 여정 자체가 자산:

| 차수 | 변경 | Δ | 배운 것 |
|---|---|---|---|
| 1 | 초기판 (변형3, lr 1e-3, q/v만) | 즉사→재실행 +25.0 | transformers bf16 자동로드 vs LoRA fp32 충돌 (수정) |
| 2 | 코퍼스 v2 (변형5·정답 고정) | +5.6 | 고LR 과학습 → 모드 붕괴 |
| 3 | **lr 3e-4 + LoRA 를 MLP 까지** | +38.9 | 사실 저장의 주 무대는 MLP |
| 4 | 스텝 300→450 | +22.2 | 스텝으로 못 고침 — 스윗스폿 문제 아님 신호 |
| 5 | 1.5B 승격 | +16.7 | 용량도 아님 → **구조 결함 확신** |
| 6 | ★ **라벨 경계 버그 수정** (BPE 가 '답: ' 공백을 합쳐 경계 어긋남 — 답 첫 토큰 마스킹/질문→사실 결합 붕괴) | **+66.7 PASS** | 파이프라인 결함은 레시피 튜닝으로 안 가려진다 |

**확정 레시피 (G-L2 표준)**: 0.5B · rank 16 · targets = attn+MLP 전체 · lr 3e-4 ·
300 스텝 · 프롬프트/답 분리 토크나이즈. 남은 오답 6/18은 유사 수치 사실 간 혼선(p95 vs
버스트 등) — 코퍼스 변형 추가로 개선 여지, G-L2 진행에는 충분.
```bash
~/sflenv/bin/pip install "transformers>=4.45"        # sflenv 에 아직 없음 (확인됨)
python sfl/experiments/run_l1.py --domain B --steps 400          # WSL, 4060에서 VRAM ~4GB
```
- **판정 (사전 등록)**: heldout 정답률 베이스 대비 **+40%p 이상** → PASS
- FAIL 시: ① 코퍼스 재가공(변형 수↑·답 축약) ② steps 800 ③ 모델 1.5B 승격 — 순서대로
- 베이스 대조는 공짜: LoRA B=0 초기화라 학습 전 출력이 베이스와 동일
- ⚠ R 배치가 도는 동안 실행 금지 — GPU·CPU 를 나눠 쓰면 측정이 오염된다 (오늘의 교훈)

### G-L2 삼면비교 — 로컬 4060 ✅ **사전판 PASS (2026-08-27, B 유사분할 B1/B2/B3)**

**A·C 도착 전 B 코퍼스를 사실 단위 6/5/5 로 갈라 유사 3기관 사전 실행.** 결과:

| 라운드 예산 | 판정 | 그리드 (B1/B2/B3 열) |
|---|---|---|
| 8×30 | FAIL | 연합 25/33/57 — **희석**: 겹치지 않는 지식의 어댑터를 매 라운드 평균 → 각자 학습분 1/3 감쇠 (유효 lr/3) |
| **16×30** | **PASS** | 베이스 0% < 단독 36% < **연합 67%** — 연합만 3도메인 전부 상승 (62.5/66.7/71.4) |

**교훈(사전 등록 갱신)**: 불교차 지식의 연합은 단독과 같은 총 스텝으로는 부족 —
**라운드 예산 2배(16×30)를 G-L2 표준으로**. A·C 본실행·이질 rank 판도 이 예산에서 시작.

**재학습 확정판 (8/31, attn+MLP 타깃 — 확정 레시피 정합)**: 16×30 재실행
PASS — 베이스 0% < 단독 36% < 연합 67% (50/66.7/85.7). l2_fed.pt 가 전체 타깃
키로 갱신되어 채팅 시연의 연합 열이 이 판을 사용한다.

**이질 랭크 사전판 (8/31, ranks 16,16,4) — FAIL, 기록**: 연합이 B1(랭크16)만
87.5%이고 B2(16)·B3(4)는 0% — 작은 랭크 기관의 지식 생존(LM-4)이 이 레시피로는
확인되지 않았고, 같은 랭크 16인 B2 지식도 사라졌다. 원인 후보: 랭크 사다리
집계에서 앞쪽 성분(모든 기관 공유)의 충돌, 라운드 부족, 랭크별 학습률 미조정.
후속: ① 라운드 2배 ② 랭크별 lr 스케일 ③ 집계 방식 대조(기여자 나눔 vs 제로패딩)
— 순서대로 시도 후 재판정. 그 전까지 "이질 랭크 기여 보존" 주장은 하지 않는다.

**카나리아 유출 계측 (같은 날, 16×30 재실행 — 그리드 PASS 재현 67%)**: 가짜 비밀
문자열을 B1 학습셋에만 주입 → 추출률 **베이스 0% / B1 단독 100% / 연합 100%**
(out/l2_canary.json). **FedAvg 평균은 한 기관의 비밀을 지워주지 않는다** — 작은
코퍼스×반복 노출에서는 연합 집계를 거쳐도 축자 암기가 온전히 살아남는다는 실증.
→ 결론: 유출 방지는 집계에 기댈 수 없고 **입력 통제(두 층 분리 — 14번 §8)가 필수**.
카나리아 감사(--canary-domain)를 배포 전 게이트로 상설화.
```bash
python sfl/experiments/run_l2.py --rounds 16 --local-steps 30                 # 동질 rank 16 (16라운드 표준)
python sfl/experiments/run_l2.py --ranks 16,16,4 --rounds 16 --local-steps 30 # 이질: C가 최약체
```
- **판정**: 평균 정답률 `베이스 < A단독 < 연합` + 그리드에서 연합만 3도메인 전부 상승
- 이질 rank 판이 데모의 급소: **rank 4 로 참여한 C 의 지식이 연합 모델에 살아 있는가**
  (= 배제 없는 학습의 화면화). C 열 정답률이 그 증거
- 산출: `out/l2_grid.json` — 발표 그리드의 원천 데이터

### G-L1.5 상한선 — V100 (승인 후), ~1시간
- 세 코퍼스를 **한 데 모아** 단일 학습 (우리가 만든 데이터라 반출 위반 아님 — 상한선 측정)
- run_l1 재사용: 통합 JSONL 만들어 `--domain 경로` 로 지정
- 삼면비교에 4행째 "중앙(상한선)" 추가 — 연합이 상한선의 몇 %를 회복하는지 정직 공개

### G-L3 분할(SFL) 실측 — 배선 작업 후, 실망(K1) 위
- fed_server/fed_client `--arch llm` 배선 (models_llm 의 LLMClient/LLMServer 연결)
- ★ models_llm 이 명시한 함정: **rank 를 줄여도 절단면 활성값 바이트는 안 준다**
  → LLM 모드에서 컨트롤러 비용모델은 bytes 상수 — 컨트롤러가 rank 로 미는 건
  연산·가중치 동기뿐임을 발표에서도 정직하게 말한다
- R6(rank 사다리 시간·품질 대가 곡선)은 여기서 함께 측정

## 2. 채점 규약 (사전 등록)

- 프롬프트 `"질문: {q}\n답:"`, 그리디 32토큰, **키워드 포함 = 정답** (LLM 심판 없음 — 재현 가능)
- heldout 은 q 해시 80/20 결정적 분할 — 재실행해도 동일
- 발표 라이브: 심사위원이 heldout 목록에서 질문을 **직접 고른다** (체리피킹 방어)

## 5. 대규모 LoRA 실측 체크리스트 — KOREN 망 위에서 확인할 것들 (사전 등록)

> G-L2 이후, K1(2사이트)·POP 다지점이 열리면 아래를 순서대로. 각 항목 = 질문 하나.

| # | 확인할 것 | 방법 | 판정/산출 |
|---|---|---|---|
| LM-1 | **어댑터 동기 vs 절단면 트래픽 분해** — "rank 는 전송을 안 줄인다" 명제의 실WAN 검증 | on-wire 바이트를 두 흐름으로 분리 계수 (배치별 활성값 왕복 vs 라운드말 어댑터 동기) | 활성값 ≫ 어댑터(KB급) 실측표 — LLM 모드 비용모델(bytes 상수)의 근거. C6 연계 |
| LM-2 | rank 사다리 대가 곡선 | rank {4,8,16,32} 고정 스윕 × (라운드 시간·클라 연산·heldout 정답률) | "rank 가 곧 폭"의 실측 곡선 (R6) |
| LM-3 | **rank 스위칭 실측** — 어댑터 그림 타임라인의 실증 | 런 중 회선 악화(HTB)/전력모드(Jetson) → rank 축소 → 회복 시 복원 | 반응 ≤2라운드 · 복원 확인 (조건3의 LLM 판) |
| LM-4 | **이질 rank 집계 품질 = 기여 보존** | rank 16,16,4 연합 후 최소 rank 기관의 고유 지식 정답률(C열) + 카나리아 | C열 생존율 — "배제 없는 학습"의 정량 지표 |
| LM-5 | 실WAN 라운드 해부 | K1 판교–대전에서 배치 왕복·어댑터 동기 시간 분해, 라운드 경계 incast 와 어댑터 동기가 겹칠 때의 지연 | 로컬 리그와의 방향 일치 (수치 일치 요구 안 함) |
| LM-6 | 다지점 rank 분포 | POP 별 기관 배치 → 지역 이질성 하에서 rank 배정이 어떻게 갈리나 | 지역×rank 분포표 (다지점 실증의 그림) |
| LM-7 | 결정 루프 스케일 | run_scale100 의 rank 판 — 기관 100 프로파일 재생 | 결정 지연 ≤ 라운드의 1% |
| LM-8 | 실사용 신호 유입 — **무수집 원칙 준수** | 체험 세션의 익명 집계(승률·카테고리)로 공백 파악 + **옵트인 기부 질문만** 검수 후 heldout 후보로 (원문 기반 원칙·사람 검수 게이트 통과분만 — 데이터 오염 방지) | 카테고리별 공백표 + 승률 표 (기획_학과_LLM_체험세션.md v2) |
| LM-9 | **rank 부채널 실측 + 패딩 방어** — 암호화 트래픽의 크기·타이밍에서 기관별 rank·라운드 참여 여부 추정이 되는가 | KOREN 실WAN pcap → 어댑터 동기 크기로 rank 분류 시도 → 최대 rank 패딩 적용 후 재시도 | 패딩 전 추정 정확도 vs 후 (무작위 수준으로 하락하면 방어 성립) — 14번 §7.3 |
| LM-10 | mTLS 상호 인증 오버헤드 | fed_server ssl wrap + 기관 인증서 → 라운드 시간 증가분 계측 | 오버헤드 ≤ 라운드의 1% 이면 상시 적용 확정 — 14번 §7.1 |
