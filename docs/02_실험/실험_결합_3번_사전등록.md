# 실험 3번 — 결합: 같은 라운드 목표 D 에서 망을 고치면 폭을 덜 깎는다 (사전등록, 2026-09-08 v2)

v1(폭 기준선 B′, 시간 이득 비교)은 폐기. 사용자 지적: 손잡이 셋을 다 켜면 시간이 주는 건 당연하다. 보여줄 것은 **"엣지·망을 개선하면 폭을 덜 줄여도 되고, 그래서
단순 분할학습보다 정확도가 높다"** 이다. 라운드 목표 D 는 응용이 주는 값으로 고정하고(FedCS 식 마감), 팔마다 D 를 맞추기 위해 폭을 얼마나 깎았는지와 정확도를 비교한다.
스케줄러는 정확도 대가가 없는 망 손잡이(엣지 변경·분할·즉시 내보내기)를 먼저 쓰고, 그래도 D 를 못 맞추는 기기(연산 낙오자)만 폭을 깎는다 — 망 병목이 없는 연산 낙오자는 자연히 폭만 줄어든다.

(엣지만은 2번 스윕에서 봤으므로 뺀다.) 실행 `run_combo.sh`(정확도 실험 끝나면 자동), 표 `SKIP=10 python scripts/analysis/combo_table.py r8mix_rho1 …`.
소요: (3 + 2 + 2) 시드 × (균등 1 + 팔 5) = 42 실행 × ~5분 ≈ 3.5h.

## 2. 계획기 (지능형 스케줄러의 판단 순서, `plan.py --deadline fixed --deadline-s 10`)
1. (P) 지금 폭으로 총비용 최소 열린 경로 집합 — 엣지 변경·분할 (정확도 대가 0). 라운드당 1대 이동.
2. 목표 배정: 이동 상한 없이 푼 배정(망 교정이 끝난 상태). 폭 판단은 이 배정 기준 — 아직 못 옮긴 기기의 폭을 잠깐 깎았다 되돌리는 왕복을 막는다.
3. (W) 기기마다 목표 배정에서 t_k(w) ≤ D 인 가장 큰 폭. 망이 풀린 기기는 전폭에서 D 를 만족하므로 안 깎이고, 연산 낙오자만 깎인다. 바닥 0.5.
4. (P) 재평가. 설명은 `plan.explain` (기기마다 "왜 이 손잡이").
→ 망 병목 없음 + 연산 부족 = 폭만 / 망 병목 + 연산 충분 = 경로·분할만 / 둘 다 = 둘 다. 기준선 A/B/B′ 는 필요 없다(D 가 입력).

## 4. 판정 (사전등록)
1. **폭을 덜 깎는다**: 같은 D 에서 폭합/N 이 결합(bothmp) > 폭+엣지(both3) > 폭만(width3). 예측 0.91 / 0.78 / 0.50. 격차 ≥ 0.1.
2. **D 를 맞춘다**: 결합의 D 충족률 ≥ 95%, 망만(mp)은 낙오자 때문에 < 90%, 폭만은 낙오자 미달로 < 95%.
3. **정확도는 재지 않는다** (사용자 결정 9/8): 폭 → 정확도 대가는 문헌(HeteroFL·FjORD·FedRolex, 리서치_폭축소_정확도대가)으로 말하고, 실험은 폭합/N 만 비교한다. 24R 정확도는 기록만 남긴다(잡음 4~6%p).
4. **손잡이 대응**: 결합에서 폭 < 1 인 기기는 낙오자 2대뿐(시드 3개 모두), 접속 병목 2대는 두 출구 + 전폭, 정상 4대 전폭 + 엣지 분산. 왕복: 폭 변경 ≤ 4회, 이동 ≤ 8회.
5. 즉시 내보내기 팔은 시간 여유(D 대비)로 읽고 정확도는 bothmp 와 나란히(BN 대가 분리).
예측 vs 실측 간극은 팔별 효율(eff_from_runs)로 정량화.

## 5. 하지 않는 것 / 후속
- A/B/B′ 기준선 비교(D 가 입력이라 불필요; B′ 코드는 남김). 1층(실제 기기 2회선). 100대는 3층 시뮬.
- 후속: 낙오자 고정에 의한 데이터 편향 → 창 굴리기(FedRolex); 즉시 내보내기 BN → m=2/GN; sBN(AWARENET_BN=none) 비교.
