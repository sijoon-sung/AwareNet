# 실험 — 고정 2연결 비교군 (2026-10-07)

## 1. 왜 하는가

32개 클라이언트 실험(그림 5)의 두 방식은 연결 수가 다르다.

- 기준 방식: 클라이언트마다 출구 A 하나(접속 상한 5 Mbps)로 보낸다.
- AwareNet: 출구 A(5 Mbps)와 출구 B(2 Mbps)를 서로 다른 중계로 보내고, 폭·경로를 매 라운드 정한다.

그래서 기준 대비 단축률(정상 24.6%, 트래픽 몰림 42.6% 등)에는 두 효과가 합쳐져 있다.

    기준 → AwareNet 단축 = (연결을 2개로 늘린 효과) + (스케줄러가 폭·경로를 정한 효과)

가운데에 "연결은 2개를 쓰지만 판단은 하지 않는" 비교군을 두면 두 효과를 따로 잴 수 있다.

| 비교 | 보이는 효과 |
|---|---|
| 기준(1연결) → 고정 2연결 | 연결 수를 늘린 효과 |
| 고정 2연결 → AwareNet | 폭·경로 판단의 효과 |

## 2. 고정 2연결(fixed2)의 정의

| 항목 | 기준(uniform) | 고정 2연결(fixed2) | AwareNet(widthpath) |
|---|---|---|---|
| 모델 폭 | 전원 1.0 고정 | 전원 1.0 고정 | 매 라운드 결정 |
| 출구 A 중계 | 엣지 1~4에 고르게(rr), 고정 | 기준과 같음, 고정 | 매 라운드 결정 |
| 출구 B | 쓰지 않음 | **다른 VM의 엣지**(1→3, 2→4, 3→1, 4→2), 고정 | 매 라운드 결정 |
| 조각 분할 | — | 접속 상한 비율 **5:2** 고정 | 예상 속도 비율 |
| 사전 진단·이동 | 없음 | 없음 | 있음 |

엣지마다 출구 A 8대와 출구 B 8대가 실려 부하가 고르다. 분할 비율을 5:2로 둔 이유는 다음과 같다. 반반(1:1)으로 나누면 느린 출구 B(2 Mbps)가 병목이 되어 비교군이 지나치게 약해진다. 9/9 기록에 따르면 가중치 없이 나눈 경우 출구 B에 39%가 실려 2배 느렸다. 비율은 `FIXED_WEIGHTS=1,1`로 바꿀 수 있다.

코드: `sfl/policies.py`의 `FixedTwo`, 서버 옵션 `--policy fixed2 --multipath --fixed-weights 5,2`.

## 3. 실행 — 두 가지 버전

### 3-1. KOREN 버전 (`run_fixed2_koren.sh`): HPC(V100) 서버와 KOREN VM 중계

기존 32개 클라이언트 실험과 같은 구성이다. 고정 2연결만 추가로 돌리고, 기존 기준·AwareNet 결과(`scen32`)와 비교한다.

```bash
# 로컬 PC(저장소 루트, 런처 켠 상태)에서 한 번에: 코드 동기화 + 실행 시작
bash scripts/exp/hpc_launch.sh fixed2
bash scripts/exp/hpc_launch.sh fixed2-status          # 진행 상황
SCEN=traffic SEEDS=1 bash scripts/exp/hpc_launch.sh fixed2   # 시간이 없으면 트래픽 몰림 1시드 (약 30분)
```

### 3-2. GPU 단독 버전 (`run_fixed2_gpu.sh`): Linux GPU 장비 한 대

KOREN VM 대신 같은 장비의 로컬 중계(`sfl/net/local_relay.py`)가 같은 회선 상한을 건다. 접속 5/2 Mbps, 엣지 56 Mbps ×4, 트래픽 몰림 시 14 Mbps, 용량 변동 계단이다. sudo와 tc는 필요 없다. 기준·고정 2연결·AwareNet 세 방식을 **모두 같은 장비에서** 다시 돌린다.

```bash
git clone -b exp/fixed2-baseline https://github.com/sijoon-sung/AwareNet && cd AwareNet
bash run_fixed2_gpu.sh                 # 점검 → 스모크 → 세 방식 → 집계 (기본: 트래픽 몰림 1시드, 약 1.5~2시간)
bash run_fixed2_gpu.sh status          # 진행 상황
SCEN="traffic normal slow vary" SEEDS="1 2 3" bash run_fixed2_gpu.sh   # 전체
```

**보고 방법:** 이 결과는 "같은 코드·같은 회선 조건을 로컬 GPU 테스트베드에서 재현한 보조 비교"로 적는다. KOREN 실측(`scen32`)과 숫자를 섞지 않는다. 결과 파일 이름도 `scen32gpu`로 따로 둔다.

## 4. 집계

```bash
python scripts/analysis/fixed2_compare.py                     # KOREN → out/fixed2_compare_scen32.csv
python scripts/analysis/fixed2_compare.py --prefix scen32gpu  # GPU 단독 → out/fixed2_compare_scen32gpu.csv
```

보고서 그림 5와 같은 기준이다. 시드마다 초기 4라운드를 뺀 makespan 평균을 구한 뒤 시드끼리 평균한다. 출력은 장면별로 세 방식의 평균 라운드 시간·평균 폭과 아래 분해다.

    기준 대비 전체 단축 = 연결 수 효과(%p) + 판단 효과(%p)

## 5. 검증

- `python tests/test_fixed2.py`: 배정 규칙을 확인한다. 출구 A는 rr과 같고, 출구 B는 다른 VM이며, 엣지당 8+8대, 이후 무개입이다.
- `python -m unittest tests.test_local_relay`: 로컬 중계의 접속 상한, 공유 엣지 상한, 실행 중 용량 변경, fixed2 학습 2라운드 관통을 확인한다.
- `python -m unittest tests.test_fixed2_e2e`: 합성 데이터로 클라이언트 2대가 2라운드를 돈다. 루프백 엣지 2개로 출구 A·B 종점이 실제로 쓰이고 분할 전송이 되는지 확인한다.
