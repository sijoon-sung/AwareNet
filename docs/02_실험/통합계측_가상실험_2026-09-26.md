# Wireshark·Grafana 통합 계측 가상 실험

## 결과와 판정

격리된 QEMU Linux 게스트에서 실제 네임스페이스·라우트·tc·TCP를 구성했다. 한 번의 실행에서 18라운드, 본 전송 144개, 실제 패킷 35,058개를 얻었다. 모든 본 전송이 서버 재조립 후 SHA-256 검증을 통과했다.

| 조건 | 단일 경로 | 고정 두 경로 | 적응 두 경로 |
|---|---:|---:|---:|
| E1 용량 감소, R2-R4 | 24.112초 | 11.508초 | 7.070초 |
| 공통 IFB 병목, R1-R2 | 7.550초 | 8.552초 | 8.419초 |

수치는 프로브 포함 평균 완료 시간이다. 용량 감소에서 적응 분할은 고정 분할 대비 38.6% 단축했다. 공유 병목에서 적응 두 경로는 단일 경로보다 11.5% 느렸다. 다중 경로 자체의 우월성보다 **공유 병목과 경로별 완료 지연을 구분해야 한다는 적용 조건**을 보여준다.

모델 폭과 바이트를 고정했다. 이 검증용 비례 분할 정책은 기존 `network`/`widthpath` 전체 계획기와 다르다. 학습 정확도, 새 KOREN 성능, 기관 간 SDN 권한 위임을 검증하지 않았다. 논리 클라이언트 8개는 한 VM 내부의 스레드이며 독립 장비 8대가 아니다.

## 계측 보정 기록

iproute2 7은 카운터를 `stats.bytes`에 넣지만 최초 파서는 top-level `bytes`를 읽어 실시간 게이지가 0이었다. 저장한 실제 tc 스냅샷을 읽어 별도 `rounds.normalized.json`을 만들었다. 원시 시간·전송 결과를 수정하지 않았다. Grafana에 올린 보정 이벤트는 `counter_normalized`로 식별하며 원래 시각의 계측인 것처럼 소급하지 않았다.

Grafana 플러그인 자동 업데이트 중 실패가 발생해 원래 배포본의 Prometheus 플러그인을 복구하고 자동 업데이트를 비활성화했다. 실제 Prometheus 기록 조회를 API와 브라우저 화면으로 확인했다. 이 과정에서 전송 실험은 다시 실행하지 않았다.

TCP ACK RTT, netem의 설정 지연, 텐서 전체의 완료 지연은 다른 수치다. TShark 재전송 분석 플래그도 실제 회선의 손실률로 해석하지 않는다. 고정 실행 순서와 TCG CPU·패킷 캡처의 영향을 포함하므로 유의성이나 현장 일반화를 주장하지 않는다.
