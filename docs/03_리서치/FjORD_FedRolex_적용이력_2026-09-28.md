# FjORD에서 FedRolex식 채널 선택으로: 적용 이력 확인

2026-09-28 코드·원기록 검토. 새 학습 실험은 실행하지 않았다.

## 확인 결과

**FjORD 계열의 고정된 앞쪽 채널 선택에서 FedRolex식 롤링 선택으로 확장한 코드와 검증 기록이 있다.** 기본값만 보고 이를 아직 검토 단계라고 설명하면 개발 이력을 놓친다. 반대로 현재 보고서의 모든 수치를 FedRolex 적용 결과라고 묶으면 서로 다른 실행을 섞게 된다.

| 확인 대상 | 저장소에서 확인한 내용 | 해석 |
|---|---|---|
| 초기 선택 | [9/8 정확도 검토](리서치_폭축소_정확도대가_2026-09-08.md)는 앞쪽 채널 고정과 작은 모델을 쓰는 클라이언트의 데이터 편향을 기록했다. | 모델 축소의 정확도 비용이 변경 동기다. |
| 롤링 구현 | [models.py](../../sfl/models.py)의 `_axis_index`는 라운드마다 채널 창을 이동하고 `slice_into`·`nested_average`가 해당 인덱스를 사용한다. | FedRolex의 롤링 추출을 반영한 코드다. |
| 롤링 검증 | [verify2.log](../../out/verify2.log)는 롤링, BN 끔, 300라운드, 폭 하한 0.25·0.5, 세 시드를 명시하고 여섯 실행의 완료를 기록했다. 각 JSONL에는 round 0–299와 요약 한 행이 있다. | 별도의 롤링 학습 실행 기록이 존재한다. |
| 현재 기본값 | `AWARENET_ROLL` 기본값은 `0`이며 `1`로 설정할 때 롤링한다. | 코드 존재와 모든 실행에서의 활성화는 구별한다. |
| 보고서 주 비교 | 32클라이언트 24라운드와 8클라이언트 200라운드 기록이다. 실행 인자·JSONL에 롤링 환경 변수나 채널 인덱스를 보존하지 않았다. 실행 스크립트에도 롤링을 켜는 지정이 없다. | 기본값 및 기존 문서는 고정 선택을 가리킨다. 과거 셸 환경을 완전히 복원할 수 없어 FedRolex 적용 결과로 단정하지 않는다. |

여섯 롤링 실행은 `policy=oracle`이고, 계획에는 네 클라이언트의 폭 비율 `[1.0, 1.0, 0.25, 0.25]` 또는 `[1.0, 1.0, 0.5, 0.5]`가 기록되어 있다. 본문의 동적 폭·경로 스케줄러 실험과 목적·조건이 다르다. 실행 제목과 모델 코드가 롤링 적용을 뒷받침하지만, 로그에 채널 인덱스와 코드 커밋까지 남아 있지는 않다. 이 자료는 전환 과정의 근거로 사용한다.

## 폭, 깊이, 채널 선택의 구분

| 용어 | 바뀌는 것 | 예 |
|---|---|---|
| 모델 깊이(depth) | 계층 수 | 모델에서 계층을 제거하거나 추가 |
| 분할 위치(split point) | 클라이언트와 서버의 계산 경계 | 전체 모델을 유지하고 어디까지 클라이언트가 계산할지 변경 |
| CNN 모델 폭(width) | 계층별 채널 수 | 128채널 중 64개 사용 |
| 채널 선택(channel selection) | 학습에 참여하는 채널의 위치 | 앞쪽 64개 고정 또는 라운드마다 64개 창 이동 |
| 파이프라인 깊이 | 동시에 처리하는 작업의 수 | 서로 다른 마이크로배치의 계산·전송을 겹침 |

FjORD에서 FedRolex로 바꾸는 차이는 **폭을 채널로 바꾸는 것**이 아니라 **부분 모델의 채널을 선택하는 방법을 바꾸는 것**이다. FjORD와 FedRolex 모두 작은 부분 모델을 학습한다. FedRolex는 선택 부분을 순환시켜 전역 모델의 여러 부분에 학습 기회를 분산한다. 이 구조만으로 정확도 손실이 항상 없어지는 것은 아니므로 동일 조건 비교가 필요하다.

‘기존 깊이의 정확도 문제’와 관련해서 저장소에서 직접 확인한 자료는 [J시리즈의 파이프라인 깊이 2 실험](../02_실험/실험_J시리즈_통합증명.md)이다. 해당 문서는 마이크로배치 적용 조건에서 정확도가 낮아져 파이프라인을 기본 해제한 과정을 기록한다. 이는 모델의 계층 수를 줄이는 것과 다르다. [SuperSFL 가변 분할 깊이](../04_설계기록/SuperSFL_AwareNet_결합알고리즘.md)는 별도의 후속 설계로 보존되어 있다. 따라서 확인한 기록만으로 ‘FjORD가 계층을 줄여 정확도가 하락했다’는 이력을 만들지 않는다.

## 보고서에 사용할 설명

> 클라이언트의 계산 부담을 줄이기 위해 부분 모델 학습을 도입했지만, 모델 축소에 따른 정확도 손실도 함께 다뤄야 했다. 초기의 고정된 채널 선택을 보완하기 위해 FedRolex식 롤링 선택을 추가·검증했다. 롤링은 학습할 채널을 순환시키고, AwareNet은 계산·통신 상태에 따라 사용할 채널 수와 전송 경로를 결정한다. 두 제어를 연결하여 불필요한 모델 축소를 줄이는 것이 설계 방향이다.

## 후속 통합에서 확인할 항목

라운드가 바뀔 때 클라이언트·서버의 채널 대응, 집계 위치, 정규화와 옵티마이저 상태를 함께 확인한다. 현재 `Aggregator.set_round`는 창 위치를 바꾸며, 캐시된 서버 부분 모델을 다시 추출하는 시점은 집계 함수에 있다. 다음 롤링 실행 전에는 이 두 시점의 일치를 검증해야 한다. 실행 로그에는 롤링 여부·보폭·채널 인덱스·정규화 설정·코드 커밋을 남긴다.

`baseline_fedrolex.py`의 오래된 머리말에는 아직 prefix 전용 슬라이싱이라고 적혀 있지만, 현재 `models.py`는 인덱스 기반 추출·집계를 포함한다. 이 주석을 현재 전체 구현 상태의 근거로 사용하지 않는다. 원 논문의 전체 학습 절차를 재현했다는 주장과 롤링 추출을 가져온 구현도 구별한다.
