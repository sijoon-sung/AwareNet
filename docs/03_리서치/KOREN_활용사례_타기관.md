## 2. 우리 도구가 도움이 되는 구체적 예 세 가지

**① 숭실대 FL/Split Computing 오케스트레이터(2023→2024)에 "망 인지 엣지 선택" 규칙.** 두 과제 모두 KOREN VM 코어+엣지 구조에서 엣지 선택·분할 배포를 고정 전략이나 사용자 UI 로 처리했고, 링크 측정을 선택에 반영했다는 기술이 없다. 우리 컨트롤러(기기별 학습량·엣지 선택)와 링크 프로브를 그대로 입력으로 붙일 수 있다 — 같은 OpenStack VM 환경.

**② FourLeaves(시즌12) 의료 연합학습 — 라운드 시간·기기별 학습량을 회선 실측으로 조정.** 병원 클라이언트가 수십 MB 파라미터를 KOREN VM 으로 보내는 구조인데 성과가 정확도뿐이고 회선 영향은 없다. 우리 "짧은 전송 실효 처리량"(55 vs 24 Mbps 현상) 측정이 정확히 이 크기에 맞고, Grafana 로 병원 노드별 회선 상태를 심사 자료에 넣을 수 있다.

**③ NIA KOREN AI CLOUD(H200 서울·대전, 400G) 이용자의 다중 사이트 학습 배치.** 2026년 3월부터 GPU 를 할당하고 서울-대전 연계 시험 옵션을 명시했지만, 사용자 VM 관점의 실효 처리량·RTT 정보는 공식 페이지에 없다. 우리 링크 프로브를 두 서버 사이에 상시 두면 "어느 쪽에 얼마만큼 배치할지"의 결정 데이터를 이용자 전체에 줄 수 있다. 2026-06 수원-대전 회선 품질 개선 작업 공지(notices/5052)처럼 작업 전후 품질 변화를 이용자 측에서 정량화한 사례가 된다.

## 3. KOREN 이 제공하는 것 / 없는 것 (공식 페이지)

제공: 10개 도시 백본(사용자 회선 최대 400G) · HPC 연계(CPU 200코어, GPU) · OpenStack VM/SDI · K-PaaS · Object Storage · Edge VM · 기술지원(IP/방화벽 개방, 시험환경, 장비 대여) · 월간 "이용기관 트래픽 현황"·"NOC Report"(hwp, 사후·월단위) · 2021 IP 백본 AI 관제(NOC 내부용) · 2026 AI CLOUD.
**없는 것**: 이용자가 직접 보는 실시간 회선 품질 대시보드나 perfSONAR 류 측정 노드(KREONET 은 perfSONAR 공개, KOREN 은 없음) · VM 간/PoP 간 실효 처리량 정보 · 사용자 셀프 망 진단 도구. "이용기관 연구활동"·"실증시험 과제" 페이지는 신규 사이트에서 비어 있음.

→ **우리 도구의 자리**: "이용자 관점의 실시간 회선 품질과 그 위에서의 배치 규칙" — KOREN 공식 서비스가 비워 둔 칸이다.

### K-MELLODDY 는 공개 자료상 KOREN 을 쓰지 않는다
- 사업단 사이트(kmelloddy.org), 2024 사업개요서(PDF 전문), 2026 RFP(39쪽 PDF 전문), 착수 보도(2024-08-13), AWS 발표 보도(2025-08-05) 어디에도 "KOREN/코렌/연구망" 없음. 교차 검색도 0건.

- **미확인**: 기관 온프레미스 ↔ AWS 를 어떤 회선(상용 VPN/Direct Connect/전용선)으로 잇는지는 비공개. 참여 대학·병원이 개별적으로 KOREN 이용기관일 수는 있으나, K-MELLODDY 트래픽이 KOREN 을 지난다는 근거는 없음.

### 우리에게 주는 뜻
1. **KOREN 위 연합학습의 공개된 실험 기록은 넷챌린지 팀들뿐**이다. 우리가 "KOREN 에서 연합학습 트래픽을 실측한 첫 기록" 자리에 있다 — 그렇게 쓰되 "공개 자료 기준"이라 단다.
2. **박래웅 제안(30개 병원 + KOREN + FL)** 이 사업화되면 우리 규칙·프로브가 정확히 필요한 자리다 — 병원 간 KOREN 구간의 라운드 지연·gradient 실효 처리량. 제안서 인용 가능.
3. **2026 AI NETWORK 실증**은 장비 벤더가 측정하므로, 우리는 "이용자 VM 관점의 종단 간 측정"으로 교차 검증 역할.
4. NIA 자체 보고서(2022)가 "연합학습 클라이언트 선택·스케줄링"을 네트워크 운용 이슈로 꼽았다 — 우리 과제가 그 질문에 실측으로 답하는 위치라고 서술할 수 있다.

### 6-4. 우리 자리 (3차 조사 후 정리)
1. KOREN 위 공식 과제는 **망 자체를 다루는 과제**(초정밀·DetNet·AI 관제·양자·5G 백본)가 대부분이고, **응용(연합학습·분산학습) 트래픽을 KOREN 위에서 실측한 공개 기록은 넷챌린지 팀들뿐**이다. 우리 과제의 자리는 "망 과제와 응용 사이" — 망이 제공하는 품질을 응용(연합학습)이 어떻게 읽고 결정에 쓰는가.
2. AI 관제(#88)·자율형 망관리(#89)·KOREN 6.0 자율네트워크 Lv.5 는 **백본 관점(패시브)** 이다. 우리 링크 프로브는 **이용자 관점 종단간(액티브)** 이라 겹치지 않고 보완한다 — 그들의 학습·검증 데이터가 될 수 있다.
3. 2026 AI NETWORK 실증(DetNet 확정지연)에 대해 "이용자 VM 에서 잰 지연 분포"를 제3자 검증으로 제공할 수 있다.
4. 병원 5곳이 KOREN 이용기관이고 2018~19 에 병원 컨소시엄이 KOREN 으로 의료정보를 유통한 선례가 있다 → 박래웅 제안(병원 30곳 연합학습)의 통신 인프라로 KOREN 을 쓰는 것은 현실적이며, 그때 필요한 것이 우리 규칙(어느 집계 지점으로, 얼마나 보낼지)이다.
