# 리서치 — SL 파이프라이닝과 staleness 처리 (15번 문서)

> 발단: RTT·incast 를 "해결"이 아니라 **겹쳐서 숨기는** 손잡이를 컨트롤러에 넣기로
> 했다 (plan_round ②③, 커밋 3941556). 구현 전에 문헌으로 정확성 문제(staleness)의
> 처리 방식을 확정한다. 연결: controller_multi.plan_round, 검증_매트릭스 FAST
> '통합계획기 규칙'.

## 0. 결론 먼저

- 우리가 만들려던 "배치 k 업로드 ∥ 배치 k+1 연산"은 **PiPar** (Zhang, Varghese
  et al., **JPDC 2024**, arXiv:2302.12803) 가 SL/SFL 에 일반화한 구조 그대로다 —
  SFL 대비 **1.12–2.3× 가속**, 정확도 차 −0.2~+2.07%p. 무선 특화 후속(C²P²SL
  arXiv:2511.23167, 멀티홉 arXiv:2505.04368)도 같은 계열.
- **이들 전부 staleness 를 GPipe 식 그래디언트 누적으로 "발생 자체를 제거"** 했다.
  SL 에 PipeDream 식 weight stashing 을 쓴 논문은 확인되지 않음.
- 금지 문구: "SL 에 파이프라이닝 최초 도입" (PiPar 선행), "staleness-free 비동기"
  (누적식이면 동기식이라 써야 정확).

## 1. CPU 바이패스와의 대응 (질문에서 출발한 지도)

CPU 포워딩은 "값은 이미 있고 배달만 늦은" 경우다. 우리 hazard 는 값(서버
그래디언트)이 **아직 원격에서 계산 중** — 존재하지 않는 값은 포워딩 불가.
대신 SGD 는 근사가 합법이라 대응물이 생긴다:

| CPU | SL 파이프라인 대응물 | 문헌 |
|---|---|---|
| stall | 직렬 depth 1 (현행) | — |
| 낡은 값 사용 (CPU 에선 불법) | staleness ≤1 허용 | delay-1 은 이론상 점근 무해 (Arjevani ALT 2020; Stich & Karimireddy JMLR 2020) — 단 SL 전용 증명은 없음 |
| 값 예측·투기 | 지연 그래디언트 보상 (DC-ASGD 계열) / PipeMare 보정 | depth 2 에선 보정항이 미미 — 과잉 장치 |
| 레지스터 사본 | weight stashing (PipeDream SOSP 2019; 2BW ICML 2021) | fwd-bwd 일관성 보장, 사본 1벌 비용 |
| 의존성 제거 (그 레지스터를 안 읽게 컴파일) | **로컬 보조 손실** — cut 위 auxiliary head 로 즉시 역전파, 서버 그래디언트 대기 소멸 (DGL ICML 2020; Han et al. FL-ICML'21; arXiv:2601.19261 — 통신 50%↓) | ★ 목적함수가 바뀌는 근사 — 정확도 대가는 실측 문제. **고 RTT 구간(KOREN 원거리)용 +α 카드로 등록** |

**보조 손실의 비용 회계 (등록)**: 연산 **+수 %** (보조 머리 fwd+bwd — 역전파는
중복되지 않음: 서버 그래디언트 대신 로컬 손실에서 출발할 뿐) / 대기 **−RTT×배치 수**
/ 통신 **−하향 그래디언트 전량** / 메모리 **감소** (활성값을 그래디언트 도착까지
붙들 필요 소멸). FjORD KD 를 기각한 원리(약한 기기에 연산 추가 금지)와 같은 잣대로
**일괄 채택 금지** — 컨트롤러가 클라이언트별 예측 시간 비교로 결정한다: 망/RTT
병목이면 남는 장사라 켜지고, 연산 병목이면 저절로 안 켜진다 (양자화·파이프라인
채택과 동일한 "결과를 본다" 규칙).

## 2. 정확성 옵션 3안과 판정

depth-2 를 넣으면 fwd(k+1)이 w_t 로 돌고 batch k 의 갱신이 그 뒤에 온다 —
PipeDream 이 정의한 staleness ≤1 의 특수형.

| 안 | 방식 | 의미론 | 비용 | 판정 |
|---|---|---|---|---|
| (a) GPipe 식 누적 | 미니배치를 마이크로배치 2개로 쪼개 m1 업로드 ∥ m2 연산, **배치 경계 일괄 갱신** | 유효 배치·갱신 빈도 불변 — 수학적으로 비파이프라인과 동일 | flush 거품 (서버 왕복 ≫ 클라 fwd 면 이득 감소), in-flight 활성값 1개 메모리 | **기본 채택** — SL 선행 전원이 이 길 |
| (b) weight stashing | fwd 에 쓴 가중치 사본으로 bwd 도 수행, 1-stale 갱신 | per-batch 갱신 유지, 거품 없음 | 클라 부분망 가중치 1벌 (얕은 cut 이라 소량) | 거품이 이득을 먹으면 **승격** (PipeDream→2BW 의 전철) |
| (c) staleness 1 방치 | 보정 없이 진행 | fwd-bwd 불일치까지 겹침 | 0 | **ablation 전용** — 주장 방어가 약함 |

**레시피 (사전 등록)**: 기본 (a). plan_round 가 T(1) vs T(2) 로 채택을 정하는 것은
그대로 두고, 실행층(fed_client)은 마이크로배치 2분할 + 도착순 backward + 배치
경계 누적 갱신으로 구현한다. 실측에서 거품(서버 왕복 지배)이 확인되면 in-flight 3
또는 (b) 로 전환 — 전환 판단도 계측에서: 거품 비율 > MEAS_UNCERT 일 때만.

## 3. 시차 동기화(stagger)의 선례 — 정당화 근거

- incast 붕괴의 정립: Phanishayee FAST 2008, Vasudevan SIGCOMM 2009.
- **앱 계층 시차의 직접 선례: Podlesny & Williamson, MASCOTS 2012** — 응답 전송을
  스케줄링해 병목 무손실이 되게 시차 배정 (우리 직렬 슬롯과 같은 사상).
- 분산학습 통신 스케줄러: P3 (MLSys 2019, +25~66%), TicTac (+19.2%),
  ByteScheduler (SOSP 2019, 최대 2.96×) — 텐서 슬라이스+우선순위가 표준 입도.
- 우리 주장 문안: "라운드 경계 다대일 업로드를 앱 계층에서 시차 배정 — incast
  회피의 MASCOTS 2012 계열 + 분산학습 스케줄러(P3/ByteScheduler) 계열의 결합을
  SFL 라운드 경계에 적용, 시차는 상수가 아니라 실측(예상 종료·용량 EWMA)에서 유도".

## 4. 채택 시 발표·보고서 문안 (그대로 복사용)

> "본 파이프라이닝은 GPipe(NeurIPS 2019)의 마이크로배치 기법을 SL 의 클라이언트–
> 서버 경계에 이식한 PiPar(JPDC 2024) 계열을 SFL 클라이언트에 적용한 것으로,
> weight staleness 는 그래디언트 누적(배치 경계 일괄 갱신)으로 발생 자체를 제거해
> 갱신 의미론이 비파이프라인 SFL 과 수학적으로 동일하다. 차이는 파이프라인 채택
> 여부·깊이·동기 시차를 고정 설정이 아니라 **컨트롤러가 클라이언트별 실측(연산·
> 전송 EWMA)에서 라운드마다 유도**한다는 점이다."
