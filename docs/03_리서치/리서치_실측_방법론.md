# 리서치 — 비슷한 논문들은 어떻게 실측했나 (16번 문서)

> 발단: "폭+경로 두 손잡이의 실측을 어디까지 하면 논문 수준인가?" — 유사 연구들의
> 평가 방법을 조사해 우리 계획(모의→실기기→실WAN)이 표준 관행과 맞는지 확인한다.
> 연결: 실험_J시리즈 §6(K-W 계획), run_l3_net(LoRA 소켓판), test_wp_mc(난수 점검).

## 1. 조사 결과 — 실측 방법은 4단 사다리로 수렴한다

| 단계 | 방법 | 대표 사례 | 우리 대응물 |
|---|---|---|---|
| ① 순수 시뮬레이션 | 실기기·실망 없음 — 기기 속도를 계층으로 모델링, GPU 클러스터에서 가상 클라이언트 | **FjORD** (NeurIPS 2021): Flower+PyTorch, V100 클러스터, 가상 클라 100대·라운드당 10% 표집, 이질성은 "기기 계층 배정"으로 모델링 — **실제 망 측정 없음** | 난수 시나리오 점검 (test_wp_mc — 300~1000판 불변식 검사) |
| ② 트래픽 제어(tc) 에뮬레이션 | 컨테이너/프로세스에 CPU 제한 + 리눅스 tc/NetEm 으로 회선을 만들어 벽시계 실측 | SplitFed 계열 하이브리드 실험(도커+대역 30Mbps 등), 전용 플랫폼 FederNet·FLEET (2025) — **tc/NetEm 이 이 분야 표준 도구** | 현행 리그 (hetero.sh/paths.sh — HTB, 루프백 위 실학습) |
| ③ 실기기 소규모 | 라즈베리파이·젯슨 몇 대의 물리 테스트베드, 라운드 벽시계 | **FedAdapt** (IoT FL): 라즈베리파이 Wi-Fi + Jetson Xavier NX, VGG-5/CIFAR-10, 대역을 바꿔 가며 적응 확인. **PiPar** (JPDC 2024): 랩 테스트베드, 대역 변화 조건에서 가속 34.6×·유휴 시간 지표 | 젯슨 계획 (§3) |
| ④ 실WAN 다지점 | 클라우드 여러 리전 또는 연구망의 실제 지연·대역 | **FEDn**: AWS EC2 4개 리전(스톡홀름·아일랜드·버지니아·프랑크푸르트)에 집계자 분산 | KOREN 판교+HPC (K-W3 접속 지점 배정) |

읽는 법: **한 논문이 네 단을 다 하지 않는다.** FjORD(우리 폭 조절의 원조)는 ①만
했고, PiPar·FedAdapt 는 ②③, FEDn 은 ④다. 우리 계획(①②는 완료, ③④ 등록)은
사다리 전체를 밟는 쪽이며, 이는 관행 대비 부족이 아니라 초과다.

## 2. 그들이 잰 지표 — 우리가 가져갈 것

- **라운드 벽시계 / 학습 완료까지의 시간(time-to-accuracy)** — 전 단계 공통 주지표.
  우리는 라운드 벽시계는 쓰고 있고, time-to-accuracy(목표 정확도 도달 시각)는
  아직 표로 뽑지 않았다 → **채택: 기존 로그(jsonl)에서 후처리로 뽑을 수 있다.**
- 전송 바이트 (FedAdapt·압축 계열) — 이미 계측 중 (up/dn_bytes).
- 유휴 시간 (PiPar) — 파이프라인 주장에만 필요. 파이프라인이 예비로 내려갔으므로 보류.
- 대역 변화 중 적응 (FedAdapt·PiPar) — 우리 "달리는 중의 악화 추적" 실험과 동형.

## 3. 젯슨 실기기 계획 (③단 — CNN 판, 사전 등록)

목적: "느린 기기"를 tc 로 흉내내지 않고 **실물로** — 젯슨(연구실 보유)은 연산이
실제로 느리므로, 사전 진단이 연산 병목을 측정으로 잡고 폭을 줄이는지 실기기로
확인한다 (FedAdapt 의 젯슨 사용과 같은 관행).

- 구성: PC 클라 2 + **젯슨 클라 1** (arm64 PyTorch/JetPack) + 서버(PC GPU),
  같은 공유기 → fed_client 는 이미 순수 파이썬 소켓이라 이식 부담 없음.
- 절차: ① 젯슨에 저장소 복사·의존성 설치 ② smoke (2라운드 CPU)
  ③ 본 실험: preflight + --policy ours 12라운드, 기준(uniform) 대조.
- 판정: 젯슨만 폭 축소·라운드 시간 단축·배제 0 — 수치가 아니라 **방향 재현**.
- 위험: JetPack 파이토치 버전 차 → 모델을 fp32 로 통일하면 회피 가능.

## 4. 난수 점검(①단)의 결과 기록 (2026-09-01)

목적: 실장비 없이 판단 규칙의 불변식을 수백 판에서 검사 (FjORD 의 "계층 모델링"
과 같은 층위 — 다만 우리는 학습이 아니라 **판단 규칙**을 검사).

- **1000판 최종: 위반 0판** — 진동(왕복 이동)·이동 상한 위반·단일 경로 개입·
  기준 대비 악화 전부 0. 기준 대비 예측 개선 중앙값 +30.0% (최선 +94.1%).
  늦은 이동이 있는 판 16개(1.6%)는 아래 발견 2의 성질.
- 발견 1: 기기 5대부터 완전탐색이 조합 폭발 (경로^n × 폭단계^n) — 대규모 판은
  근사 탐색 필요 (보고서 "100대 결정 루프" 항목과 연결).
- 발견 2: 잡음(±10%)과 채택 문턱(10%)이 같은 크기라, 정착 후 드물게 1회 더
  움직이는 판이 있다. **재확인 규칙**(같은 지시 2라운드 연속일 때만 집행)으로
  절반으로 줄었고, 남은 것은 왕복 없이 개선을 유지하므로 성질로 기록.
- 발견 3: 예측 시간이 거의 같은 배정이 둘 있는 판(1000판 중 1판)에서 잡음이
  문턱을 양방향으로 넘겨 갈라섰다-합쳤다 왕복이 났다 → **왕복 재확인 규칙**
  (떠나온 경로로 되돌아가는 이동은 세 라운드 연속 지시를 요구 — 원래 이동이
  틀렸거나 상황이 변했다는 뜻이라 증거를 더 요구)으로 해소, 재검사 위반 0.
