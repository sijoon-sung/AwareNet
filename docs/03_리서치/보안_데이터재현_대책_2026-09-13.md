# 보안 — "학습 데이터를 그대로 내뱉는" 문제의 대책 조사 (2026-09-13, 조사만 · 적용 안 함)

사용자 요청: "현재 시스템에서 보안 문제 — 데이터를 그대로 내뱉는 문제를 해결하는 방안까지만 찾아줘. 적용 X."
대상 시스템: 분할 + LoRA 연합 학습 (`sfl/experiments/run_fed_split_lora.py`). 기기 = 임베딩 + 앞 2층 + LoRA, 서버 = 나머지 층 + 출력층 + LoRA, 라운드마다 기기 어댑터 평균.
기존 문서와의 관계: `리서치_FL_프라이버시_방어_표준.md` §8(축자 재현 통제의 업계 관행), `보안_위협과_입장.md`(위협 등급 T0~T3·코드 결함 L1~L4)를 이 시스템에 맞춰 좁힌다. 겹치는 설명은 되풀이하지 않는다.

## 1. 결론 먼저

"그대로 내뱉는" 경로는 **셋**이고, 지금 코드에서 가장 큰 구멍은 모델이 아니라 **프로토콜**이다.

| # | 경로 | 누가 보나 | 지금 상태 | 가장 먼저 할 대책 (적용 안 함) |
|---|---|---|---|---|
| ① | **정답 토큰이 평문으로 서버에 간다** | 서버 운영자, 경로상 도청자 | 기기가 `labels`(답 토큰 ID)를 매 스텝 그대로 보낸다 — 공격도 필요 없다 | **U 자형 분할**: 출력층·손실을 기기에 두어 서버는 중간 활성값만 본다 + 전송 구간 TLS |
| ② | **절단면 활성값에서 입력 문장이 복원된다** | 서버, 도청자 | 앞 2층 출력(896차원×길이)을 평문 전송. LLM 은 잔차 연결로 입력이 보존돼 복원이 쉽다 | TLS(도청자), 상호정보 정규화·어댑터 워밍업(서버) |
| ③ | **완성 모델이 학습 문장·비밀을 그대로 답한다** | 모델을 쓰는 누구나 | 이번 실험의 카나리아(가짜 비밀) 추출률로 실측 (§4) | 데이터 층 분리 + 배포 전 카나리아 감사 게이트 + 출력 필터, 필요하면 Goldfish 손실·기기 단위 DP |

①②는 "데이터가 기기를 떠나지 않는다"는 서사를 깨고, ③은 연합이 끝난 뒤 모델 사용자에게 새는 문제다. 대책은 서로 다른 층에 걸리므로 하나로 해결되지 않는다.

## 2. 경로별 근거와 대책

### ① 답 토큰이 서버로 간다 — 프로토콜 누출 [코드 확인]

- 위치: `run_fed_split_lora.py` 기기 루프의 `send_msg(s, ACT, {"shape": …, "labels": lab.tolist()}, …)`. 서버는 이 라벨로 `cross_entropy` 를 계산한다.
- 의미: 다음 토큰 예측에서 라벨은 입력 문장 자체다. 서버는 기기의 **답 문장을 토큰 단위로 그대로** 받는다. 분할이 입력을 가려도 라벨 채널이 전부 연다. 기존 결함 L1(CNN 판, `fed_server.py`)과 같은 구조가 LLM 판에서 더 치명적으로 반복된다.
- 대책 후보:
  1. **U 자형(머리·몸통·꼬리) 분할** — 기기 = 임베딩 + 앞 k 층 + **마지막 j 층 + 출력층 + 손실**, 서버 = 가운데 몸통. 서버는 활성값만 받고 기울기만 돌려준다. 문헌: 머리-몸통-꼬리 분할 LLM(arXiv 2606.14210)이 입력·응답 양쪽 누출을 다룬다.
     - 비용: Qwen2.5-0.5B 출력층은 임베딩과 가중치를 공유하므로 기기 메모리 추가가 작다(마지막 1층 ≈ 0.06 GB). 7B 는 출력층이 따로라 약 2.2 GB 가 더 든다. 통신은 절단면이 둘이라 왕복이 두 배.
     - 우리 크기 사다리(§ 실험_대형모델_분할LoRA)의 "기기 몫 비율" 결론은 꼬리 층 수만큼 올라간다 — 적용 전 다시 재야 한다.
  2. **전송 구간 TLS/mTLS** — 도청자(T0)만 막는다. 서버 운영자에게는 효과 없음. 기존 백로그 P1.
- 하지 말아야 할 착각: "라벨을 해시하거나 섞으면 된다" — 서버가 손실을 계산하려면 라벨 값이 필요하므로 가릴 수 없다. 손실 계산 위치를 옮기는 것만이 구조적 해법이다.

### ② 절단면 활성값에서 입력 복원 [문헌]

- LLM 은 입력→은닉 상태가 단사(injective)라 복원 가능하다는 증명과 알고리즘 SIPIT: 20토큰 프롬프트를 **토큰 정확도 100%** 로 복원(Nikolaou 외, ICLR 2026, arXiv 2510.15511). 분할 LLM 대상 공격 PIDI 는 금융 데이터에서 BLEU 0.89(arXiv 2606.14210).
- 절단점을 깊게 해도 방어가 안 된다는 점은 `보안_위협과_입장.md` §1-① 과 같다. 우리 k=2 는 얕아서 더 쉽다.
- 대책 후보:
  1. **상호정보 정규화 + 어댑터 기반 로컬 워밍업(ADMI)** — PIDI 공격을 BLEU 0.892 → 0.004 로 낮추고 유용성(METEOR) 0.550 → 0.527(약 96% 유지) (arXiv 2606.14210).
  2. **NoPeek**(절단면 출력과 원 입력의 거리 상관을 손실에 추가, Vepakomma 2020) — 가볍지만 강한 역전 공격(BiSR)에는 약하다고 보고됨.
  3. **활성값 잡음(DP forward)** — 이론 보장은 있으나 문헌 비교에서 유용성 손실이 크다.
- 우선순위: ① 을 먼저 막지 않으면 ② 방어는 의미가 없다(라벨로 이미 답이 샌다).

### ③ 완성 모델이 학습 데이터를 그대로 답한다 [이번 실험에서 실측]

- 정의: 학습 문장 앞부분으로 물었을 때 이어지는 50토큰 축자 일치(Carlini 2021 USENIX Security), 또는 카나리아(심은 가짜 비밀)를 모델이 답하는지(Secret Sharer, Carlini 2019).
- 우리 이전 실측(8/27, 비분할 연합): 가짜 비밀을 한 기관에만 넣었더니 **단독 100% · 연합 100%** — 평균이 비밀을 희석하지 못했다. 이번 분할 연합에서 다시 잰다(§4).
- 긴장 관계: 이 데모의 목적(겹치지 않는 사실을 연합으로 모델에 넣기)은 **사실을 외우게 하는 것**이다. 외우지 못하게 하는 방어는 목적도 같이 깎는다. 그래서 대책은 "외우지 마라"가 아니라 **"무엇을 외워도 되는가"를 가르는 것**에서 시작한다.

| 층 | 대책 | 효과 근거 | 부작용 · 우리 조건에서의 문제 |
|---|---|---|---|
| 데이터 | **승인층/원문층 분리** — 배포해도 되는 사실만 학습에 넣고, 비밀·원문은 투입 금지 | 기존 문서 §8 규격 | 운영 규칙이라 기술로 강제되지 않는다 → 아래 감사 게이트가 필요 |
| 데이터 | 중복 제거 · PII 스크러빙 | 중복 제거만으로 축자 재현 약 10배 감소(Lee 외 2022) | 우리 코퍼스는 사실당 5문형 반복이 **의도**다(지식 주입 요건) — 원문층에만 적용 |
| 학습 | **Goldfish 손실** — 토큰 일부를 무작위로 손실에서 뺀다. 전체 문장을 연속으로 감독받은 적이 없어 축자 재현이 안 된다 | Llama-2 수십억 규모에서 추출 가능 암기 크게 감소, 벤치마크 영향 거의 없음(Hans 외, NeurIPS 2024, arXiv 2406.10209) | 짧은 답(숫자 하나)은 한 토큰이라 빠지면 학습이 안 된다 → 긴 원문에만 의미 |
| 학습 | 낮은 LoRA rank · 조기 종료 | LoRA 는 전체 미세조정 대비 연합에서 암기 최대 10배 감소, rank 4 가 1024 보다 훨씬 적게 외움(arXiv 2502.05087) | rank 를 낮추면 사실 주입도 준다 — 우리 폭 노브와 같은 손잡이 |
| 집계 | **어댑터 델타 노름 클리핑 + 가우스 잡음(기기 단위 DP-FedAvg)** | 사용자 수가 충분하면 유용성 손실이 거의 없이 기기 단위 DP(McMahan 외, ICLR 2018, arXiv 1710.06963). LoRA 판: DP-LoRA(arXiv 2312.17493), FFA-LoRA(Sun 외 ICLR 2024) | **기기 3대에서는 잡음이 신호를 덮는다** — 이 논문의 전제(수천 명)가 우리 규모와 다르다. 연합 참여자가 수백 이상일 때 후보 |
| 집계 | 보안 집계(SecAgg) | 서버가 개별 어댑터를 못 본다(Bonawitz 2017) | 완성 모델이 외운 것은 그대로 남는다 — ③ 은 못 막는다. 이질 rank 에서는 좌표 익명성도 깨진다(기존 문서 §1-②) |
| 사후 | **배포 전 카나리아 감사 게이트** — 가짜 비밀을 심고 추출되면 배포 중단 | Secret Sharer 노출 지표 | 감사일 뿐 막지는 않는다. 게이트 기준(예: 추출 0/3)을 사전 등록해야 한다 |
| 사후 | 출력 필터 — 원문층과 n-gram 대조, 비밀 패턴(키·주민번호 형식) 정규식 차단 | Copilot 중복 필터류 서빙 관행 | 문형을 바꾸면 우회된다. 마지막 방어선으로만 |
| 사후 | 기계 언러닝 — 새어 나온 항목만 지운다 | SemEval-2025 Task 4 벤치마크(arXiv 2504.02883) | 효과·검증이 아직 미성숙. 우리 E1 언러닝 실험과 연결 가능 |

## 3. 우리 시스템에 맞춘 적용 순서 (제안 · 적용 안 함)

1. **U 자형 분할로 라벨 채널 제거** — 구조 결함이라 다른 대책보다 먼저. 크기 사다리를 꼬리 층 포함으로 다시 잰다.
2. **TLS/mTLS** — 도청자 차단, 비용 작음.
3. **데이터 층 분리 + 카나리아 감사 게이트 상설화** — 이번 실험의 카나리아 계측(`fed_split_eval.py`)을 배포 전 검사로 고정. 게이트: 가짜 비밀 추출 0/3.
4. **Goldfish 손실을 원문층(긴 문장) 학습에만** — 짧은 사실 주입은 건드리지 않는다.
5. **상호정보 정규화(ADMI 계열)** — 서버를 신뢰하지 않는 조건에서 입력 복원 방어.
6. **기기 단위 DP-FedAvg** — 참여 기기가 수백 이상일 때. 3~32대 규모에서는 유용성 대가를 먼저 잰다.
