# 클라이언트, 모델 폭, LoRA: 9월 28일 개정 기준

이 문서는 9월 27일 보고서의 ‘모델 폭 = 채널 비율’이라는 부정확한 정의를 수정한다. 현재 제출 보고서·홈페이지·그림은 아래 구분을 따른다.

## 용어와 출처

| 용어 | 이 프로젝트에서의 의미 | 근거 |
|---|---|---|
| 클라이언트(client) | 데이터로 모델 앞부분을 학습하는 참여 프로그램. 물리 장비와 논리 프로세스를 실행 조건에서 구분한다. | [TTA 클라이언트](https://terms.tta.or.kr/dictionary/dictionaryView.do?word_seq=038620-1), [SplitFed](https://ojs.aaai.org/index.php/AAAI/article/view/20825) |
| 모델 폭(model width) | CNN 합성곱 계층에서는 채널 수로 표현하는 모델의 너비 | [FjORD §3.1](https://proceedings.neurips.cc/paper/2021/file/6aed000af86a084f9cb0264161e29dd3-Paper.pdf) |
| 채널 수(number of channels) | 해당 합성곱 계층의 입력·출력 특징 맵 개수. 현재 폭 조절에서는 계층별 출력 채널과 연결되는 입력 채널을 함께 선택한다. | [PyTorch Conv2d](https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv2d.html), [models.py](../../sfl/models.py) |
| 폭 비율(width multiplier) w | 원래 채널 수에 곱하는 비율. 코드는 `ceil(w*C)`를 사용한다. 현재 실험의 후보는 0.5·0.75·1.0이다. | [MobileNets §3.3](https://arxiv.org/html/1704.04861v1#S3.SS3), [models.py](../../sfl/models.py)의 `w(c,p)`와 `ClientNet` |
| LoRA 랭크(rank) r | 추가로 학습하는 저랭크 행렬의 내부 차원. CNN 채널 수와 다른 변수다. | [LoRA 원문](https://arxiv.org/abs/2106.09685), [공식 구현 설명](https://github.com/microsoft/LoRA/blob/main/README.md) |

‘모델 폭’과 ‘채널 제어’를 별개 알고리즘으로 나열하지 않는다. 문장에서는 **‘CNN의 채널 수를 조절하여 모델 폭을 변경한다’**, 수식·표에서는 **‘폭 비율 w’**를 쓴다. 128채널에 w=0.75를 적용하면 96채널이다. 평균 w=0.977은 무차원 비율이며 채널 개수 자체가 아니다. λ는 폭 축소 페널티의 가중치로, 정확도 손실의 예측값과 구별한다.

## 초기 코드에서 혼동이 생긴 이유

[models_llm.py](../../sfl/models_llm.py)는 `rank_of(p)`로 공통 비율 p를 랭크 4·8·16·32에 대응시킨다. CNN의 p와 LLM의 p가 가리키는 실제 조절 대상이 다르므로, 문서에서 둘을 모두 ‘폭’이라고 쓰면 CNN의 채널 조절을 언어모델에서도 그대로 수행한다고 오해할 수 있다. 현재 보고서는 CNN에 w, LoRA에 r을 사용하고 기존 실행 코드·인자·원로그는 그대로 보존한다.

## 계산과 통신에서의 차이

CNN 채널 조절은 분할 지점의 활성값과 반환 기울기의 채널 차원도 바꾼다. 따라서 고정된 배치 크기·분할 위치·자료형에서는 해당 텐서의 바이트 수가 w에 비례한다. 보고서의 b×w 항은 이 관계를 나타낸다.

LoRA는 기본 가중치를 고정하고 ΔW=BA를 학습한다. 랭크 r은 A와 B의 내부 차원을 바꾸지만 기본 계층의 입력·출력 차원을 바꾸지 않는다. [run_scale_lora.py](../../sfl/experiments/run_scale_lora.py)의 분할 활성값은 배치×시퀀스 길이×은닉 차원이다. 모델·배치·길이·자료형이 같다면 랭크만 변경해도 이 활성값의 크기는 유지된다. 학습 파라미터 수와 라운드별 어댑터 집계량은 r에 따라 바뀔 수 있다. 배치별 활성값 통신과 라운드별 파라미터 집계를 구분해야 한다.

## 보고서에 실제로 제시하는 실험

| 구분 | 조절·고정 조건 | 결과가 답하는 질문 |
|---|---|---|
| CNN 주 실험 | 폭 비율 w와 중계 경로 선택, 분할 위치 고정 | 스케줄러가 시간·전송량·정확도에 어떤 변화를 만드는가 |
| Jetson 보조 측정 | Qwen2.5-0.5B, LoRA 랭크 32 고정, 전력 모드 변경 | 하드웨어의 전력 모드에 따라 학습 스텝 시간이 얼마나 달라지는가 |
| KOREN LoRA 연합 실행 | Qwen2.5-0.5B, 랭크 16 고정, 논리 클라이언트 3개 | 분할 실행과 어댑터 집계로 각 클라이언트의 학습 내용을 반영할 수 있는가 |

랭크 대응 코드의 존재와 동적 랭크·경로 제어의 실험 검증은 구별한다. [run_fed_split_lora.py](../../sfl/experiments/run_fed_split_lora.py)는 고정 `--rank`로 모델을 만들고 LoRA 파라미터를 집계한다. 현재 보고서의 결과는 고정 랭크 실행이다. LoRA를 소개하는 목적은 언어모델의 학습 파라미터를 줄여 분할·연합 실행을 확인한 보조 실험의 선택 이유를 설명하는 것이다.

## 채널 축소와 LoRA를 함께 쓰는 확장

LoRA는 모델 폭을 줄인 모델에도 적용할 수 있다. CNN의 채널 수에 대응하는 언어모델의 표현 크기는 ‘은닉 차원’으로 표기한다. [SliceGPT 원문 §4.1](https://arxiv.org/html/2401.15024v2)은 은닉 차원을 줄인 모델의 LoRA 추가 학습을 제시한다. 그러므로 ‘LoRA만으로는 채널 수가 줄지 않는다’와 ‘모델 폭 축소 + LoRA가 가능하다’는 함께 성립한다.

후속 검증은 **은닉 차원 축소 → 고정 랭크 LoRA 학습 → 분할 전송·경로 제어** 순서로 진행한다. 기존 Qwen·Jetson 측정의 조건은 유지한다. [확장 설계](../04_설계기록/LoRA_은닉차원축소_확장검토_2026-09-28.md)에 실제 페이로드 계산, 모델별 호환성, 폭 전환·집계 조건과 단계별 검증을 정리했다.

## 문체와 개정 범위

장·절은 중간보고서 양식을 유지한다. Ⅰ장은 목적과 특징, Ⅱ장은 목표·추진 내용과 단계별 구현, Ⅲ장은 수행 현황·KOREN 활용·멘토 의견 및 후속 방향, Ⅳ장은 중간 결과물과 기대 효과, Ⅴ장은 참고문헌으로 배치했다. 멘토 의견은 [설계 전환 회의록](../04_설계기록/설계전환_회의록.md)의 기록에서 가져오고 이번 사용자의 원고 검토 의견과 구분했다.

기대 효과는 병원 등 기관 간 공동 학습을 중심으로 정리했다. ‘스케줄링으로 계산·통신 대기 완화 → 공동 학습 지속 → 여러 기관의 데이터를 반영한 전역 모델 개선의 기반’이라는 적용 논리를 사용한다. [EXAM 연구](https://doi.org/10.1038/s41591-021-01506-3)는 기관 간 연합학습의 활용 근거이며 AwareNet의 임상 검증 결과로 사용하지 않는다. 최종 효과는 기관별 모델 성능과 목표 성능 도달 시간으로 평가한다.

참여 주체는 ‘클라이언트’, 물리 장비를 지칭할 때는 ‘Jetson 장비’ 등 실제 이름을 쓴다. 개발 주체는 ‘이 프로젝트’로 통일하고 ‘문제가 드러났다’보다 ‘대역폭 재배분만으로 대기를 충분히 줄이지 못했다’처럼 수행한 행동과 결과를 직접 서술한다. 원래 논문 제목·인용문·공식 제출 문구는 필요한 고유 표현을 유지한다.

보고서 요약·서론에서 CNN 평가와 LoRA 보조 실험의 관계를 먼저 설명하고, Ⅲ장 4절에 비교 그림을 추가했다. 표·수식의 소수 값은 ‘폭 비율’로, 그림의 개수는 ‘채널 수’로 표기한다. 원측정값과 학습 알고리즘은 이번 문서 개정에서 변경하지 않았다.
