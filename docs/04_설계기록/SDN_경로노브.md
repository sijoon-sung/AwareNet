# SDN을 어떻게 살리나 — 경로를 **네 번째 노브**로 (8번 문서)

> 다중 경로가 가능하다는 전제에서 다시 쓴다. 6번 문서(고민 노트)를 대체한다.
>
> **결론 먼저**: 경로 배정은 **정확도 대가가 0인 유일한 노브**다.
> 그래서 순서상 **맨 앞**에 온다 — 공짜인 것을 먼저 쓰고, 모자랄 때 비싼 것을 쓴다.

---

## 1. 노브 표에 경로를 넣으면 답이 나온다

오늘 다중 노브 컨트롤러를 만들면서 정리한 표에 한 줄을 더한다.
앞의 셋은 전부 실측값이다 (E8, N=4 전원 30Mbps).

| 노브 | 바이트 | 연산 | **실효 대역** | 정확도 대가 |
|---|---|---|---|---|
| 폭 p (OD) | ∝ p | ∝ p^1.04~1.35 | 불변 | **−0.50pp** |
| 양자화 8비트 | ÷4 | 불변 | 불변 | **−1.20pp** |
| 배분층(한 회선 안 재분배) | 불변 | 불변 | 불변 | 0 — **효과도 0** |
| **경로 배정** | **불변** | **불변** | **바뀐다** | **0** |

**경로가 특별한 이유가 이 표에 다 있다.**
폭과 양자화는 *보내는 것을 줄여서* 시간을 산다 — 그래서 학습을 대가로 낸다.
경로는 *같은 것을 더 좋은 선으로 보낸다* — **대가가 없다.**

그래서 순서가 정해진다:

```
① 경로 배정   대가 0        →  먼저. 공짜다
② 폭 p        대가 −0.5pp   →  경로로 모자라면
③ 양자화      대가 −1.2pp   →  폭 바닥에서도 모자라면
```

## 2. 배분층은 죽었는데 경로는 왜 사나 — 같은 식으로 설명된다

두 번 실측으로 죽은 배분층과 무엇이 다른가. 한 줄로 갈린다.

```
한 회선 안:   makespan ≥ 총바이트 / C
              ★ TCP 가 **가만 둬도 이 하한에 닿는다** (work-conserving)
              → 우리가 나눠봐야 이미 최적인 것을 흔들 뿐. 그래서 죽었다

경로 여럿:    makespan ≥ 총바이트 / (C₁+C₂+…)
              ★ TCP 는 **가만 두면 이 하한에 못 닿는다**
                — 흐름 하나는 경로 하나만 쓴다. 나머지 경로는 논다
              → **기본 동작과 하한 사이에 틈이 생긴다. 그 틈이 우리 자리다**
```

배분층이 죽은 진짜 사인은 "하한이 있어서"가 아니라 **"TCP 가 가만 둬도 그 하한에 닿아서"** 였다.
경로가 여럿이면 그 성질이 깨진다.

**그리고 경로 배정은 재분배가 아니라 매칭이다.** 숫자로 보면 명확하다
(경로 100M·20M, 클라 2명, 각 50MB):

| 배정 | makespan |
|---|---|
| 둘 다 100M 경로 | 50MB×2 / 100M = **8초** |
| 하나씩 나눠 태움 | max(4초, 20초) = **20초** |

같은 자원인데 배정에 따라 **2.5배** 차이가 난다. 한 회선 안에서는 이런 일이 없었다
(어떻게 나눠도 총량이 같아 makespan 이 같았다). 그게 결정적 차이다.

## 3. 그래서 SDN 이 할 일 — 딱 하나

**흐름을 경로에 배정하는 것.** 그것뿐이다.

- ~~"SDN 으로 대역을 배분한다"~~ → 배분층은 죽었다. 되살리지 않는다
- ~~"SDN 으로 망을 통제한다"~~ → 이 과제는 망을 통제하는 과제가 아니다 (7번 문서)
- **"SDN 으로 어느 클라를 어느 경로에 태울지 정한다"** → 이건 산다

배정 문제 자체는 어렵지 않다. 경로 p 에 클라 집합 S 가 붙으면
그 경로의 완료 시각은 `Σbytes(S) / C_p` 다. 즉 **최대 경로 부하를 최소화하는 부하분산**이고,
클라 8명·경로 3개 정도면 탐욕(큰 것부터 가장 빨리 끝나는 경로에)으로 충분하다.

## 4. 폭과 경로가 만나는 자리 — 여기가 제일 흥미롭다

두 노브가 상호작용한다:

```
느린 경로에 탄 클라        →  폭을 깎아야 한다 (학습 손실)
그 클라를 빠른 경로로 옮기면 →  깎을 필요가 없어진다 (학습 보존)
```

즉 **경로를 잘 배정하면 폭을 덜 깎아도 된다.** 경로 배정이 곧 **학습 손실을 줄이는 수단**이 된다.
이건 폭만 있을 때는 존재하지 않던 선택지다.

우리 컨트롤러 구조가 이미 이 모양이라 자연스럽게 들어간다 —
`decide()` 가 "마감선을 넘는 클라를 가장 싼 노브부터 구제한다"이고, 경로가 그중 제일 싼 노브다.

**조사 범위에서 이 조합(폭 × 경로 공동 최적화)의 선례를 못 찾았다.**
SmartFLow(2025)는 경로만, FjORD·HeteroFL·FedRolex·HeteroSplitFed는 폭만 다룬다.
다만 **"못 찾았다"는 "없다"가 아니다** — 주장하려면 별도 조사가 필요하다.

## 5. 무엇을 주장할 수 있고 무엇을 못 하나

| 필요한 것 | 상태 |
|---|---|
| 알고리즘을 로컬에서 시험 | **된다** — 경로를 주소별 HTB 클래스로 만들면 된다 (회선 이질성과 같은 방법) |
| 경로가 실제로 둘 이상 있나 | **가능하다고 확인됨** |
| 경로를 고를 권한 (컨트롤러 접근) | **아직 없다** |

| 주장할 수 있는 것 | 주장할 수 없는 것 |
|---|---|
| "경로 배정이 makespan 을 X% 줄인다" | "실제 SDN 컨트롤러로 집행했다" |
| "경로를 쓰면 폭을 덜 깎아 정확도를 지킨다" | (권한이 열리기 전까지) |

권한이 안 열리면 **"에뮬레이션"이라고 정확히 쓴다.** 실증했다고 쓰지 않는다.

## 5.5 "실제 연합학습에서 가능한가" — 성립 조건 세 무대 (디펜스용)

인터넷 한가운데의 라우팅을 바꾸는 것은 불가능하고 주장하지 않는다.
경로 선택지가 **실재하는** 무대는 셋이고, 각각 집행 방법이 다르다:

| 무대 | 경로 선택의 실체 | 권한 | 실배치 조사 판정 (8/27, 9번 문서) |
|---|---|---|---|
| ① 관리형·전용망 (KOREN·자가망) | SDN/QoS 로 진짜 경로 제어 | 필요 | ✅ 유효 — 단 SD-WAN(사이트 IT)·슬라이스(통신사)는 **통제권이 남의 손**이라 관측 입력으로 강등. 진짜 제어는 권한 있는 연구망·자가망뿐 = KOREN 필연성 논거 |
| ② 멀티호밍 단말 (WiFi+LTE, MPTCP) | 단말이 접속망 선택 | 불필요 | ❌ **크로스디바이스 프로덕션에서 무효** — 비과금 WiFi 자격 조건이 셀룰러를 원천 배제 (Google·Apple 동일). 소비자 FL 무대에선 주장 금지 |
| ③ ★ 다중 집계기 매핑 (계층형 FL) | "어느 집계기/ingress 에 붙을지"를 운영자가 프로비저닝 | **불필요 — 순수 앱 레벨** | ✅ **유일하게 FL 운영자 완전 통제** — NVIDIA FLARE 가 계층형(클라→하위→상위 집계기)·FL Hub 를 공식 지원, 매핑은 운영자 권한·라운드 단위 변경 가능. **경로 노브의 실전형은 이것** |

배정 명령은 폭과 같은 체크인 응답의 필드 하나다 (FjORD 식 폭 배포와 동일 채널).
실배치 지형 전체와 주장 금지 목록은 **9번 문서(실전_포지셔닝_FL배치지형.md)** 가 정본이다.
M2′와 실전의 남은 차이는 둘뿐: 참값→EWMA 추정(+히스테리시스 — 폭에서 검증된
패턴의 이식, 0번 칸 온라인 통합), 완전탐색→탐욕(N>8, assign_greedy 확장).
둘 다 "불가능"이 아니라 "엔지니어링"이다.

## 6. 사전 등록 실험 (하기 전에 판정 기준을 박아둔다)

| # | 실험 | 폐기 기준 | 결과 (2026-08-27 실측, run_m1.py) |
|---|---|---|---|
| **M1** | 경로 배정 이득 — 경로 2개 × 클라 4대, 무작위 배정 vs 컨트롤러 배정 | makespan **15% 이상** 개선 없으면 폐기 | ✅ **PASS +42.9%** — 탐욕 12.88s vs 무작위 평균 22.55s. 탐욕이 전원을 빠른 경로(100M)에 몰아 태움 — §2의 "매칭" 산수가 실물로 |
| **M2** | 폭 손실 절감 — 경로를 쓸 때 평균 폭이 얼마나 덜 깎이나 | 평균 폭이 유의미하게 안 오르면 M1만 남기고 폐기 | ❌ **FAIL — 폐기 (킬 기준 집행, 8/27)**. 폭 보존은 성립(0.807→1.000, Δ+0.193 ✓)했으나 **makespan 가드 위반**(탐욕 12.92s vs 무작위 11.46s): 폭 컨트롤러가 나쁜 배정의 유배 클라를 좁히자 빠른 경로 부하까지 줄어 더 빨라짐. ★ **폭이 살아있으면 M1 의 답(몰아 태우기)이 뒤집힌다** — 경로는 폭을 알아야 하고 폭은 경로를 알아야 하는 순환 의존. "경로가 폭을 면제한다"는 단순 명제 폐기, **폭×경로는 공동 최적화 문제**라는 실측 근거로 전환 (선례 공백이 자명하지 않음을 스스로 증명) |
| **M2′** | 개선 재도전 — (배정, 폭벡터) **공동 완전탐색**(`paths.joint_plan`, 2^4×4^4, 목적 = makespan/평균폭) | C 가 A·B 를 ratio 10% 이상 못 이기면 공동 계획도 기각 | ✅ **PASS (8/27)** — C 8.17s/폭0.75/ratio **10.89** vs A 14.20·B 12.92 (판정선 11.63). 계획: c3 를 느린 경로에 **폭 0.5 로** 유배(느린 경로 6.7s ≤ 빠른 경로 — 공짜 유배)+c0·c1 0.75. **예측 10.55 vs 실측 10.89, 오차 3%** — 계획 모형까지 검증. M1→M2(역설)→M2′(해소)로 "폭×경로 공동 최적화"가 필요성 실증+첫 해법 실측이 됨 |
| **M3** | 경로 분할(한 클라가 두 경로) | 합계 용량의 **80%** 못 내면 폐기 (재조립 비용) | 대기 |
| **M4** | 경로가 균질할 때 | **아무것도 안 해야 한다** — 하면 그게 결함이다 | ✅ **PASS** — 탐욕이 저절로 2:2 분산, 균등 대비 차이 0.9% |

M4 를 넣은 이유: 폭 노브에서 배운 것이다. **균질할 때 가만있는 것**이
이질할 때 움직이는 것만큼 중요하다. 문턱 상수로 판정하면 여기서 깨진다.

## 7. ⚠ 먼저 정리해야 할 것 — 지금 이 컴퓨터로는 못 잰다

오늘 밝혀진 것: **클라 8대에서 측정이 무너진다.** 원인은 GPU 가 아니라
**CPU 스레드 과다구독**이었다 — 클라는 `--device` 기본값이 `cpu` 라 전부 CPU 에서 돌고,
torch 기본이 프로세스당 8스레드라 **8대 × 8스레드 = 64스레드가 코어 16개**에 몰렸다.
`--threads` 를 붙여 나눠주면 나아지는지 지금 확인 중이다.

**이게 정리되기 전에는 경로 실험을 해도 결과를 믿을 수 없다.**
순서는 ① 스레드 정리 → ② N=4·8 측정 회복 확인 → ③ 경로 실험이다.

→ **①②는 8/26 완료**(--threads 배선, R 재실측 통과), **③은 8/27 집행 완료** — 위 결과표.
집행기: `sfl/net/paths.sh`(경로 HTB + 필터 교체 재배정 — 학습 중 즉시 적용) + `sfl/experiments/run_m1.py`.
주장 가능 범위(§5 그대로): "경로 배정이 makespan 을 42.9% 줄인다 (에뮬레이션)" —
실SDN 컨트롤러 집행 주장은 KOREN 권한 이후에만.

## 한 문단 요약

경로 배정은 **정확도 대가가 0인 유일한 노브**라서 순서상 맨 앞에 온다.
배분층이 죽은 것과 경로가 사는 것은 같은 식으로 설명된다 — 한 회선 안에서는 TCP 가
가만 둬도 하한에 닿아 개입할 틈이 없지만, 경로가 여럿이면 흐름 하나가 경로 하나만 써서
**기본 동작과 하한 사이에 틈이 생긴다.** 그 틈이 SDN 의 자리이고, SDN 이 할 일은
대역 배분이 아니라 **흐름을 경로에 배정하는 것 하나**다.
가장 흥미로운 것은 폭과의 상호작용이다 — 경로를 잘 배정하면 폭을 덜 깎아도 되므로
**경로 배정이 학습 손실을 줄이는 수단**이 된다. 다만 지금 이 컴퓨터는 클라 8대에서
측정이 무너지므로(CPU 스레드 과다구독), 그것부터 정리한 뒤에 경로 실험을 한다.
