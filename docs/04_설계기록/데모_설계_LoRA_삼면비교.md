# 데모 설계 — LoRA 연합 튜닝의 "답변이 다르네?" 를 시스템으로 만들기

> 질문: "LoRA 연합학습이 클라우드(중앙 학습)보다 뭐가 좋은데?"
> 이 문서는 그 질문에 **말이 아니라 화면으로** 답하는 설계다.

## 0. 먼저 — 질문의 전제를 바로잡는 답 (말로 하는 부분)

"클라우드보다 좋다"고 주장하지 않는다. **클라우드 중앙 학습은 데이터를 모을 수 있을 때의
이야기이고, 우리의 전제는 데이터가 못 움직이는 상황이다** (규제·소유권·기관 경계).
그 전제에서 선택지는 셋뿐이다:

| 선택지 | 성능 | 데이터 반출 |
|---|---|---|
| ① 중앙(클라우드) 학습 | 상한선 | **위반** — 전제상 불가 |
| ② 각자 따로 학습 | 하한선 — 남의 도메인은 영원히 모름 | 없음 |
| ③ **연합 튜닝 (우리)** | ①에 얼마나 다가가나가 우리 수치 | **없음** |

주장: **"② < ③ ≤ ①"을 실측으로 보인다.** 그리고 우리 대회 기여는 ③ 자체(기시감 주제)가
아니라 **③을 이기종 실망에서 배제 없이 완주시키는 인프라**다 — 데모는 그 학습이 실제로
일어났음을 눈으로 확인시키는 장치.

## 1. 핵심 원리 — 데이터 설계가 곧 데모 설계다

"답변이 달라 보이려면" 베이스 모델이 **원리적으로 알 수 없는 지식**이어야 한다.
일반 상식 데이터로 튜닝하면 차이가 안 보인다. 그래서 각 노드(기관 역할)에
**초로컬(hyper-local) 도메인 코퍼스**를 배정한다 — 베이스 Qwen이 맞힐 수 없는 것:

| 노드 | 코퍼스 (예시) | 성격 |
|---|---|---|
| A (판교) | 학교 학사제도·규정 Q&A (졸업요건, 수강 규정) | 공개돼 있어도 모델이 암기 못 한 초로컬 사실 |
| B (대전) | 넷챌린지·KOREN 문서 Q&A (신청 절차, 거점 구성) | 이번 과제 도메인 |
| C (Jetson·최약체) | 특정 연구실 장비 매뉴얼·위키 Q&A | 비공개 문서 — "반출 불가"의 실물 |

각 코퍼스는 Q&A 반복 형식으로 가공한다 (0.5B급 LoRA 지식 주입은 서술문 원문보다
Q&A 반복 노출이 훨씬 잘 든다).

## 2. 화면 — 3×3 그리드 한 장

같은 질문 3개(도메인 A·B·C 각 1개)를 세 모델에 던져 ✓/✗로 채운다:

|  | A 질문 | B 질문 | C 질문 |
|---|---|---|---|
| 베이스 (튜닝 전) | ✗ 환각 | ✗ | ✗ |
| A 단독 학습 | ✓ | ✗ | ✗ |
| **연합 튜닝 (우리)** | **✓** | **✓** | **✓** |

- 심사위원이 보는 것: 베이스 0/3 → 단독 1/3 → 연합 3/3.
  **"데이터는 한 발짝도 안 움직였는데, 지식은 합쳐졌다."**
- 라이브 순서: 심사위원이 질문 하나를 고르게 함 → 세 모델 답변이 나란히 뜸 →
  "답변이 다르네?"가 남의 대사가 아니라 심사위원의 대사가 된다.
- ★ C 열이 급소다: **가장 약한 노드(최소 rank로 참여한 Jetson)의 지식이 최종 모델에
  살아 있다** = "배제 없는 학습"이 답변으로 보이는 순간. `canary.py`(기기별 기여 생존 판정)
  의 LLM판이다.

## 3. 정량 병행 (화면 뒤에 두는 것)

- 도메인별 held-out Q&A 정답률 (키워드/EM 채점, 사전 등록) — 3×3 그리드의 대수화
- perplexity (보조) · rank별 대가 곡선 (R6 rank 사다리와 공용)

## 4. 예상 공격과 방어

| 공격 | 방어 |
|---|---|
| "그거 RAG로 하면 되잖아" | RAG는 질의 시점에 문서 접근이 필요 — 기관 간 공유 인덱스가 곧 반출이다. 연합 튜닝은 반출 없이 모델에 내재된다. 그리고 우리 기여는 지식주입 기법이 아니라 **그 학습을 실망에서 완주시키는 인프라**다. 필요하면 연합 모델+로컬 RAG 는 병행 가능(직교) |
| "0.5B가 지식이 들어가?" | 그래서 Q&A 반복 형식 + 파일럿 게이트: 단일 노드 로컬 튜닝으로 A 도메인 정답률이 오르는지 먼저 확인 후 연합으로 확장 (§5) |
| "질문을 골라 온 것 아니냐" | held-out 세트 사전 등록 + 현장에서 심사위원 선택 |
| "중앙 학습이 더 잘하잖아" | 맞다 — ①은 상한선이고 전제상 불가라는 프레임(§0)을 먼저 박는다. ①과의 격차 수치도 정직하게 제시 |

## 5. 파일럿 게이트 (사전 등록 — 비용 낮은 순서)

1. **G-L1**: Qwen 0.5B + LoRA 로컬 튜닝(노드 A 코퍼스만, 단일 GPU)으로 A 도메인
   정답률 베이스 대비 **+40%p 이상** 오르는가. 안 오르면 → 모델 1.5B 승격 또는
   코퍼스 재가공. **여기서 실패하면 데모 설계 전체 재검토 — 연합 배선 전에 안다**
2. **G-L2**: 3노드 연합(로컬 리그)에서 3/3 그리드 재현
3. **G-L3**: 실망(K1) 위에서 재현 + rank 사다리(R6) 결합

## 6. 클라우드 GPU 질문과의 연결

①(상한선) 수치를 만들려면 중앙 학습 1회가 필요하다 — 이건 반출 위반이 아니라
**우리 손으로 상한선을 재는 실험**이다(전 코퍼스를 우리가 만들었으므로).
KOREN/NIA 측 AI·GPU 클라우드 자원이 있으면 여기(상한선 학습 + SFL 서버 뒷단)에 쓴다.
→ 안효준 부장님 문의 항목에 포함.
