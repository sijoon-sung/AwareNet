# 망 개입을 다시 넣으려면 — 원리부터 (5번 문서)

> ⚠ **이 문서는 "고민 노트"이지 계획서가 아니다.** 여기 있는 어느 것도 지금 하지 않는다.
>
> **우선순위는 하나다 — 우리 가설(망·기기를 재서 학습 폭 p를 정한다)의 검증.**
> 조건 사다리(1 동일회선 → 2 이질회선 → 3 교란 → 4 다중클라 → 5 진짜모델)가 전부이고,
> 이 문서의 N1~N5 는 **그게 다 끝난 뒤에 볼 목록**이다.
>
> ⚠ **비동기 FL을 하자는 게 아니다.** §4의 ③④(기회주의·부분참여)는
> "왜 우리가 그걸 안 하는가"를 적은 것이지 제안이 아니다.
> §4-② 배치 수 조절도 **지금은 안 한다** — 폭 p 하나만 민다는 원칙 그대로다.

---

## 1. 죽은 이유를 식으로 다시 쓴다

라운드 완료 시각의 하한은 이것이다:

```
makespan  ≥  (전송해야 할 총 바이트) / (실효 용량)
```

**재분배는 분자도 분모도 안 바꾼다.** 누구에게 더 주고 덜 주든 총 바이트는 그대로고 용량도 그대로다.
그래서 두 번 죽었다:

| 죽은 것 | 무엇을 재분배했나 | 결과 |
|---|---|---|
| 배분층 (워터필링) | **공간** — 대역 몫 | 32.0초 → 34.7초 (오히려 악화) |
| 토큰 admission | **시간** — 전송 순서 | 느린 쪽 5.348→5.359초(불변), 빠른 쪽만 52% 악화 |

> **원리 한 줄**: 붕괴가 없는 공유 자원에서 참가자 간 재분배는 완료 시각을 못 당긴다.

**따라서 살아 있는 길은 셋뿐이다** — 식의 각 항을 보면 자명하다:

| # | 어디를 건드리나 | 방법 | 우리 상태 |
|---|---|---|---|
| **A** | **분자를 줄인다** (총 바이트↓) | 폭 p · 양자화 | **현재 방식** |
| **B** | **분모를 키운다** (실효 용량↑) | **다중 경로 · 경로 재선택 · 손실 감소** | **← 여기가 SDN의 진짜 자리** |
| **C** | 하한이 병목이 아닌 경우 | 아래 §4 조건들 | 조건부 |

## 2. B — SDN이 실제로 용량을 키우는 세 가지

여기가 **"SDN을 다시 쓴다면 무엇을 하나"**의 답이다. 재분배가 아니라 **용량 확대**다.

### B0. **먼저 — 우리는 이미 회선을 다 못 쓰고 있다** [실측] ← 여기가 진짜 자리

다중 경로를 논하기 전에 확인할 것이 있었다. **지금 있는 회선조차 다 못 쓴다.**

| 동시 클라 | 굿풋 (회선 50Mbps) | 사용률 |
|---|---|---|
| 1대 | 18.1 Mbps | **36%** |
| 2대 | 30.9 Mbps | 62% |
| 4대 | 37.3 Mbps | 75% |
| 8대 | 37.0 Mbps | 74% |

**1대일 때 64%가 논다.** 왜? 분할 학습은 *계산 → 보냄 → 기다림 → 역전파*의 닫힌 순환이라
**계산하는 동안 회선이 비어 있다.** 여러 대가 붙으면 서로의 빈 시간을 메워 74%까지 오른다.

> **이 노는 몫을 쓰는 것은 재분배가 아니다. 분모를 키우는 것이다.**
> 그리고 **망을 새로 만들 필요가 없다 — 엔드포인트만으로 된다.**

| 방법 | 어떻게 | 우리 상태 |
|---|---|---|
| **파이프라이닝** | 그래디언트를 기다리는 동안 다음 배치를 미리 계산 → 빈 시간을 메움 | **구현 완료.** 대기 0.048→0.017초, 배치 −14% (localhost 하한) |
| **TCP 튜닝** | 혼잡제어(BBR)·소켓 버퍼. 긴 RTT에서 단일 흐름은 파이프를 못 채운다 | 미측정 — **N5 신설** |
| **병렬 연결** | 한 클라가 흐름을 여러 개 열어 창 크기 제약을 넘음 | 미측정 — N5에 포함 |

**파이프라이닝이 이미 그 일을 하고 있었다.** 우리가 "RTT 은닉"이라 부른 것이
사실은 **용량 확대**였다 — 분류를 잘못하고 있었던 셈이다.

### B1. 다중 경로 (multipath) — 원리는 맞지만 **우리에겐 아마 없다**

한 경로만 쓰면 실효 용량은 그 경로의 용량이다. **두 경로를 동시에 쓰면 분모가 커진다.**

```
현재:  클라 ──[경로1: 20Mbps]── 서버        실효 20Mbps
다중:  클라 ┬─[경로1: 20Mbps]─┬ 서버        실효 최대 32Mbps
           └─[경로2: 12Mbps]─┘
```

- **왜 재분배와 다른가**: 재분배는 파이를 다시 자르는 것이고, 이건 **파이를 하나 더 가져오는 것**이다.
  총량 불변 논증에 걸리지 않는다. **3관문 ③을 통과하는 유일한 재분배 아닌 망 개입.**
- **SDN이 필요한 이유**: 경로를 계산하고 스위치에 설치하는 것이 정확히 SDN의 일이다.
  OpenFlow로 흐름을 두 경로에 나눠 태울 수 있다.
- **선행**: SmartFLow(2025)가 ONOS+OpenFlow로 FL 트래픽 **경로 재배정**을 해 동기화 시간 최대 47% 개선.
  단 그쪽은 **경로 바꾸기**이고 다중 경로 동시 사용은 아니다.
- **⚠ 현실 조건이 가혹하다 — 셋 중 하나가 있어야 한다:**

| 필요 조건 | 우리 상황 |
|---|---|
| ① 경로를 정하는 권한 (SDN 컨트롤러 접근) | **없다.** KOREN SDN 컨트롤러를 못 받았다 |
| ② 호스트가 인터페이스를 둘 이상 가짐 (MPTCP) | VM이 단일 인터페이스일 가능성이 높다 |
| ③ 우리가 망을 직접 만든다 | **범위 밖.** 과제가 감당할 규모가 아니다 |

> **따라서 다중 경로는 "원리는 맞지만 우리 손에 없을 가능성이 크다"로 강등한다.**
> 남의 망 위에서 경로를 바꾸려면 그 망의 권한이 필요하고, 권한이 없으면
> 남는 선택지는 **우리 망을 만드는 것뿐인데 그건 과제 범위를 벗어난다.**
> N1으로 확인은 하되, **설계는 B0(엔드포인트) 위에 세운다.**

### B2. 경로 재선택 — 혼잡한 경로를 피한다

용량이 같아도 **혼잡한 경로는 실효 용량이 낮다.** 여유 있는 경로로 옮기면 분모가 커진다.

- 재분배가 아니다 — 학습 참가자끼리 뺏는 게 아니라 **바깥 트래픽을 피하는 것**이다.
- 우리 '지키기'(HTB 보호)와 같은 논리 계열: **제로섬이 아니다.**
- SDN 텔레메트리(경로별 부하)가 입력이 된다 — 우리 관측 루프가 이미 그 모양이다.

### B3. 손실 감소 — 재전송을 줄이면 실효 처리량이 는다

버퍼 튜닝·AQM·우선순위로 손실을 줄이면 같은 회선에서 더 나간다.

- ⚠ 우리 실측에서는 **붕괴가 없었다**(굿풋이 용량의 74%에서 평평). 손실이 문제라는 증거가 없다.
- **관문 ①②를 통과해야 손댈 수 있다.** 지금은 아니다.

## 3. 그래서 SDN을 어떻게 쓰나 — 역할이 바뀐다

| | 옛 설계 (죽음) | 새 설계 |
|---|---|---|
| SDN이 하는 일 | **참가자별 대역 몫 배분** | **경로 제공 · 경로 상태 보고** |
| 컨트롤러 입력 | 회선 상태 | 회선 상태 **+ 경로별 여유** |
| 컨트롤러 출력 | 대역 몫 | **폭 p** (+ 조건부: 경로 선택) |
| 논증 | 총량 불변에 걸림 ✗ | 용량을 키움 ✓ |

```
        ┌──────────── 컨트롤러 ────────────┐
 관측 → │  기기 성능 · 회선 속도            │
        │  + SDN 텔레메트리(경로별 여유)    │ → 집행 ┬→ 학습 폭 p   (수요 축소)
        └──────────────────────────────────┘        ├→ 경로 선택   (용량 확대) ★새로
                                                     └→ HTB 보호   (외부 방어)
```

**핵심**: SDN이 미는 대상이 "누가 얼마나 쓰나"에서 **"어디로 가나"**로 바뀐다.
전자는 제로섬이라 죽었고, 후자는 아니다.

## 4. C — 재분배가 되살아나는 조건 (전부 실측 전제)

원리는 "붕괴가 없으면 재분배 무용"이었다. **그러니 아래 넷 중 하나가 실측되면 되살아난다.**

| 조건 | 왜 되살아나나 | 우리 실측 상태 |
|---|---|---|
| ① **실제 포화 + 붕괴** (ρ>1, 굿풋 하락) | 붕괴가 있으면 admission이 붕괴를 막아 **분모를 회복**시킨다 | **✗ 없었다** — 74%에서 평평, 하락 없음 |
| ② **클라별 데이터 양이 다름** | 총 바이트가 클라마다 다르면 "느린 회선 ↔ 적은 데이터" 매칭이 makespan을 줄인다 | 미실험. **지금은 안 한다** — 손잡이를 둘로 늘리면 무엇이 효과를 냈는지 못 가린다 |
| ③ **회선이 시변** | 지금 좋은 사람에게 지금 더 보내면 총 시간이 준다(기회주의적 스케줄링) | ⚠ **TCP가 이미 암묵적으로 한다.** 우리가 이기려면 TCP보다 잘해야 하는데 그 근거가 없다 |
| ④ **부분 참여 허용** | 전원이 끝날 필요가 없으면 순서가 의미를 갖는다 | 우리는 전원 참여(배제 없는 학습)를 택했다 — **설계 철학과 충돌** |

**넷 다 지금은 안 한다.** ③④는 비동기·부분참여 계열인데 우리 철학(배제 없는 학습)과 충돌하고,
②는 손잡이를 둘로 늘리는 일이라 변인이 흐려진다. **기록만 해 두고 폭 p 하나만 민다.**

## 5. 실험으로 답할 것 — 사전 등록

| # | 실험 | 무엇을 묻나 | 판정 |
|---|---|---|---|
| **N5** | **회선 사용률 회복** ★1순위 | TCP 튜닝(BBR·버퍼)·병렬 연결·파이프라이닝으로 1대 사용률 36%를 얼마나 올리나 | 50% 못 넘으면 파이프라이닝만 남기고 나머지 폐기 |
| N1 | 경로 여유 실측 (KOREN) | 판교–대전에 경로가 둘 이상 있나. 우리가 고를 권한이 있나 | 권한이 없거나 경로가 하나면 **B1 전체 폐기** |
| N2 | 다중 경로 이득 | 두 경로 동시 사용이 실효 용량을 실제로 키우나 | 합계의 **80% 이상** 못 내면 폐기 (재조립 비용) |
| **N3** | **배치 수 노브** (②) | B_k를 회선에 맞추면 makespan이 주나 | 폭 p 단독 대비 **10% 이상** 개선 없으면 폐기 |
| N4 | 포화·붕괴 재확인 | 클라 16대·좁은 회선에서도 붕괴가 없나 | 붕괴가 나오면 admission 관문 ①② 재개 |

**순서**: **N5 → N3 → N4** → (KOREN 권한이 열리면) N1 → N2.
N5·N3·N4는 지금 장비로 가능하고 망을 새로 만들 필요가 없다.
N3는 지금 장비로 가능하고, N1·N2는 KOREN 접속 구조를 알아야 한다.

## 6. 하지 말아야 할 것 — 되돌아오면 끊을 목록

| 유혹 | 왜 안 되나 |
|---|---|
| "SDN으로 학습 클라들에게 대역을 다시 나눠주자" | **총량 불변.** 두 번 죽었다 |
| "우선순위 큐로 중요한 클라를 먼저" | 시간 축 재분배 = 토큰과 같은 벽 |
| "붕괴가 없어도 admission이 도움될 것" | 실측했다. 느린 쪽을 못 올리고 빠른 쪽만 늦춘다 |
| "경로가 여럿일 것이다" | **가정 금지.** N1로 재고 나서 말한다 |

## 한 문단 요약

**재분배는 죽었고 되살릴 수 없다** — 공간이든 시간이든 총량 불변의 벽에 걸린다.
분모(용량)를 키우는 것만이 그 벽을 통과하는데, **다중 경로는 남의 망에 대한 권한이 필요하고
우리에겐 없다.** 우리 망을 새로 만드는 것은 과제 범위를 벗어난다.

**그런데 망을 만들 필요가 없는 자리가 이미 있었다.** 우리는 **지금 있는 회선조차 36%만
쓰고 있다**(1대 기준). 계산하는 동안 회선이 비기 때문이다. 이 빈 시간을 메우는 것 —
파이프라이닝·TCP 튜닝·병렬 연결 — 은 **엔드포인트만으로 되는 용량 확대**이고,
파이프라이닝은 이미 구현해 대기 시간을 0.048→0.017초로 줄여 놨다.
분류를 잘못하고 있었을 뿐, **우리는 이미 분모를 키우고 있었다.**

다중 경로는 N1로 확인만 하고, **설계는 엔드포인트 위에 세운다.**
