## 1. 문제와 목적

여러 참여자(기관·기기)가 데이터를 넘기지 않고 하나의 AI 를 함께 학습한다
(연합학습). 모두가 한 걸음씩 같이 가는 방식이라 가장 느린 참여자가 전체 속도를
정하고, 시간 안에 못 오면 그 참여자를 빼고 진행하는 것이 관행이다 — 빠진
참여자의 데이터는 반영되지 않는다.

**목적: 아무도 빼지 않으면서, 목표 정확도에 도달하는 총 시간을 최소로.**

총 시간은 두 곱으로 이루어진다:

> 총 시간 = (목표까지 필요한 라운드 수) × (한 라운드에 걸리는 시간) + 전환 비용

라운드 수는 각자 얼마나 학습하느냐(학습량)에 달려 있고, 라운드 시간은 계산·전송
속도와 접속 방법에 달려 있다. 이 두 곱을 함께 줄이는 것이 시스템의 일이다.

## 2. 원칙 네 가지

1. **실측이 유일한 근거** — 모든 결정은 잰 값(계산 시간, 전송 시간, 출구 속도)에서
   나온다. 미리 정한 등급이나 가치 평가를 쓰지 않는다
2. **튜닝 상수 없음** — 쓰는 값은 기준선 배율(보통 참여자의 1.2배까지 기다림)과
   계측 오차 한계(10%) 둘뿐이다. 전자는 정책, 후자는 측정 정밀도의 한계다
3. **아무도 배제하지 않음** — 학습량은 최소 4분의 1 아래로 내리지 않는다
4. **통제권 안에서만** — 우리가 손댈 수 있는 곳은 양 끝(기기의 우리 소프트웨어,
   서버·컨트롤러)뿐이다. 기기와 서버 사이의 망에 기능을 넣지 않는다

## 3. 측정 — 무엇을 어떻게 재나

- **사전 진단** (시작 전 1회, 1초 미만): 기기가 시험 배치 한 번을 돌려 계산
  시간을 재고, 왕복 시간에서 전송 속도를 추정한다. 출구(회선·인터페이스)가 여러
  개면 목록과 각 속도도 보고한다 → 첫 라운드부터 배정이 선다
- **라운드 관측** (매 라운드): 서버가 기기별로 계산 시간, 순수 전송 시간, 주고받은
  바이트를 잰다 — 별도 장치 없이 학습 트래픽 그대로
- **평활**: 관측은 흔들리므로 이동평균(지수이동평균)으로 안정화해 쓴다
- **정규화**: 저장은 전부 "전체 학습량 기준"으로 되돌려 저장한다 — 학습량을 줄인
  기기의 측정도 같은 자로 비교되게

## 4. 수단 사다리와 결정 책임

수단은 세 개이고, **대가가 싼 순서**로 사다리를 이룬다. 이 순서는
규칙으로 정한 것이 아니라, 1절의 목적식을 최소화하면 저절로 나오는 성질이다.

| 순서 | 수단 | 무엇을 하나 | 대가 | 결정 주체 |
|---|---|---|---|---|
| 0 | **분할 전송** | 출구가 2개인 기기가 전송을 나눠 동시에 보냄 | 없음 (자기 출구만 사용) | 기기 로컬 |
| 1 | **접속 지점 이동** | 붐비는 지점의 기기를 한가한 지점으로 | 전환 비용만 (정확도 무손실) | 중앙 + 안정화 |
| 2 | **학습량(폭) 축소** | 느린 기기의 숙제를 한 단계 줄임 | 정확도 (점진적) | 중앙 |

**결정 책임의 분리** — 남에게 영향을 주는 결정(접속 지점·학습량: 공유 자원과
집계에 영향)은 중앙 컨트롤러가 내리고, 자기에게만 영향인 결정(분할 전송)은
기기가 스스로 내린다. 2절의 통제권 원칙이 결정 구조에도 이어진다.

## 5. 수단 ② 학습량(폭) 축소 — 기존 본체

### 5-1. 구조 — 모델 분할과 폭

모델을 앞뒤로 잘라(절단 계층) 기기는 앞부분만 계산하고 중간 결과를 서버로 올린다
(분할 학습). 여기에 **폭**을 더한다: 느린 기기는 각 층에서 앞쪽 일부 채널만
계산한다 (Ordered Dropout — 항상 앞쪽부터). 폭 4분의 1 기기는 계산도 전송도
대략 4분의 1이 된다.

**기여 보존** — 항상 앞쪽부터 쓰기 때문에, 폭을 줄인 기기가 학습한 부분은 전체
모델의 핵심부에 반드시 포함된다. 결합은 중첩 평균: 각 부분을 실제로 학습한
기기들의 값만 평균한다. 빠진 기기가 아니라 **적게 참여한 기기**가 되는 이유다.

### 5-2. 결정 규칙

매 라운드:

1. **예측** — 기기별로 "전체 학습량이면 몇 초 걸릴지"를 실측(이동평균)에서 추정
2. **기준선** — 참여자들의 중앙값 × 1.2. "보통 참여자의 1.2배까지는 기다린다"는
   뜻이다. 고정 문턱값(예: 30초)을 쓰지 않으므로 판이 전체적으로 빠르든 느리든
   기준이 따라 움직인다
3. **조치** — 기준선을 넘는 기기만, 많이 넘는 순서로 학습량을 **한 단계씩** 줄인다
   (4분의 1 아래로는 안 내림). 아무도 안 넘으면 아무것도 하지 않는다
4. **안정** — 한 라운드에 기기당 한 단계까지만 바꾼다 (급격한 출렁임 방지)

중앙값을 기준으로 쓰는 이유: 최솟값 기준은 참여자가 늘수록 기준 자체가 극단으로
쏠려, 균질한 판에서도 모두를 깎게 된다(통계적 성질). 중앙값은 규모가 커져도
"보통 참여자"를 가리킨다.

## 6. 수단 ① 접속 지점 이동

### 6-1. 성립 조건

접속할 곳이 실제로 여러 개일 때만 성립한다: 집계 서버가 여러 지역에 있는 운영
(실재 사례 있음), 또는 기관의 이중화 회선. 접속처가 하나뿐이면 이 수단은 자동으로
비활성이다.

### 6-2. 학습량과 함께 정하는 이유 — 순환 의존

접속 지점 배정의 입력(각 기기가 보낼 양)은 학습량이 정하고, 학습량 결정의
입력(각 기기의 실효 전송 속도)은 접속 지점이 정한다. 서로가 서로의 입력을 정하는
순환 관계라 **따로 풀면 틀린다** — 실제로 따로 돌린 실험에서는 나쁜 배정을
학습량 조절이 깎아서 메꿔버려, 나쁜 배정이 좋아 보이는 역효과가 관측됐다.

그래서 둘을 한 문제로 푼다. 참여자가 적으면 완전탐색으로 최적을 보장하고, 많으면
**교대 최적화**(접속 지점을 고정하고 학습량을 풀고, 학습량을 고정하고 지점을
풀기를 반복 — 이런 결합 문제의 문헌 표준 해법)로 근사한다.

### 6-3. 이동의 판단 — 방어 규칙이 아니라 경제성 모델

이동할지 말지는 비용과 이득의 비교로 정한다:

> **이동한다 ⇔ 라운드당 절감 > 전환 비용 ÷ 남은 라운드 수 + 계측 오차 여유**

- 전환 비용은 측정되는 물리량이다 (재접속 + 지점이 여럿이면 지점 간 모델 동기화)
- 남은 라운드로 상각되므로, 학습 초반에는 작은 이득에도 움직이고 막바지에는
  저절로 신중해진다 — 별도 규칙 없이 모델의 성질로
- 잡음으로 생긴 가짜 이득은 계측 오차 여유(10%)가 거른다. 왕복 이동은 갈 때와
  올 때 비용을 각각 지불하므로 모델이 스스로 벌한다
- 집행 단위는 한 라운드에 한 기기 (이동 자체의 운영 단위)

난수로 만든 환경 수백 개(측정 잡음 주입)에서 진동·과잉 이동·성능 악화 0건을
확인했다. 별도의 다중 라운드 확인 절차는 이 모델 도입으로 제거했다.

### 6-4. 전환 비용

이동에는 비용이 있다: 기기 쪽 재접속은 무시할 수준이지만, 집계 지점이 여럿이면
지점 간에 모델을 맞추는 비용이 있다(측정 결과, 라운드 시간의 상당 부분이 될 수
있음). 이동 판단은 "라운드당 절감 × 남은 라운드 수 > 전환 비용"의 비교이며,
이 비용 항을 실험 설계에 반드시 포함한다.

## 7. 수단 ⓪ 분할 전송 (신규 — 상세는 별도 설계서)

출구가 2개인 기기(이중화 회선, 유선+무선)가 보낼 데이터를 조각으로 잘라 두
연결로 동시에 보낸다. 분배는 "먼저 한가해진 연결이 다음 조각을 가져간다" —
비율 계산 없이 속도 차이가 자동 반영된다. 서버는 조각을 위치대로 재조립해 기존
처리에 전달한다.

- 켜는 조건: 출구 2개 감지 + 예상 이득 > 계측 오차 + 전송량 충분. 조건이 깨지면
  자동으로 단일 전송 복귀 — 켜서 손해 보는 경우가 구조적으로 없다
- 병목이 기기의 단일 회선(갈림길보다 앞)이면 이득이 0이므로 켜지 않는다 —
  병목 위치는 이미 재는 값으로 판별된다
- 부수 효과: 한 출구가 도중에 죽어도 남은 연결로 완료(내결함성)

## 8. 상호작용 — 사다리가 하나의 시스템인 이유

- **분할 전송이 학습량을 보호한다** — 전송이 빨라진 기기는 학습량을 깎일 이유가
  줄어든다
- **접속 지점이 학습량을 보호한다** — 한가한 지점으로 옮기면 학습량을 깎지 않고
  시간을 번다
- 즉 대가 없는 수단(0·1번)이 먼저 소진되고, 그래도 모자랄 때만 대가 있는
  수단(2번)이 쓰인다 — 정확도를 지키는 방향으로 사다리가 작동한다
- 반대 방향도 있다: 학습량이 바뀌면 보낼 양이 바뀌어 지점 배정과 분할의 이득이
  바뀐다 — 그래서 중앙 결정(학습량×지점)은 한 문제로 풀고, 분할은 그 결과를
  입력으로 로컬에서 판단한다

## 9. 한 라운드의 흐름 (통합)

1. (첫 라운드 전) 사전 진단 — 계산·전송 속도, 출구 목록 보고
2. 중앙 결정 — 총 시간 최소화로 **학습량과 접속 지점**을 함께 결정. 기기의 전송
   능력은 출구 합산 속도로 계산. 이동은 경제성 모델(6-3)을 통과할 때만
3. 지시 하달 — 라운드 시작 메시지에 학습량·접속 지점 동봉
4. 기기 — 학습 후, 출구가 2개면 로컬 판단으로 **분할 전송**; 아니면 단일 전송
5. 서버 — (조각이면 재조립 →) 집계 → 기기별·출구별 측정 수집 → 다음 라운드

## 10. 검증 체계

| 층 | 방법 | 상태 |
|---|---|---|
| 규칙 | 단위 테스트 (규칙마다 시험 등록) | 상시 통과 유지 |
| 안정성 | 난수 환경 1000개 + 측정 잡음 주입 — 진동·과잉 이동·악화 없음 | 위반 0 유지 |
| 동작 | 트래픽 제어 테스트베드 (실제 학습 위에서) | 예비 실험 완료 |
| 실기기 | 젯슨 포함 구성 | 계획 |
| 실WAN | KOREN (사전 진단 검증 → 학습량 재현 → 접속 지점 배정) | V100 VM 확보 |

판정 원칙: 실험 전에 판정 기준을 등록하고, 불성립이면 불성립으로 기록한다.
본 실증의 비교 기준은 "사전 진단 1회 후 고정" 방식(많은 연구의 가정)을 포함한다 —
변동이 없는 환경에서는 본 시스템이 그것과 같아지고(개입 0), 변동이 있을 때만
나아야 정직한 비교다.

## 11. 한계와 조건 (총정리)

- 접속 지점 이동: 접속처가 여럿일 때만 · 지점 간 모델 동기화 비용을 계산에 포함
- 분할 전송: 출구 2개가 실재하고 운영체제 라우팅 협조가 있을 때만 · 병목이
  단일 회선이면 무효
- 학습량 축소: 정확도 대가의 정량 평가가 남은 과제 (폭별 정확도 궤적의 전용 실험
  필요 — 현재 재료 부족 확인됨)
- 필요 라운드 수 추정: 이론 상계 없이 실측 적합으로 — 적합 신뢰도가 남은 과제
- 모든 예비 실험 수치는 임의 설정 조건의 것 — 본 실증은 근거 있는 조건으로 재설계
