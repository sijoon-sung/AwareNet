## 0. 두 기둥에서 정확히 무엇을 가져오나

| 출처 | 가져오는 것 | 안 가져오는 것 |

## 1. 시스템 한 장

```
                ┌────────── 컨트롤러 (기존 코드 개조) ──────────┐
 [관측]          │  클라별 실측치 EWMA:                          │
  · 배치별 로그    │   t_cli(p) 연산 · n(p) 전송 · t_srv(p) 서버몫  │
  · 소켓 바이트    │            ↓ 결정 규칙 (§3)                  │
  · Jetson 전력   │   p_k ∈ {0.25, 0.5, 0.75, 1.0}  매 라운드    │
                └──────────────┬───────────────────────────┘
                               ↓ check-in 응답에 p_k 동봉 (표준 구조 그대로)
 [클라이언트 k]  ── 앞단 모델(폭 p_k)로 순전파 ──▶ A_k 활성값 (p_k 폭 슬라이스) ──▶
 [서버]         ── 뒷단 모델(폭 p_k)로 순·역전파 ──▶ 그래디언트 반환 ──▶ 클라 역전파
                 ... 배치마다 반복 (SFL의 정체성 = 매 배치 실전송) ...
 [라운드 끝]     클라 앞단 가중치 → Fed 서버 → 중첩 폭 집계(FjORD식) → 재배포
```

- **관측·결정·집행 3평면 구조 유지.** 집행 손잡이만 회선몫 → 폭 p. 이것이 방향정리 결정 1의 실체.
- 배분층과의 결정적 차이 — 회선몫은 **고정 총량을 나누는** 일이라 work-conserving 앞에서 죽었다.
  폭 p는 **수요 자체(연산량·바이트)를 바꾼다.** 0번 문서 ⓑ(근원 제어)에 해당 — 같은 함정에 빠지지 않는다.

## 2. 노브의 물리 — p 하나가 세 군데를 동시에 민다

| 항 | p에 어떻게 반응하나 | 근거 꼬리표 |
|---|---|---|
| 클라 연산 t_cli | **실측 p^1.04~1.35** (절단1→3). 이론 FLOPs는 p²이지만 벽시계는 메모리·층당 고정비에 묶여 훨씬 완만하다 | **[실측완료 G0 2026-08-25]** — p²는 폐기. 적대검토 T4가 맞았다 |
| 전송 바이트 | A_k 채널 수 = ⌈p·C⌉ → **~p 비례** | **[설계확정]** — 우리 구현은 슬라이스 전송(제로패딩 전송 금지). G0에서 소켓 바이트로 검증 |
| 서버 몫 t_srv | 같은 이유로 p²보다 완만 (위 지수에 포함 측정) | [실측완료 G0] |

활성값 크기 어림 (ResNet-18 / CIFAR-10 / batch 32, fp32) — **[추정→G0 실측으로 교체]**:

| 절단 위치 | A_k 크기/배치 | 50Mbps에서 왕복(활성+그래디언트) |
|---|---|---|
| layer1 뒤 (64ch·32²) | ~8.4MB | ~2.7초 |
| layer2 뒤 (128ch·16²) | ~4.2MB | ~1.3초 |
| layer3 뒤 (256ch·8²) | ~2.1MB | ~0.7초 |

**G0 실측이 이 산수를 확인했다** (netem 24구성): 통신 지분 56~97%,
운영점(RTT 10~30ms · 20~50Mbps)에서 68~94%. 통신이 배치 시간을 지배한다 —
그래서 이 과제가 네트워크 과제다. 단 용량 제한은 **엣지 업링크의 재현**이라고 명시한다(§12-1 C1).

- **절단점은 고정한다** (G0에서 3후보 중 1개 선정 후 전 실험 동일). 이유: AdaptSFL과의 차별선이자 변인 통제. 절단점 민감도는 부록 1실험.
- 활성값 압축(양자화 등)은 **넣지 않는다** — 직교 축이고, 넣는 순간 무엇이 이득을 냈는지 흐려진다.

**G0가 바꾼 것 — p는 연산 노브가 아니라 통신 노브다.**
바이트는 p에 정확히 비례하는데(A2 검증) 연산은 p^1.2 수준으로만 준다.
따라서 p를 줄여 얻는 시간의 대부분은 **전송 바이트 감소**에서 온다.
이는 과제의 네트워크 정체성을 **약화가 아니라 강화**한다 — 손잡이가 실제로 미는 것이 망이다.
동시에 **컨트롤러는 이론 지수로 외삽하면 안 된다**: p²를 가정하면 좁은 폭의 이득을
체계적으로 과대평가한다(G1에서 예측이 일관되게 -8~-23% 낙관적). 사다리 각 단을
**기기마다 실측**하는 프로파일 라운드(§3)가 선택이 아니라 필수다.

## 3. 컨트롤러 결정 규칙 — ABR 그대로 옮긴다

측정기·사다리·전환 규칙. 전부 사전 등록.

```
프로파일 라운드 (최초 1회):
  각 클라가 사다리 전 단계에서 배치 몇 개씩 실행 → b_k(p) 초기표

매 라운드 r 시작:
  b̂_k(p) ← 항별 EWMA 갱신 (직전 라운드 배치 로그 — 능동 프로브 없음, 전부 학습 트래픽에서)
  T̂_k(p) = B_k · b̂_k(p) + w(p)/bw_k          # B_k = 로컬 배치 수, w(p) = 가중치 동기 바이트
  D ← α · min_k T̂_k(1.0)                      # 기준: 가장 빠른 클라의 전폭 예상시간 × α (α=1.2 시작)
  p_k ← max{ p ∈ 사다리 : T̂_k(p) ≤ D },  하한 p_min = 0.25
  히스테리시스: 라운드당 최대 한 칸 이동
```

- **D의 의미가 곧 정책이다**: "가장 빠른 참가자를 α배 이상 기다리게 하지 않는 선에서, 각자 최대 폭." α는 실험 축(1.1/1.2/1.5 스윕).
- **p_min이 '배제 없는 학습'의 새 형태다.** 옛 커버리지 하드 보장(0회 0대)이 폭 하한 보장으로 이사한다 — 아무리 느려도 0.25폭으로는 반드시 참여하고, FjORD 집계상 그 갱신은 앞쪽 채널에 반드시 반영된다.
- 능동 측정 없음 — ABR이 재생 버퍼로 재듯, 우리는 **학습 트래픽 자체가 측정 신호다** (in-band). 제어 메시지는 기존 VNI 100 채널.

## 4. 정직한 주장 사다리 — 무엇까지 주장할 수 있나

여기가 이번 재설계에서 가장 중요한 절이다. **KOREN 같은 연구망은 조용하고, RTT도 안정적일 가능성이 높다.** "동적이 정적을 이긴다"는 변동이 있어야만 참인 명제다. 그래서 주장을 3단으로 나눈다:

| 단 | 주장 | 성립 조건 | 검증 |
|---|---|---|---|
| 1단 **자동 배정** | 손으로 p_k표를 짜지 않아도(HSF는 사전 정의), 실측만으로 오라클 정적 배정의 ≥95% 성능 | 무조건 성립 가능 | G2 |
| 2단 **교란 대응** | 링크 절반 축소·배경 트래픽 주입·전력모드 강등 시 p가 따라 움직여 makespan 회복 | **교란은 우리가 주입** — 그렇다고 명시 | G2/G4, 개입→반응 폐루프 데모 |
| 3단 상시 변동 대응 | 실환경의 자연 변동에서 정적 대비 이득 | KOREN·Jetson에서 변동이 **실측되어야만** | G3/G4에서 변동 먼저 측정, 없으면 **주장 안 함** |

1단만 서도 과제는 선다("측정 기반 자동화"). 2단이 데모의 심장이다. 3단은 데이터가 허락할 때만.

## 5. 실험 게이트 — 순서대로, 킬 기준 먼저

| 게이트 | 질문 | 셋업 | 사전 등록 판정 |
|---|---|---|---|
| **G0** (지금, 로컬) | 배치 시간에서 통신 지분이 실재하나 + 바이트∝p 확인 | 컨테이너 2개(클라/서버), ResNet-18/CIFAR-10, 절단 3후보 × netem RTT{2,10,30,60ms} × bw{20,50,100Mbps} × p{0.25,0.5,1.0}. 소켓 바이트 직접 계수 | 운영점(실측한 KOREN급 RTT·bw)에서 통신 지분 **<10% → 이 방향 폐기**. 10~30% → 보류 후 재협의. >30% → 진행 |
| **G1** | T̂_k(p) 예측이 맞나 | G0 리그에서 예측 vs 실측 | 오차 >25% → 결정 규칙 재설계 (진행은 하되 규칙 교체) |
| **G2** | 컨트롤러가 이기나 | 컨테이너 8~16 + cgroup·netem 이질성 3프로파일(정적/계단교란/랜덤워크) × 기준선 4종 | 1단: 오라클 정적의 TTA ≥95% 달성. 2단: 교란 프로파일에서 정적 대비 TTA 단축 (폭은 실측 후 등록) |
| **G3** | 실기기에서 재현되나 | Jetson 보유분(전력모드 = 자연 이질성) + PC | G2 결론 방향 유지 여부 |
| **G4** | 실광역망에서 서나 | KOREN 판교–대전 분리, iperf 교란 주입, 폐루프 데모 | 교란→p 이동→makespan 회복이 대시보드에서 수 초 내 관측 |

**기준선 (전부 동일 시드·동일 리그):**
- B1 균등 전폭 SFL (바닐라 SplitFed) — straggler에 묶이는 현행
- B2 **오라클 정적 p** — 사전 전체 프로파일로 최적 정적 배정 (HSF의 이상형, 가장 억센 상대)
- B3 무작위 p (평균 폭 동일) — "측정이 이긴 건가, 그냥 작아서 이긴 건가" 분리
- B4 AdaptSFL — **구현하지 않는다.** 문헌 수치로 프레이밍 대조만 (그쪽 절단점·시뮬 / 우리 폭·실장비)

**지표:** TTA(주지표) · 라운드 makespan과 빠른 클라 대기율 · 라운드당 총 바이트 · **클라별 최종 정확도(p_min 클라가 얼마나 손해 보나 — 배제 없음의 검증)** · p 시계열(진동 여부) · 컨트롤러 결정 지연·제어 트래픽량.

## 6. 스케일 정직성 — 100노드 문제

SFL은 매 배치 서버 연산이 들어간다. **N개 클라의 뒷단 연산이 전부 서버 GPU에 쌓인다** — 100노드 SFL 실학습은 우리 장비에서 비현실적이고, 억지로 돌리면 서버 GPU 대기가 병목을 오염시킨다.

- **주 실험 N = 8~16** (컨테이너) + Jetson 보유분. 이 숫자를 보고서에 그대로 쓴다 — cross-silo(기관 연합) 규모로는 오히려 표준적이다 [문헌: NVFLARE 배치].
- **100노드 리그의 새 역할 둘**: ① 컨트롤러 확장성 — 실학습 없이 재생 프로파일로 결정 루프만 100클라 구동, 결정 지연 실측 (SmartFLow가 50클라 400ms로 자인한 그 지점) ② (옵션) 분할 없는 순수 FjORD 폭-FL 모드 — 100노드 유지 명분이 필요할 때만.

## 7. 구현 경로

| 선택지 | 판정 |
|---|---|
| Flower 위에 SFL | **부적합** — 라운드 단위 프레임워크에 매 배치 왕복을 끼우면 싸움만 남 |
| **자체 PyTorch + 기존 gRPC 뼈대** | **채택.** 배치 루프가 곧 request/response. 이미 있는 소켓·컨테이너·측정 코드 재사용 |
| HSF 저자 코드 | 류지현 저자 메일에 **코드 공유 요청 한 줄 추가** — 받으면 대조 검증용, 못 받아도 진행 |

구현 순서: ① OD 적용 ResNet-18 앞/뒷단 분리 + 슬라이스 전송 (G0 겸용) → ② 배치 로그·소켓 바이트 계측 → ③ FjORD식 중첩 집계 → ④ 컨트롤러 결정 루프 연결 → ⑤ Grafana 패널(개입→반응).

- 절단점: G0 결과로 1개 확정 (통신 지분 있는 표준적 위치, 체리피킹 방지 위해 HSF/문헌 관행 위치 우선)

- α·EWMA 계수·히스테리시스 폭: G1에서 스윕 후 등록

## 10. 망 개입 재진입 규칙 — "수요만 조절하나"에 대한 답

**죽은 것 (재확인):** 학습 플로우끼리 공유 회선 몫 재분배. work-conserving 하에서
전송해야 할 총 바이트 / 회선 용량이 완료 시각의 하한이고, 재분배는 하한을 못 깬다.
어떤 형태로 부활해도 같은 벽 — 이것이 배분층의 사인(死因)이다.
**폭 p가 다른 이유: 파이를 자르는 게 아니라 총 바이트(수요) 자체를 줄여 하한을 낮춘다.**

**망 개입 3관문** — 망에 손대는 기능은 셋을 전부 통과해야 켠다. 기본값 off:

| 관문 | 내용 | 판정 주체 |
|---|---|---|
| ① 실재 | 그 공유 지점이 우리 배치에 실재함을 실측 | G0/G2 계측 |
| ② 지속 | 경합이 지속됨을 실측 — 도착 수요 > 용량 (ρ>1) | G2 |
| ③ 논증 | "총량 불변" 원리를 피해 가는 논증 성립 | 설계 문서에 서면으로 |

**관문을 통과하는/심사 중인 노브:**

| 노브 | 3관문 판정 | 상태 |
|---|---|---|
| 관측 (링크·큐·기기 실측 → p 입력) | 집행이 아니라 감각 — 관문 대상 아님 | **기본 탑재** |
| **지키기** — 외부(비학습) 트래픽 대비 학습 클래스 HTB 보장 | ③ 통과: 빼앗는 대상이 학습 밖(제로섬 아님). ①②는 교란 주입 실험에서 자명 | **탑재** — 2단 응답의 1차 방어 |
| ~~**줄 세우기**~~ — 서버 인입 앞 수신자 주도 허가(토큰) | **①통과 ②실패 ③실패** — 실측으로 사망 (아래) | **폐기.** 코드는 `--tokens`로 남기되 기본 off, 재현용 |

### 줄 세우기 사망 기록 (2026-08-25 실측, N=8×3회 반복)

| 관문 | 결과 |
|---|---|
| ① 실재 | **통과** — 경합은 실재한다. N=1→8에서 배치당 통신시간 5.57배 (서버 연산은 평평, GPU 대기 ~0) → **A7 깨짐 확정** |
| ② 지속·붕괴 | **실패** — 총 굿풋이 18→37Mbps로 오르다 회선의 74%에서 평평. **줄지 않는다 = 붕괴 없음.** WAN에 incast 3전제가 없다는 문헌과 일치 |
| ③ 논증 | **실패** — 토큰 admission(Homa 계열, SFL 선례 없음)을 구현해 실측: 벽시계·굿풋 모두 3회 반복 범위가 겹쳐 **효과 미확인**. 공평비만 1.76→1.20으로 개선됐으나 **내려서 맞춘 것**: 최저속 5.348→5.359초(변화 없음), 최속 3.052→4.640초(52% 느려짐) |

**사인(死因)이 배분층과 똑같다.** admission은 시간 축의 재분배이고,
붕괴가 없는 회선에서 재분배는 **work-conserving 하한을 못 깬다.**
makespan은 최저속이 정하는데 토큰은 최저속을 건드리지 못했다.

> **이번 재설계로 얻은 원리 한 줄:**
> 붕괴가 없는 공유 자원에서, 참가자들 사이의 재분배는 — 공간(대역)이든 시간(순서)이든 —
> 완료 시각을 당기지 못한다. 당기려면 **총 수요를 줄이거나(폭 p), 바깥에서 지켜야(HTB 보호) 한다.**

이 판정은 **부정적 결과이자 산출물이다.** SFL에 수신자 주도 admission을 적용한 선례가 없고
(조사 2026-08), "TCP 공정 공유로 충분하다"는 실측 답 자체가 문헌의 빈자리를 메운다.

**용어 규율:** 서버 인입 현상은 'incast'가 아니라 **"서버 회선 포화"**로 부른다 —
incast 붕괴는 µs-RTT·얕은 버퍼·동기 플로우의 DC 3전제가 필요하고 WAN에는 부재 (3번 문서 §2, 조사 2026-08).

**2단 응답 (교란 대응의 새 구조):** 교란 발생 → ① 망이 막을 수 있으면 망이 먼저(HTB 보장) →
② 잔여 열화만 학습이 양보(p 하향). G2/G4에서 3비교: 보호 없이 p만 / 보호만 / 둘 다.
이것이 개입→반응 데모의 각본이고, "망을 버리지 않았다"의 실물 증거다.

**개념 방어선:** p 조절 자체가 혼잡 제어를 전송계층에서 응용계층으로 올린 것 —
패킷을 무작위로 버리는 대신 덜 중요한 채널을 애초에 안 보낸다. ABR과 같은 계보로, 수요 조절도 망 제어다.

## 12-1. 적대 검토 반영 (2026-08-25) — 수용한 보수 조치

외부 시점 적대 검토(전 문서 대상)에서 나온 공격 중 수용분. **이번 주 조건 3개**부터:

| # | 조치 | 내용 |
|---|---|---|
| C1 | **운영점 정당화 문서화** | "연구망을 조여놓고 WAN 병목이라 부른다" 방어 — **RTT는 진짜(KOREN 실측), 용량 제한은 재현(문헌의 엣지 업링크 분포: 5G 실측 26.8%가 업링크 경합·가정용 비대칭 회선)**이라고 보고서에 명시. G0 통과 조건에 **N>1 지분 재분해**(t_lock 이동 확인) 추가 |
| C2 | ~~멘토 랩 선점 확인 최우선~~ → **우선순위 아님 (팀 판단 2026-08-25)** | 팀 결정: 멘토 관계·선점은 리스크로 취급하지 않는다. 우선순위는 **기술 검증(프로젝트가 정확하게 작동하는가)** — sfl/verify.py 5종(분할≡단일체·학습 성립·집계 산술·netem 충실도·파이프라인)이 그 실행. 선점 시 대응 경로(1·2층 무게 이동)는 기록으로만 유지 |
| C3 | **희생 순서 서면 확정** | 일정 적자 시 버리는 순서: ① LoRA rank 보조 → ② 100노드 결정루프 → ③ 토큰 관문 실측 → ④ 파이프라인 정확도 검증. **G4 최소 정의 = 2사이트 + 교란 1종 + 폐루프 1개.** G2 최소 = 이질성 2프로파일 × 기준선 3종(B1·B2·ours) 필수, 나머지 여유분 |

기술 보수 (설계 반영):

| # | 공격 | 수용 조치 |
|---|---|---|
| T1 | "파이프라인 켜면 되잖아" — 자기 실측이 통신 서사를 벰 | **ours는 pipeline-on이 기본.** p의 1차 표적을 재명시: 연산(~p², Jetson)과 대역 제한 구간(t_up>t_cli이면 파이프라인 무력). G0 판정도 pipeline-on 지분으로 병기 |
| T2 | T̂가 결합계(공유 GPU·인입)를 독립계로 모델링 | **t_lock을 T̂의 공유항으로 승격** (A7 확장). 항별 EWMA에 p² 곡선 적합 병용 — 낡은 사다리 단 문제 완화 |
| T3 | 컨트롤러에 정확도 항 부재 — 좁은 폭은 라운드 수를 부풀림 | 오라클을 **TTA-오라클**(라운드시간 아닌 목표도달시간 최소)로 정의. G2 산출물에 **p-정확도 곡선** 추가(ABR의 rate-quality 곡선 완성) |
| T4 | ~p²는 FLOPs지 벽시계가 아님 — GPU에서 사다리 하단 무의미 가능 | G0에서 기기별 t(p) 곡선 실측 → **시간상 평평한 단은 사다리에서 제거** (시간 기준 축소 규칙) |
| T5 | 2단 응답은 자작극 구조 | 자연 교란 1종 추가: **Jetson 열 스로틀링·전력모드는 무주입 실재 변동** — 최소 1시나리오는 이걸로 |
