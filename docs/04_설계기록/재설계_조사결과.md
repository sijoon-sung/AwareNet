## A. 문제 실재성 — 조건부로 실재한다. 조건을 명시해야 기여가 선다

**성립 조건 (셋이 겹칠 때):**
1. **동기 cohort + 마감 폐기가 유지되는 프로토콜** — 구글 130% 초과선발·라운드당 6~10% 드롭, REFL이 명시한 마감 폐기·라운드 재시도, SAFA류는 학습자 계산의 ~80%를 낭비
2. **업데이트가 크거나 인입이 좁을 때** — 수백 노드×VGG16이면 에폭당 ≥50GB(FedCH), cross-silo에서 orchestrator가 병목(Marfoq NeurIPS'20), **실 5G 실측에선 2.9MB 모델·6노드로도 동시 업로드 경합 — 업링크가 라운드의 26.8%, 실험의 30%에서 경합형 straggler** (arXiv 2025)
3. **SecAgg·DP·커버리지 요구로 비동기로 도망갈 수 없을 때**

**불성립 조건 (정직하게):**
- cross-device 소형 모델(Gboard 1.4MB) + 유휴·충전·Wi-Fi 게이팅 → 인입 경합 사실상 없음
- 비동기 전환이 마감 절벽 자체를 제거 — **Meta Papaya는 프로덕션을 비동기로 전환해 5×** , FedBuff 3.3×
- 압축이 업링크를 100~1000× 절감 (Konečný 2016)
- 실배치 낙오의 주원인은 인입 경합이 아니라 **단말 상태 변화·참여 편향** (136K 스마트폰 실측, Flash WWW'21)

**→ 정직한 주장 형태:** ~~"서버 인입이 FL 낙오의 주범"~~ 이 아니라
**"대형 업데이트 × 제한 인입(45Mbps급) × 동기 cohort(SecAgg·커버리지 요구) 조건에서, 마감 탈락과 자원 낭비를 수신자 주도 스케줄로 줄인다."**
그리고 **바로 그 조건의 실측 문헌이 얇다** — FL 인입 incast를 실측한 공개 연구가 없다 (UniFL은 NS3 시뮬, LTP는 데이터센터). **우리 100노드+OVS 체계로 처음 낼 수 있다.**

## B. Novelty 지도 — 개별 메커니즘은 전부 선점, 빈자리는 '3축 결합 + 실측'

| 선점된 것 | 대표 | 하는 범위 |
|---|---|---|
| 자원 인지 선발 | FedCS, Oort, PyramidFL, REFL | **선발까지만** |
| SDN 연계 선발 | **Mahmod 계열 (WCNC'24 → ComMag'25)** — 최근접 위협 | 망 부하·지연을 **선발에만** 반영, 테스트베드 있음 |
| 도착 시각 제어 | FedCompass | 수단이 연산량(로컬 스텝 수)이지 망이 아님 |
| 동기/비동기 혼합 | FedAT(티어), SAFA, FedBuff | 티어·버퍼 단위, **노드별 모드 결정 아님** |
| 마감 적응 | FedBalancer | 라운드 종료 시각이지 업로드 시작 스케줄 아님 |
| 업로드 타이밍 | 구글 pace steering | **무작위** — 가치·마감 무관 |

**미점유로 판정된 자리 (B·C 갈래 공통):**
> **유선 SDN 텔레메트리를 입력으로, 서버 인입 앞에서 ① 선발 ② 업로드 시각(admission) ③ 노드별 동기/비동기 모드를 한 제어 루프에서 결정하고, ④ 커버리지를 하드 보장하는 오케스트레이터 — 를 실측 테스트베드에서 실증**

커버리지 하드 보장 자체도 미점유다 — REFL은 가용성 편향이 non-IID 정확도를 10pt 깎는 걸 **관찰만** 했고, 보장 메커니즘을 제시한 시스템은 없다. **우리 선별층이 이미 그 답이다.**

## C. 자체 SDN — 새 에뮬레이터 불필요. 지금 OVS에 진짜 컨트롤러를 붙이면 된다

- 우리 구성(도커 100노드 + OVS/VXLAN + 다중 VM)은 **Containernet + MaxiNet이 하는 일을 이미 수작업으로 해놓은 상태**
- 최소 추가 경로: **기존 OVS 브리지를 실제 OpenFlow 컨트롤러에 연결**
  - 커스텀 스케줄링 로직 → **OS-Ken** (Ryu 후계 — Ryu는 개발 중단, 공식 문서가 OS-Ken을 안내)
  - 정책·슬라이싱 수준 → **Faucet** (프로덕션급 경량, pip/Docker)
  - ONOS는 우리 규모엔 과잉 (VM 3대급)
- 이러면 제어평면(OpenFlow·컨트롤러 코드·OVS 데이터패스)이 **전부 실물** — 주장 가능 범위는 "실 SDN 제어평면 + 에뮬레이트된 링크(HTB/netem 45Mbps급)". KOREN 실WAN 검증은 아니라고 명시
- KOREN 컨트롤러 대안: **KREONET-S** (ONOS 기반 VDN, 국내 연구망 실운영 SDN) 문의 가치 있음
- ⚠ 선행 존재: **SmartFLow(2025)** — ONOS+OpenFlow로 FL 트래픽 **경로 재배정**, 동기화 시간 최대 47% 개선. 'SDN으로 FL 제어' 자체는 신규성 없음. 단 **admission·모드 결정·커버리지는 안 했고**, 50클라이언트에서 컨트롤러 연산 400ms 피크로 확장성 한계 자인 — **100노드 제어 오버헤드 실측 자체가 기여**
- FLEET·MininetFed(FL 에뮬 테스트베드 최신작들)에 **실제 SDN 컨트롤러를 통합한 공개 사례 없음** — 빈자리

## D. 보여주기 — 대시보드는 상용구, '개입→반응' 폐루프가 답

Grafana/Prometheus 대시보드 자체는 NVFLARE·Flower·CoLExT가 기본 제공 — 차별화 안 됨.
학회 데모에서 먹히는 것은 **지표 나열이 아니라 인과의 라이브 시연**. 우선순위:

1. **개입→반응 폐루프** — 심사석에서 버튼 하나(대역 절반 축소·노드 강제 이탈·배경 트래픽 주입) → 스케줄러 재배분 결정과 커버리지/마감 지표 변화가 **수 초 내** 대시보드 반영
2. **before/after 2패널 동시 재생** — 같은 시드·같은 트레이스에서 균등분배 vs 우리 스케줄러, 마감위반·커버리지 카운터가 실시간으로 벌어지는 화면
3. **의사결정 로그 패널** — 어떤 노드를 왜(가치·마감 여유·커버리지 기여) 받았는지 실시간 표출 — 하드 보장을 눈으로 증명
4. **Jetson 체감 데모** — 브라우저 캔버스 손글씨를 관객이 직접 그려 추론, 라운드마다 정확도 상승 체감
5. **원클릭 재현 아티팩트** — `docker-compose up` 한 번으로 100노드 기동→실험→그래프 (NSDI Artifacts 배지 기준)
6. SIGCOMM/INFOCOM 데모 초록 형식 2페이지 + 백업 영상

## E. P2P — 주 설계로는 리스크, 확장 축으로

- 이론상 서버 병목 제거 (D-PSGD, NIPS'17). 망 용량 기반 토폴로지 설계는 **Marfoq(NeurIPS'20) → MobiHoc'24 → ICCCN'25로 이미 활발히 점유**
- 단 전부 **정적/간헐 재계산** 또는 언더레이 비협조(토모그래피 추정) — **SDN이 언더레이를 직접 알고 매 라운드 재구성 + 커버리지 하드 보장**은 미점유
- 반대 증거: 희소 토폴로지의 스펙트럴 갭이 수렴·일반화를 악화(ICML'20/'22), gossip은 churn에 취약, 실장비 DFL 실증은 **4대 데모 수준**이 최전선
- **판정: 100노드 단일 도메인에선 수신자 주도 스타 스케줄링이 같은 문제를 더 적은 리스크로 푼다. DFL은 비교 축/확장 실험으로**

## 종합 — 설계 후보 하나로 수렴한다

```
                    ┌─ SDN 컨트롤러 (OS-Ken/Faucet + 기존 OVS) ─┐
   텔레메트리 →      │  ① 선발 (선별층 — 커버리지 하드 보장, 존속)  │
   (링크 부하·큐·    │  ② 업로드 admission — 인입 앞, 가치·마감     │ → 집행 (OVS/HTB — 존속)
    기기 연산 실측)   │  ③ 노드별 모드 — 동기 / 버퍼 비동기(FedBuff류)│
                    └────────────────────────────────────────┘
   확장 축: ④ 노드별 서브모델 크기 (HeteroSplitFed — 멘토 랩) · ⑤ SDN 라운드별 P2P 토폴로지 (E)
```

- **주장 조건 명시**: 대형 업데이트 × 제한 인입 × 동기 cohort(SecAgg·커버리지 요구로 비동기 불가). 이 조건 밖에서는 개입하지 않음(무해성 장치 존속)
- **차별점 방어선**: Mahmod(선발만) · SmartFLow(경로만) · FedCompass(연산량만) · FedAT(티어만) · pace steering(무작위) — 전부 한 축씩만. 우리는 결합 + 커버리지 보장 + 실측
- **첫 실험은 설계가 아니라 N1**: 제한 인입에서 실 gRPC FL 트래픽의 incast 실측 — 세계에 없는 데이터이고, 이게 나와야 나머지가 선다
