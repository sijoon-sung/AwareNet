# 정식화와 결합 시스템 설계 — 인지·계획·집행 (2026-09-07)

> 사용자 지시(2026-09-07): "멀티패스도 실험 · 모든 걸 합하기 전에 정식화와 합치는 시스템(코드)을 설계 · 망·기기 능력을 인지하는 코드는 별도로".
> 이 문서는 (1) 문제를 수식으로 적고, (2) 어떻게 푸는지, (3) 코드를 세 층(인지 sense / 계획 plan / 집행 act)으로 어떻게 나누는지 정한다.
> 근거가 된 실측: 두 갈래(연산→폭 −26/−33%, 망→경로 총비용 −29/−27%), 폭별 정확도 대가(400R: 0.5~0.75 대가 없음, 0.25 −2~5%p), 분할 전송 단독(−26%).

## 0. 한 문장

**매 라운드, 기기마다 "얼마나 학습할지(폭 w_k)"와 "어느 엣지들로 보낼지(열린 경로 집합 S_k)"를 정한다. 경로는 대가가 없으니 총 비용을 줄이는 데 먼저 쓰고, 폭은 대가가 있으니 남은 꼬리(기준선을 넘는 기기)에만 쓴다.**

## 1. 기호

| 기호 | 뜻 | 어디서 오나 (인지 층) |
|---|---|---|
| K, R | 기기 집합, 경로(엣지) 집합 | 조건 |
| C_k | 기기 k 의 전폭 배치당 연산 시간 (초) | 사전 진단 1회, **고정** |
| γ_k | 연산의 폭 지수 (기본 1.2, 실측 1.04~1.35) | 사전 진단/적합 |
| a_k | 접속 회선 상한 (bit/s) | **단독 업로드 프로브**(사전 진단 2단계) — 지금은 오라클 |
| c_r | 경로 r 의 공유 용량 (bit/s) | 조건 + 관측 창 최대값 |
| B_k | 전폭 배치당 왕복 바이트 | 사전 진단, 폭에 비례(B_k·w) — 실측 A2 |
| n1_k | 관측된 배치당 전송 시간(최근 창 최선값) | 라운드 관측 |
| δ | 경로 전환 비용(초) | 실측 0.045 (재접속) |
| w_k ∈ L | 폭, 사다리 L (기본 {0.5,0.75,1.0}, 0.25 는 마지막 수단) | 결정 |
| S_k ⊆ R, S_k≠∅ | 열린 경로 집합. \|S_k\|=1 엣지 선택, ≥2 분할 전송 | 결정 |

분할 비율 x_{k,r} 은 **결정하지 않는다.** 기기의 "먼저 한가해진 연결이 다음 조각을 가져간다" 규칙이 실측으로 정한다(설계_멀티패스 §3-3). 모형에서는 그 결과를 물 채우기 균형해로 예측한다.

## 2. 시간 모형

경로 r 에서 기기 k 가 받는 몫 rate_{k,r} 는 **물 채우기(water-filling)** 의 고정점이다:
- 경로 r 의 용량 c_r 을 r 을 연 기기들이 **균등**하게 나눈다 (TCP 흐름 공정성 — 리그 자가 검사 B 가 확인).
- 단, 기기 k 의 모든 경로 몫의 합은 접속 상한을 넘지 못한다: Σ_r rate_{k,r} ≤ a_k. 상한에 닿은 기기의 남는 몫은 같은 경로의 나머지가 균등하게 가져간다.
- 두 조건을 만족하는 고정점을 반복(≤20회)으로 구한다 (`plan.water_fill`). 경로 2개·기기 8대에서 1ms 미만.

기기의 배치당 시간:
    t_k(w, S) = C_k · w_k^γ_k + B_k · w_k / Σ_{r∈S_k} rate_{k,r}(S)     (+ δ, 이번 라운드에 경로가 바뀌면)
옮기지 않은 기기는 모형과 관측 중 큰 쪽: net_k = max(모형, n1_k · w_k) — 모형이 놓치는 실제 느림을 잡는다(설계기록 §9).
라운드 시간 = batches × max_k t_k, 총 비용 = Σ_k t_k.

## 3. 목적과 제약 — 왜 하나의 목적함수로 합치지 않나

두 손잡이의 대가가 다르다. 경로·분할은 정확도 대가 0, 폭은 대가가 있다(0.25 만 −2~5%p; 0.5~0.75 는 400R 예산에서 대가 없음 — rw_long). 대가가 다른 것을 한 목적함수에 계수로 넣으면 그 계수가 근거 없는 상수가 된다(구판 joint 의 makespan÷평균폭이 그것이었다). 그래서 **사전순(lexicographic)** 으로 푼다:

    (P) 망 층:   min_S  Σ_k t_k(w, S)                 총 비용 (사용자 지시 2026-09-06)
                 s.t.  이동은 이득 > 계측 불확도(10%)·현재값 + δ/남은 배치 일 때만, 라운드당 ≤ m 대
    (W) 기기 층: 각 k:  w_k = max{ w ∈ L : t_k(w, S) ≤ D },   D = α · median_k t_k(1, S)
                 s.t.  라운드당 한 칸, 폭을 올리는 복귀는 2라운드 연속 확인, 바닥 0.5 (0.25 는 마지막 수단)

(W) 는 "라운드 시간을 중앙값의 α 배로 묶는다"는 제약의 기기별 그리디 해다. (P) 가 먼저 총 비용을 줄이면 중앙값이 내려가고 D 가 내려가므로 (W) 가 더 많이 깎을 수도, 혼잡이 풀려 덜 깎을 수도 있다 — 그래서 P→W→P 로 한 번 더 돈다(§4).

이것이 두 손잡이의 **시너지 정의**다: 둘다가 **총비용과 라운드 시간 둘 다**에서 각 단독보다 낫고, 기기마다 병목에 맞는 손잡이가 간다(연산→폭, 혼잡→경로/분할, 접속 병목→폭). 시뮬(test_plan2 ⑤): 둘다 총비용 9.7 < 경로만 14.0 < 폭만 18.8, 라운드 3.4 < 5.2 < 6.9.
주의 — 처음 가설 "경로가 혼잡을 풀면 연산 낙오자의 폭을 덜 깎는다"는 **틀렸다**(2026-09-07 시험). 경로가 풀려 모두의 망 시간이 줄면 기준선(중앙값)도 내려가 연산 낙오자가 더 드러나고 더 깎인다. 그것이 상대 기준선의 정의다. "덜 깎는다"는 접속 병목 기기가 몫을 더 받게 될 때만 성립한다. 폭이 바이트를 줄여 경로 부하를 덜어 주는 방향(전환 비용 절감)은 유효.

## 4. 풀이

1. **P 단계**: S 를 열거한다. 경로 2개면 기기당 {1},{2},{1,2} — 3^N (N=8: 6561, 각 물 채우기 20회 → 0.1초). N>8 이면 탐욕(큰 기기부터, LPT 근사비 ≤ 2m/(m+1)). 문턱·이동 상한·재확인은 지금 규칙 그대로. 분할({1,2})은 전송이 조각 2개 이상일 때만 후보.
2. **W 단계**: D 규칙, 관측 max, 히스테리시스.
3. **P 재평가**: W 가 바이트를 바꿨으면 S 를 한 번 더 열거. 격자가 유한하고 총 비용이 단조 감소라 2회면 멈춘다.
4. 출력: (w, S, 예측 t, 사유). 사유는 사람이 읽는 문장 — 기기마다 "왜 이 손잡이인가".

   사전 진단 ① 연산 1배치

경계 규칙: **sense 는 plan 을 모르고, plan 은 소켓을 모르고, act 는 규칙을 모른다.** `MultiKnobController` 는 셋을 잇는 얇은 층으로 줄인다(기존 `plan_two_stage` 는 plan.py 를 부르는 껍데기가 된다).

시험: sense — 프로브 값이 리그 자가 검사 값과 ±20% 안 / plan — 물 채우기 해석해(2기기·2경로)·불변식(무진동·상한·무개입)·혼합 집단·시너지 방향 / act — 팔 규약(폭만은 안 옮김 등), 조각 재조립 바이트 일치.

## 6. 능력 인지(sense) — 무엇을 어떻게 재나

| 능력 | 측정 | 언제 | 고정/갱신 |
|---|---|---|---|
| 연산 C_k | 전폭 1배치 순·역전파 시간 (PROBE, 있음) | 시작 전 1회 | 고정 |
| 접속 회선 a_k | **단독 업로드**: 서버가 기기를 하나씩 불러 4MB 를 올리게 하고 나머지는 쉰다 (SOLO/SOLORES 메시지, 신규). rate = min(a_k, 그 경로 용량). 경로 용량이 접속보다 크면 a_k 가 잡힌다 | 시작 전, 기기 수 × 약 1초 | 고정 (회선 바뀌면 재측정) |
| 경로 용량 c_r | 조건값 + 라운드 관측(같은 경로 기기들의 바이트 합 / 최대 전송 시간)의 창 최대값 | 매 라운드 | 갱신 |
| 왕복 지연 | 연결 시간 | 사전 진단 | 고정 |
| 관측 전송 n1_k | 배치당 전송 시간, 최근 3라운드 최선 | 매 라운드 | 갱신 |
| 바이트 B_k | 사전 진단 활성값 크기 × 2 | 시작 전 | 고정 (폭에 비례) |

오라클(`--access-caps`)은 sense 가 값을 못 낸 항목에만, 그리고 프로파일에 "오라클"이라 표시된 채로만 쓴다.

## 7. 멀티패스 실험 (h5m) — 사전 등록 초안

조건: 기기 4대 동질 연산, 접속 50×4, 공유 경로 60/60 **대칭**, 전원 경로 1 시작(혼잡). 이진 선택이 불리한 판을 만들기 위해 **기기 5대**(홀수) 판도 등록(h5m5).
팔: 균등 · 경로만(이진, |S|=1) · **분할 전송**(|S|≤2 허용) · 폭+분할.
판정: (1) 분할 ≥ 경로만 (총비용·라운드 시간 둘 다) (2) 경로별 부하 균형(최대/최소 몫 비)이 분할에서 더 1 에 가깝다 (3) 조각 분배 비 ≈ 예측 몫 비(±20%) (4) 접속 병목 기기는 분할해도 변화 없음.
리그: 기기마다 출발 주소 2개(127.0.0.i → 경로 A, 127.0.1.i → 경로 B). 자가 검사 D: 두 출구 동시 처리량 = 두 경로 몫 합.
