# KOREN을 쓰는 이유와 결합 알고리즘 실증 전략

> **9/22 현재 기준:** 아래는 가변 깊이 결합을 검토했던 9/19 제안이다. 현재는 [기기 연산 예산과 통신 지연의 구분](../04_설계기록/문제정의_기기연산예산_SFL_2026-09-22.md)에 집중한다. 종점 선택은 앱 수준 실행이며 OS-Ken은 학습 런타임 연결 전이다.

> 2026-09-19. 실측 완료, 제어 가능한 범위, 다음 실험을 분리해 서술한다. 기존 문서의 날짜와 배치가 다른 값을 한 조건의 결과처럼 합치지 않는다.

## 과제의 중심 주장

KOREN은 단순한 발표 배경이 아니다. **물리 연구망의 왕복 지연·접속 방향·거점별 처리량을 재고, 실제 KOREN VM을 경유하는 분할학습의 활성값·기울기 왕복을 관측하며, 그 관측을 다음 라운드의 분할 깊이 결정에 넣는 검증 장소**다. SuperSFL이 기기 자원에 맞춰 깊이를 고른다면, AwareNet 결합안은 **기기 자원과 그 시점의 KOREN 경로 상태를 함께** 본다. SDN은 우리가 소유한 엣지에서 이 결정을 집행한다.

현재 실험의 엣지 경로 결정은 **애플리케이션 종점 선택**이고 상한·보호는 **우리 VM의 `tc`**가 집행한다. 이번에 추가한 OS-Ken/OpenFlow 코드는 운영 VM의 OVS에 실제로 연결하고 흐름 카운터를 확인하기 전까지 **구현·단위시험 단계**다. KOREN 백본 SDN 컨트롤러 권한이나 광역 QoS 집행은 확인되지 않았다.

## 기기↔엣지 권한 문제의 해법

기기에서 첫 엣지까지의 통신사·캠퍼스·KOREN 언더레이는 우리 소유가 아니다. 이 구간의 라우터 설정 권한을 요구하는 설계는 실증할 수 없다. 따라서 제어를 두 경계로 나눈다.

1. **기기 측 동의와 엔드포인트 선택:** AwareNet 클라이언트가 서버가 제공한 허용 엣지 주소 중 하나(또는 두 출구)를 스스로 선택한다. 이는 애플리케이션 연결이며 기기 OS의 라우팅 권한을 요구하지 않는다. 미설치·미동의 기기는 제어 대상이 아니다.
2. **보유 엣지 측 실제 SDN:** 우리가 관리하는 VM의 OVS 브리지에 OS-Ken(OpenFlow 1.3)을 연결한다. 분할 깊이 계획기 결정의 `route`를 출구별 원본 IP → 허용 OVS 포트 규칙으로 변환한다. 규칙은 지정한 DPID, 진입 포트, 서비스 IP/포트, 허용 출력 포트에만 적용한다. `sfl/sdn/policy.py`가 이를 검증하고 원자적으로 게시하며 `sfl/sdn/osken_controller.py`가 OpenFlow flow-mod로 집행한다.
3. **확인 지점:** OVS 포트/흐름 카운터와 서버 수신 바이트를 대조한다. 현재 역방향 SSH 터널이 OVS를 우회하면 flow 카운터가 증가하지 않으므로, 그 구성은 SDN 실증으로 세지 않는다. 실제 전송 경로를 OVS ingress/veth로 재배선한 뒤에만 SDN 효과를 주장한다.

이 구조로 **권한 없는 기기·사업자 망은 건드리지 않고**, 통제권이 있는 엣지에서 SDN을 사용한다. 타 기관의 기기를 강제 이동시키는 기능은 아니다. OS-Ken은 OpenFlow 컨트롤러이고 OVS는 OpenFlow 스위치다([OS-Ken 공식 문서](https://docs.openstack.org/os-ken/latest/writing_os_ken_app.html), [OVS 공식 문서](https://docs.openvswitch.org/en/latest/faq/openflow/)).

## 다음 실험: K-SuperSFL

1. 같은 기기·모델·데이터에 대해 각 prefix 깊이의 연산 초, 메모리, 활성값·기울기 왕복 바이트를 잰다. SuperSFL 정적 배정과 결합 배정이 **동일한 후보 표**를 쓴다.
2. KOREN VM 두 대의 엣지 경유 경로마다 맨 회선 처리량·TCP 왕복·실제 학습 트래픽 완료 시각을 기록한다. 리그 상한을 건 판은 별도 표기한다.
3. 정상, 한 엣지의 경쟁 트래픽 증가, 회복, 기기 연산 저하를 사전 등록한다. 각 상황에서 `depth`, `route`, 실효 전송률, 총 라운드 시간, 정확도와 총 바이트를 같은 로그에 기록한다.
4. **고정 깊이 SFL / SuperSFL 자원 기반 깊이 / 동적 깊이만 / 동적 깊이+SDN 경로**를 같은 시드와 실행 횟수로 비교한다. 주효과는 깊이 변경이고, SDN 경로 선택의 추가 이득을 절제로 분리한다.
5. 실망 실행 전에는 `sfl/supersfl_net.py`의 예측과 소규모 리그 측정을 비교한다. 오차가 큰 경우 예측 성능 수치를 성과로 쓰지 않고 원인(활성값 크기, 접속 상한, 터널 오버헤드)을 기록한다.

**성공 판정은 실험 전 수치로 고정해야 한다.** 우선 기준선은 같은 정확도 목표에서 실제 시간·바이트가 줄고, 장애 뒤 경로/깊이 결정이 재현 가능하며, 품질 손실이 허용 범위 안인 것이다. 현재 결합형의 성능 향상 수치는 없다.

발표 첫 문장은 다음처럼 쓸 수 있다: **“KOREN 실회선에서 분할학습의 중간 데이터 왕복을 재고, 기기 능력뿐 아니라 거점별 회선 상태에 맞춰 모델 분할 깊이와 전송 경로를 함께 고르는 연합학습을 검증한다.”**
