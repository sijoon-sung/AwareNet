# KOREN을 어떻게 쓰나 — 짧게 (7번 문서)

> **범위 확인 먼저.** 이 과제는 **망을 통제하는 과제가 아니다.**
> 망은 ① **관측 대상**(재서 폭을 정하는 입력) ② **실증 무대**(진짜 광역망에서 돌린다) 이고,
> 통제는 딱 하나 — **바깥 트래픽에서 학습 몫을 지키는 것**뿐이다.
> 그 이상으로 키우지 않는다.

---

## 1. KOREN이 이미 우리에게 준 것 [실측 완료, 2026-08-10]

가장 중요한 자산은 **"우리 실험 조건이 억지가 아니라는 증거"**다.

| 항목 | 실측값 | 우리 실험이 쓴 값 |
|---|---|---|
| **RTT** (PC ↔ KOREN VM, 100회) | 중앙값 **30.8ms**, p95 86.4ms | netem **10~30ms** ✓ |
| **업로드 처리량** | 평균 **55.0 Mbps** | HTB **20~80 Mbps** ✓ |
| 어댑터 실효 굿풋 | **24.2 Mbps** | 최저 구간 20Mbps ✓ |

> **이게 왜 중요한가** — 적대 검토에서 나온 가장 아픈 지적 중 하나가
> *"KOREN은 빠른 연구망인데 억지로 조여놓고 병목이라 부르는 것 아니냐"* 였다.
> **아니다. 우리가 쓴 20~50Mbps는 조인 값이 아니라 잰 값이다.**
> 이 표 하나로 답이 된다.

### 그리고 진짜 광역망에서 혼잡을 관측했다

| 라운드 경계 버스트 (13플로우 × 8.68MB 동시 업로드, 실WAN) | RTT 중앙값 | RTT p95 |
|---|---|---|
| 평상시 | 30.8 ms | 86.4 ms |
| **버스트 중** | **74.2 ms** | **448.0 ms** |
| 회복 후 | 29.9 ms | 78.0 ms |

**p95 지연이 5배로 뜁니다.** 이건 에뮬레이션이 아니라 진짜 망에서 잰 것이고,
**"라운드 경계에 몰리면 실제로 느려진다"의 실물 근거**다.

## 2. 이번 과제에서 앞으로 할 것 — 최소 정의로

욕심내지 않는다. **셋만 한다.**

| # | 무엇 | 왜 |
|---|---|---|
| **K1** | **2사이트 분리** — 서버와 클라를 판교·대전에 나눠 두고 조건 2·3을 재현 | "에뮬이 아니라 진짜 망에서 돌았다"의 근거. **이게 KOREN을 쓰는 유일한 이유** |
| **K2** | **자연 변동 관측** — 우리가 주입하지 않은 변동이 실제로 있는지 며칠 재둔다 | 있으면 "교란은 우리가 주입한 것"이라는 지적을 정면으로 푼다. **없으면 없다고 쓴다** |
| **K3** | **개입→반응 폐루프 시연** — 배경 트래픽을 넣고 보호(HTB)를 켜고 끄는 것을 화면으로 | 유일하게 살아있는 망 통제를 눈에 보이게 |

**판정 기준 (사전 등록)**
- K1: 조건 2·3의 **결론 방향이 유지**되면 통과. **수치 일치는 요구하지 않는다**
- K2: 변동이 없으면 **"연구망은 조용했다"고 그대로 쓴다.** 억지로 찾지 않는다
- K3: 보호 on/off에서 학습 라운드 시간 차이가 눈에 보이면 통과

**막히면**: 지연·대역 실측값만 가져와 로컬 재현으로 대체하고,
**"RTT는 실측, 용량은 재현"**이라고 명시한다(이미 §1에 근거가 있다).

## 3. 이번 과제 이후 — KOREN을 계속 쓴다면

| 쓸 곳 | 무엇이 필요한가 | 현실성 |
|---|---|---|
| **다기관 배치 모사** | 사이트 3곳 이상. 기관별 회선 이질성을 진짜 지리적 거리로 만든다 | 사이트 확보 협의 필요 |
| **장기 변동 데이터** | 몇 주간 RTT·처리량을 계속 재서 **공개 데이터셋으로 낸다** | **가장 싸고 가장 유용.** 지금도 시작 가능 |
| 경로 배정 실험 | SDN 컨트롤러 접근 권한 | **권한 없음.** 6번 문서 참조 |
| 후속 과제·논문 | 위 데이터 + 2사이트 실증 | K1이 되면 자연히 따라옴 |

**가장 값싸고 확실한 것은 "장기 변동 데이터"다.** 조사에서 확인했듯
**SFL 트래픽을 실광역망에서 잰 공개 데이터가 없다.** 우리는 이미 재는 도구를 갖고 있고
(`scripts/measurement/`), 며칠 걸어두기만 하면 된다. 실험이 아니라 **자산 축적**이다.

## 4. KOREN에 대해 하지 말아야 할 것

| 유혹 | 왜 안 되나 |
|---|---|
| "KOREN에서 SDN으로 대역을 배분하겠다" | 배분층은 죽었다. 그리고 컨트롤러 권한도 없다 |
| "KOREN 망 자체의 성질을 규명하겠다" | **우리 과제가 아니다.** 우리는 그 위에서 학습을 돌릴 뿐 |
| "연구망이 조용하니 교란을 크게 주자" | 교란 크기를 결과에 맞춰 고르면 그게 조작이다. **미리 정하고 그대로 쓴다** |
| KOREN 실측 없이 "실증했다"고 쓰기 | K1이 안 되면 **"에뮬레이션"이라고 정확히 쓴다** |

## 한 문단 요약

**망은 통제 대상이 아니라 관측 대상이자 무대다.** KOREN은 이미 우리에게 가장 중요한 것을 줬다 —
**우리 실험 조건(RTT 10~30ms, 20~50Mbps)이 억지가 아니라 실측값이라는 증거**다
(실측 RTT 중앙값 30.8ms, 업로드 55Mbps). 게다가 라운드 경계 버스트에서
**p95 지연이 5배로 뛰는 것을 진짜 망에서 관측**했다.
앞으로는 셋만 한다 — **2사이트 분리 재현 · 자연 변동 관측 · 개입→반응 시연.**
그 이후로 가장 값싸고 확실한 것은 **장기 변동 데이터를 쌓아 공개하는 것**이다.
SFL 트래픽의 실광역망 공개 데이터가 없으니, 도구가 이미 있는 우리가 걸어두기만 하면 된다.
