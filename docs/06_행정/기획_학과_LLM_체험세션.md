# 기획 — 학과 LLM 체험 세션 v2 (13번 문서)

> v1 폐기 사유를 먼저 적는다: v1 은 사용자 질문을 수집하는 설계였다 — "데이터가
> 밖으로 나가지 않는다"는 플랫폼 정체성과 정면 모순이고, 스스로 보안 공격면을
> 만드는 짓이었다. v2 의 원칙: **보안이 곧 차별점이다. 수집하지 않는다.**

## 1. 차별점 두 축 — 성능으로 겨루지 않는다

**축 ① 이 모델만 아는 것** — 학과 내규·수강 규정·행정 절차는 외부 챗봇이 원리적으로
모르는 영역이고, 모집 대상(학과 구성원)이 정확히 그 지식의 수요자다.

**축 ② 묻는 내용이 남지 않는다** — 이게 v2 의 핵심이다. 학과 챗봇에 묻는 질문은
민감한 것이 많다: 학사경고, 재수강 요건, 휴학 절차, 장학 요건. 외부 클라우드
챗봇에는 계정에 대화가 남고, 묻기 꺼려진다. 우리 모델은 **교내/로컬에서 돌고,
질문을 저장하지 않는다** — "부담 없이 물어볼 수 있는 학과 상담"은 성능 열세를
상쇄하는 진짜 사용 이유이며, 분할학습 플랫폼의 서사("원본 비이동")와 한 몸이다.

## 2. 무수집 원칙 — 세션 설계가 곧 보안 시연이다

| 항목 | 처리 |
|---|---|
| 질문 텍스트 | **저장하지 않음** (메모리 내 처리 후 폐기 — 세션 안내문에 명시) |
| 남기는 것 | 익명 집계 숫자만: A/B 투표 결과, 질문 카테고리(체크박스 선택) |
| 지식 공백 파악 | 자유 텍스트 수집이 아니라 **카테고리 체크**("수강/장학/행정/기타에서 못 맞힘") |
| 코퍼스 확장 | 사용자 수집이 아니라 **지식 소유자 협업** — 과사무실 FAQ·조교 공지 등 공식 문서에서 (원문 기반 원칙 그대로) |
| 자발 기여 | 세션 끝에 "이 질문을 학습에 기부할까요?" **옵트인 버튼** — 기부는 수집이 아니다 |

세션 안내문에 "저희가 하지 않는 것" 카드를 넣는다 — 질문 저장 안 함 · 계정 없음 ·
외부 전송 없음. **보안 원칙 자체가 데모의 일부**가 되고, 4번 문서(보안 위협 적대
점검 34건)가 그 뒷배가 된다. "너무 투명해서 공격당할" 지점이 "설계로 막아둔"
지점으로 바뀐다.

## 2.7 예상 공격 — "일반 LLM 도 대화를 수집하는데, 안 모은다는 걸 어떻게 믿나"

다섯 겹으로 답한다 (질의응답 대비 순서 그대로):

| 겹 | 방어 | 한 줄 답변 |
|---|---|---|
| ① 구조 | 도착지가 우리 통제 장비(교내/로컬). **0.5B 라서 노트북 한 대에서 돈다** — 작은 모델이 프라이버시 축의 전제조건 | "질문이 남의 서버에 도착하지 않습니다" |
| ② 코드 | 질문을 기록하는 경로 자체가 코드에 없음 — 공개해 감사 가능, 무상태 프로세스 | "믿으라는 게 아니라 읽어보시라는 겁니다" |
| ③ 실증 | ★ **에어갭 시연** — 시연 중 네트워크를 물리로 끊고 질문→답. 보조: 아웃바운드 트래픽 캡처 화면 0건 | "안 하는 게 아니라 불가능한 걸 보여드립니다" |
| ④ 운영 | 무수집 명문화(동의서·안내문), 기부는 옵트인 버튼의 분리 경로만 | — |
| ⑤ 정체성 | 일반 LLM 이 수집하는 이유 = 개선에 중앙 데이터가 필요해서. **그 전제를 깨는 게 이 플랫폼** — 개선은 각자의 자리에서, 모이는 건 어댑터뿐 | "저희는 모을 필요가 없는 구조를 만들었습니다. 그게 이 기술입니다" |

시연 각본 반영: 에어갭 장면(랜선/와이파이 차단 → 질문 → 답)을 세션과 최종 시연
양쪽의 고정 절차로 넣는다 — 백로그의 demo_server 확장에 '오프라인 모드 표시' 포함.

## 3. 세션 흐름 — "학과 지식 대결" 15분 (v2)

1. 안내 30초: "질문은 저장되지 않습니다" (하지 않는 것 카드)
2. 궁금한 학과 질문 입력 → 두 답이 블라인드 A/B — 투표
3. 못 맞힌 질문은 카테고리만 체크 (텍스트는 폐기)
4. (옵트인) "이 질문 기부하기" — 누른 것만 코퍼스 후보로
5. 정체 공개 + 기프티콘 응모 (연락처 분리 보관, 추첨 후 삭제)

## 4. 메시지 수위 — 내부 지표와 대외 문구를 가른다

- **내부 지표**(개선용): 학과/일반 질문 승률 분리, 카테고리별 공백 — 팀 안에서만
- **대외 문구**(발표·모집): "학과 질문 정답률 X% + 질문이 남지 않는 상담" —
  강점 축으로만. 한계는 보고서의 통제된 '한계' 절에서 다루지, 모집 문구나 시연
  중에 자학적으로 노출하지 않는다
- 질의응답 대비: 보안 질문이 오면 방어 자산(4번 문서 34건 점검·무수집 설계·TLS·
  온프레미스)으로 받는다 — 약점 자백이 아니라 설계 답변

## 5. 게이트

파일럿 5명(지인) → 투표 완료율·무수집 파이프라인 무사고 확인 후 확대.
demo_server 확장(블라인드 A/B·비저장 모드·옵트인 버튼)은 백로그 — 저장 없는
처리를 코드로 보증(로그에 질문 미기록)하는 것까지가 구현 범위다.
