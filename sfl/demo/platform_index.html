실증 플랫폼

같은 스케줄러가 두 종류의 모델을 KOREN 실망 위에서 돌립니다. 영상(CNN)은 채널 폭을, 언어모델은 LoRA 랭크를 "학습량 손잡이"로 쓰고, 망 손잡이(엣지 바꾸기·두 회선 나눠 보내기)는 둘이 같습니다.

① CNN 영상 처리 — 분할 연합학습 라이브

ResNet-18 / CIFAR-10. HPC 기기 8대가 KOREN 엣지 4개로 보내고 서버가 뒷부분을 계산합니다. 심사위원이 기기 회선이나 엣지 용량을 줄이면 다음 라운드에 스케줄러가 대응하는 것을 카드와 그래프로 봅니다.
~/env/bin/python sfl/demo/run_demo_real.py --cond r8mix_rho1 --arm bothmp # 무대 안전망(리그 없이 기록 재생) python sfl/demo/run_demo_real.py --replay out/wp_r8mix_rho1_s1_bothmp_widthpath.jsonl
라이브 화면 열기
상태: 실회선 8대 실험 완료(9/8), 라이브 화면 준비됨

② 언어모델 LoRA 연합 튜닝 — 삼면 비교

Qwen2.5-0.5B에 LoRA 어댑터만 학습해 기관별 데이터를 반출하지 않고 지식을 합칩니다. 같은 질문에 베이스 / 단독 학습 / 연합 튜닝 세 모델이 나란히 답합니다. 랭크(4·8·16·32)가 학습량 손잡이입니다.
python sfl/demo/demo_server.py --port 8777 # 라이브 채팅 (체크포인트 자동 로드) python sfl/demo/make_demo.py # 정적 재생 페이지 out/reports/삼면비교_데모.html
삼면 비교 열기 (8777)
상태: 코퍼스·체크포인트(data/lora_ckpt) 있음, 정적 페이지 생성됨. 실망 위 rank 사다리 실험은 후속

시연 순서 (안)

  1. ①을 켜 둔 채 라운드 몇 개를 보여 준다. 카드에서 계산 느린 기기만 폭이 줄고, 회선 약한 기기는 두 가닥으로 나눠 보내는 것을 가리킨다.
  2. 심사위원이 정상 기기 하나의 "회선 절반"을 누른다. 다음 라운드에 그 기기가 나눠 보내기나 엣지 이동으로 목표를 지키는지, 그래도 안 되면 폭이 줄는지를 본다. "복구"로 되돌린다.
  3. 엣지 하나의 "용량 절반"을 누른다. 그 엣지에 있던 기기들이 다른 엣지로 옮겨 가는 것을 본다.
  4. ②로 넘어가 심사위원이 질문 하나를 고른다. 베이스 ✗ / 단독 1개 ✓ / 연합 3개 ✓를 본다.
