# J 시리즈 — "단순 결합이 아니라 시스템"의 실측 증명 (사전 등록)

> 목적: 같은 부품(학습량·파이프라인·전송 시차)을 ① 따로 적용했을 때와 ② 한
> 컨트롤러가 측정을 근거로 함께 판단했을 때를 같은 판에서 비교한다.
> 함께가 따로를 이기면(계측 불확도 10% 초과) "정보 연계·종합 판단"의 가치가
> 숫자로 선다. 폭×경로에서 이미 한 번 증명했고(따로=역효과, 함께=오차 3%),
> 이번엔 폭×파이프라인×시차다.

## 1. 실험 조건 (전부 동일 시드·동일 이질 판)

판: 기기 4대, 회선 20/40/60/80Mbps(HTB), 공유 병목 200M, 14라운드 × 6배치,
ResNet-18/CIFAR-10. 재현: `bash scripts/exp/run_joint.sh`

| 조건 | 학습량(폭) | 파이프라인 | 전송 시차 | 뜻 |
|---|---|---|---|---|
| A 기준 | 전원 전폭 | 끔 | 끔 | 아무것도 안 함 |
| B 폭만 | 컨트롤러 | 끔 | 끔 | 기존 확정 결과 (−40%) |
| C 파이프만 | 전원 전폭 | 전원 켬(깊이 2) | 끔 | 단독 효과 |
| D 따로 결합 | 컨트롤러 | 전원 켬(고정) | 고정 등간격 0.5초 | **각 기능을 독립 적용 — 서로의 정보를 모름** |
| E 통합 | 컨트롤러 | 측정에서 유도 | 측정에서 유도 | **한 컨트롤러가 함께 판단** (plan_round) |

D와 E의 차이가 곧 주장이다: 켜고 끄는 기능 목록은 같고, **판단이 연계되어
있는가만 다르다** — E에서는 폭이 바뀌면 전송량이 바뀌고, 그것이 파이프라인
채택과 시차 계산의 입력이 된다.

## 2. 판정 (사전 등록)

- 주 지표: 평균 라운드 완료 시간(makespan). 부 지표: 최종 정확도(동급 확인용).
- **성립**: E 가 D 보다 10%(계측 불확도) 넘게 빠르거나, D 에서 역효과(B 보다
  느려짐)가 관측되고 E 는 그렇지 않을 때.
- **불성립이면 불성립으로 기록한다** — 이 판에서 세 부품의 상호작용이 약하다는
  것도 유효한 결과다(그 경우 폭×경로 실측이 유일한 증명으로 남는다).

## 3. 구현 변경 (이 문서와 같은 커밋)

1. `fed_client.py` — 깊이 2 파이프라인: 배치를 마이크로배치 2개로 갈라, 첫
   조각을 올리는 동안 둘째 조각을 계산한다. 갱신은 배치 경계에서 한 번
   (그래디언트 0.5 배 누적 — 직렬과 같은 평균 의미). 서버 뒷단은 마이크로배치
   단위로 갱신됨을 명기한다. 라운드 시작 지연(start_delay)도 집행.
2. `fed_server.py` — RSTART 에 depth·start_delay 동봉. `--pipeline {off,on,auto}`,
   `--stagger {off,fixed,auto}`(+`--stagger-gap`), `--policy joint`
   (= ours + plan_round 로 깊이·시차 유도).
3. `scripts/exp/run_joint.sh` — 5조건 자동 실행 + 결과표.
4. 시험: FULL 에 파이프라인 등가성 스모크(깊이 1 vs 2 의 학습 손실 곡선 근접).


## 4. 결과와 판정 (2026-08-31 실측, 시드 1)

| 조건 | 평균 라운드 시간 | 최종 정확도 |
|---|---|---|
| A 기준 | 25.48초 | 32.2% |
| B 폭만 | **14.10초 (−45%)** | 28.0% |
| C 파이프만 | 24.22초 (−5%) | 25.4% |
| D 따로 결합 | 14.54초 | 22.9% |
| E 통합 | 15.03초 | 22.5% |

**판정: 불성립** — E 와 D 의 차이는 계측 불확도 안이다. 등록한 대로 기록한다.

**원인 분석 (배운 것):**
1. 이 판의 시계(최저 회선 기기)는 시간의 97%가 전송이라, 계산을 숨기는
   파이프라인이 시계를 못 움직인다 — max 구조의 재확인. 통합 컨트롤러는 시계
   기기에 파이프라인을 켜지 않았고(이득<불확도), 시계가 아닌 기기에만 켰다
   (무해·무익). 파이프라인·시차가 유효한 국면은 계산과 전송이 비슷한 판
   (원거리 WAN + 왕복 지연)이며, 그 검증은 KOREN 2사이트로 이월한다.
2. **파이프라인의 정확도 대가 발견**: 파이프라인이 켜진 세 조건 모두 정확도가
   낮다(32→25, 28→23%). 추정 원인은 배치 절반 분할에 따른 배치정규화(BN) 통계
   변화 — "갱신 의미 동일"이 SGD 산수에선 성립하나 BN 에서 깨진다. **등가성
   확인 전까지 파이프라인은 기본 끔으로 두고 주장하지 않는다.** 등가성 시험
   (BN 고려)을 후속 항목으로 등록한다.
3. "함께 판단"의 성립 사례는 폭×경로(따로=역효과, 함께=예측 오차 3%)가 유일하게
   유지된다 — 보고서의 해당 주장은 폭×경로로 한정해 서술한다.


## 5. 후속 — 폭×경로 온라인판 (widthpath, 8/31 실측)

두 손잡이 체제 확정(폭+경로, 양자화·파이프라인은 보조로 강등) 후, M2′(정답
회선값을 아는 오프라인 계산)를 실측 기반 온라인으로 옮겨 검증했다.

조건: 경로 2개(100/20Mbps), 기기 4대 전원을 빠른 경로에 몰아넣고 시작, 12라운드.

| 조건 | 평균 라운드 시간 | 마지막 폭 |
|---|---|---|
| 기준 (전원 빠른 경로·전폭) | 13.08초 | 전원 1.0 |
| **온라인 공동 판단** | **11.77초 (−10%)** | 평균 0.94 |

관찰된 동작 (전부 규칙대로):
- 측정 전(라운드 0)은 무개입 → 사전 진단·첫 측정 후 1명을 느린 경로로 이동하며
  폭을 줄임(공짜 유배 형태) → 이후 폭 회복 → 몇 라운드 재조정 후 정착 →
  나머지 라운드는 전부 "유지 (이득 ≤ 계측 불확도)" — 히스테리시스가 진동을 막음.
- 이동은 항상 한 라운드 1명 (상한 규칙 동작).

**병목 심한 판 재검 (같은 날, 경로 30/10Mbps)**: 기준 42.56초 → **33.73초
(−21%)** — 병목이 심할수록 이득이 커졌다. 특히 이번에는 **학습량을 전혀 깎지
않고**(전원 전폭 유지) 1명의 경로 이동만으로 해결하고 즉시 정착했다 — "경로는
공짜 손잡이(정확도 손실 0)부터 쓴다"는 규칙의 정확한 실측 사례. 남은 재검은
실WAN(§6 K-W 시리즈)뿐이다.

**time-to-accuracy (16번 문서 채택 지표, 후처리 — scripts/analysis/tta.py)**: 병목 심한
판에서 정확도 15% 도달 217초→**78초**, 20% 도달 304초→**179초 (−41%)** — 라운드가
빨라진 만큼 같은 정확도에 먼저 닿는다. 여유 판은 12라운드 안에서 정확도 궤적의
시드 요동이 커서 차이가 혼재 — 이 지표는 병목 판·장기 실험에서 쓴다.


## 6. KOREN(HPC·VM) 검증 계획 — 두 손잡이의 실WAN 판 (사전 등록)

로컬 실험의 "경로"는 트래픽 제어로 만든 모의다. 실제 KOREN 에서 경로의 실전형은
**접속 지점 선택** — 어느 집계 서버로 붙을 것인가 — 이며, 이것이 운영자가 실제로
가진 경로 권한이다. 검증은 세 단계로 올린다 (앞이 안 되면 뒤는 안 한다).

**K-W1. 사전 진단의 실WAN 검증** — 준비물: 기존 판교 VM (지금 가능)
- 클라이언트(로컬 PC·WSL)가 KOREN 판교 VM 의 서버에 접속해 사전 진단 실행.
- 확인: 왕복 지연 30ms 가 낀 조건에서 진단값(계산·전송 추정)이 이후 라운드
  실측과 20% 이내로 맞는가. 안 맞으면 진단의 왕복 보정을 추가한다.

**K-W2. 폭 판단의 실WAN 재현** — 준비물: 판교 VM + 클라 2~4대(로컬·연구실)
- 로컬의 이질 환경 실험(조건2)을 실WAN 으로: 클라이언트 회선을 실제로 다르게
  (유선/무선/공유기 뒤) 두고 12라운드.
- 판정: 방향 재현 — 느린 기기만 폭이 줄고 라운드 시간이 준다 (수치 일치는 요구
  하지 않는다 — 등록된 3단 주장 원칙).

**K-W3. 접속 지점 배정 — 경로의 실전형** — 준비물: **HPC V100 VM 승인(신청 중)**
- 집계 서버 2개: 판교 VM + HPC V100. 클라이언트 4대(로컬 2·Jetson 1·연구실 1)가
  둘 중 어디로 붙을지를 컨트롤러(plan_width_path)가 폭과 함께 배정.
- 구현 추가 항목: 클라이언트 재접속 — 체크인 응답에 다음 라운드 서버 주소를
  동봉하고, 클라가 라운드 경계에 재접속 (연결 유지 이동은 후속).
- 판정: ① 배정이 측정에서 유도되고 히스테리시스로 안정 ② 서버 쪽 회선이 다른
  두 지점 사이에서 "느린 지점 배정자는 폭 축소" 형태가 실WAN 에서 재현.
- 병행 측정: 두 지점의 회선·지연 차이표 (다지점 실증의 근거 그림).

일정: K-W1 은 즉시 가능. K-W2 는 회선 이질 클라 확보 시(연구실+자택). K-W3 은
V100 승인 후 — KOREN 신청서에 "집계 서버 이중화용 VM" 명목을 포함한다.


## 7. LoRA(언어모델) 판 — 실소켓·실경로 위의 경로 손잡이 (2026-09-01 실측)

구성: 실제 0.5B 모델 3기관(B1/B2/B3)이 라운드마다 로컬 LoRA 학습(GPU 실측) 후
어댑터(각 35MB)를 **실제 소켓으로, tc 경로 위에서 동시 업로드**. 컨트롤러는
실측만 보고 접속 경로를 옮긴다 (랭크 사다리는 이질 랭크 검증 전까지 잠금).
러너: sfl/experiments/run_l3_net.py, 실행기: scripts/exp/run_l3net.sh. 세 판을 순서대로 기록한다.

**판 1 (경로 30/10M) — 정확한 무개입.** 3기관 × 용량비 3:1 에서는 "3명이 30M
공유"(각 b/10)와 "1명을 10M 으로 분리"(b/10)가 정확히 같은 시간 — 이득이 0인
판이었고, 컨트롤러는 6라운드 내내 "유지"만 냈다. 이득 없는 판에서 안 움직이는
것은 무개입 원칙의 실증이다 (우연이지만 기록 가치가 있어 남긴다).

**판 2 (경로 40/20M) — 리그 결함 발견.** 예측 이득 33%로 1명을 옮겼는데 실측은
오히려 악화(20.9→28.3초). 노드별 시간이 7/14/21/28초 계단 — **수신 서버가 한
연결씩 순차 처리**해 동시 업로드가 줄서기가 되고 있었다 (경로 공유 모형과 리그가
어긋남). 예측-실측 괴리가 컨트롤러가 아니라 리그의 결함을 잡아낸 사례.

**판 3 (수정판 — 연결별 스레드 수신) — 성립.**

| 조건 | 업로드 구간 (정착 후) | 배정 |
|---|---|---|
| 기준 (전원 40M) | 20.5초 | 전원 경로 1 |
| **온라인 판단** | **14.7초 (−29%)** | 1명을 20M 으로 분산 |

- 이동은 재확인 규칙대로 2라운드째 집행, 이후 전 라운드 유지 — 즉시 정착.
- 예측 33% vs 실측 31% — 예측 오차 2%p (CNN 판의 "예측 오차 3%"와 같은 급).
- 의미: 경로 손잡이가 CNN(활성값 트래픽)만 아니라 **LLM(어댑터 트래픽)에서도
  같은 규칙으로 동작**한다 — 두 손잡이 체제의 트래픽 일반성.
