# 용어, 설계 선택과 활용 시나리오

2026-09-27. 현재 보고서의 설명을 문헌, 코드, 개발 이력에 연결한다. 과거 문서의 제안은 당시 판단으로 읽고, 현재 구현·실험 결과는 제출 보고서와 원자료 E1–E8을 따른다.

## 1. 용어를 확인한 출처

| 사용하는 표현 | 뜻과 선택 이유 | 출처 |
|---|---|---|
| 연합학습(FL) | 기기에서 학습하고 모델 갱신을 집계한다. TTA 표제어는 ‘연합 학습’이다. | [TTA 정보통신용어사전](https://terms.tta.or.kr/dictionary/dictionaryView.do?subject=federated+learning) |
| 합성곱 신경망(CNN) | 여러 채널의 특징 맵을 계산하는 신경망. ‘합성곱’ 표기를 사용한다. | [TTA 기술보고서 TTAR-10.0137 목록](https://committee.tta.or.kr/standard/standard.jsp?by=desc&commit_code=PG1005&order=t.kor_standard), [PyTorch Conv2d](https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv2d.html) |
| 분할 연합학습(SFL) | 모델을 기기·서버로 나누어 학습하고 여러 기기의 갱신을 집계한다. 문헌의 Split Federated Learning을 병기한다. | [SplitFed, AAAI 2022](https://ojs.aaai.org/index.php/AAAI/article/view/20825) |
| 모델 폭(model width) | CNN에서는 사용하는 채널 수로 설명한다. 본 구현의 w는 원래 채널 수에 대한 비율이다. | [FjORD §3.1](https://proceedings.neurips.cc/paper/2021/file/6aed000af86a084f9cb0264161e29dd3-Paper.pdf), [models.py](../../sfl/models.py) |
| 활성값(activation), 기울기(gradient) | 순전파의 중간 계산 결과와 역전파에 필요한 값. 처음 나올 때 역할을 풀어 쓴다. | SplitFed 및 [PyTorch 자동미분](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html) |
| 중계 서버, 전송 연결 | 현재 구현이 제어하는 대상을 직접 가리키는 표현. ‘중계 종점’, ‘출구’를 대신한다. | [전송 구현](../../sfl/proto.py) 및 [시스템 코드 지도](../../sfl/ARCHITECTURE.md) |
| 폭 축소 페널티 λ | 채널 수 감소에 비용을 부여하는 이 프로젝트의 설정값. 정확도 손실의 예측값으로 설명하지 않는다. | [plan.py](../../sfl/plan.py) |

위 목록은 표준화 기구의 용어, 논문의 용어, 구현을 설명하는 일반 표현을 구분한다. SFL의 한국어 표기나 ‘폭 축소 페널티’를 공인 표준 명칭으로 주장하지 않는다. 처리량과 회선의 설정 대역폭도 구분한다. 식의 R은 공유 관계를 반영해 계산한 실효 전송률이며, 관측 바이트/시간으로 이를 보정한다.

## 2. 왜 이런 설계가 되었는가

| 질문 | 개발 과정에서 확인한 문제 | 현재 선택 | 기록 |
|---|---|---|---|
| 대역폭만 나누면 충분한가? | 고정된 공유 병목에서는 자원 재분배만으로 전체 대기를 크게 줄이기 어렵다. 일반 기기망의 통제권도 제한된다. | 학습 프로그램이 바꿀 수 있는 채널 수와 사용 가능한 중계 서버 선택을 함께 다룬다. | [8/29 방향 검토](../01_제출발표/방향검토보고서_AwareNet.md), [배치·통제권 검토](실전_포지셔닝_FL배치지형.md) |
| 왜 CNN인가? | 모델을 작게 만들면서 분할 지점의 전송량도 조절할 방법이 필요하다. | ResNet-18의 채널을 선택한다. 계층 분할 지점은 고정한다. | [모델 구현](../../sfl/models.py), [FjORD](https://arxiv.org/abs/2102.13451) |
| 왜 학습 서버를 여러 개 두지 않았는가? | 뒷부분 모델을 여러 서버에 복제하면 모델 상태를 맞추는 추가 전송이 필요하다. | 중계 서버는 텐서를 전달하고, 뒷부분 계산과 집계는 학습 서버가 맡는다. | [9/2 다중 경로 설계](../04_설계기록/설계_멀티패스_분할전송.md) |
| 왜 경로를 먼저 평가하는가? | 경로 이동이 진행 중일 때의 혼잡으로 폭을 줄이면, 이동 직후 다시 늘리는 동작이 생긴다. | 예정된 재배정이 끝난 상태에서 채널 감소의 이득을 계산한다. | [컨트롤러 기록 §11–12](../04_설계기록/설계기록_컨트롤러.md) |
| 왜 고정 시간 목표만 쓰지 않았는가? | 목표가 느슨하면 모델을 전혀 줄이지 않고, 너무 짧으면 여러 기기의 모델이 과도하게 작아진다. | 시간 감소와 채널 감소 페널티를 함께 비교한다. | [컨트롤러 기록 §12](../04_설계기록/설계기록_컨트롤러.md) |
| 왜 가장 늦은 기기에 집중하는가? | 전체 기기의 시간 합만 줄여도 마지막 기기가 늦으면 동기식 라운드는 끝나지 않는다. | 경로 점수에 최대 시간과 평균 시간을 함께 넣고, 폭 단계는 라운드 완료 시간을 줄이는 후보를 평가한다. | [컨트롤러 기록 §13](../04_설계기록/설계기록_컨트롤러.md), [plan.py](../../sfl/plan.py) |

문서의 날짜는 내부 작성 기록이다. Git 이력에서는 관련 문서가 `c21b831`(9/10 정리), `8296de8`(9/10 계측·폭 유지), `bdfa733`(9/11 시드·정확도), `28a61e3`(9/11 최종 시나리오)에 걸쳐 정리·보완되었다. 공개 저장소는 개발 저장소의 최종 작업본을 별도로 게시하므로, 원래 커밋 식별자와 문서 사본을 함께 보존한다.

과거의 ‘일찍 도착한 조각부터 학습’ 구상은 전송 완료와 계산 의존성을 함께 고려해야 한다. 현재 경로 전송은 조각을 모아 텐서를 완성한 뒤 계산에 넘긴다. 조각의 빠른 도착 자체를 학습 시간 단축 성과로 집계하지 않는다.

## 3. CNN 그림의 수치 근거

`sfl/models.py`의 `BASE=(64,128,256,512)`, `ClientNet(cut=2)`, CIFAR-10 입력 32×32, 배치 32, FP32를 사용한다. 분할 지점은 128×16×16이며 w=0.75는 96채널, w=0.5는 64채널이다. 활성값 크기는 `32 × 채널 수 × 16 × 16 × 4 bytes`, 즉 4·3·2MiB다. 반환 기울기는 같은 모양이다. 이는 코드의 텐서 모양에 따른 계산으로 새 네트워크 측정값이 아니다. 레이블·프레이밍·TCP/IP·집계 바이트는 포함하지 않는다.

층 분할(계산 장소), 채널 선택(부분 모델), 텐서 조각 나누기(전송)와 모델 집계(기기 간 학습 결과 통합)를 구별한다. 폭을 절반으로 줄였다고 계산 시간이 정확히 절반이 되지는 않는다. 보고서 식의 지수 γ와 실측 보정은 이 차이를 반영한다.

## 4. 활용 그림의 범위

예시는 여러 사업장·연구실의 소형 기기가 중앙 GPU 서버와 영상 분류 모델을 함께 갱신하는 환경이다. 현장별 계산 능력과 전송 혼잡이 달라 수동 설정을 반복해야 하는 부담을 줄이는 데 목적이 있다. 현장 데이터로 앞부분을 계산하고, 허용된 중계 서버를 거쳐 뒷부분 계산과 라운드 집계를 수행한다.

이 예시는 구조에 근거한 적용 제안이다. 제품 검사 현장 실증, 정확도 보장, 개인정보 보호의 입증으로 표시하지 않는다. 적용 전제는 프로그램 설치 권한, 중계 서버 사용 권한, 관측값 수집이다. 대체 경로에 여유가 없다면 경로 변경의 이득도 제한된다. 도입 시 확인할 지표는 정해진 정확도에 도달하는 시간, 기기별 채널 학습 기회, 총 전송량이다.

## 5. 정확도 기록을 읽는 방법

개발 커밋 `b3ec4aa14f984edbd990af6f56e657d061e7092b`은 자체 정확도 수치를 소개 페이지에서 제외했다. [당시 페이지 생성기](../../scripts/analysis/final_results_page.py)의 이유는 24라운드·소수 시드의 큰 변동, 반복해서 작은 모델을 쓰는 기기의 데이터가 뒤쪽 채널에 덜 반영되는 문제였다.

현재 보고서는 사용자의 시간·모델 성능 비교 요청에 맞춰 원로그를 다시 집계하되, 24라운드 값을 중간 관측으로, 200라운드·2시드 값을 시간과 정확도의 탐색 결과로 제시한다. λ는 정확도 보장값이 아니다. FjORD의 정확도를 우리 구현의 정확도로 가져오지 않는다. 원시 결과는 [E1·E7·E8 색인](../EVIDENCE.md)으로 연결한다.
