# 모델 폭 축소와 LoRA를 함께 사용하는 확장 설계

상태: **문헌·기존 코드에 근거한 설계 검토**. 현재 공개한 KOREN·Jetson 측정의 모델 구조와 수치는 기존 실행 조건을 따른다. 이 문서의 축소 모델은 아직 학습·측정하지 않았다.

## 1. 결론과 용어

모델 폭을 줄인 뒤 그 모델을 LoRA로 학습할 수 있다. CNN에서는 모델 폭을 **채널 수**, Transformer 언어모델에서는 계층 사이 표현의 **은닉 차원(hidden dimension)**으로 설명한다. LoRA는 학습 방법이므로 모델 폭 축소와 함께 사용할 수 있다. LoRA 랭크만 줄이면 기본 모델의 입출력 차원은 유지된다.

SliceGPT는 표현 좌표를 회전한 뒤 중요도가 낮은 차원을 제거하여 모델 행렬과 계층 사이 활성값을 함께 줄인다. 원문의 §4.1은 축소한 Llama-2·Phi-2에 LoRA를 적용한 추가 학습도 보고한다. 따라서 **은닉 차원 축소 → 축소 모델의 LoRA 학습 → 분할 실행**은 문헌에 근거한 확장 방향이다. 해당 논문의 정확도·속도는 우리 Qwen 실험으로 다시 확인할 항목이다.

| 방법 | 실제로 줄이는 대상 | 배치별 활성값·기울기 통신 | 이 프로젝트의 판단 |
|---|---|---|---|
| LoRA 랭크만 축소 | 학습하는 저랭크 행렬 | 기본 은닉 차원이 같으면 크기 유지 | 폭 제어와 별도 변수로 관리 |
| 은닉 차원 축소 + LoRA | 기본 모델의 표현 차원과 관련 행렬 | 분할 지점도 작아지면 감소 | 모델 폭과 경로 제어를 연결하는 우선 검토안 |
| 분할 지점의 활성값 압축 + LoRA | 전송할 표현 또는 잔차 | 압축 형식에 따라 감소 | 통신 절감 대안; 모델 전체의 폭 축소와 구별 |

FFN 내부 뉴런이나 일부 attention head만 제거하는 방법은 분할 지점의 은닉 차원을 유지할 수 있다. 통신량 감소는 실제 전송 텐서 모양으로 판정한다.

## 2. 폭 비율과 랭크가 함께 쓰이는 방식

원래 은닉 차원을 d, 축소 후 차원을 d′라고 하면 폭 비율은 w=d′/d다. LoRA 랭크 r은 별도로 고정한다. 예를 들어 d=1024를 d′=768로 줄여도 r=16을 유지할 수 있다. 이는 설명용 차원 예시이며 Qwen 실측값이 아니다.

선형 계층 W의 LoRA 갱신이 BA라면, 입력·출력 차원을 고르는 행렬 P_in, P_out에 대해 축소 계층의 갱신은 (P_out B)(A P_inᵀ)로 구성할 수 있다. 랭크와 모델 입출력 차원이 독립적인 변수임을 보여 주는 관계다. 실제 Transformer 축소에는 잔차 연결·정규화·attention 구성의 일관성을 함께 맞춰야 한다. 단순히 hidden_size 설정만 바꾸어 사전학습 가중치를 적재하는 것으로 끝나지 않는다.

배치 크기 B, 길이 L, 원소당 바이트 수 s가 같고 활성값과 반환 기울기를 모두 같은 자료형으로 보낸다면, 배치별 텐서 페이로드는 다음과 같다.

`V(w) = 2 × B × L × d′ × s`, 따라서 `V(w)/V(1) = d′/d = w`.

w=0.75이면 이 두 텐서의 페이로드는 25% 줄어든다. 라벨·헤더·어댑터 집계·재전송 등은 따로 계산한다. 계산 시간은 w에 선형 비례한다고 가정하지 않고 클라이언트별로 측정한다.

`완료 시간 추정 = 클라이언트 계산 + 서버 대기·계산 + 활성값 전송 + 기울기 반환 + 모델 전환 비용`

경로 변경으로 시간을 줄일 수 있으면 큰 폭을 유지하고, 계산 또는 공유 회선의 병목이 남으면 품질 기준을 만족하는 축소 모델을 검토한다. 이 판단은 CNN 스케줄러의 문제 설정을 언어모델로 확장한 설계다.

## 3. 구현 순서와 통과 기준

1. **고정된 한 가지 축소 모델부터 검증한다.** 기존 Qwen2.5 모델을 대상으로 원본과 축소본을 준비한다. SliceGPT 논문의 검증 모델과 우리 Qwen 구조가 다르므로 모델 어댑터·잔차 연결·정규화 처리를 먼저 확인한다. w=1.0의 변환 전후 출력도 비교한다.
2. **같은 랭크로 추가 학습한다.** 축소 전후 모두 r=16, 같은 데이터·길이·스텝·분할 위치를 사용한다. 미세조정 전후 언어모델 성능, 최대 메모리, 계산 시간을 비교한다. 현재 자체 문답 18개 외에 고정 평가 데이터의 perplexity 또는 과제 점수를 추가한다.
3. **실제 분할 전송을 확인한다.** 송수신 텐서의 모양과 바이트, 역전파 기울기, 같은 축소 모델의 연결 실행과 분할 실행을 대조한다. 서버와 클라이언트는 같은 모델 버전·차원·좌표 변환을 사용해야 한다.
4. **경로와 폭의 효과를 분리한다.** 같은 연결 수에서 원본/축소 모델 × 고정/적응형 경로의 네 조건을 비교한다. 폭 선택에 사용한 검증 데이터와 최종 평가 데이터를 분리한다. 목표 품질에 도달하는 시간과 전체 통신량을 보고한다.
5. **동적 폭 전환은 위 검증 다음에 연결한다.** 다른 폭의 어댑터는 행렬 모양이 다르다. 공통 좌표 변환·파라미터 위치 대응·집계 규칙·옵티마이저 상태 전환을 먼저 정하고 라운드 경계에서 전환한다. 독립적으로 압축한 모델의 어댑터를 그대로 평균하지 않는다. 초기 후보는 원폭과 완만한 축소 한 단계로 제한한다.

한 가지 고정 축소 모델의 성공과 라운드별 동적 폭 선택의 성공을 각각 기록한다. 축소로 잃은 성능이 LoRA 학습으로 충분히 회복되는지는 평가 결과로 판단한다.

## 4. 통신 압축 대안과 선행연구

SplitLite는 같은 샘플의 이전 활성값·기울기를 저장하고, 차이를 저랭크 분해·양자화하여 보내는 분할 LoRA 방식이다. 은닉 차원을 삭제하는 방법과 구분한다. 우리 시스템에 검토하려면 샘플별 캐시, 재동기화, 압축·복원 계산 비용을 함께 측정해야 한다. 원문의 유효 랭크 논의는 작은 갱신과 근사에 의존하므로 비선형 다층 모델에서 모든 잔차의 정확한 랭크 보장으로 사용하지 않는다.

모델 축소와 LoRA의 결합 자체는 선행연구가 있다. AwareNet에서 추가로 평가할 질문은 **품질 기준과 실제 장비 비용을 반영하여 폭과 허용 중계 경로를 함께 선택할 때 언제 완료 시간이 줄어드는가**다.
