# 회의 1 — 2026.07.31 (금) 12:00~14:00 · 공대 5호관 세미나실

**v1 → v2 : "누구를 부를까"에서 "어떻게 도착시킬까"로**

- **참석** 성시준(총괄·SDN/인프라), 석태경(분산학습·시각화)
- **배경** 전날 **1차 멘토링(7/30)** 지적 2건 — ① 혼잡제어와의 경계가 불분명 ② 시뮬레이션만으로는 설득 부족
- 7/12 1차 멘토링의 *"선택되지 못한 노드가 정말 쓸모없는 노드인가"* 도 미해결로 남아 있었음

〔사진 삽입 — 회의1_화이트보드.jpg〕

## 1. 안건 — "혼잡제어와 무엇이 다른가"에 답하려다 발견한 것

- 멘토 지적 ①에 답하려면 **우리가 무엇을 건드리고 무엇을 안 건드리는지**부터 적어야 했다. 그 정리를 하다 v1의 문제가 드러남
- v1은 **단일 선발기**였다. 가치 상위 K개를 뽑고 나머지는 버린다
- 코드를 같이 읽다가 **선발 장치 5개 중 3개가 사실상 같은 일을 하고 있음**을 발견
  - 속도 감점 / 마감 필터 / 대기 보정이 모두 "느린 노드의 점수를 낮춘다"로 수렴
  - → 파라미터를 튜닝해도 어느 장치가 효과를 냈는지 분리 불가
- 1차 멘토링의 *"선택되지 못한 노드가 정말 쓸모없는 노드인가"* 와 겹친다는 데 합의 — **결국 셋 다 "느린 노드를 버리는 장치"**

## 2. 논의 — 버리지 않으려면 무엇이 필요한가

- 석태경 : 버리지 않으려면 기다려야 하고, 기다리면 라운드가 느려진다. 교환을 피할 방법이 있나
- 성시준 : 느린 이유가 **연산이면 못 바꾸지만 회선이면 바꿀 수 있다.** 우리가 게이트웨이 큐를 쥐고 있음
- → **문제 정의 자체가 틀렸다**는 결론. "누구를 부를까"가 아니라 **"부른 노드 중 누가 마감에 도착하는가"** 가 비어 있는 질문

## 3. 검증하기로 한 가설과 결과

- **가설 1** 손실이 높은 노드가 희귀 데이터를 가질 것이다 → **기각** (희귀 커버리지 20.8% → 16.4%로 악화)
- **가설 3** 희귀 데이터 보유 노드는 대체로 느릴 것이다 → **기각** (18.0s 대 21.8s, 상관 −0.084)
- 검증 방법과 수치는 **중간보고서 부록 A 표 A-1** 참조

- 가설 1의 원인 규명 : 손실은 "희귀"가 아니라 **"아직 못 배움"**을 가리킴. 표본이 많고 클래스가 다양한 노드가 $\sqrt{n}$ 까지 커서 우선순위를 가져감
- 가설 3 기각으로 **표적 구제(느린 희귀 노드만 밀어주기) 노선 폐기** → 전수 커버리지로 방향 전환

## 4. 결정 사항

- ✅ **문제 정의 교체** : 선발 문제 → **도착 문제**
- ✅ **구조 변경** : 단일 선발기 → **선발 + 배분** (이 시점에는 아직 동일 구간)
- ✅ **배분 방식** : 상위 K개 우선 → **초과선발 + 마감 기반**
- ✅ 희귀 데이터 보호를 **가치식에서 떼어내** 별도 장치로 이관 (→ 후에 커버리지 보장으로 발전)
- ✅ **계층 경계 명문화** (멘토 지적 ①) — 혼잡제어는 *전송률의 공정성*, 우리는 *마감 내 도착 순서*. 총량·마감·집계 규칙은 불변으로 고정
- ✅ **실증망 전환** (멘토 지적 ②) — 시뮬레이션만으로는 부족하므로 KOREN VM을 신청해 실장비에서 재검증하기로
- ❌ **보류** : 선발 장치 5개 정리 — 어느 것이 불필요한지 데이터가 아직 없음

## 5. 조치 (담당 / 기한)

| 조치 | 담당 | 기한 |
|---|---|---|

# 회의 2 — 2026.08.07 (금) 12:00~14:00 · 온라인(Discord) + Notion 동시 편집

- **배경** 전날 **2차 멘토링(8/06)** 지적 2건 — ① *"가치가 다음 라운드에도 유지된다고 확신할 수 있는가"* ② LoRA·LLM 서술이 초점을 흐림

〔사진 삽입 — 회의2_멘토링_메모.jpg〕

## 1. 안건 — 멘토 지적 ①이 왜 치명적인가

- 우리 설계는 **"이번 라운드에 가치 높은 노드는 다음 라운드에도 가치가 높다"** 를 암묵적으로 깔고 있었음
- 이 전제가 깨지면 → 배분이 **매 라운드 무의미하게 요동**치고, 균등 배분보다 나쁠 수 있음
- 성시준 : 전제를 논증으로 방어하려 하면 반박당한다. **측정 대상으로 바꾸자**
- 석태경 : 라운드 간 자기상관을 매 라운드 계산하고, 낮으면 스스로 균등으로 복귀시키면 됨

## 2. 논의 — "언제 개입하지 않을 것인가"를 설계에 넣기

- 지금까지 우리는 **개입하는 방법만** 설계했음. 개입을 **철회하는 조건**이 없음
- 세 가지 안전장치로 정리
  - **가치 자기상관 감시** → 낮으면 균등 배분 복귀
  - **경합비 ρ 판정** → ρ ≤ 1(전원 마감 내 도착 가능)이면 아예 개입 안 함
  - **물리 상한 클램프** → 배분값이 링크 용량을 넘지 못하게 집행 시점에 강제
- 이 셋이 있으면 **최악의 경우 성능이 균등 분배와 같음**이 설계로 보장됨 → 방어 논리가 아니라 설계 속성이 됨

## 3. 검증하기로 한 가설과 결과

- **가설 2** 느린 노드를 잘라내거나 미루면 라운드가 빨라질 것이다 → **둘 다 유해**
- **가설 6** 배분값을 올리면 느린 노드가 구제될 것이다 → **부분 기각** (물리 상한 미달 **52개 노드**는 전 대역을 받아도 불가)
- **가설 10** HTB 부모 상한이 자동 집행될 것이다 → **기각** (경고만 하고 집행 안 함)
- 검증 방법과 수치는 **중간보고서 부록 A 표 A-1·A-2** 참조

- 가설 6이 뼈아팠다 — **초기 코드가 물리 상한을 검사하지 않아 "물리적으로 불가능한 구제"를 성과로 집계**하고 있었음
  - → 구제 가능 범위를 **48/100으로 재정의**하고 전수 재계산
- 가설 10 때문에 **컨트롤러 측 총량 클램프**를 별도로 넣고 매 라운드 총량 보존을 로그로 기록하기로 함

## 4. 결정 사항

- ✅ **무해성 3장치 도입** (자기상관 감시 / ρ 판정 / 물리 클램프)
- ✅ **선발 장치 5개 → 2항 단일 점수식으로 축소**
  - 근거 : *"설명할 수 없는 항을 남기면 심사에서든 운영에서든 근거로 쓸 수 없다"*
- ✅ **집행 정확도를 독립 측정**하는 도구를 따로 구현 (1차 멘토링 "시뮬레이션만으로는 설득 부족"에 대한 답) → 이후 **평균 98.9%** 확인
- ✅ **LLM 워크로드 축소** : 비전으로 한정, LLM은 확장 항목으로 이동 (2차 멘토링 지적 ②)
- ✅ 문서 주장과 코드 구현의 일치를 **전수 감사**하기로 — 1차 멘토링 "시뮬레이션만으로는 부족" 지적의 확장

- **참석** 성시준, 석태경
- **배경** 회의 2에서 결정한 **코드베이스 전수 감사** 결과 보고 — **결함 2건이 설계 근간을 흔들었다**

〔사진 삽입 — 회의3_실험실_KOREN실증.jpg〕

## 1. 안건 A — 전수 감사에서 나온 치명적 결함

- **가설 7** 이전 실험의 "FedAvg보다 빠르다"가 우리 기법의 성과일 것이다 → **기각.** 시간 모형에 **네트워크 항이 없어** 대역폭 배분 기여가 정확히 **0**
- **가설 8** Oort 기준선이 제대로 재현되었을 것이다 → **기각 2건.** ε-greedy 자리 계산 오류로 실질 탐색률 50%, 목표마감 고정으로 페널티 포화
- 상세는 **중간보고서 부록 A 표 A-2** 참조

- **가설 7의 검산이 결정적이었다** — 연산이 3초/15초 이분법이고 네트워크 항이 없으면 라운드 시간의 기대값은
  - $0.330 \times 3 + 0.670 \times 15 = 11.0\text{초}$
  - 실측 165초 / 15라운드 = **11.0초**. **소수점까지 일치**
  - → 우리가 "우리 기법 덕분"이라 믿었던 속도 개선은 **동전던지기 결과**였음
- 즉시 합의 : **속도 주장 전면 폐기, 시간 모형 수정 후 전 실험 재실행**
- 가설 8의 수정 2건은 **둘 다 기준선(Oort)에 유리해지는 방향** — 그래도 고치기로 함
  - 성시준 : 기준선을 불리하게 둔 비교는 심사에서 한 번에 무너진다

## 2. 안건 B — FedScale 50만 대 재계산 결과

![FedScale 재계산](../../out/fig/fedscale_bw.png)

- 회의 2에서 5G 데이터셋 인용을 철회(가설 11 기각 — 100개 기관이 아니라 **단일 테스트베드의 설정 스윕**이었음)한 뒤,
  대체 근거로 FedScale 실측 프로파일 **50만 대 전수**를 직접 재계산

- **통신 이질성 37.1배가 연산 이질성 10.0배의 3.7배** — 병목의 큰 쪽이 네트워크다
- 분위값 전체는 **중간보고서 표 2** 참조

- **결정적 수치 : 두 이질성의 상관 ρ = +0.0024** — 사실상 독립
- 석태경 : 연산이 느린 노드와 회선이 느린 노드가 **서로 다른 집단**이라는 뜻
- 성시준 : 그러면 **하나의 규칙으로 두 병목을 동시에 다룰 수 없다.** 지금 우리 설계가 정확히 그걸 하고 있음

## 3. 논의 — 계층을 어디서 자를 것인가

- 두 병목이 독립 → **두 지렛대를 서로 다른 물리 구간에 배치**하자
  - **클라이언트 → 엣지** : 병목은 **계산 시간**, 지렛대는 **누구를 뽑나** → **선별층**
  - **엣지 → 서버** : 병목은 **대역폭**, 지렛대는 **얼마씩 주나** → **배분층**
- 부수 효과 발견 : 2계층이면 백본에 올라가는 것이 **엣지당 부분집계 1개뿐**
  - 부하 N·P → E·P (본 실험 기준 **1/20**)
  - 커버리지 보장의 비용이 **엣지 LAN 안에 갇혀** 공유 회선으로 전파되지 않음
  - → **"공정성을 속도로 사지 않는다"** 가 구조에서 나옴
- 배분식도 교체 : **Softmax 가중은 총량 보존과 마감 충족을 보장하지 못함**
  - → **마감 워터필링** — 마감 $T$를 제약으로 두고 $\sum_e P/(T-r_e) \le C_B$ 를 만족하는 최소 $T^*$ 를 이분탐색

## 4. 결정 사항

- ✅ **2계층 분리** — 선별층(클라이언트↔엣지) / 배분층(엣지↔서버)
- ✅ **배분 방식 교체** : Softmax 가중 → **마감 워터필링** (총량 보존, 물리 클램프 유지)
- ✅ **선발 로직 확정** : **커버리지 보장 + 가치÷비용**
  - Oort의 곱셈 페널티 `× min(1, T/tᵢ)` 는 느린 노드를 0으로 수렴시킴 → **나눗셈** `vᵢ/cᵢ` 로 바꿔 순위만 낮춤
- ✅ **2×2 절개 실험 설계** — 두 층의 기여가 겹치는지 겹치지 않는지를 직접 재기로 함
- ✅ 전 실험 **3시드 재실행**, 결과는 "이전 설계 시기"와 "현재 설계"로 **출처 표기해 분리 게재**
